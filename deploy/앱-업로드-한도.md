# 앱 쪽에서 함께 올려야 하는 것 — 업로드 본문 한도

〈2026-08-22 · 한도를 **파일 하나 30MB · 한 번에 100MB** 로 올리면서〉

---

## 왜 이 문서가 있나

엔진에서 한도를 올렸다. 그런데 **엔진까지 오지도 못하고 끊기는 자리가 하나 더 있다.**

```
휴대폰 ──▶ 앱 Node API(8181) ──▶ 엔진(report-api)
              ▲
              └── express.json() 의 본문 한도.
                  기본값이 100KB 다. 여기서 먼저 끊긴다.
```

**여기서 끊기면 오류가 전혀 다른 얼굴로 나온다.** 화면은 「파일 하나 30MB 까지
올릴 수 있습니다」라고 적혀 있는데 25MB 짜리를 올리면 `413 Payload Too Large`
또는 그냥 「전송이 끊겼습니다」가 뜬다. **화면이 말하는 한도와 실제로 걸리는
한도가 달라서**, 사장님도 저도 「30MB 라더니 왜 안 되나」로 한참 헤매게 된다.

---

## 무엇을 넣나

파일은 **base64** 로 실려 온다 — 원본보다 약 **33% 크다.**

| | 파일 크기 | 실려 오는 본문 |
|---|---|---|
| 파일 하나 | 30 MB | 약 **40 MB** |
| 한 번에 | 100 MB | 약 **133 MB** |

그래서 본문 한도는 **최소 141MB** 로 잡는다 (여유 8MB 포함).
이 값은 엔진이 계산해서 내준다 — 손으로 적지 않는다.

```js
const { MIN_BODY_BYTES } = require('.../im-agent/ui/api-router.cjs');

app.use(express.json({ limit: MIN_BODY_BYTES }));   // 약 141MB
```

**엔진 값을 그대로 쓰는 것이 요점이다.** `'150mb'` 처럼 적어 두면 다음에 한도를
올린 날 이 줄만 옛 숫자로 남고, 그때 증상은 위에 적은 그대로 다시 나온다.

---

## 어디에 넣나

앱 본체(`linkpilot-platform`)의 Node API 부팅 코드에서 **라우터를 붙이기 전**에
`express.json()` 을 거는 자리다. 대개 `app.js` · `server.js` · `api/index.js`
중 하나에 있다. `express.json(` 으로 찾으면 나온다.

**이미 `express.json()` 이 걸려 있다면 그 줄에 `limit` 만 더한다.** 새로 하나 더
걸면 안 된다 — 앞에 걸린 것이 먼저 잡아서 여전히 100KB 에서 끊긴다.

---

## 넣고 나서 확인하는 법

1. 「자료 업로드」 탭에서 **25MB 짜리 파일 하나**를 올린다
2. 「올렸습니다」가 뜨면 된 것이다
3. 여전히 안 되면 **어디서 끊겼는지**를 이렇게 가른다

| 나오는 말 | 어디서 끊겼나 | 할 일 |
|---|---|---|
| `413` · `PayloadTooLargeError` | **앱 express** — 아직 100KB 다 | 위 `limit` 을 넣는다 |
| 「파일이 너무 큽니다 — N MB (한도 30.0 MB)」 | **엔진** — 정상 동작이다 | 파일을 나눠 올린다 |
| 「전송이 끊겼습니다」 | 앞단(리버스 프록시)일 수 있다 | 아래 |

---

## 앞단이 하나 더 있을 수 있다

Synology 의 리버스 프록시나 nginx 를 거친다면 **거기에도 본문 한도가 있다.**
nginx 기본값은 `client_max_body_size 1m` 이다.

```nginx
client_max_body_size 141m;
```

DSM 에서는 **제어판 → 응용 프로그램 포털 → 역방향 프록시** 에서 해당 규칙을
편집하고, **사용자 지정 헤더** 가 아니라 **고급 설정**에 있다. 이 자리는 화면에
잘 안 보여서 대개 여기서 막힌다.

---

## 함께 봐 둘 것 — 메모리

운영 NAS 는 **RAM 1.8GB** 다. 133MB 본문을 파싱하면 문자열과 디코드 버퍼로
순간 **300MB 안팎**을 쓴다. 한 사람이 올릴 때는 견디지만,
**여럿이 동시에 100MB 를 올리는 상황을 견디는 값은 아니다.**

그때는 엔진 한도를 낮추는 것이 아니라 **앱 쪽에서 동시 업로드 수를 제한한다** —
한도를 낮추면 큰 파일을 아예 못 올리게 되어 원래 요청이 무의미해진다.
