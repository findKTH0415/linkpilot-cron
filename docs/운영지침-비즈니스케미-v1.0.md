- 작성일: 2026-10-17 · Asia/Seoul
- 문서 버전: v1.0
- 메뉴명: **비즈니스 케미**
- 화면 타이틀: **명리학으로 풀어보는 우리들의 사업궁합**
- 문서 상태: 기획·구현 지침. 실제 플랫폼 적용 및 배포는 별도 작업.
- 대상: 국내외 사업주·투자자·구매자·판매자·공급사·현지 파트너·자문사 등 사업 당사자

## 1. 서비스 목적과 운영 원칙

명함에 등록한 파트너와 출생정보를 연결해, 전통 명리학의 관점에서 사업 관계를 돌아보는 서비스를 제공한다. 해석을 읽은 뒤 역할 분담·소통·협의 질문·후속 업무로 연결한다.

핵심 질문은 “이 사람과 어떤 방식으로 협력하면 좋을까?”로 한다.

- 명리학을 중심 콘텐츠로 구성한다.
- 명함은 인물 식별과 사업 관계 연결에 사용한다. 이름·직책·회사명에서 사주나 성격을 추정하지 않는다.
- 계산된 명식, 전통 해석, 일반적인 실무 제안, 당사자의 실제 응답을 구분한다.
- 출생정보만으로 실제 성격·신용·재무능력·거래 안전성·사업 성공 확률을 판정하지 않는다.
- 초대·분석 참여·공유는 사용자가 선택한다. 기본 화면은 비공개로 운영한다.

### 서비스 안내 문구

> 전통 명리학에 따른 문화·자기성찰 콘텐츠입니다. 실제 성격·신용·사업성과를 검증하거나 예측하지 않습니다. 사업 판단은 확인된 자료와 당사자 간 협의를 바탕으로 해주세요.

메인 메뉴에는 독립 진입점을 제공하고, 인맥관리의 명함 상세에도 같은 기능으로 연결한다.

## 3. 회원가입 — 생일 축하를 통한 선택 입력

### 화면 문구

**회원님의 특별한 날을 알려주세요 🎂**

생일을 알려주시면 특별한 날, LinkPilot이 따뜻한 축하 메시지를 전해드립니다.

**생년월일 · 선택 입력**

[출생연도 · 선택] [월] [일] [양력 / 음력]

월·일만 입력해도 생일 축하를 받을 수 있어요. 출생연도까지 등록하면 ‘비즈니스 케미’ 이용 시 다시 입력할 필요가 없습니다.

생일 정보는 기본 비공개입니다. 사업궁합에 활용할 때에는 해당 기능의 이용 목적을 안내하고 참여 여부를 확인합니다.

[ ] 생일 축하 알림 받기 · 선택

**[생일 저장하고 계속] [나중에 입력]**

### 입력·알림 처리

- 생일을 입력하지 않아도 가입과 기본 서비스를 이용할 수 있다.
- 출생연도는 선택 입력으로 둔다. 가입 완료를 위해 연도를 강제하지 않는다.
- 월과 일은 함께 입력하거나 함께 비워둔다.
- 음력 선택 시 윤달 여부를 표시한다.
- 출생연도 없는 음력 생일도 축하용으로 저장할 수 있지만, 정확한 출생일 변환과 궁합에는 연도 추가 입력이 필요하다.
- 윤달 생일, 해당 월에 일자가 없는 생일, 2월 29일의 축하 기준일은 사용자가 선택하거나 명시된 대체일 정책을 적용한다. 조용히 임의 변경하지 않는다.
- 생일 정보 저장, 축하 알림 수신, 궁합 참여, 상대방 공유의 선택 상태를 분리한다.
- 앱 내 알림·이메일·문자는 채널별로 사용자가 선택한다. 마케팅 수신 동의와 묶지 않는다.
- 사용자 시간대의 생일에 발송하고, 같은 연도·사용자·채널에 중복 발송하지 않는다.
- 가입 당시 고지·동의한 목적을 넘어 정보를 사용할 때에는 필요한 안내와 적법한 처리 근거를 갖춘다.
- 개인정보 동의 화면에는 실제 수집항목·목적·보유기간·거부 시 영향 등을 연결한다. 위 문구만으로 법적 고지를 대체하지 않는다.

### 생일 축하 메시지 예시

> 회원님, 생일을 진심으로 축하드립니다. 오늘은 소중한 분들과 따뜻한 시간을 보내시고, 앞으로의 사업과 일상에도 좋은 인연이 함께하시길 바랍니다. — LinkPilot

실제 이름을 넣는 개인화는 회원이 설정한 표시 이름을 사용한다. 나이·출생연도·궁합 결과는 축하 메시지에 자동으로 노출하지 않는다.

## 4. 궁합 이용 흐름과 입력항목

### 이용 순서

1. 나의 출생정보 확인
2. 명함에서 파트너 선택 또는 파트너 초대
3. 상대방이 직접 출생정보 입력 및 분석 참여 선택
4. 사업 관계 유형 선택
5. 명식 계산 및 관계 해석
6. 결과 확인 후 공유 범위 선택
7. 협의 질문을 메모·일정·할일로 연결

명함 등록과 초대만으로 상대방의 분석 참여가 승인된 것으로 처리하지 않는다. 사용자가 알게 된 타인의 생년월일을 동의 없이 입력해 인물 평가를 생성하는 기본 흐름을 만들지 않는다.

| 입력항목 | 기준 |
| --- | --- |
| 이름·회사·직책 | 명함에서 불러오되 사용자 확인 |
| 생년월일 | 궁합에는 연·월·일 필요 |
| 달력 종류 | 양력 또는 음력, 음력은 윤달 여부 확인 |
| 출생시간 | 정확히 앎 / 대략 앎 / 모름 |
| 출생 국가·도시 | 출생 당시 지역의 시간대·보정 처리에 사용 |
| 관계 유형 | 동업 / 투자 협의 / 거래 / 프로젝트 협력 |
| 결과 언어 | 사용자 선택 |
| 참여·공유 | 분석 참여와 결과 공유를 별도 선택 |

기본 두 사람 관계 해석에는 성별을 필수로 수집하지 않는다. 대운 등 별도 체계의 확장 기능이 필요해질 경우 입력 필요성과 해석 기준을 다시 검토한다.

### 정보 부족 시 처리

- 출생연도가 없으면 생일 축하만 이용하고, 궁합을 시작할 때 연도를 요청한다.
- 출생시간을 모르면 임의 시각을 넣지 않고 시주를 미확정으로 둔다.
- 대략적인 시간만 알면 시간 범위를 저장하고, 그 범위에서 달라지는 결과를 구분한다.
- 절입·일주 경계 등에 걸린 경우 연주·월주·일주도 달라질 수 있으므로 영향을 받는 해석을 제한한다.
- 계산 지원 범위를 벗어난 출생일·지역은 지원 불가 사유를 안내한다.
- 상대방 미참여 상태는 “파트너의 참여를 기다리고 있어요”로 표시한다.
- 초대 링크는 만료·취소가 가능해야 하며, 링크만으로 원시 출생정보나 다른 인맥 자료를 열람할 수 없게 한다.

## 5. 결과 화면과 관계 유형별 구성

결과 화면의 순서는 종합 관계 유형 → 사업별 해석 → 명리 근거 → 함께 확인할 질문 → 협의 메모로 한다.

| 결과 카드 | 내용 |
| --- | --- |
| 우리의 관계 유형 | 전통 해석상 공통점·보완점·조율할 부분 |
| 사업 추진 관계 | 아이디어·실행·관리 관점의 해석 |
| 의사결정과 소통 | 의견 차이를 돌아볼 관점 |
| 자금·보상 협의 | 비용·권한·수익 배분을 확인할 질문 |
| 장기 협력 관계 | 책임 범위·관계 유지에 관한 제안 |
| 명리 해석 근거 | 계산된 일간·오행·십성·합충 등의 설명 |
| 다음 협의 | 실제로 확인할 질문과 메모 |

결과는 “공통점이 많은 관계”, “보완점을 살펴볼 관계”, “조율을 논의할 관계” 등 설명형으로 제공한다. 초기에는 성공 확률이나 신용 점수로 오인할 수 있는 종합 백분율 대신 설명형 태그를 사용한다.

“입력정보 확인 상태”와 “해석의 의미”를 분리한다. 출생정보가 완전하다는 표시를 과학적 예측 정확도나 사업 적합성의 보증으로 표현하지 않는다.

| 관계 유형 | 추가로 제공할 협의 질문 |
| --- | --- |
| 동업 | 출자·역할·결정권·보수·수익 배분·의견 충돌 해결 방법 |
| 투자 협의 | 자금 집행·자료 보고·주요 승인·회수 조건 |
| 거래 | 사양·대금·납기·검수·변경 승인 |
| 프로젝트 협력 | 업무 범위·일정·산출물·승인 책임 |

관계 유형은 실무 질문의 구성을 바꾸는 데 사용한다. 같은 두 사람의 기초 명식을 관계 유형에 맞춰 임의로 바꾸지 않는다.

## 6. 명리 해석과 문장 생성 기준

| 요소 | 해석 범위 |
| --- | --- |
| 일간 | 전통적으로 설명하는 기본 기질 |
| 오행·계절 | 분포와 계절을 함께 살핀 전통 해석 |
| 십성 | 표현·실행·관리·자원 등과 연결한 전통적 관점 |
| 천간·지지 관계 | 합·충 등 관계 요소 |
| 종합 해석 | 여러 요소를 함께 고려한 설명 |

- 채택한 명리 체계와 학파별 차이를 문서화한다.
- 오행 개수만으로 좋고 나쁨을 판정하지 않는다.
- 합·충 한 가지로 동업 가능·불가를 결론 내리지 않는다.
- 전통 해석의 근거와 일반적인 실무 조언을 구분해 표시한다.
- 실제 성향은 당사자가 확인하고 수정 의견을 남길 수 있게 한다.
- 배신·사기·파산·질병·수명·필연적 실패 같은 단정적 인물 평가를 생성하지 않는다.
- 투자자 검색, 신용 판단, 채용, 거래 승인·거절의 자동 결정에 궁합을 연결하지 않는다.
- 특정 국적·성별·나이·종교를 사업 역량의 대리 지표로 사용하지 않는다.

### 결과 문구 예시

아래는 화면 설명을 위한 예시이며 실제 사주 계산 결과가 아니다.

**우리의 비즈니스 케미 — 추진과 점검의 균형**

**명리 해석**  
이 조합은 전통 해석상 새로운 방향을 여는 관점과 조건을 살피는 관점을 함께 돌아보는 관계로 설명할 수 있습니다.

**협업에 적용해보기**  
제안을 만드는 역할과 예산·일정을 검토하는 역할을 나누는 방식을 논의해보세요. 실제 업무 성향이 해석과 맞는지는 서로 확인하는 것이 좋습니다.

**첫 협의에서 나눌 질문**

1. 어느 금액까지 각자 결정할 수 있나요?
2. 추가 비용은 누가 승인하나요?
3. 의견이 다를 때 어떻게 결정하나요?

**버튼:** 협의 메모 작성 / 미팅 준비에 추가 / 공유 요청

## 7. LinkPilot 기존 섹션 연동

| 섹션 | 연동 내용 |
| --- | --- |
| 인맥관리·명함 | 명함 상세의 “사업궁합 보기” |
| 프로젝트 | 참여 동의가 확인된 두 사람의 결과 연결 |
| 일정 | 미팅 준비에 사용자가 선택한 질문 추가 |
| 할일 | 질문의 후속 업무를 사용자 확인 후 생성 |
| 오늘의 브리핑 | 예정된 미팅의 준비 항목 표시 |
| 오늘의 인사이트 | 감사·축하·후속 연락 문구 제안 |
| 커뮤니티 | 선택형 궁합 참여 초대 |
| 내 정보 | 출생정보·알림·참여·공유·삭제 관리 |

미팅 준비에 추가할 때 원시 출생정보와 전체 궁합을 자동으로 복사하지 않는다. 공유 캘린더에는 사용자가 선택한 일반 협의 질문만 넣는다.

프로젝트에 결과를 연결해도 프로젝트 전체 참여자에게 자동 공개하지 않는다. 연락처·프로젝트의 기존 열람 권한이 출생정보 열람 권한으로 확대되지 않도록 한다.

## 8. 계산 엔진·API·AI 역할

### 처리 구조

출생정보 정규화 → 명식 계산 → 명리 규칙 적용 → AI 해설 → 사용자 확인

| 구분 | 역할 |
| --- | --- |
| 달력 처리 | 양·음력 변환, 윤달 확인, 지원 범위 점검 |
| 시간 처리 | 출생 당시의 지역 시간대·서머타임과 경계 처리 |
| 명식 엔진 | 연주·월주·일주·시주 계산 |
| 해석 엔진 | 계산 결과에 명리 규칙 적용 |
| AI 해설 | 확정된 계산·해석 자료를 쉬운 문장으로 설명 |
| 버전 기록 | 입력·계산 정책·엔진·해석·번역 버전 보관 |

### 필수 구현 기준

- AI가 생년월일만 보고 사주팔자나 절입 시각을 임의 생성하지 않게 한다.
- 연주·월주의 경계는 채택한 명리 기준과 정확한 절입 자료에 따라 처리한다. 양력 1월 1일이나 음력 초하루로 단순 대체하지 않는다.
- 한국 달력 API의 간지 필드를 사주명리용 연주·월주와 무조건 동일하다고 가정하지 않는다.
- 일주 경계, 야자시 처리, 표준시·태양시 보정 등은 학파 차이가 있으므로 계산 정책을 명시하고 검증한다.
- 구현 전 채택 정책을 확정해 버전으로 고정한다. 서로 다른 기준을 한 결과에 섞지 않는다.
- 해외 출생자를 모두 한국시간으로 일괄 변환하지 않는다. 지역·시대별 시간 규칙과 채택한 명리 계산 정책을 함께 적용한다.
- 같은 입력·같은 계산 정책·같은 엔진 버전에서는 동일한 명식이 나와야 한다.
- 입력 수정 시 영향을 받는 결과는 재계산하고, 과거 결과에는 이전 정보에 따른 결과임을 표시한다.
- 개인정보를 제외한 계산정보로 재사용이 가능한 구간을 구분한다. 이름·회사·연락처는 해설에 꼭 필요하지 않으면 외부 모델에 전송하지 않는다.
- 명함 OCR 텍스트는 외부 입력 데이터로 처리하고, 포함된 문구를 AI 실행 지시로 받아들이지 않도록 한다.

## 9. 개인정보·권한·공유 기준

다음은 제품 설계 기준이며, 실제 서비스 국가와 제공 방식에 맞춘 개인정보 고지·보유기간·국외 이전 등은 출시 전에 확정한다.

- 출생정보는 일반 명함 연락처와 별도 권한으로 관리한다.
- 분석 참여·생일 알림·결과 공유를 목적별로 구분한다.
- 회원과 초대받은 당사자가 자신의 정보를 확인·수정·삭제할 수 있게 한다.
- 생년월일·출생시간·출생지·파생 명식·관계 해석 결과를 모두 접근 통제 대상에 포함한다.
- 전송·저장 구간을 보호하고 관리자 접근도 업무상 필요한 범위로 제한한다.
- 오류 로그·사용자 행동 분석·공유 링크에 원시 출생정보를 남기지 않는다.
- 실제 개인정보를 개발 테스트 데이터로 복사하지 않는다.
- 공유 결과는 출생정보를 기본으로 숨긴다. 명식도 출생정보를 추론할 수 있는 정보로 취급한다.
- 공유 권한은 해제·만료가 가능하게 한다. 이미 내려받은 파일이나 캡처는 회수할 수 없다는 점을 공유 시 안내한다.
- 삭제·참여 철회 시 기존 분석과 파생 데이터의 처리 범위를 명확히 하고, 관련 공유 링크와 재분석 권한을 해제한다.
- 외부 AI·번역·명리 API 전송은 실제 처리 목적과 범위를 고지하고 필요한 처리 근거를 갖춘다.
- 암호화나 이름 제거만으로 개인정보가 익명화되었다고 표현하지 않는다.

## 10. 화면·다국어·모바일 기준

- 모바일에서는 1열 카드로 구성하고, 출생정보 → 관계 선택 → 결과 순서를 유지한다.
- 한자·전문용어는 펼침 영역에서 설명하고 기본 화면은 쉬운 말로 제공한다.
- 합·충, 일간, 십성 등 주요 용어는 언어별 용어집으로 관리한다.
- 번역은 문장 표현을 바꾸되 명식·간지·날짜·계산 기준은 바꾸지 않는다.
- 긴 해외 인명·회사명·번역문이 카드나 버튼에서 겹치지 않게 한다.
- 색상만으로 결과를 구분하지 않고 문구와 아이콘을 함께 사용한다.
- 절대적인 길흉·공포 문구로 추가 구매를 유도하지 않는다.
- 계산 지연·실패·지원 불가·정보 부족 상태를 구분해 안내한다.
- 출생정보 수정 버튼과 계산 기준 보기 버튼을 결과 화면에서 찾기 쉽게 배치한다.

## 12. 운영 지표와 실행 지시

초기 운영에서는 생일 입력률, 명함 연계 시작률, 파트너 참여율, 궁합 완료율, 협의 메모 작성률, 미팅 준비 연결률을 확인한다. 개인정보 삭제·알림 해제와 부정확한 계산 신고도 함께 모니터링한다.

조회 수만으로 성과를 판단하지 않고, 결과가 당사자 간 실제 대화 준비에 도움이 되었는지 확인한다. 해석 적중률이나 사업 성공률을 사용자 만족도와 동일한 지표로 발표하지 않는다.

### 개발 담당자 전달문

> LinkPilot에 독립 메뉴 “비즈니스 케미”를 추가하고, 화면 타이틀을 “명리학으로 풀어보는 우리들의 사업궁합”으로 적용한다. 회원가입에서는 생일 축하 메시지 혜택을 안내해 생년월일 선택 입력을 유도한다. 명함은 파트너 선택과 사업 관계 연결에 사용하고, 출생정보는 당사자가 직접 입력·확인하도록 한다. 검증된 명식 계산과 명리 규칙을 기반으로 관계 해석을 제공하며, AI는 계산 결과를 설명하는 역할을 담당한다. 결과는 협의 질문·메모·일정·할일로 연결한다. 원시 출생정보와 해석 결과는 기본 비공개로 관리하고, 참여·알림·공유를 분리한다. 계산 경계와 개인정보·권한 검수를 완료한 뒤 실제 플랫폼에 반영한다.
