## 0-1. **화면을 올리는 길은 둘이다** — 어느 쪽이든 된다 〈2026-08-21 추가〉

Secret 다섯을 기다리는 동안 **화면은 지금도 올릴 수 있다.** 둘의 차이만 알면 된다.

| | **사람이 손으로** (지금 바로 된다) | **Actions 로** (Secret 다섯 필요) |
|---|---|---|
| 무엇을 올리나 | 화면 사본 (`im-flow`) | 화면 사본 **+ 엔진** |
| 어디서 | 내 Mac 에서 두 저장소를 오가며 | 저장소 Actions 단추 하나 |
| 지문 대조 | 앱 쪽 게이트가 한다 | `verify:nas` 가 한다 |
| 언제 쓰나 | **화면만 고쳤을 때** | 엔진까지 고쳤을 때 · 손이 못 닿을 때 |

**손으로 올리는 최단 경로** — 경로를 한 번만 정해 두면 그 뒤로는 세 줄이다:

```bash
export LP_APP_DIR="$HOME/…/24.홈페이지"      # ← 한 번만. ~/.zshrc 에 넣어 둔다
cd ~/linkpilot-cron && npm run im:embed      # 사본을 앱 폴더로 낸다
cd "$LP_APP_DIR" && node test-integration-contract.js && python3 deploy-filestation.py
```

★★ **자리표시를 그대로 붙여 넣어 죽은 적이 있다** (2026-08-21). 그래서
`npm run im:embed` 는 자리표시·없는 폴더·`im-flow` 아닌 곳을 **거절하고 무엇이
잘못됐는지 말한다.** 그래도 첫 줄의 경로는 **직접 고쳐야 한다** — 그 한 곳뿐이다.

★ **엔진을 고쳤으면 이 길로는 안 간다.** `deploy:nas` 나 Actions 가 필요하다.
  화면만 올리고 엔진이 옛 판이면 **화면이 없는 API 를 부른다.**

## 1. 넣어야 하는 것 — 저장소 `Settings › Secrets and variables › Actions`

### 화면만 올리려면 — **셋**

| Secret | 무엇 | 없으면 |
|---|---|---|
| `TS_OAUTH_CLIENT_ID` | Tailscale OAuth client ID (tag:ci 권한) | **지금 여기서 멈춘다** |
| `TS_OAUTH_SECRET` | 〃 secret | 〃 |
| `NAS_SSH_HOST` | NAS 의 tailnet 주소 | 붙어도 어디로 보낼지 모른다 |
| `NAS_SSH_USER` | ssh 계정 | 〃 |
| `NAS_SSH_KEY` | ssh 개인키 (전문) | 〃 |

★ 셋이 아니라 다섯이다 — `NAS_SSH_*` 셋은 이미 D-12 목록에 있던 것이다.

### 엔진까지 올리고 **잰 것을 남기려면** — 셋 더

| Secret | 무엇 | 없으면 |
|---|---|---|
| `LP_BASE` | 공개 주소 (`https://…`) | **올리긴 했는데 잰 것이 없다.** 지문 대조를 못 해 「초록인데 옛 판」을 못 잡는다 (M-12) |
| `NAS_WEB_ROOT` | 웹 루트 (기본 `/volume1/web`) | 기본값으로 간다. 다르면 엉뚱한 곳에 올라간다 |
| `NAS_ENGINE_ROOT` | 엔진 루트 (기본 `/volume1/docker/linkpilot`) | 〃 |

> **값은 여기에도, 코드에도, 커밋에도 적지 않는다.** GitHub Secrets 에만 넣는다
> (CLAUDE.md §2 · D-10). 워크플로에 주소가 한 글자도 없는 것을 검사가 지킨다.

## 1-1. 먼저 — **이게 다 무슨 이야기인가** (쉬운 말로)

낯선 낱말이 여러 개 나옵니다. 하나씩 풀면 이렇습니다.

### 왜 이 일이 필요한가

지금 상황을 사람에 비유하면 이렇습니다.

> 제가 **원고를 다 썼는데**, 그 원고를 **인쇄소(NAS)에 갖다 줄 수가 없습니다.**
> 인쇄소가 회사 건물 안에 있고 저는 출입증이 없기 때문입니다.
> 그래서 **심부름꾼(GitHub 서버)** 에게 맡기려는 것인데,
> 그 심부름꾼도 **출입증이 있어야** 건물에 들어갑니다.
>
> **지금 넣어 달라는 다섯 가지가 그 출입증입니다.**

### 낱말 풀이 — 다섯 개만 알면 됩니다

| 낱말 | 쉬운 말 |
|---|---|
| **NAS** | 사무실에 있는 저장 장치. 여기에 화면 파일이 올라가야 앱에 반영됩니다 |
| **Tailscale** | 사무실 밖에서도 NAS 에 안전하게 들어가게 해 주는 **전용 통로**. 이 통로가 있어야 바깥 컴퓨터가 NAS 를 볼 수 있습니다 |
| **OAuth 클라이언트** | 그 통로를 쓸 수 있는 **출입증 한 장**. 사람 계정이 아니라 **기계 전용** 출입증입니다 |
| **ACL** (액세스 컨트롤) | 「누가 어디까지 들어갈 수 있나」를 적어 둔 **출입 규정표** |
| **SSH 키** | NAS 문을 여는 **열쇠**. 두 조각으로 나옵니다 — **공개키**(자물쇠)는 NAS 에 붙이고, **개인키**(열쇠)는 GitHub 금고에 넣습니다 |

### 그래서 하는 일이 셋입니다

```
① 출입 규정표에 「CI 라는 이름표를 단 기계는 들어와도 된다」를 적는다   (Tailscale)
② 그 이름표를 단 출입증을 한 장 발급한다                              (Tailscale)
③ NAS 문 열쇠를 만들어, 자물쇠는 NAS 에 붙이고 열쇠는 GitHub 금고에    (SSH)
```

그다음 **GitHub 금고(Secrets)** 에 다섯 개를 넣으면 끝입니다.

> **금고에 넣는 이유**: 출입증과 열쇠를 코드에 적으면 **누구나 볼 수 있습니다.**
> 이 저장소는 공개(public)라 더 그렇습니다. GitHub Secrets 는 넣고 나면
> **본인도 다시 못 봅니다** — 그게 정상이고, 그래서 안전합니다.

### 얼마나 걸리나

처음 하시면 **15~20분**, 막히면 30분쯤 봅니다. 막히는 자리는 아래에 미리 표시해 뒀습니다.

## 1-2. 어떻게 만드나 — **순서대로**

> **값을 채팅·커밋·문서에 붙여넣지 않는다.** GitHub Secrets 칸에 **직접** 넣는다.
> 한 번 넣으면 다시 못 본다 — 그것이 정상이다.

### ① Tailscale OAuth — `TS_OAUTH_CLIENT_ID` · `TS_OAUTH_SECRET`

**★ 순서가 중요하다. 태그를 먼저 만들지 않으면 ②에서 막힌다.**

#### 1-①. 무엇을 하는 것인가 — 먼저 이해하고 들어간다

앞의 비유를 이어 가면 이렇습니다.

> 심부름꾼(GitHub 서버)에게 **출입증**을 주려고 합니다. 그런데 출입증을 만들려면
> **먼저 「이런 이름표를 단 사람은 들어와도 된다」는 규정이 있어야** 합니다.
> 규정에 없는 이름표는 출입증에 찍을 수가 없습니다.
>
> **`tag:ci` 가 그 이름표이고, 규정표에 그 이름을 올리는 것이 이 단계입니다.**

- **태그(tag)** — 기기에 붙이는 이름표. 사람 계정이 아니라 **기계에 붙인다.**
  CI 러너는 매번 새로 생겼다 사라지므로 사람 계정을 줄 수 없다.
- **`tagOwners`** — 「이 이름표를 **누가 붙일 수 있나**」를 적는 칸.
- **정책 파일(policy file)** — 출입 규정표 전체. 콘솔에서 글로 고친다.

---

#### 1-②. ★★ 시작하기 전에 — **기존 정책을 지우지 않는다** 🔴

여기가 이 문서에서 **제일 위험한 자리**입니다.

> **아래 예시는 「파일 전체」가 아닙니다.** 화면에 이미 있는 내용을 지우고
> 예시만 붙여 넣으면, **지금 있는 접속 허용 규칙까지 함께 지워집니다.**
> 그러면 **본인의 NAS 접속이 끊길 수 있습니다.**

**하는 일은 딱 하나입니다 — 지금 있는 파일에 `tagOwners` 를 「더한다」.**

시작 전에 **지금 내용을 통째로 복사해 메모장에 붙여 두십시오.** 잘못되면
그대로 되돌리면 됩니다. 30초면 되고, 이것을 안 해서 곤란해지는 경우가 많습니다.

---

#### 1-③. 어디를 눌러야 하나 — 순서대로

**1)** 브라우저에서 **login.tailscale.com** 으로 들어가 로그인합니다.

**2)** 위쪽 메뉴에서 **`Access controls`** 를 누릅니다.
   (관리자 계정으로 로그인해야 이 메뉴가 보입니다. 안 보이면 §1-⑦ 을 봅니다.)

**3)** 큰 글상자에 지금 정책이 글로 보입니다. **여기 내용을 전부 복사해 둡니다.**
   (1-② 에서 말한 그 백업입니다.)

**4)** 파일이 대개 이렇게 생겼습니다 — **맨 바깥이 중괄호 하나**입니다.

```jsonc
{
	"acls": [
		{"action": "accept", "src": ["*"], "dst": ["*:*"]},
	],
}
```

**5)** 여기에 **`tagOwners` 만 더합니다.** `acls` 는 **그대로 둡니다.**

```jsonc
{
	// ★ 더하는 것은 이 세 줄뿐입니다
	"tagOwners": {
		"tag:ci": ["autogroup:admin"],
	},

	// ↓ 원래 있던 것 — 지우지 않습니다
	"acls": [
		{"action": "accept", "src": ["*"], "dst": ["*:*"]},
	],
}
```

- `autogroup:admin` 은 「이 tailnet 의 관리자면 이 이름표를 붙일 수 있다」는 뜻입니다.
- 이 파일은 **주석(`//`)과 마지막 쉼표를 허용**합니다 (HuJSON). 보통 JSON 과 다릅니다.
- 원래 파일에 `tagOwners` 가 **이미 있으면** 그 안에 `"tag:ci": [...]` 한 줄만 더합니다.
  `tagOwners` 를 두 번 적으면 저장이 거부됩니다.

**6)** 오른쪽 아래 **`Save`** 를 누릅니다.
   틀린 곳이 있으면 저장이 안 되고 **몇 번째 줄이 문제인지** 알려 줍니다.

---

#### 1-④. 저장됐는지 **확인**하고 넘어간다

저장만으로는 됐는지 알기 어렵습니다. **다음 단계 화면에서 확인**하는 것이 확실합니다.

관리자 콘솔 › **`Settings`** › **`OAuth clients`** › **`Generate OAuth client…`**

이 창의 **`Tags`** 칸에서 **`tag:ci` 가 고를 수 있게 떠 있으면 성공**입니다.
**안 뜨면 5)번이 저장되지 않은 것입니다** — 되돌아가 다시 봅니다.

#### 1-⑤. OAuth 클라이언트를 만든다

같은 창에서 이어서 합니다.

| 고를 것 | 값 | 왜 |
|---|---|---|
| **Scope** | **`Auth Keys`** — **`write`** | 러너가 접속할 때 쓸 **1회용 열쇠를 스스로 만들어야** 하기 때문입니다 |
| **Tags** | **`tag:ci`** | 그 열쇠로 붙은 기기에 이 이름표가 붙습니다 |

`Generate client` 를 누르면 **Client ID 와 Client Secret 이 나옵니다.**

> ★★ **Secret 은 이 화면에서 한 번만 보입니다.** 창을 닫으면 다시 못 봅니다.
> **그 자리에서 바로** GitHub 에 붙여넣으십시오 (아래 ③). 잃어버리면 지우고
> 새로 만들면 됩니다 — 되찾는 방법은 없습니다.

- 다른 칸(설명·만료 등)은 **기본값 그대로** 둬도 됩니다.
- **사람 계정 로그인 정보를 CI 에 주지 않습니다.** 이 한 쌍만 줍니다.
  나중에 이 클라이언트만 지우면 CI 접근이 깨끗이 끊깁니다.

#### 1-⑥. (선택) 나중에 **좁힌다** — 지금은 안 해도 됩니다

기본 정책이 「전부 허용」이라, 위까지만 해도 배포는 돕니다.
**한 번 성공한 뒤에** 아래처럼 좁히는 것을 권합니다 — 러너는 남의 컴퓨터이고,
배포에 필요한 것은 NAS 의 22 번 하나뿐입니다.

```jsonc
"acls": [
	// 원래 있던 규칙들은 그대로 두고, 아래 한 줄을 더한 뒤
	// 전부 허용(`"src": ["*"], "dst": ["*:*"]`) 규칙을 지운다
	{"action": "accept", "src": ["tag:ci"], "dst": ["<NAS 기기이름>:22"]},
],
```

- 기기 이름은 콘솔 **`Machines`** 목록에 있는 것을 그대로 씁니다.
- ★ **성공하기 전에 좁히지 마십시오.** 안 될 때 원인이 둘(ACL·열쇠)이 되어
  어느 쪽인지 가리기 어려워집니다.

★ 콘솔 화면은 Tailscale 이 이따금 바꿉니다. **메뉴 이름이 조금 다르면**
`Access controls` 는 「정책·ACL」, `OAuth clients` 는 「Settings 안의 키·토큰」
근처를 찾으십시오. 하는 일은 같습니다.

### ② NAS ssh 열쇠 — `NAS_SSH_HOST` · `NAS_SSH_USER` · `NAS_SSH_KEY`

**1) NAS 에서 SSH 를 켠다** — DSM › 제어판 › **터미널 및 SNMP** › `SSH 서비스 활성화`

**2) 열쇠 한 쌍을 만든다** (내 PC 에서. **암호는 비워 둔다** — CI 는 암호를 칠 수 없다)

```bash
ssh-keygen -t ed25519 -C "linkpilot-ci" -f ~/.ssh/lp_ci -N ""
```

**3) 공개키를 NAS 에 넣는다**

```bash
ssh-copy-id -i ~/.ssh/lp_ci.pub <계정>@<NAS주소>
```

`ssh-copy-id` 가 없으면 손으로:

```bash
cat ~/.ssh/lp_ci.pub | ssh <계정>@<NAS주소> \
  'mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys'
```

**4) ★ 권한을 맞춘다 — Synology 는 이것이 틀리면 열쇠를 조용히 무시한다**

```bash
ssh <계정>@<NAS주소> 'chmod 700 ~/.ssh; chmod 600 ~/.ssh/authorized_keys; chmod 755 ~'
```

- **홈 디렉터리가 그룹 쓰기 가능이면 거부된다.** 오류 메시지가 「Permission
  denied (publickey)」로만 나와서 **열쇠가 틀린 것처럼 보인다** — 이것이 두 번째로
  흔한 막힘이다.
- 그래도 안 되면 DSM 에서 `/etc/ssh/sshd_config` 의 `PubkeyAuthentication yes` 와
  `AuthorizedKeysFile .ssh/authorized_keys` 가 주석 처리되어 있지 않은지 본다.

**5) 되는지 먼저 확인한다** — GitHub 에 넣기 **전에** 내 PC 에서

```bash
ssh -i ~/.ssh/lp_ci <계정>@<NAS주소> 'echo ok'
```

`ok` 가 안 나오면 GitHub 에 넣어도 안 된다. 여기서 먼저 통과시킨다.

### ③ GitHub 에 넣는다

저장소 › **Settings › Secrets and variables › Actions** › `New repository secret`

| Name | Secret 칸에 넣을 것 |
|---|---|
| `TS_OAUTH_CLIENT_ID` | ①-2 의 Client ID |
| `TS_OAUTH_SECRET` | ①-2 의 Client Secret |
| `NAS_SSH_HOST` | NAS 의 **tailnet 이름 또는 주소** (콘솔 Machines 에 있는 것) |
| `NAS_SSH_USER` | ②의 `<계정>` |
| `NAS_SSH_KEY` | `cat ~/.ssh/lp_ci` 전체 — **`-----BEGIN`/`-----END` 줄까지** |

★ `NAS_SSH_KEY` 는 **개인키**(`lp_ci`)다. `.pub` 이 아니다.
★ 마지막 줄바꿈까지 그대로 붙여넣는다. 잘리면 「invalid format」이 난다.

### ④ 됐는지 확인 — **말해 주십시오, 제가 돌립니다**

넣으신 뒤 알려 주시면 제가 배포를 띄우고 결과를 확인해 드립니다.
직접 보시려면: 저장소 › **Actions › deploy-nas › Run workflow** ›
`dry_run` 을 **끄고** 실행.

성공하면 이슈 [#7](https://github.com/findKTH0415/linkpilot-cron/issues/7) 이 닫힙니다.

## 2. 넣은 뒤 — 무엇이 저절로 되나

### 지금 당장 되는 것 (`deploy-nas.yml` · **이미 main 에 있다**)

화면 16개를 웹 루트로 올린다. `npm run im:embed` 는 **원본을 그대로 복사**하므로
(`build-embed.js` — 변환이 없다) 저장소 파일을 바로 올려도 지문이 같다.

### `deploy-im.yml` 이 main 에 올라간 뒤 되는 것

```
npm ci → npm test → check:reachable → im:embed → (tailnet) → 화면 → 엔진 → verify:nas
```

- **올리기 전에 시험을 통과해야 한다.** 빨간 판은 거기서 멈춘다 (§7)
- **올리고 끝내지 않는다.** `verify:nas` 가 지문을 대조한다
- 덮어쓰기 전에 **백업을 뜬다**. 앱 본체는 건드리지 않는다
- 실패하면 **알린다** (`alert-failure.yml`)

> ⚠ **`workflow_dispatch` 는 기본 브랜치에 있는 워크플로만 띄울 수 있다.**
> `deploy-im.yml` 은 아직 작업 브랜치에만 있어서 지금은 못 띄운다 (API 가 404).
> PR #6 이 병합되면 그때부터 된다.
