## 0-1. **화면을 올리는 길은 둘이다** — 어느 쪽이든 된다 〈2026-08-21 추가〉

Secret 다섯을 기다리는 동안 **화면은 지금도 올릴 수 있다.** 둘의 차이만 알면 된다.

| | **사람이 손으로** (지금 바로 된다) | **Actions 로** (Secret 다섯 필요) |
|---|---|---|
| 무엇을 올리나 | 화면 사본 (`im-flow`) | 화면 사본 **+ 엔진** |
| 어디서 | 내 Mac 에서 두 저장소를 오가며 | 저장소 Actions 단추 하나 |
| 지문 대조 | 앱 쪽 게이트가 한다 | `verify:nas` 가 한다 |
| 언제 쓰나 | **화면만 고쳤을 때** | 엔진까지 고쳤을 때 · 손이 못 닿을 때 |

**손으로 올리는 최단 경로** — 경로를 한 번만 정해 두면 그 뒤로는 세 줄이다:

```bash
export LP_APP_DIR="$HOME/…/24.홈페이지"      # ← 한 번만. ~/.zshrc 에 넣어 둔다
cd ~/linkpilot-cron && npm run im:embed      # 사본을 앱 폴더로 낸다
cd "$LP_APP_DIR" && node test-integration-contract.js && python3 deploy-filestation.py
```

★★ **자리표시를 그대로 붙여 넣어 죽은 적이 있다** (2026-08-21). 그래서
`npm run im:embed` 는 자리표시·없는 폴더·`im-flow` 아닌 곳을 **거절하고 무엇이
잘못됐는지 말한다.** 그래도 첫 줄의 경로는 **직접 고쳐야 한다** — 그 한 곳뿐이다.

★ **엔진을 고쳤으면 이 길로는 안 간다.** `deploy:nas` 나 Actions 가 필요하다.
  화면만 올리고 엔진이 옛 판이면 **화면이 없는 API 를 부른다.**

## 1-1. 먼저 — **이게 다 무슨 이야기인가** (쉬운 말로)

낯선 낱말이 여러 개 나옵니다. 하나씩 풀면 이렇습니다.

### 왜 이 일이 필요한가

지금 상황을 사람에 비유하면 이렇습니다.

> 제가 **원고를 다 썼는데**, 그 원고를 **인쇄소(NAS)에 갖다 줄 수가 없습니다.**
> 인쇄소가 회사 건물 안에 있고 저는 출입증이 없기 때문입니다.
> 그래서 **심부름꾼(GitHub 서버)** 에게 맡기려는 것인데,
> 그 심부름꾼도 **출입증이 있어야** 건물에 들어갑니다.
>
> **지금 넣어 달라는 다섯 가지가 그 출입증입니다.**

### 낱말 풀이 — 다섯 개만 알면 됩니다

| 낱말 | 쉬운 말 |
|---|---|
| **NAS** | 사무실에 있는 저장 장치. 여기에 화면 파일이 올라가야 앱에 반영됩니다 |
| **Tailscale** | 사무실 밖에서도 NAS 에 안전하게 들어가게 해 주는 **전용 통로**. 이 통로가 있어야 바깥 컴퓨터가 NAS 를 볼 수 있습니다 |
| **OAuth 클라이언트** | 그 통로를 쓸 수 있는 **출입증 한 장**. 사람 계정이 아니라 **기계 전용** 출입증입니다 |
| **ACL** (액세스 컨트롤) | 「누가 어디까지 들어갈 수 있나」를 적어 둔 **출입 규정표** |
| **SSH 키** | NAS 문을 여는 **열쇠**. 두 조각으로 나옵니다 — **공개키**(자물쇠)는 NAS 에 붙이고, **개인키**(열쇠)는 GitHub 금고에 넣습니다 |

### 그래서 하는 일이 셋입니다

```
① 출입 규정표에 「CI 라는 이름표를 단 기계는 들어와도 된다」를 적는다   (Tailscale)
② 그 이름표를 단 출입증을 한 장 발급한다                              (Tailscale)
③ NAS 문 열쇠를 만들어, 자물쇠는 NAS 에 붙이고 열쇠는 GitHub 금고에    (SSH)
```

그다음 **GitHub 금고(Secrets)** 에 다섯 개를 넣으면 끝입니다.

> **금고에 넣는 이유**: 출입증과 열쇠를 코드에 적으면 **누구나 볼 수 있습니다.**
> 이 저장소는 공개(public)라 더 그렇습니다. GitHub Secrets 는 넣고 나면
> **본인도 다시 못 봅니다** — 그게 정상이고, 그래서 안전합니다.

### 얼마나 걸리나

처음 하시면 **15~20분**, 막히면 30분쯤 봅니다. 막히는 자리는 아래에 미리 표시해 뒀습니다.

## 1-2. 어떻게 만드나 — **순서대로**

> **값을 채팅·커밋·문서에 붙여넣지 않는다.** GitHub Secrets 칸에 **직접** 넣는다.
> 한 번 넣으면 다시 못 본다 — 그것이 정상이다.

### ① Tailscale OAuth — `TS_OAUTH_CLIENT_ID` · `TS_OAUTH_SECRET`

**★ 순서가 중요하다. 태그를 먼저 만들지 않으면 ②에서 막힌다.**

> **2026-08-21 개정 — 실제로 따라 하다 세 번 넘어졌다.** 넘어진 자리를 그대로
> 반영했다. 앞 판은 ⓐ 콘솔 메뉴 이름이 옛것이었고 ⓑ 예시에 **자리표시**(`<…>` ·
> `...`)를 남겨 두어 그대로 붙여 넣게 만들었다. **이 절에는 자리표시가 없다 —
> 적힌 그대로 치면 된다.**

#### 1-①. 무엇을 하는 것인가

> 심부름꾼(GitHub 서버)에게 **출입증**을 주려고 합니다. 그런데 출입증을 만들려면
> **먼저 「이런 이름표를 단 기계는 들어와도 된다」는 규정이 있어야** 합니다.
> 규정에 없는 이름표는 출입증에 찍을 수가 없습니다.
>
> **`tag:ci` 가 그 이름표이고, 규정표에 그 이름을 올리는 것이 이 단계입니다.**

| 낱말 | 쉬운 말 |
|---|---|
| **태그(tag)** | 기기에 붙이는 **이름표.** 사람 계정이 아니라 기계에 붙인다 — CI 러너는 매번 새로 생겼다 사라지므로 사람 계정을 줄 수 없다 |
| **`tagOwners`** | 「이 이름표를 **누가 붙일 수 있나**」를 적는 칸 |
| **정책 파일** | 출입 **규정표 전체.** 콘솔에서 글로 고친다 |

#### 1-②. ★ 맥에 깔린 **Tailscale 앱에서는 못 한다**

메뉴막대의 Tailscale 아이콘 › **Settings** 창에는 이 기능이 **없다.**
**브라우저**로 관리자 콘솔에 들어가야 한다.

```
https://console.tailscale.com
```

★ 옛 주소(`login.tailscale.com/admin`)도 여기로 넘어온다.

#### 1-③. 어디를 눌러야 하나

왼쪽 차림표 **`Policies`** › **`JSON editor`**

★ 콘솔이 새로 바뀌면서 **`Access controls` 라는 이름은 없어졌다.** `Policies` 가
그것이고, 글로 고치는 곳은 그 아래 **`JSON editor`** 다.

★ `Policies` 첫 화면의 **`All users and devices → All ports and protocols`** 줄이
기본 「전부 허용」 규칙이다. **지우지 않는다** — 지우면 본인 접속이 끊긴다.

#### 1-④. ★★ 시작 전에 — **지금 내용을 통째로 복사해 둔다** 🔴

글상자 내용을 전부 복사해 메모장에 붙여 두십시오. 30초면 되고, **잘못되면
그대로 되돌리면 된다.** 아래 1-⑦ 의 사고 둘이 전부 이 백업으로 해결된다.

#### 1-⑤. **넣을 것 — 이 세 줄이 전부다**

```
	"tagOwners": {
		"tag:ci": ["autogroup:admin"],
	},
```

**넣는 자리**: 파일 **맨 위의 여는 `{` 바로 다음 줄.**

파일은 이렇게 생겼다. 1번 줄은 주석이고, **`{` 는 그 아래**에 있다:

```
// Example/default ACLs for unrestricted connections.
{
```

넣고 나면 이렇게 된다:

```
// Example/default ACLs for unrestricted connections.
{
	"tagOwners": {
		"tag:ci": ["autogroup:admin"],
	},
	// (원래 있던 내용이 여기부터 그대로 이어진다 — 아무것도 지우지 않는다)
```

★★ **여는 `{` 안에 넣는다.** 파일 끝에 붙이면 **덩어리가 둘**이 되어 저장이 거부된다.
★ 이 파일은 **주석(`//`)과 끝쉼표를 허용**한다 (HuJSON). 보통 JSON 과 다르다.
★ 원래 파일에 `tagOwners` 가 **주석으로** 들어 있을 수 있다(`// "tagOwners": {`).
  그건 그냥 두면 된다 — 주석은 세지 않는다. **주석이 아닌 것이 둘이면** 거부된다.

#### 1-⑥. 저장 — **오류가 나면 줄 번호를 읽는다**

위쪽 **`Preview changes`** 로 늘어난 것이 `tagOwners` 뿐인지 보고, **`Save`**.

오류는 **몇 번째 줄인지 정확히 알려 준다.** 그 줄만 보면 된다.

#### 1-⑦. 실제로 넘어진 자리 — **셋**

| 오류 · 증상 | 무슨 일인가 | 고치는 법 |
|---|---|---|
| 저장이 안 되고 파일에 `{` 가 **두 번** 보인다 | 파일 **끝에** 붙였다. 정책 파일은 중괄호 **한 쌍**이어야 한다 | 붙인 덩어리를 지우고, **여는 `{` 다음 줄**에 다시 넣는다 (1-⑤) |
| `parsing value: unexpected EOF` | 잘못 붙인 것을 지우면서 **맨 끝 `}` 까지 지웠다** | 마지막 줄에 **`}` 한 글자**를 넣는다 |
| `Tags` 칸에 `tag:ci` 가 안 뜬다 | `tagOwners` 가 저장되지 않았다 | 1-⑤~⑥ 을 다시 한다 |

★ 무엇이든 꼬이면 **1-④ 에서 복사해 둔 내용을 그대로 붙여 넣고 저장**하면
원래대로 돌아간다.

#### 1-⑧. 출입증을 만든다 — **길이 둘이다. 되는 쪽으로 간다**

★★ **콘솔 판에 따라 OAuth client 를 못 만드는 경우가 있다** 〈2026-08-21 실측〉.

없었다. 그래서 **워크플로가 둘 다 받도록 고쳤다** — 만들 수 있는 쪽으로 가면 된다.

**㉮ 를 먼저 찾아본다.** 만료가 없어서 손이 덜 간다. 없으면 **㉯ 로 간다 —

**㉮ OAuth client** — `Settings` › **`Trust credentials`**

| 고를 것 | 값 |
|---|---|
| Scope | **`Auth Keys`** — `write` |
| Tags | **`tag:ci`** |

**㉯ Auth key** — `Settings` › **`Keys`** › **`Generate auth key…`**

**★ 셋을 반드시 켠다. 하나라도 빠지면 붙어도 안 된다.**

| 켤 것 | 왜 |
|---|---|
| **Reusable** | 배포할 때마다 쓴다. 1회용이면 두 번째 배포가 죽는다 |
| **Ephemeral** | 러너는 끝나면 사라진다. 안 켜면 **기기 목록에 시체가 쌓인다** |

- ★★ **`Tags` 칸에 `tag:ci` 가 뜨는지**가 1-⑤ 성공의 확인표다. 안 뜨면 1-⑦.

> ★★ **열쇠 값은 만드는 화면에서 한 번만 보인다.** 창을 닫으면 다시 못 본다.
> **그 자리에서 바로** GitHub 에 붙여넣는다 (③). 잃어버리면 지우고 새로 만든다.

★ **사람 계정 로그인 정보를 CI 에 주지 않는다.** 이 열쇠 하나만 준다. 나중에
이것만 지우면 CI 접근이 깨끗이 끊긴다.

#### 1-⑨. (선택) 나중에 **좁힌다** — 성공한 뒤에

기본 정책이 「전부 허용」이라 위까지만 해도 배포는 돈다.
**한 번 성공한 뒤에** 좁히는 것을 권한다.

★★ **문법이 두 가지다.** 파일을 열어 **어느 쪽이 있는지 먼저 보고** 그쪽에 맞춘다.

`"grants"` 가 있으면 (새 문법):

```
	{"src": ["tag:ci"], "dst": ["NAS기기이름"], "ip": ["22"]},
```

`"acls"` 가 있으면 (옛 문법):

```
	{"action": "accept", "src": ["tag:ci"], "dst": ["NAS기기이름:22"]},
```

- `NAS기기이름` 은 콘솔 **`Machines`** 목록에 있는 이름을 그대로 쓴다.
- ★ **성공하기 전에 좁히지 않는다.** 안 될 때 원인이 둘(정책·열쇠)이 되어
  어느 쪽인지 가릴 수가 없다.

### ② NAS ssh 열쇠 — `NAS_SSH_HOST` · `NAS_SSH_USER` · `NAS_SSH_KEY`

**0) 먼저 두 값을 정해 둔다** — 이 창에서만 쓰는 임시 이름이다

```bash
NAS_USER="여기에NAS계정이름"          # ← 자기 값으로 바꾼다
NAS_HOST="여기에NAS주소"              # ← 콘솔 Machines 에 있는 이름 또는 주소
echo "$NAS_USER@$NAS_HOST"           # 찍어 보고 맞는지 눈으로 확인한다
```

★ **마지막 줄을 꼭 확인한다.** 여기가 틀리면 아래가 전부 헛돈다.

**1) NAS 에서 SSH 를 켠다** — DSM › 제어판 › **터미널 및 SNMP** › `SSH 서비스 활성화`

**2) 열쇠 한 쌍을 만든다** (내 Mac 에서. **암호는 비워 둔다** — CI 는 암호를 칠 수 없다)

```bash
ssh-keygen -t ed25519 -C "linkpilot-ci" -f ~/.ssh/lp_ci -N ""
```

**3) 공개키를 NAS 에 넣는다**

```bash
ssh-copy-id -i ~/.ssh/lp_ci.pub "$NAS_USER@$NAS_HOST"
```

`ssh-copy-id` 가 없으면 손으로:

```bash
cat ~/.ssh/lp_ci.pub | ssh "$NAS_USER@$NAS_HOST" \
  'mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys'
```

**4) ★ 권한을 맞춘다 — Synology 는 이것이 틀리면 열쇠를 조용히 무시한다**

```bash
ssh "$NAS_USER@$NAS_HOST" 'chmod 700 ~/.ssh; chmod 600 ~/.ssh/authorized_keys; chmod 755 ~'
```

- **홈 디렉터리가 그룹 쓰기 가능이면 거부된다.** 오류가 「Permission denied
  (publickey)」로만 나와서 **열쇠가 틀린 것처럼 보인다** — 두 번째로 흔한 막힘이다.
- 그래도 안 되면 `/etc/ssh/sshd_config` 의 `PubkeyAuthentication yes` 와
  `AuthorizedKeysFile .ssh/authorized_keys` 가 주석 처리되어 있지 않은지 본다.

**5) 되는지 먼저 확인한다** — GitHub 에 넣기 **전에** 내 Mac 에서

```bash
ssh -i ~/.ssh/lp_ci "$NAS_USER@$NAS_HOST" 'echo ok'
```

`ok` 가 안 나오면 GitHub 에 넣어도 안 된다. **여기서 먼저 통과시킨다.**

**6) 개인키를 클립보드로** — 다음 단계에서 그대로 붙여넣는다

```bash
pbcopy < ~/.ssh/lp_ci
```

★ **`.pub` 이 아니다.** 확장자 없는 `lp_ci` 가 개인키다.

### ③ GitHub 에 넣는다

저장소 › **Settings › Secrets and variables › Actions** › `New repository secret`

| Name | Secret 칸에 넣을 것 |
|---|---|
| `TS_OAUTH_CLIENT_ID` | ①-⑧ ㉮ 의 Client ID — **㉯ 로 갔으면 넣지 않는다** |
| `TS_OAUTH_SECRET` | ①-⑧ ㉮ 의 Client Secret — 〃 |
| `TS_AUTHKEY` | ①-⑧ ㉯ 의 auth key — **㉮ 로 갔으면 넣지 않는다** |
| `NAS_SSH_HOST` | NAS 의 **tailnet 이름 또는 주소** (콘솔 Machines 에 있는 것) |
| `NAS_SSH_USER` | ②에서 쓴 NAS 계정 이름 |
| `NAS_SSH_KEY` | `cat ~/.ssh/lp_ci` 전체 — **`-----BEGIN`/`-----END` 줄까지** |

★ `NAS_SSH_KEY` 는 **개인키**(`lp_ci`)다. `.pub` 이 아니다.
★ 마지막 줄바꿈까지 그대로 붙여넣는다. 잘리면 「invalid format」이 난다.

### ④ 됐는지 확인 — **말해 주십시오, 제가 돌립니다**

넣으신 뒤 알려 주시면 제가 배포를 띄우고 결과를 확인해 드립니다.
직접 보시려면: 저장소 › **Actions › deploy-nas › Run workflow** ›
`dry_run` 을 **끄고** 실행.

성공하면 이슈 [#7](https://github.com/findKTH0415/linkpilot-cron/issues/7) 이 닫힙니다.

## 2. 넣은 뒤 — 무엇이 저절로 되나

### 지금 당장 되는 것 (`deploy-nas.yml` · **이미 main 에 있다**)

화면 16개를 웹 루트로 올린다. `npm run im:embed` 는 **원본을 그대로 복사**하므로
(`build-embed.js` — 변환이 없다) 저장소 파일을 바로 올려도 지문이 같다.

### `deploy-im.yml` 이 main 에 올라간 뒤 되는 것

```
npm ci → npm test → check:reachable → im:embed → (tailnet) → 화면 → 엔진 → verify:nas
```

- **올리기 전에 시험을 통과해야 한다.** 빨간 판은 거기서 멈춘다 (§7)
- **올리고 끝내지 않는다.** `verify:nas` 가 지문을 대조한다
- 덮어쓰기 전에 **백업을 뜬다**. 앱 본체는 건드리지 않는다
- 실패하면 **알린다** (`alert-failure.yml`)

> ⚠ **`workflow_dispatch` 는 기본 브랜치에 있는 워크플로만 띄울 수 있다.**
> `deploy-im.yml` 은 아직 작업 브랜치에만 있어서 지금은 못 띄운다 (API 가 404).
> PR #6 이 병합되면 그때부터 된다.
