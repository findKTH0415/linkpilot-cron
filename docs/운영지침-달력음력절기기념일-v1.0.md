# 1부 · 실사 결과 〈2026-09-13 · 읽기 전용 · 실측〉

지침이 **「기존 화면 반영항목」**이라 부른 여덟 가지를 두 저장소에서 직접 세었다.

★★★ **여덟 중 넷만 있다. 넷은 «없다».** 그리고 **그 여덟을 켜고 끄는 설정 스위치는 한 개도 없다.**

| # | 항목 | 실측 | 상태 |
|---|---|---|---|
| 1 | 간지(干支) | 두 저장소에 **0회** | `NOT_IMPLEMENTED` |
| 2 | 공휴일 | 고정표 + 일요일 대체 어림 있음 | `PARTIAL` |
| 3 | 법정기념일 | 양력 기념일 표 있음 | `PARTIAL` |
| 4 | 음력 | **명절만** 있고 **날마다의 음력 날짜는 없다** | `PARTIAL` |
| 5 | 세시풍속 | **주석에 1회** — 기능 없음 | `NOT_IMPLEMENTED` |
| 6 | 24절기 | 황경으로 **계산**한다 | `IMPLEMENTED` |
| 7 | 메모 제목 보기 | 달력에 메모 제목을 켜고 끄는 자리 **없음** | `NOT_IMPLEMENTED` |
| 8 | 손 없는 날 | 두 저장소에 **0회** | `NOT_IMPLEMENTED` |
| — | **위 여덟의 설정 스위치** | **0개** (달력 보기 설정 화면 자체가 없다) | `NOT_IMPLEMENTED` |

★ **이것이 이 작업의 출발점이다.** 지침은 「기존 8개 설정항목을 목적별로 재구성한다」고 적는데,
  **재구성할 여덟이 없다.** 넷은 새로 만드는 일이고, 스위치 여덟은 통째로 새로 만드는 일이다.
  이 사실을 안 적으면 「재구성」이 「신규 개발」인 줄 모르고 일정이 잡힌다.

★★ **그러면 사장님이 보신 그 화면은 무엇인가** — 지침에 「간지(干支) 보기 / 안보기」 같은 문구가
  있는 것으로 보아 **다른 달력 앱의 화면**일 가능성이 크다. **그 화면을 우리 것으로 적지 않는다.**
  어느 화면인지는 사장님께 여쭤 확인할 일이다 (미결 · 아래 6장).

## 1.2 지침이 새로 요구하는 것 중, 이미 있는 것

| 항목 | 실측 | 상태 |
|---|---|---|
| 24절기 계산 | 황경 15도 배수로 계산 · **자정에서 한 시간 안에 드는 절기는 안 쓴다** | `IMPLEMENTED` |
| 실제 날씨 | 기온·체감·최고·최저·강수확률 | `IMPLEMENTED` |
| 옷차림 추천 | **체감온도**로 정한다 · 일교차 · 강수확률 3단 | `IMPLEMENTED` |
| 오늘의 브리핑 | 코드가 고르고 AI 는 설명만 한다 | `PARTIAL` |
| 「오늘은 특별한 날인가요?」 | 경조사 여럿 · 관계별 어투 · 인사말 세 줄 | `IMPLEMENTED` |
| 자동발송 금지 | 공유 화면을 사람이 눌러야 나간다 | `IMPLEMENTED` (지침보다 엄함) |

★ **2026년 24절기 중 «넷은 안 쓴다.»** 저정밀 태양 위치식은 15분쯤 오차가 있어, 절기 순간이
  자정 바로 앞뒤면 **날짜가 하루 밀린다**(백로에서 실제로 났다). **틀린 날을 자신 있게 말하는 쪽이
  안 말하는 것보다 훨씬 나쁘다.** 그래서 스물넷 중 **스물**을 쓴다. 이 수를 줄이는 것이 개선이다.

## 1.3 지침이 요구하는데 **값이 없어서 못 하는 것**

| 요구 | 왜 못 하나 |
|---|---|
| 바람 | 지금 받는 날씨 값에 없다 |
| 미세먼지·대기질 | 없다 |
| 기상특보 | 없다 |
| 실내·야외 일정 비중 | 일정에 그 값이 없다 |
| 격식 있는 미팅 여부 | 일정에 그 값이 없다 |

★★★ **없는 값으로 추천을 만들지 않는다.** 지침 자신이 「확인할 수 없는 값은 추천에 사용하지 않는다」
  고 적는다 — 이 다섯은 그 조항에 걸린다. **받는 값을 먼저 늘린 뒤에** 추천에 넣는다.
★ **건강상태·질병은 어떤 경우에도 추정하지 않는다** — 지침과 우리 규칙이 같다.

### ★★★ 같은 날 열린 길 — 기상청 관측·통계 〈2026-09-13 사장님: 「활용해줘」〉

사장님이 **기상청 관측·통계**와 **공공데이터 인증키**를 활용신청해 주셨다. 위 다섯 중
**바람 · 기상특보**가 이것으로 열릴 수 있다. 다만 **그대로 켜지 않는다** — 순서가 있다.

| 차례 | 무엇을 | 왜 |
|---|---|---|
| ① | **도는 자리를 먼저 잰다** | 공공데이터포털 쪽은 해외 IP(러너)에서 안 열린다. 기상청 API허브(`apihub.kma.go.kr`)는 **다른 호스트**라 열릴 수도 있다 — **재 보기 전에는 모른다** |
| ② | **응답 본문부터 본다** | 규격을 모르는 채 파라미터를 추측해 넣지 않는다. 한 API 를 그렇게 **여섯 번 다시 썼다** |
| ③ | 값이 오면 커넥터 배선 | 무엇을 버리는지도 함께 본다 — 버리는 코드는 아무 오류도 안 낸다 |
| ④ | 그 뒤에 추천에 넣는다 | 값이 오기 전까지 옷차림은 **체감온도·일교차·강수확률 셋**으로만 정한다 |

★ **미세먼지는 아직 아니다** — 그쪽은 한국환경공단 자료이고 별도 신청이다.
★★ **월드뉴스 열쇠는 이 지침의 일이 아니다.** 이름과 가림만 등록했고, 규격은 진단으로
  확인한 뒤에 쓴다.
  ★★★ **이름은 «화면에서» 읽었다** 〈2026-09-13 · 실측〉. 말씀으로 받은 철자는
    `WORLD_NES_KEY` 였는데 **비밀 목록에 그 이름이 없었다** — 실제로 들어 있는 것은
    **`WORLDWIDE_NEWS`** 와 **`WORLD_NEWS_API`** 둘이다. 앞 판이 여기에 「넣으신 그대로가
    정본이다」라고 적어 두었는데, 그 말은 **화면을 보기 전까지만** 맞았다.
    ★ 말씀으로 들은 철자도 **가림 목록에는 남겨 둔다** — 나중에 그 이름으로 넣으실 수 있고,
      가림에 없으면 그 값이 로그에 평문으로 남는다 (§2). 다만 **정본은 화면의 이름**이다.

## 1.4 **도는 자리**가 정해지는 것 — 이것이 가장 큰 제약이다

지침은 음력·윤달·간지·절기·공휴일의 정본을 **정부·천문 공식자료**로 정한다. **옳다.**
다만 **그 자료를 부르는 자리가 GitHub Actions 가 아니다.**

- `apis.data.go.kr` 이 **러너에서 안 열린다** — 특일정보 첫 실행에서 **스무 칸 전부** 응답 없이 죽었다.
  러너가 해외 IP 라서다. **활용신청·키와는 아무 상관이 없다.**
- 그러므로 **이 갈래 수집은 국내 자리(NAS)에서 돈다.** 부르는 것은 NAS 의 작업 스케줄러다.
- ★★★ **그 수집이 아직 한 번도 안 돌았다.** 그래서 지금 달력이 쓰는 것은 **손으로 적은 표**다 —
  음력 명절은 세 해, 공휴일은 고정표, 대체공휴일은 **「일요일이면 다음날」 어림**이다.
  **어림을 공식값으로 적지 않는다.**

★ **그러니 이 지침의 Gate 1(데이터)은 「국내 수집이 한 번이라도 돌 때까지」 열리지 않는다.**
  없는 것을 있는 척 적지 않는다.

# 2부 · 부딪히는 자리

## 2.1 낱말이 겹치는 자리 — **셋** (새로 둘, 이미 하나)

겹침 자체는 사고가 아니지만 **어느 뜻인지 안 적히면 조용히 틀린 것을 만든다.**
**접두어로 부른다.**

- ★★★ **「Gate 번호」 — 아홉째 겹침이다.**
  이미 `RELEASE:Gate 3`(Staging 실환경) · `INSIGHT:Gate 3`(콘텐츠·디자인) · `BRIEF:Gate 3`(기능 E2E)
  가 갈려 있는데, 이 지침이 **Gate 0~8** 을 또 둔다. 여기서 **Gate 3 은 「기능」**이고
  **Gate 8 이 「승인」**이다. 숫자라 자동 검사에 안 걸리므로 **사람이 적는다** — **`CAL:Gate 3`**.
  **접두어 없이 「Gate 3」만 적힌 글은 `RELEASE:` 것으로 읽는다**(그 규칙은 그대로다).

- ★★★ **「3안」과 「세 줄」 — 다른 것이다.**
  이 지침의 **「인사말 3안」**은 *짧고 담백 / 따뜻하고 자연스러움 / 격식* **세 가지 후보**다.
  우리 화면의 **「인사말 세 줄」**은 *① 오늘이 어떤 날인지 ② 오늘에 맞는 한마디 ③ 맺음* —
  **한 편의 글을 이루는 세 줄**이다. **완전히 다른 축이다.**
  이것을 안 가르면 「3안을 만들라」가 **세 줄을 세 개로 쪼개는 일**로 배선될 수 있다.
  **접두어로 부른다**: `GREET:3안`(후보 셋) · `GREET:3줄`(한 글의 구성).
  ★ 지금 있는 것은 `GREET:3줄` 이다. `GREET:3안` 은 **새로 만드는 일**이다.

- ★★ **`READY_TO_DEPLOY`** — 이미 갈라 두었다. 이 지침의 그것은 **`RELEASE:READY_TO_DEPLOY`** 다
  (코드의 디자인 게이트 마지막 칸인 `DESIGN:READY_TO_DEPLOY` 가 아니다).

## 2.2 앞 지시가 이기는 자리 — **둘**

지침이 새것이라고 앞 지시를 덮으면, **사장님이 따로 적어 주신 것이 조용히 사라진다.**

- **「인사말 전달채널」** → **`[SNS 공유]` 로 둔다.**
  사장님이 「[지금공유. 카톡.SNS] → **[SNS 공유]** · 카톡 인사말 → **SNS 인사말**」로 이름을 정하셨다.
  그리고 **카카오톡은 친구에게 바로 보내는 공개 창구가 없다** — 되는 것은 복사와 공유 화면뿐이라,
  「카톡으로 보내기」 단추를 만들면 **안 되는 길을 되는 척 그리는 것**이다.

- **「기존 디자인 보존」의 이모지** → **혼자 판단해 아이콘으로 바꾸지 않는다.**
  UI 이모지는 「안 넣는다」가 아니라 **「라인 아이콘으로 갈아 끼운다」**이고, 그 규격은
  **1단계 로고·아이콘 지시서**가 정한다 — **디자이너 시안 납품 대기**이고 **혼용 금지**다.
  지금 할 수 있는 것은 **새로 만드는 칸에 이모지를 안 넣는 것** 하나뿐이다.
  ★ 이것은 지침의 「디자인 보존」과 **같은 방향**이다 — 어기는 것이 아니라 더 엄하게 지키는 것이다.

## 2.3 이미 있어서 **새로 만들지 않는 것** — 다섯

- **「Validation Manager 를 둔다」** → **미결로 이미 올라가 있다.** 이름도 이미 받았다.
  **여전히 실체가 없다** — 만드는 손과 재는 손이 같다. **없는 것을 있는 척 적지 않는다.**
- **「사용자 승인 전 main 병합·운영배포·운영 DB 변경·외부 공개·비용발생 금지」** → **이미 규칙이다.**
- **「증빙 없는 것을 정상으로 적지 않는다 · `UNVERIFIED`」** → **이미 규칙이다.**
  `guard` 가 **「못 잰 것은 통과가 아니다」**로 이미 그렇게 끝난다(되돌아오는 값 2).
- **「모바일 화면규칙」** → 재는 자리가 이미 있다 — 폰(390)·맥(1440) 두 폭에서 **실제로 그려** 잰다.
  ★ 다만 **새로 잴 것 셋이 생겼다**: 터치영역 44×44 · 본문 글자 15px · 사이드바와 하단 내비 동시 노출 금지.
  이 셋은 「그려지는가」로는 안 잡히고 **자리와 크기를 재야** 잡힌다.
- **「자동발송 금지」** → **이미 지켜지고 있고 더 엄하다.**

## 2.4 ★★★ 지침과 **우리 실측이 어긋나는 자리** — 하나

지침은 「**기존 사용자 설정값을 100% 보존**」을 Gate 2 로 둔다.
그런데 **보존할 설정값이 없다** — 달력 보기 설정 자체가 없기 때문이다(1부).

★ **그러니 Gate 2 는 「보존」이 아니라 「처음 만드는 기본값이 기존 사용자에게 어떻게 닿는가」**다.
  **없는 것을 보존했다고 적으면 그 게이트는 영원히 거짓 초록이다.**
★★ 다만 **인사말·명언 쪽에는 기억된 설정이 있다**(고른 관계 · 배경 큰분류 · 명언 테마 · 맺음말·이름).
  **그것들은 진짜로 보존 대상이다.** Gate 2 는 그쪽을 잰다.

# 3부 · 실행 규격

## 3.1 변하지 않는 차례

> **정확한 날짜 → 사용자 설정 → 간결한 표시 → 개인화 안내 → 사용자 행동**

편의를 이유로 **공식 데이터의 정확성 · 개인정보 · 기존 디자인 · 사용자 통제권**을 낮추지 않는다.

## 3.2 데이터 상태 — 넷을 갈라 적는다

`VERIFIED` · `STALE` · `UNVERIFIED` · `FAILED`

- **`STALE`·`UNVERIFIED`·`FAILED` 는 브리핑·인사이트·인사말 추천에서 뺀다.**
- **API 가 죽었을 때 어제 값을 오늘 값처럼 그리지 않는다.** 캐시는 **날짜로 거른다.**
- ★ **「못 닿음」을 「승인 안 됨」으로 적지 않는다.** 앞 판이 그렇게 적어 **이미 하신 활용신청을
  또 하시게 만들었다.** 진단은 `unreachable` 을 따로 갈라 준다.

## 3.3 표시 우선순위 (달력·브리핑 공통)

```
기상특보 → 사용자 일정 → 개인 기념일 → 공휴일 → 법정기념일
 → 명절 → 24절기 → 실제 날씨 → 음력 → 세시풍속 → 간지 → 손 없는 날
```

- **낮은 것은 숨기는 것이 아니라 상세화면으로 옮긴다.**
- **실제 날씨가 절기·계절 상식보다 앞선다.**
- ★ 공휴일이 있는 날에 절기를 첫 줄에 쓰면 **「오늘은 추분입니다」가 추석을 덮는다.**

## 3.4 월간 달력 — 한 칸에 넷까지

1. 양력 날짜 2. 공휴일 또는 가장 중요한 일정 3. 음력 날짜 4. 보조 라벨 최대 2개
나머지는 점 또는 `+숫자`. **글자를 줄여 다 넣지 않는다.**

★ **한 화면에 할 일 하나만 둔다.** 전부 보이는 것이 곧 「고를 수 있다」는 아니다.

## 3.5 설정화면 — 넷으로 나눈다

| 묶음 | 항목 |
|---|---|
| 기본 달력정보 | 공휴일 · 대체공휴일 · 법정기념일 · 음력 · 윤달 · 24절기 |
| 전통 달력정보 | 간지 · 세시풍속 · 손 없는 날 |
| 개인 일정정보 | 메모 제목 · 생일 · 개인 기념일 · 프로젝트 일정 · 할 일 마감일 |
| 브리핑·인사이트 연결 | 브리핑 표시 · 인사이트 반영 · 날씨·옷차림 · 특별한 날 · 추천 인사말 |

**스위치 표기** — 제목과 상태를 겹쳐 쓰지 않는다.

| 이렇게 쓴다 | 이렇게 쓰지 않는다 |
|---|---|
| 제목 「간지(干支)」 · 설명 한 줄 · 상태 「켬/끔」 | 「간지(干支) 보기 / 안보기」 |

- 설명은 **최대 두 줄**. 하위 설정은 **켰을 때만** 그린다.
- ★ **조건이 이미 채워진 칸은 감추는 것이 아니라 안 그린다.** 감추면 접힘을 열 때 다시 나온다.

## 3.6 기본값 — **새 사용자에게만**

켬: 공휴일 · 대체공휴일 · 법정기념일 · 음력 · 윤달 · 24절기 · 생일 · 개인 기념일 · 날씨·옷차림 · 추천 인사말
끔: 간지 · 세시풍속 · 손 없는 날 · 메모 제목

- **기존 사용자에게 강제로 적용하지 않는다.**
- ★ **기본값은 «기억이 없을 때»만 쓰인다.** 고르신 값이 언제나 이긴다.
- ★★ **기본값을 바꿀 때 그 값이 표에 있는지 확인한다.** 없는 값을 골라 두면 **화면이 빈 채로 열린다.**

## 3.7 항목별 금지선

- **간지** — 운세·미래예측으로 늘려 읽지 않는다. 날짜 경계 규칙을 한 곳에서 정한다.
- **공휴일 / 법정기념일** — **쉬는 날이 아닌 기념일에 공휴일 표시를 쓰지 않는다.**
- **음력** — 음력 생일을 **고정 양력일로 바꿔 저장하지 않는다.** 해마다 다시 셈한다.
- **세시풍속** — 지역 풍속을 전국 공통사실처럼 적지 않는다. 미신·건강효과를 사실로 단정하지 않는다.
- **손 없는 날** — 전통 생활 참고정보다. **이사·계약일을 자동으로 정하지 않는다.**
- **메모 제목** — 기본 끔. **잠금화면·공유화면에 기본 비공개.**
- **민감정보** — 임신·출산·질병·상실·종교는 **사용자 확인 없이 추천하거나 밖에 표시하지 않는다.**

## 3.8 인사말

- `GREET:3줄` 은 그대로 둔다(이미 규격이다).
- `GREET:3안`(짧음/따뜻함/격식)은 **새로 만드는 일**이다 — `GREET:3줄` 을 쪼개서 만들지 않는다.
- **자동발송하지 않는다.** 사람이 이름·호칭·내용을 확인한 뒤 보낸다.
- ★ **이름을 못 뽑으면 그 인사를 안 쓴다.** 「오늘은 님의 생일입니다」가 나가는 쪽이
  안 보내는 것보다 훨씬 나쁘다.
- ★★ **딱지가 여럿인데 글이 같으면 그 딱지는 거짓이다.** 「표가 있는가」가 아니라
  **「눌러서 실제로 다른 글이 나오는가」**를 잰다. **미리보기뿐 아니라 나가는 자리까지** 같은 값을 쓰는지 본다.

## 3.9 개인정보

- 개인 생일·기념일은 **승인 후** 저장한다.
- **로그에 메모 원문·민감 기념일을 남기지 않는다.**
- 사용자가 지운 것은 **캐시·브리핑·인사이트에서도 지운다.**
- 개인 기념일을 광고 타기팅에 쓰지 않는다.
- ★ **한 번 이어 붙인 바깥 연동은 로그아웃으로 끊지 않는다.** 끊는 것은 사람이 [해제]를 누를 때뿐이다.

## 3.10 상태를 바꾸는 기능

**갱신시각을 함께 남기고, 그 시각은 한 곳에서만 만든다.**
상태 토글을 만들거나 고칠 때는 **상태 토글 검증 체크리스트 열네 칸**을 전부 확인한다.

## 3.11 게이트 — `CAL:Gate 0` ~ `CAL:Gate 8`

| Gate | 통과조건 | 지금 |
|---|---|---|
| `CAL:Gate 0` 현행실사 | 항목별 상태표 | **이 문서 1부로 완료** |
| `CAL:Gate 1` 데이터 | 공식값과 일치 | **막힘** — 국내 수집이 아직 한 번도 안 돌았다 |
| `CAL:Gate 2` 마이그레이션 | 기존 설정 보존 | 달력 설정은 **없어서 해당 없음** · 인사말·테마 설정은 대상 |
| `CAL:Gate 3` 기능 | 설정·달력·상세·브리핑 연결 | 미착수 |
| `CAL:Gate 4` 디자인 | 기존 디자인 유지 · 모바일 가독성 | 재는 자리 있음 (+새로 셋) |
| `CAL:Gate 5` 개인정보 | 메모·기념일·로그·삭제 | 미착수 |
| `CAL:Gate 6` 실기기 | S22 · iPhone · Safari · Chrome | **여기서 못 잰다** — `UNVERIFIED` |
| `CAL:Gate 7` 운영 | API 장애 · 백업 · 복원 · 롤백 | 배포가 일부 잰다 |
| `CAL:Gate 8` 승인 | `RELEASE:READY_TO_DEPLOY` + 사장님 승인 | — |

★★★ **`CAL:Gate 6` 은 이 자리에서 못 잰다.** 실기기가 없다. **초록으로 적지 않는다.**
★★ **CRITICAL/HIGH 가 남았거나 핵심 항목이 `UNVERIFIED` 면 배포를 막는다.**

## 3.12 완료로 치지 않는 것

**문서 · 화면 시안 · 표본 데이터 · Agent 응답만으로 구현 완료를 선언하지 않는다.**

★ **「만들었다」와 「닿는다」는 다른 사실이다.** 저장소에는 있고 NAS 에는 없는 상태가 실제로 있었고
  **검사는 초록이었다.**
★★ **「걸었다」와 「올라갔다」도 다른 사실이다.** 배포를 건 것과 파일이 닿은 것은 다르다.

# 4부 · Orchestrator 최종 실행명령

> 아래 한 벌을 그대로 Orchestrator 에게 건넨다.

```text
이 문서를 LinkPilot 달력·음력·절기·기념일 통합 개선작업의 정본으로 삼는다.
지침 원문과 어긋나는 자리는 이 문서의 2부가 이긴다 — 2부는 실측과 앞 지시로 쓰였다.

[0] 먼저 읽을 것
 0-1 이 문서의 1부(실사)를 먼저 읽는다. 여덟 중 넷이 «없다». 스위치는 «0개»다.
     「재구성」이 아니라 「신규 개발」인 항목을 일정에 그렇게 적는다.
 0-2 이 문서의 2부(부딪히는 자리)를 읽는다. 접두어 셋을 쓴다 —
     CAL:Gate n · GREET:3안 · GREET:3줄. 접두어 없는 「Gate 3」은 RELEASE 것으로 읽는다.

[1] 실사를 다시 하지 않는다 — 대신 «빠진 자리»만 마저 잰다
 1-1 메모 제목·개인 기념일·프로젝트 일정·할 일 마감일이 달력에 닿는지 각각 잰다.
 1-2 인사말·명언·배경 테마의 «기억된 설정»을 전부 뽑아 적는다 (CAL:Gate 2 의 진짜 대상이다).
 1-3 잰 것은 IMPLEMENTED / PARTIAL / DOCUMENTED / NOT_IMPLEMENTED / UNVERIFIED 로 적는다.
     ★ 못 잰 것을 통과로 적지 않는다.

[2] 막힌 것을 먼저 푼다 — 이것이 1순위다
 2-1 CAL:Gate 1 은 «국내 자리 수집»이 한 번이라도 돌 때까지 열리지 않는다.
     해외 IP 에서는 그 공공 API 가 안 열린다 — 키·활용신청 문제가 아니다.
 2-2 그 수집이 돌기 전까지 달력은 손으로 적은 표로 돈다. 그 표를 «공식값»으로 적지 않는다.
     대체공휴일은 지금 「일요일이면 다음날」 어림이다. 어림이라고 적는다.
 2-3 수집이 돌면 음력 날짜·잡절·대체공휴일·2029년 이후 명절을 그 자료로 갈아 끼운다.

[3] 업무를 나눈다
 3-1 Calendar  — 음력·윤달·간지·24절기. 공식 원문과 «날짜별로» 대조한다.
     ★ 절기는 자정에서 한 시간 안에 드는 것을 안 쓴다(지금 스물넷 중 스물).
       그 수를 늘리는 것이 이 칸의 개선 목표다.
 3-2 Holiday   — 공휴일·대체공휴일·법정기념일. 쉬는 날과 아닌 날을 갈라 표시한다.
 3-3 Weather   — 날씨·옷차림. 바람·미세먼지·기상특보는 «받는 값이 없다» —
     먼저 값을 늘린 뒤에 추천에 넣는다. 없는 값으로 추천을 지어내지 않는다.
     건강상태·질병은 어떤 경우에도 추정하지 않는다.
 3-4 Personalization / Insight — 특별한 날과 GREET:3안. GREET:3줄 을 쪼개 만들지 않는다.
 3-5 Platform / Data — 설정화면 넷 분류 · 달력 표시 · 동기화. 화면은 linkpilot-platform 것이다.
 3-6 Security  — 메모·개인기념일·로그·삭제. 잠금·공유 화면 기본 비공개.
 3-7 Validation Manager — 아직 «실체가 없다». 있는 척 적지 않는다.
     지금은 만드는 손과 재는 손이 같다는 사실을 승인서에 그대로 쓴다.

[4] 만든다
 4-1 설정화면을 기본·전통·개인·브리핑 연결 넷으로 나눈다.
 4-2 스위치는 제목 / 설명 한 줄 / 켬·끔 으로 적는다. 「보기 / 안보기」로 겹쳐 쓰지 않는다.
 4-3 기본값은 «기억이 없을 때»만 쓴다. 고르신 값이 언제나 이긴다.
 4-4 기본값을 바꿀 때 그 값이 표에 있는지 확인한다 — 없으면 화면이 빈 채로 열린다.
 4-5 월간 달력은 넷까지만 그리고 나머지는 상세로 보낸다. 글자를 줄여 다 넣지 않는다.
 4-6 실제 날씨가 절기·계절 상식보다 앞선다.

 4-8 오늘과 직접 관련된 것만 브리핑에 싣는다. 설정값을 나열하지 않는다.
 4-9 인사말은 자동발송하지 않는다. 전달은 [SNS 공유] 다 — 「카톡으로 보내기」를 만들지 않는다.
 4-10 STALE / UNVERIFIED / FAILED 는 브리핑·인사이트·인사말에서 뺀다.
 4-11 새로 만드는 칸에 이모지를 넣지 않는다. 이미 있는 것을 혼자 판단해 아이콘으로 바꾸지 않는다.
 4-12 상태를 바꾸는 기능에는 갱신시각을 함께 남기고, 그 시각은 한 곳에서만 만든다.

[5] 잰다
 5-1 «그려서» 잰다. 소스만 보면 조건부로 그려지는 칸은 늘 「있다」로 읽힌다.
 5-2 딱지를 더하면 «눌러서 실제로 다른 것이 나오는가»를 잰다. 미리보기뿐 아니라 나가는 자리까지 본다.
 5-3 개수·이름을 검사에 손으로 적지 않는다. 표에서 세어 견준다.
 5-4 블록을 «첫 등장 낱말»로 끊지 않는다. 짝이 맞는 구조로 끊는다.
 5-5 검사가 찾는 표시 이름을 주석에 글자로 적지 않는다.
 5-6 고친 검사는 «되돌려» 본다. 되돌려도 안 빨개지면 그것은 약하게 고친 것이다.
 5-7 「못 잼」이 뜬 칸은 그 턴에 «왜 못 쟀는지» 본다. 실패는 그날 고쳐지고 못 잼은 반년 간다.
 5-8 한 실행의 칸들을 서로 대 본다. 두 칸이 어긋나면 어느 한쪽이 못 잰 것이다.
 5-9 모든 문제에 중요도·상태·영향·근거·담당자·조치·완료조건·목표일·승인 여부를 적는다.
 5-10 같은 문제가 두 번 이상 나면 직접원인·구조원인·탐지실패·영구대책·재발방지시험·책임자·완료일을 낸다.

[6] 배포를 막는다
 6-1 CRITICAL/HIGH 0건과 핵심 시나리오 전부 통과를 확인한다.
 6-2 RELEASE:READY_TO_DEPLOY 판정 전에는 배포하지 않는다.
 6-3 사장님 승인 전에 main 병합·운영배포·운영 DB 변경·외부 공개·비용발생 작업을 하지 않는다.
 6-4 초안(draft) PR 까지가 이쪽 몫이다. 합치는 것은 사람이 한다.
 6-5 쌓아 올린 PR 은 «합치는 순서»를 함께 적는다. 순서가 반대면 뒤엣것이 갇힌다 —
     실제로 그렇게 커밋 하나가 갇혔다. 합쳐졌는지 조상 관계로 «센다».

[7] 보고한다 — 이 차례로
 종합상태 → 한 줄 요약 → 구현현황 → 기존 설정 보존결과 → 데이터·API 검증결과
 → 신규 문제 → 미해결 CRITICAL/HIGH → 완료·검증 조치 → 우선조치 TOP 3
 → 확인 불가 항목 → 사장님 결정·승인사항

 ★ 끝냈다는 보고에는 미리보기 주소와 그 판의 지문을 함께 적는다.
 ★★ 못 잰 것을 통과로 그리지 않는다. 무엇을 못 쟀는지 말하고 낸다.
```
