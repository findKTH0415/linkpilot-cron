# 재검증 — 「클라우드 폴더 자료 공유 및 작업지시」 지시서 vs 엔진

**2026-08-22** · 앞선 검증([2026-08-21](클라우드폴더-지시-교차검증-2026-08-21.md))을 **오늘 코드로 다시 대조**했다.

---

## 0. 물음에 먼저 답한다

> **「외부 클라우드 폴더를 지정해서 자료 스캔이 되는가?」**

| | |
|---|---|
| **폴더를 지정해서** | ❌ **안 된다.** 폴더를 가리키는 자리가 코드에 **없다** |
| **파일을 골라서** | ✅ **엔진은 끝까지 돈다** — 오늘 실제로 돌려서 확인했다 |
| **실제 클라우드로** | ⏸ **사람 작업 두 가지가 남았다** (앱 피커 · 콘솔 등록) |

**왜 「폴더」가 안 되는가** — 참조를 받는 함수(`connectors/storage.js` `normalizeRef`)가
**파일 식별자와 판(rev)을 필수로** 받는다. 폴더에는 그 둘이 없다. 그리고 라우트
어디에도 폴더를 받는 자리가 없다:

```text
/projects/:id/linked          ← 파일 하나를 연결
/projects/:id/linked/verify   ← 그 파일이 그대로인지
/projects/:id/scan            ← 연결된 것을 읽는다
```

`storage.js` 의 `MODES.folder`(「폴더 연결」)는 **설명글이지 구현이 아니다.**
화면에 「폴더를 연결해서」라고 적혀 있어서 되는 것처럼 보이는데, 실제로 도는 것은
**파일 단위**다. 이 어긋남 자체가 이번 재검증에서 가장 중요한 발견이다.

## 1. 앞선 검증에서 **달라진 것**

| 절 | 2026-08-21 | 2026-08-22 | 왜 달라졌나 |
|---|---|---|---|
| §2·§9·§10 폴더 연결 | 🔴 충돌 | ✅ **결정됨** (D-72) · ⬜ **구현 없음** | 사용자가 폴더 연결을 승인했다. 결정은 났고 **코드는 아직 파일 단위다** |
| §15 파일명 표준 | ⬜ 미구현 | 🟡 **부분** | `core/outputspec.js` 에 규칙이 있다. 다만 **자리 하나가 다르다** (아래) |
| §9 변경 감지 | 🟡 부분 | 🟡 부분 **+ 결함 하나 고침** | 실제로 돌려 보니 거짓 경보가 나왔다 (§3) |

나머지 절의 판정은 **그대로다** — 일치 7 · 부분 5 · 미구현 4.

### §15 — 규칙은 있는데 자리 하나가 다르다

```text
지시서   [Project]_[DocType]_[Subject]_[Version]_[YYYYMMDD]
엔진     {Project}_{DocType}_{LANG}_{version}_{YYYYMMDD}
                              ~~~~~~
```

셋째 자리가 **주제(Subject)** 가 아니라 **언어(LANG)** 다. 한 자리 차이지만
같은 프로젝트에서 IM 과 Teaser 를 각각 낼 때 **이름이 겹친다.**
어느 쪽이 맞는지는 정하지 않았다 — 사양과 코드가 다르면 정하기 전까지 양쪽 다
고치지 않는다 (CLAUDE.md §9). **D-79 로 등록했다.**

## 2. 실제로 돌려 본 결과

말로만 「된다」고 하지 않기 위해 **끝까지 밟아 보는 도구**를 만들었다.

```bash
npm run im:try-linked
```

제공자(Dropbox·구글 드라이브…) 자리에 **우리가 띄운 HTTPS 서버**를 놓는다.
엔진 쪽에서 보면 달라지는 것이 없다 — 연결은 「참조 + 짧게 사는 내려받기 주소」로
이뤄지고 **그 주소가 어디서 왔는지 엔진은 모른다.** 그래서 여기서 통과하면
엔진 쪽은 준비된 것이고, 남은 것은 그 주소를 만들어 주는 쪽뿐이다.

**가짜 함수로 바꿔치기하지 않는다.** `fetchLinked` 를 주입하면 훨씬 쉽지만
그러면 handoff·https·크기 한도·지문 계산이 **한 줄도 안 밟힌다.**

실행 결과:

```text
3) 자료를 연결한다 — 파일을 가져오지 않는다. 참조 + 접근권만 맡긴다
  ✓ 장부에 올랐다 · key=gdrive:demo-file-0001
  ✓ 접근권은 30분만 산다

4) 장부에 열쇠가 섞여 들어갔는지 본다 (§2 · 절대 규칙)
  ✓ 장부에는 참조만 있다 (주소·토큰 없음)

5) 자료 스캔 — 잠깐 가져와 읽고, 읽고 나서 지운다
  ✓ 읽은 파일 1건 · 값 3개

6) 원본이 그때 그대로인가 물어본다 (§9)
  · 사업개요_v2.txt — 확인 못 함: 판(rev)을 알려 주지 않아 비교하지 못했습니다

7) 값이 실제로 들어갔는가 · 출처에 무엇이 적혔는가
  ✓ land.area_sqm = 2644          출처: 사업개요_v2.txt
  ✓ investment.total = 1200       출처: 사업개요_v2.txt

8) 작업 사본이 지워졌는가
  ✓ 남은 사본 없음

제공자 서버가 받은 요청: 2회 (HEAD 1 + GET 1)
결과: 연결 → 스캔 → 값 → 출처 까지 끝까지 돌았다
```

## 3. 이번에 잡은 결함 — **「모른다」가 「바뀌었다」로 둔갑했다**

돌려 보니 아무것도 안 바꾼 파일이 이렇게 나왔다:

```json
"changed": [{ "name": "사업개요_v2.txt", "was": "r2", "now": "null" }]
```

**왜** — 엔진 기본 구현(`core/linked-fetch.js` `headLinked`)은 임시 내려받기
주소로 HEAD 를 칠 뿐이라 **판(rev)을 알 방법이 없다.** 그래서 일부러 `null` 을
돌려준다("모르면 지어내지 않는다"). 그런데 받는 쪽이 `String(null) !== String('r2')`
로 비교해서 **「바뀌었다」로 분류했다.**

화면은 「원본이 바뀌었습니다 · 다시 읽어야 합니다」라고 말했을 것이고, 사용자는
멀쩡한 파일을 들여다봤을 것이다. **거짓 경보는 침묵보다 나쁘다** — 두어 번 겪으면
이 확인 자체를 안 믿는다.

**시험들이 왜 못 잡았나** — 전부 `rev` 를 넣어 주는 가짜 함수를 쓰고 있었다.
**실제로 실려 나가는 구현만 rev 를 안 준다.** M-15 와 같은 냄새다 — 재는 눈과
하는 눈이 달랐다.

**고친 것** — 판을 모르면 「확인 못 함」으로 보내고 **왜 못 했는지 사유를 적는다.**
화면도 그 사유를 그대로 쓴다(안 그러면 방금 읽은 사람에게 「안 읽었다」고 말한다).
`im-agent/test/linked.test.js` 가 고치기 전 판에서 실제로 걸리는 것을 확인했다.

## 4. 실제 클라우드로 가려면 — **남은 것은 사람 작업 둘**

엔진은 준비됐다. 화면도 준비됐다. 막힌 곳은 **그 사이 두 군데**다.

### ① 앱이 파일 고르기 창을 넘긴다 — `pickFrom`

화면(`files.html`)은 이미 그것을 기다린다:

```js
var canOpen = typeof C.pickFrom === 'function';
```

없으면 단추를 **누를 수 없게 두고** 「파일 고르기 창이 아직 연결되지 않았습니다」라고
말한다. 브라우저 탓을 하지 않는다 — 원인을 틀리게 말하면 사용자가 엉뚱한 것을
고치러 간다.

앱이 넘겨야 하는 것: 제공자 피커를 열고, 고른 결과를 이 모양으로 돌려주는 함수.

```js
{ ref:    { provider, fileId, name, rev, path },
  access: { url, headers } }        // https 여야 한다. 30분만 보관된다
```

### ② 제공자 콘솔 4곳에 앱을 등록한다

| 제공자 | 고를 것 | 막히기 쉬운 곳 |
|---|---|---|
| Dropbox | Access type = **App folder** | **되돌릴 수 없다.** Full Dropbox 로 만들면 앱을 다시 만들어야 한다 |
| Google Drive | 범위 **`drive.file`** | `drive.readonly` 는 드라이브 **전체**를 읽는다 |
| OneDrive · SharePoint | **`Files.Read.Selected`** | 업무용/개인 계정이 지문 방식이 다르다 |
| Box | 폴더 단위 승인 | 기업 계정은 **관리자 승인**이 있어야 붙는다 |

목록과 문구는 `connectors/storage.js` `SCOPES` 한 곳에서 나온다 — 화면·문서가
같은 문장을 쓴다. **D-72 가 「켜기 전에 채울 칸」 셋을 아직 비워 두고 있다**
(열쇠를 어디 두는가 · 철회 동선 · 읽기 전용 유지). Dropbox 앱 타입은 되돌릴 수
없으므로 **그 셋을 채우기 전에 등록하지 않는다.**

| 하고 싶은 것 | 지금 | 무엇이 있어야 하나 |
|---|---|---|
| 파일을 손으로 올려 스캔 | ✅ **된다** | — (「파일업로드」 갈래) |

| 클라우드 **폴더**를 지정해 통째로 | ❌ **코드 없음** | 폴더 참조·목록 조회·주기 감시를 새로 만든다 |
