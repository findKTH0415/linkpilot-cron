# 요청 지침서 — SketchUp Agent 엔진을 GitHub 에 붙이기 전, 값과 시점

> **무엇을 위한 문서인가.** 12/13 Agent(계획·수령)를 GitHub Actions 엔진에서
> 실제로 돌리려면 **값이 있어야 한다.** 그런데 값마다 **들어오는 시점이 다르다**
> — 배포 전에 한 번만 넣는 것, 프로젝트 만들 때 사람이 주는 것, 실행 중
> 공공데이터에서 자동으로 오는 것, 사람이 비동기로 되돌려 주는 것.
> 이 문서는 그 시점표다. **시점을 놓치면 오류가 아니라 빈칸으로 나타난다** —
> 그래서 미리 챙겨야 한다.

**근거**: 작업지시서(단계 0~5 완료) · 규격(`스케치업-모델-계획-규격.md`) ·
D-95·D-96·D-99 결정 · CLAUDE.md §4.

---

## 시점 0 — 배포 전, 한 번만 (지금 챙길 것)

GitHub 에 붙이기 **전에** 갖춰져 있어야 하는 것들이다. 여기가 이 문서의 핵심이다.

| # | 값 | 어디에 넣나 | 없으면 |
|---|---|---|---|
| 0-1 | **PR #9 머지** | GitHub → Pull requests → #9 → draft 해제 → Merge | 코드 자체가 main 에 없어 아무것도 안 돈다 |
| 0-2 | `VWORLD_KEY` + `VWORLD_DOMAIN` | 저장소 → **Settings → Secrets and variables → Actions** | 지적 폴리곤이 없어 **바닥이 근사 사각형**이 된다 (오류 아님 — 계획 notes 에 사유만 남는다) |
| 0-3 | `DATA_GO_KR_KEY` (Decoding 키) | 위와 같은 곳 | 건축물대장 값(대지면적·연면적·층수)이 문서 추출에만 의존한다 |
| 0-4 | **D-100 답** — 개념 배치 파라미터 | 사장님 결정 (⚪ 결재) | 통상치(판상형 13m·인동계수 0.8·사용률 0.8)로 계속 돈다 — ASSUMPTION 표기 유지 |

**여기서 대개 막힌다** — 키 두 가지 함정 (CLAUDE.md §4.1, 이미 겪은 사고):

- `VWORLD_DOMAIN` 은 VWorld 콘솔의 **서비스URL 을 글자 그대로** 넣는다.
  스킴(`https://`)이나 경로를 벗기면 **간헐적으로만** 인증이 거부돼(5회 중 2회
  실측) 「가끔 값이 안 들어온다」로 보인다 — 원인 추적이 가장 오래 걸리는 유형이다.
- `DATA_GO_KR_KEY` 는 **Decoding(일반) 인증키**다. Encoding 키를 넣으면 한 번
  더 인코딩되어 인증만 실패하고, 증상이 「키가 틀렸다」와 구분되지 않는다.

**넣었는지 확인하는 법** (키는 넣는 것보다 확인이 중요하다 — §4.3 스모크):

```
npm run im:smoke
```

지오코딩·지적 항목이 초록인지 본다. **스모크가 빨간데 배포부터 하지 않는다.**

## 시점 1 — 프로젝트 만들 때 (사람이 주는 값)

| 값 | 누가 | 어디로 가나 |
|---|---|---|
| 요청문 + **자산유형** | 사장님 (앱 입력) | `project.assetType` — 아파트 계열이면 개념 배치 분기 |
| **원본자료** (사업계획서 등) | 사장님 (업로드) | 02_extraction 이 대지면적·연면적·층수·높이·용도지역을 뽑는다 |
| **주소** | 사장님 (앱 입력) | 07_geo 가 지오코딩 → PNU → 지적 폴리곤·용도지역·건축물대장 |

★ 이 시점의 값이 곧 **모델의 뼈대**다. 대지면적·층수·층고가 셋 다 확보되지
않으면 12_sketchup_plan 은 **계획을 내지 않는다** (거절 규칙 — 반쪽 계획은
반쪽인 것이 안 보인 채 모델이 되기 때문이다).

## 시점 2 — 파이프라인 실행 중 (자동, 손댈 것 없음)

```
07_geo(지적·용도지역) → 09_massing(법정한도·링 계산 — 계산 자리는 여기 하나)
→ 12_sketchup_plan(계획 파일 = 링 mm 변환 + 법정 분석 + 개념 배치)
→ 13_sketchup_intake(결과가 있으면 대조) → 05_validation
```

- 용적률 상한은 키가 없어도 **문서의 용도지역 문자열만으로** 나온다
  (국토계획법 시행령 기준 — 지자체 조례 확인 필요 표기가 붙는다).
- 매스가 상한 초과(RED)면 계획 자체가 나오지 않는다 — 이건 결측이 아니라 판정이다.

## 시점 3 — 평면 B (사람, 비동기 — 시간이 걸려도 된다)

| 값 | 누가 | 어디에 넣나 |
|---|---|---|
| `model-result.json` | 사장님 (맥북 절차서 ⑦) | 프로젝트 폴더 `04_Property/` |
| `.skp` · 장면 PNG | 사장님 (다운로드 주소에서 받아서) | 〃 — **엔진 프록시가 sketchup.com 을 막아(403) 반입은 사람 몫이다** |
| Veras 렌더 (선택) | 사장님 | 〃 — `renders` 에 disclaimer 필수, 없으면 YELLOW |

## 시점 4 — 결과 반입 뒤 (재실행이 필요하다 — 여기를 놓치기 쉽다)

**파일을 폴더에 넣는 것으로 끝나지 않는다.** 13_intake 는 파이프라인이 돌 때
읽는다 — 결과를 넣은 뒤 **보고서 재생성(또는 재실행)을 한 번 해야** 대조가
돌고 검증에 반영된다. 넣기만 하고 재실행을 안 하면 화면은 계속 「결과 없음」
상태를 보여준다.

## 결측 시 행동표 — 무엇이 없으면 무엇이 되는가

| 없는 값 | 결과 | 성격 |
|---|---|---|
| VWorld 키 | 바닥 폴리곤 `null` + notes 사유 | 조용한 저하 — **오류 아님** |
| 대지면적·층수·층고 중 하나 | 계획 미생성 + `PLAN_MISSING` YELLOW | 거절 규칙 |
| 용적률 상한 초과 | 계획 미생성 + `PLAN_SKIPPED` | 판정 (매스 RED) |
| model-result.json | intake `unavailable` — 그 절 비움 | 정상 (사람 시간) |
| 렌더 disclaimer | `RENDER_DISCLAIMER` YELLOW | 표기 의무 (D-34) |

어느 경우에도 **한 소스가 죽어 IM 생성 전체가 죽지는 않는다** (§4.6).
