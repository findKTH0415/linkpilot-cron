# 스케치업 모델 만드는 법 — 맥북에서

> **누가**: 사장님이 직접 (D-95, 2026-08-24 결정).
> **어디서**: 맥북 — **SketchUp 을 설치할 필요가 없다.** 2026-08-24 실측으로
> SketchUp 이 **클라우드에서 돈다**는 것을 확인했다: GitHub 에서 띄운 Claude
> 웹 세션에서 `build_model` 이 성공했고, 저장하면 `.skp` 가 **다운로드
> 주소**로 온다. 맥북에 필요한 것은 Claude 뿐이다.
> **무엇을 위해**: 엔진이 만든 계획(`model-plan.json`)대로 3D 모델을 만들고,
> 결과(`.skp`·그림·`model-result.json`)를 프로젝트 폴더에 돌려놓기 위해서다.
> 자동 실행(크론)은 이 연결이 있는지 보장되지 않아, 이 부분만 사람 자리에서 한다.
>
> ✅ **2026-08-25 전 과정 1회 실측 완료** (원격 세션): 실제 계획(지상 8층·
> 층고 4500mm)으로 클라우드 모델 생성 → 저장 → 결과 기록 → 수령 Agent 대조
> **플래그 0건.** 저장은 무료 구간 **30회 한도**를 쓴다(1회 저장 = 1회 차감).
> 사장님 손으로의 첫 완주는 아직이다 — 막히는 곳이 나오면 알려 주시면
> 문서를 고친다. 막힌 곳이 이 문서의 버그다.

## 준비물 — 하나뿐이다

**Trimble SketchUp 커넥터가 연결돼 있어야 한다.** 커넥터란 Claude 가 외부
서비스(여기서는 클라우드 SketchUp)를 부리게 해 주는 연결이다.

- 확인하는 곳: **claude.ai → 설정(Settings) → 커넥터(Connectors)** 에서
  Trimble SketchUp 이 「연결됨」인지 본다. 없으면 거기서 연결하고 로그인한다.
- **여기서 대개 막힌다.** 연결이 안 돼 있으면 Claude 는 「SketchUp 도구가
  없다」고만 하고 이유를 말해 주지 않는다. 도구가 없다고 하면 십중팔구 이거다.
- SketchUp 프로그램 설치·실행은 필요 없다. 화면에 SketchUp 창이 뜨지 않는
  것이 정상이다 — 확인은 그림(장면 PNG·저장 미리보기)으로 한다.

## 순서 — 일곱 단계

### ① 맥북에서 Claude 를 연다

둘 중 편한 쪽이면 된다:

- **브라우저**: claude.ai 에서 새 대화를 연다
- **터미널**: `claude` 를 쳐서 Claude Code 를 연다

### ② 계획 파일을 준비한다

엔진이 만든 `model-plan.json` 을 준다 — 파일을 올리거나, 내용을 붙여 넣거나,
저장소 경로를 알려 주면 된다.

- **처음 연습이라면**: 저장소의 `docs/model-plan.sample.json` 을 쓴다.
  예시 데이터라고 파일 안에 적혀 있다.

### ③ 이렇게 시킨다

아래 문장을 그대로 붙여 넣는다.

> SketchUp 스킬 목록을 확인하고 baseline 스킬을 전부 읽은 다음,
> model-plan.json 을 읽고 그 계획대로 SketchUp 매스 모델을 만들어 줘.
> 새 작업이니 clean 하게 시작해 줘. 단위는 mm 다.
> 만들고 나면 지오메트리 정리와 검증을 하고, 카메라·스타일을 잡고
> 장면을 만든 뒤 저장해 줘.
> 규칙은 im-agent/prompts/sketchup-engineering-agent.md 를 따른다.

- 「baseline 스킬을 전부 읽는다」는 생략하면 안 된다. **읽지 않고 만들면
  깨진 코드가 나온다고 도구 설명이 직접 경고한다** — 우리 규칙이 아니라
  도구의 계약이다. 위 문장에 이미 들어 있으니 그대로 쓰면 된다.

### ④ 눈으로 확인한다

SketchUp 창이 없으므로 **그림으로 확인한다.** Claude 에게 장면 그림을
보여 달라고 하고, 이 둘을 본다:

- 매스가 **실제로 생겼는가** (빈 그림이면 뭔가 잘못됐다)
- 층수·비례가 계획과 **눈대중으로라도 맞는가**

### ⑤ 저장한다

「저장해 줘」라고 하면 `.skp` 파일의 **다운로드 주소와 미리보기 그림**이 온다.
주소를 눌러 파일을 받는다. 장면 그림(PNG)도 함께 받아 달라고 한다.

### ⑥ 결과 기록을 만들게 한다

> model-result.json 을 만들어 줘.
> 규격은 docs/스케치업-모델-계획-규격.md §3 이다.
> plan_created 에는 계획 파일의 created 값을 그대로 복사해 줘.

### ⑦ 파일을 프로젝트 폴더에 돌려놓는다

받은 것 전부 — `.skp` · PNG · `model-result.json` — 를 해당 프로젝트의
**`04_Property/`** 폴더에 넣는다. 새 폴더를 만들지 않는다.

이것으로 끝이다. 이후는 엔진 쪽(수령 Agent, 단계 4)이 결과를 계획과 대조한다.

## 사실적 표현 워크플로 — 표준은 Veras 〈2026-08-25 재구성〉

> **무엇을 위해**: 개념 매스를 **사실적 표현**(표지·티저용 그림)으로 바꾸기
> 위해서다. **경계 하나만 지키면 된다** (D-34): AI 렌더는 **표지·티저용**이다.
> IM 본문 조감도는 지적도에서 그린 것(`birdseye.js`)을 쓴다 — AI 그림은
> 그럴듯할수록 설계안으로 오해되기 쉽고, 그것이 사고다.

### 왜 Veras 인가 〈2026-08-24 사장님 확정〉

- **Revit·SketchUp·Rhino 등 7개 주요 BIM/CAD 플랫폼에 직접 연동되는 유일한
  AI 렌더링 도구**다 — 모델 안에서 뷰를 잡고 그 자리에서 렌더한다.
- **최신 4.0 은 Nano Banana Pro 기반**으로 건축 시각화에서 특히 좋은 결과를
  낸다. 같은 계열 모델이 Gemini 앱에서 무료로 돌므로 구독 전 감을 볼 수 있다
  (아래 무료 경로).

### 흐름 — 매스에서 사실적 표현까지 넉 단계

```
① 매스        ② 뷰 잡기        ③ Veras 4.0 렌더      ④ 수령
클라우드/손     장면(SC-xxx)      형태 유지 낮게         renders 규격
.skp            각도 고정          여러 장 뽑기           disclaimer 필수
```

**사장님이 SketchUp 에서 매싱 모델을 만들고 → 그 뷰를 Veras 로 렌더한다.**
매싱은 손으로 만들어도 되고, 위 ①~⑤(Claude 클라우드)로 만들어 받은 `.skp`
를 열어도 된다 — **어느 쪽이든 결과를 받는 규격은 같다.**

1. **맥북의 SketchUp 에서 모델을 연다.** Veras 플러그인은 SketchUp 안에서
   돌므로 이 단계만은 데스크톱 SketchUp 이 필요하다.
2. **Veras 를 설치한다** (한 번만): SketchUp 메뉴 **Extensions →
   Extension Warehouse** 에서 "Veras" 를 검색해 설치하고, EvolveLAB 계정으로
   로그인한다. **여기서 대개 막힌다** — 로그인 없이는 렌더 단추가 안 눌린다.
3. **렌더할 뷰를 잡는다.** 장면(SC-001 부지 전경 등)과 같은 각도로 맞추면
   나중에 「어느 뷰에서 나온 그림인지」가 이어진다.
4. **Veras 에서 렌더한다.** 형상 유지 슬라이더(Geometry Override)를 **낮게**
   두는 것이 요령이다 — 높이면 AI 가 매스 형상 자체를 바꿔 버려서, 우리
   매스와 다른 건물 그림이 나온다.
5. **저장 이름 규칙**: `render_SC-001_veras_01.png` 처럼
   `render_<장면ID>_veras_<번호>.png` 로 저장한다.
6. **`04_Property/` 에 넣고**, `model-result.json` 의 `renders` 에 적는다 —
   `ai_generated: true` 와 `"AI 렌더 — 실제 설계안이 아님"` 문구가 **필수다**
   (규격 §3-1). 문구가 빠지면 수령 Agent 가 노란 플래그를 낸다.
   **도구·버전도 같이 적는다** — `"tool": "veras", "tool_version": "4.0",
   "engine": "Nano Banana Pro"`. 세대마다 그림이 달라서 이것이 출처 표기다
   (없으면 역시 노란 플래그). 형상 유지 슬라이더 값과 프롬프트를 `settings`
   에 남기면 나중에 **같은 그림을 다시 만들 수 있다** — 권장.

### 무료로 바로 해 보는 길 — Gemini 앱

Veras 를 설치·구독하기 전에 **같은 계열 모델(Nano Banana Pro — Veras 4.0 이
쓰는 것)을 Gemini 앱에서 무료로** 돌려 감을 볼 수 있다. 이 길은 SketchUp
설치도 필요 없다 — 클라우드로 만든 **장면 PNG 만 있으면 된다.**

1. Gemini 앱(또는 gemini.google.com)을 연다
2. 장면 PNG(`scene_001.png`)를 올리고 이렇게 시킨다:
   「이 건물 매스를 사실적인 건축 렌더로 만들어 줘. **건물의 형태·층수·
   비례는 그대로 유지**하고, 재질과 주변 환경만 입혀 줘.」
3. 결과를 `render_SC-001_gemini_01.png` 로 저장한다 — 규칙은 Veras 와 같고
   `tool` 만 `"gemini"` 로 적는다 (`engine` 은 똑같이 `"Nano Banana Pro"`,
   `tool_version` 은 앱이라 버전이 안 보이면 `"app"` 으로).
   **disclaimer 필수도 같다** (규격 §3-1).

⚠️ **올리는 것은 매스 그림뿐이다.** 원본 도면·사업계획서·주소가 박힌 문서를
외부 서비스에 올리지 않는다 (CLAUDE.md §2 와 같은 결).

⚠️ 형태가 바뀌어 나오면 그 그림은 버린다 — **우리 매스와 다른 건물 그림**이
표지에 실리는 것이 이 경로의 사고다. 「형태 유지」를 다시 강조해서 돌린다.

### 자동화는 아직 안 붙인다

Veras 를 엔진이 자동으로 부르는 길(API)은 **실측 전이다** (D-34 — 「붙이기
전에 API 존재를 실측해야 한다」). 그래서 이 단계는 사람 손으로 한다.
API 가 실측되면 그때 커넥터로 옮긴다.

## 막히면

| 증상 | 원인일 가능성이 큰 것 |
|---|---|
| 「SketchUp 도구가 없다」 | 커넥터 미연결 — 준비물로 돌아간다 |
| 사용 한도 안내(업그레이드 화면)가 뜬다 | 무료 구간 한도다. 한도·요금은 아직 실측 전이라(D-95 비고) 뜨면 그 화면을 알려 주시면 등록부에 적는다 |
| 크기가 이상하다 (너무 크거나 작다) | 단위 사고다. 계획은 mm 인데 다른 단위로 읽었다 — 「단위는 mm 다」를 다시 말해 준다 |
| 이전 작업 잔재가 섞인다 | 「clean 하게 새로 시작해 줘」라고 한다 (새 작업 첫 호출은 초기화가 규칙이다) |

문제가 반복되면 그 화면을 찍어 알려 주시면 된다 — 절차서를 고치는 것이
이 문서의 유지보수다.
