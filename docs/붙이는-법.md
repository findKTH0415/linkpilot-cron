# 본체 플랫폼에 보고서 생성 엔진 붙이기

앱의 **[보고서 생성]** 섹션에 이 저장소의 엔진을 연결하는 순서다.
붙이는 곳은 세 군데뿐이다 — **서버 라우터 · 화면 파일 · 환경변수**.

> 지금 그 섹션은 기반정보를 **내보내는 곳**이고 값 입력은 바깥 AGENT 가 받는다.
> 그러면 출처 필수 · 계산 항목 입력 금지 · 사양 확정(LOCK)을 **앱이 강제할 수 없다.**
> 이 문서는 값 입력을 앱 안으로 들여오는 절차다. **내보내기 경로는 그대로 둔다** —
> 둘 다 쓸 수 있어야 한다.

---

## 0. 붙이기 전에 정해야 하는 것

| 항목 | 왜 먼저인가 |
|---|---|
| `IM_AGENT_ROOT` 경로 | 프로젝트 폴더가 여기 쌓인다. 나중에 바꾸면 기존 프로젝트를 못 찾는다 |
| 인증 함수 | **없으면 서버가 뜨지 않는다** (fail closed). 나중에 붙이는 것이 불가능하다 |
| 화면 서빙 위치 | 앱과 **같은 출처**여야 한다. 다르면 화면 높이를 못 재 잘려 보인다 |

---

## 1. 서버 — 라우터 두 개를 마운트한다

읽기와 쓰기를 **일부러 갈라 두었다.** 쓰기는 파일을 만들고 LLM 을 부르고 공공데이터
쿼터를 쓴다. 같은 라우터에 얹으면 대시보드 폴링과 같은 권한으로 돈 드는 동작이 열린다.

```js
// 본체 server.js (포트 8181)
const path = require('path');
const AGENT = '/volume1/linkpilot/im-agent';        // 이 저장소를 놓은 경로
const ROOT  = '/volume1/linkpilot/im-projects';     // 산출물이 쌓이는 곳

const read    = require(path.join(AGENT, 'ui/api-router.cjs'));
const reports = require(path.join(AGENT, 'ui/report-api.cjs'));
const { createQueue } = require(path.join(AGENT, 'ui/run-queue.cjs'));

const queue = createQueue({ agentRoot: ROOT, concurrency: 1 });

// ① 읽기 — 대시보드·화면이 폴링한다
app.use('/api/linkpilot', read.createRouter({
  agentRoot: ROOT,
  agentModulePath: AGENT,
}));

// ② 쓰기 — 인증 필수
app.use('/api/linkpilot', reports.createRouter({
  agentRoot: ROOT,
  agentModulePath: AGENT,
  authenticate: (req) => req.session && req.session.user,   // ★ 없으면 마운트에서 예외
  startRun: (projectId, spec, user) => queue.startRun(projectId, spec, user),

  // ★★ 이 줄을 빠뜨리기 쉽다 — 아래 「함정」 참조
  runningFor: (projectId) => {
    const r = queue.latestFor(projectId);
    return r && (r.status === 'running' || r.status === 'queued') ? r : null;
  },
}));

process.on('SIGTERM', () => queue.stop());   // 안 하면 배포마다 고아 프로세스가 쌓인다
```

`authenticate` 가 돌려줄 것: `{ name, planId, status }`
(`planId` 는 `free|basic|pro|business`, `status` 는 `active|expired`)

### ★ 함정 — `runningFor` 를 안 넘기면 조용히 규칙이 꺼진다

`report-api` 는 **생성이 도는 중에는 값 저장을 거부한다.** 파이프라인이 읽는
도중에 값이 바뀌면 산출물과 데이터가 어긋나기 때문이다.

그 판정을 `runningFor` 로 물어보는데, **안 넘기면 검사 자체를 건너뛴다.**
오류도 경고도 없다 — 평소에는 아무 일 없이 돌다가, 생성 중에 누가 값을 고친
그날 산출물이 데이터와 다르게 나온다.

큐에는 `runningFor` 라는 이름의 메서드가 없다 (`latestFor` 다). 위 코드처럼
직접 이어 준다.

## 2. 화면 — 섹션 자리에 파일 하나

`im-agent/ui/platform/` 의 아래 파일들을 앱과 **같은 출처**에 올린다.

```
report-flow.html      ← [보고서 생성] 섹션 본체
flow-core.js          ← 4단계 정의 (단일 출처)
gate-core.js  catalog.js  inapp.js
intake.html  fields.html  reports.html   ← 단계 화면
```

`report-flow.html` 의 설정 블록만 채운다. **다른 곳에 값을 박지 않는다.**

```js
window.LINKPILOT_REPORT_FLOW = {
  api:  '/api/linkpilot',       // 없으면 단계가 잠기고 사유가 뜬다
  base: '/im/',                 // 단계 화면들이 놓인 경로 (같은 폴더면 '')
  session: currentUser,         // { authenticated, planId, status, name }
  projectId: null,              // 이어서 작업할 프로젝트가 있으면

  external: {                   // 지금 쓰는 외부 분석 경로 — 지우지 않는다
    repoUrl:  'https://…',      // [LinkPilot AGENT 저장소]
    agentUrl: 'https://…',      // [보고서 생성 AGENT 열기]
  },
};
```

- 앱의 사이드바·로고는 **끼울 때만 자동으로 감춰진다** (`flow-core.js` 의 `EMBED_CSS`).
  화면 소스는 건드리지 않으므로 따로 열면 원래대로 보인다
- 단계 화면을 **복사하지 말 것.** 복사하면 「출처 없는 값은 저장할 수 없다」 같은
  검사가 두 벌이 되고, 한쪽만 고치는 날 규칙이 갈린다
- 4단계를 늘리거나 순서를 바꾸려면 `flow-core.js` **한 곳만** 고친다.
  제품 화면과 미리보기가 같이 따라온다

## 3. 환경변수 — 본체 프로세스에 넣는다

**GitHub Secrets 만으로는 아무 일도 일어나지 않는다.** 실제로 공공데이터를 쓰는 것은
본체(NAS)에서 도는 프로세스이므로, 값은 **거기에** 들어가야 한다.

| 이름 | 없으면 |
|---|---|
| `IM_AGENT_ROOT` | 프로젝트 폴더 위치를 모른다 (필수) |
| `VWORLD_KEY` · `VWORLD_DOMAIN` | 07 Geo 통째로 건너뜀 — 입력란이 8→9칸으로 는다 |
| `DATA_GO_KR_KEY` | 실거래가·건축물대장·건축인허가 건너뜀 |
| `ECOS_API_KEY` | 금리가 가정치로만 남는다 |
| `DART_API_KEY` | 시행사를 대조하지 않는다 |
| `GEMINI_API_KEY` | 추출·문장이 규칙 기반만 동작 |

- `DATA_GO_KR_KEY` 는 **Decoding(일반) 인증키**다. Encoding 쪽을 넣으면 인증만
  실패하고 증상이 "키가 틀렸다"와 똑같다 (커넥터가 부르기 전에 막고 알려 준다)
- `VWORLD_DOMAIN` 을 빠뜨리기 쉽다. 서버 호출에는 Referer 가 없어 **키가 맞아도
  거부된다**

## 4. 순서대로 확인 (건너뛰지 말 것)

```bash
# ① 엔진만 먼저 — 서버·키 없이 돈다
npm test                                   # 534 pass / 0 fail 이어야 한다
npm run im:demo                            # 샘플로 파이프라인 1회

# ② 키를 넣고 공공데이터 실측 — 응답 필드명까지 대조한다
IM_AGENT_DEBUG_HTTP=1 npm run im:smoke

# ③ 화면만 먼저 — 서버 없이 파일 하나로 열린다
npm run im:section                         # section-preview.html
```

**②를 건너뛰지 말 것.** 커넥터의 응답 필드명은 공식 문서 기준으로 작성했고
**실제 키로 검증한 적이 없다.** 필드명이 다르면 조회는 성공하는데 값이 전부 비고,
화면에는 아무 경고도 안 뜬다 — 가장 잡기 어려운 종류의 오류다.

## 5. 붙인 뒤 첫 확인

| 보이는 것 | 뜻 |
|---|---|
| 단계가 전부 잠기고 「서버(api)가 연결되어 있지 않습니다」 | `api` 를 안 채웠다 |
| 2~4단계만 잠기고 「1단계에서 프로젝트를 먼저 만듭니다」 | 정상. 1단계부터 하면 된다 |
| 화면이 아래쪽에서 잘린다 | 단계 화면이 **다른 출처**에 있다 (화면이 그 사실을 적는다) |
| [프로젝트 만들기] 옆 「API 주소가 없어 만들 수 없습니다」 | 정상 표시. 눌리는 척하지 않는다 |
| 서버가 아예 안 뜨고 `authenticate` 예외 | 정상. 인증 없이 생성 API 를 열 수 없다 |

## 6. 아직 붙일 수 없는 것

| | 막고 있는 것 |

## 되돌리는 법

라우터 두 줄을 빼고 섹션을 원래 화면으로 되돌리면 끝이다. **엔진은 앱 밖에서
파일로만 돌아가므로 본체 데이터에 손대지 않는다** — 프로젝트 폴더(`IM_AGENT_ROOT`)만
남고, 그것도 지우면 흔적이 없다.
