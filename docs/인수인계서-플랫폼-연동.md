## 0. 한 장 요약 — 지금 앱과 무엇이 달라지는가

지금 앱의 **[보고서 생성]** 은 이렇게 적혀 있다.

> 「보고서는 외부 분석 환경에서 만듭니다. 이 화면에서 보고서를 직접 만들지 않습니다.
> 앱은 **내부환경 기반정보**를 내보내고, 외부 분석 AGENT 툴이 그것을 분석해
> 보고서를 만듭니다.」

그래서 **PROJECT CONTROL TOWER** 에 「변환기 — 연결 대기」 「등록된 완성본 0건」이
남아 있고, 값 입력·검증·사양 확정이 전부 앱 밖에서 일어난다.

**이 인수인계의 목적은 그 바깥을 앱 안으로 들여오는 것이다.**

| | 지금 (캡처 기준) | 붙인 뒤 |
|---|---|---|
| 값 입력 | 앱 밖 AGENT 가 받는다 | 앱 2단계에서 받는다 — **출처 없으면 저장이 안 열린다** |
| 계산 항목 | 사람이 적어 넣을 수 있다 | 입력란을 아예 만들지 않는다 (19개) |
| 자료 읽기 | 「보관만 됩니다」 8종 | **그대로 읽음 19종 · 옮겨 적어 읽음 6종 · 변환 필요 3종** |
| 사양 확정 | 없음 | 3단계에서 잠근다 — 확정 전에는 생성이 시작되지 않는다 |
| 등록된 완성본 | 0건 (밖에서 받아 등록) | 앱이 만들고 목록에 바로 뜬다 |
| 검증 | 밖에서 | 05·11 이 값 충돌·범위·정합성을 RED/YELLOW/GREEN 으로 |

> **내보내기 경로는 지우지 않는다.** 「기반정보 복사·내려받기」와 외부 AGENT 링크는
> 그대로 둔다. 둘 다 쓸 수 있어야 한다 — 붙이는 일이 기존 흐름을 끊으면 안 된다.

## 2. 붙이는 곳은 세 군데뿐이다

### 2-1. 서버 — 라우터 두 개

읽기와 쓰기를 **일부러 갈라 두었다.** 쓰기는 파일을 만들고 LLM 을 부르고 공공데이터
쿼터를 쓴다. 같은 라우터에 얹으면 대시보드 폴링과 같은 권한으로 돈 드는 동작이 열린다.

```js
// 본체 server.js (포트 8181)
const path = require('path');
const AGENT = '/volume1/linkpilot/im-agent';        // 이 저장소를 놓은 경로
const ROOT  = '/volume1/linkpilot/im-projects';     // 산출물이 쌓이는 곳

const read    = require(path.join(AGENT, 'ui/api-router.cjs'));
const reports = require(path.join(AGENT, 'ui/report-api.cjs'));
const { createQueue } = require(path.join(AGENT, 'ui/run-queue.cjs'));

const queue = createQueue({ agentRoot: ROOT, concurrency: 1 });

app.use('/api/linkpilot', read.createRouter({ agentRoot: ROOT, agentModulePath: AGENT }));

app.use('/api/linkpilot', reports.createRouter({
  agentRoot: ROOT,
  agentModulePath: AGENT,
  authenticate: (req) => req.session && req.session.user,   // ★ 없으면 마운트에서 예외
  startRun: (projectId, spec, user) => queue.startRun(projectId, spec, user),
  runningFor: (projectId) => {                              // ★★ 빠뜨리기 쉽다
    const r = queue.latestFor(projectId);
    return r && (r.status === 'running' || r.status === 'queued') ? r : null;
  },
}));

process.on('SIGTERM', () => queue.stop());
```

**★ `runningFor` 를 안 넘기면 조용히 규칙이 꺼진다.** `report-api` 는 생성이 도는
중에는 값 저장을 거부하는데, 그 판정을 이 함수로 물어본다. 안 넘기면 **검사를 건너뛴다** —
오류도 경고도 없다. 생성 중에 값을 고친 그날 산출물이 데이터와 어긋난다.
큐에는 `runningFor` 라는 이름의 메서드가 없다 (`latestFor` 다). 위처럼 직접 이어 준다.

### 2-2. 화면 — 섹션 자리에 파일 몇 개

`im-agent/ui/platform/` 의 파일들을 앱과 **같은 출처**에 올리고, `report-flow.html` 의
설정 블록만 채운다. **다른 곳에 값을 박지 않는다.**

```js
window.LINKPILOT_REPORT_FLOW = {
  api:  '/api/linkpilot',
  base: '/im/',                 // 단계 화면들이 놓인 경로 (같은 폴더면 '')
  session: currentUser,         // { authenticated, planId, status, name }
  projectId: null,
  external: {                   // 지금 쓰는 외부 분석 경로 — 지우지 않는다
    repoUrl:  'https://…',
    agentUrl: 'https://…',
  },
};
```

- 앱 사이드바·로고는 **끼울 때만 자동으로 감춰진다** (`flow-core.js` 의 `EMBED_CSS`)
- 단계 화면을 **복사하지 말 것** — 복사하면 「출처 없는 값은 저장할 수 없다」 같은
  검사가 두 벌이 되고, 한쪽만 고치는 날 규칙이 갈린다
- 4단계를 늘리거나 순서를 바꾸려면 `flow-core.js` **한 곳만** 고친다

### 2-3. 환경변수 — 본체 프로세스에 넣는다

**GitHub Secrets 만으로는 아무 일도 일어나지 않는다.** 실제로 공공데이터를 쓰는 것은
본체(NAS)에서 도는 프로세스이므로 값은 **거기에** 들어가야 한다.

`.env.example` 을 그대로 복사해 채우면 된다 (`cp .env.example .env`).

| 이름 | 없으면 |
|---|---|
| `IM_AGENT_ROOT` | 프로젝트 폴더 위치를 모른다 (**필수**) |
| `VWORLD_KEY` · `VWORLD_DOMAIN` | 07 Geo 통째로 건너뜀 — 입력란이 8→9칸으로 는다 |
| `DATA_GO_KR_KEY` | 실거래가·건축물대장·인허가·REC 건너뜀 |
| `KMA_APIHUB_KEY` (+ `KMA_STN`) | 태양광 딜의 일사량·일조시간이 빈다 |
| `REB_API_KEY` | **공시지가 시점수정이 안 된다** — 8월 IM 이 1월 1일 값을 쓴다 |
| `ECOS_API_KEY` | 금리가 가정치로만 남는다 |
| `DART_API_KEY` | 시행사를 대조하지 않는다 |
| `GEMINI_API_KEY` | 추출·문장이 규칙 기반만 + **스캔본·사진을 아예 못 읽는다** |

- `DATA_GO_KR_KEY` 는 **Decoding(일반) 인증키**다. Encoding 쪽을 넣으면 증상이
  "키가 틀렸다"와 똑같다 (커넥터가 부르기 전에 막고 알려 준다)
- `VWORLD_DOMAIN` 은 콘솔의 **서비스URL 을 글자 그대로** 넣는다 (스킴·경로 포함).
  호스트만 넣으면 `ned/*` 계열이 간헐적으로 거부한다 — 실측 5회 중 2회

## 4. 화면 4단계와 데이터 흐름

```
1 보고서 생성 입력   POST /projects → POST /projects/:id/sources
     ↓  요청문에서 뽑은 값은 「미확인」으로 표시
2 가이드 필드 입력   GET /fields → PUT /projects/:id/facts
     ↓  사전 60항목 중 아무도 못 채우는 9칸만 묻는다
     ↓  출처가 비면 그 줄이 빨갛게 서고 저장이 안 열린다
     ↓  계산 19항목은 입력란을 만들지 않는다
3 출력 사양 확정     POST /projects/:id/spec → /spec/confirm (LOCK)
     ↓  확정 전에는 생성이 시작되지 않는다
4 생성               POST /projects/:id/reports → GET /reports → GET /file
        검증 통과한 산출물만 열린다
```

**필수 17개 중 사람이 직접 넣는 것은 9개** — 시행사/스폰서 · 대지면적 · 토지 확보상태 ·
연면적 · 총사업비 · 토지비 · 공사비 · 연간 매출(안정화) · 인허가 현황.
(대지면적은 `VWORLD_KEY` 가 없어서 내려온 것이다. 키가 있으면 8개)

## 5. 반영될 모든 요소 — 체크리스트

### 5-1. 앱(본체)에서 해야 하는 일

- [ ] `server.js` 에 읽기 라우터 마운트 (§2-1)
- [ ] `server.js` 에 쓰기 라우터 마운트 — `authenticate` · `startRun` · **`runningFor`**
- [ ] `SIGTERM` 에 `queue.stop()` (안 하면 배포마다 고아 프로세스가 쌓인다)
- [ ] `[보고서 생성]` 섹션을 `report-flow.html` 로 교체 (같은 출처에 올린다)
- [ ] 설정 블록 4줄 채우기 — `api` · `base` · `session` · `external`
- [ ] **「기반정보 복사·내려받기」와 외부 AGENT 링크는 그대로 둔다**
- [ ] 환경변수 7종 등록 (§2-3) — `IM_AGENT_ROOT` 는 필수

## 6. 인수 조건 — 순서대로, 건너뛰지 말 것

```bash
# ① 엔진만 먼저 — 서버·키 없이 돈다
npm test                                   # 613 pass / 0 fail 이어야 한다
npm run im:demo                            # 샘플로 파이프라인 1회

# ② 키를 넣고 공공데이터 실측 — 응답 필드명까지 대조한다
IM_AGENT_DEBUG_HTTP=1 npm run im:smoke

# ③ 자료 읽기 실측 — 실무 파일 몇 개로
npm run im:read -- ~/사업계획서.pdf ~/감정평가서.hwp

# ④ 화면만 먼저 — 서버 없이 열린다
npm run im:section                         # 눌러 볼 수 있는 판
npm run im:static                          # 스크립트 없이도 보이는 판
```

**②를 건너뛰지 말 것.** 커넥터의 응답 필드명은 공식 문서 기준으로 작성했고
**실제 키로 검증한 적이 없다.** 필드명이 다르면 조회는 성공하는데 값이 전부 비고,
화면에는 아무 경고도 안 뜬다 — 가장 잡기 어려운 종류의 오류다.

### 붙인 뒤 첫 확인

| 보이는 것 | 뜻 |
|---|---|
| 단계가 전부 잠기고 「서버(api)가 연결되어 있지 않습니다」 | `api` 를 안 채웠다 |
| 2~4단계만 잠기고 「1단계에서 프로젝트를 먼저 만듭니다」 | 정상 |
| 화면이 아래쪽에서 잘린다 | 단계 화면이 **다른 출처**에 있다 |
| 서버가 안 뜨고 `authenticate` 예외 | 정상 — 인증 없이 생성 API 를 열 수 없다 |
