# 안내 — 국가법령정보 공동활용 API (LAW_OC) 받기

〈2026-08-25 사장님 지시: 「국가법령정보 공동활용 API 확보」〉

## 0. 무엇을 위해 하는가

지금까지 **법정 한도만은 출처가 사람의 기억**이었습니다. 용적률 800%,
방화구획 1,500㎡, 인동거리 0.5배 — 전부 맞는 말이지만 **어느 조문인지가
문서에 안 적혀 있었습니다.** 이 저장소는 「출처 없는 숫자는 못 들어온다」가
설계의 전부인데, 그 한 곳만 비어 있었던 것입니다.

이 API 를 붙이면 두 가지가 됩니다.

1. **법령·시행령 조문을 원문 그대로** 가져와 출처로 답니다.
2. **지자체 건축조례**를 찾습니다. ★ 이쪽이 더 중요합니다 —
   용적률·건폐율의 **실제 한도는 시행령이 아니라 조례**가 정하는데,
   지금까지는 그 자리를 「조례 확인 사항」이라고만 적어 왔습니다.

## 1. 다른 기관과 다른 점 — 셋 (여기서 대개 막힙니다)

**① 키가 아니라 「OC」입니다.**
다른 기관은 긴 인증키를 줍니다. 여기는 **신청에 쓴 이메일의 `@` 앞부분**이
그대로 인증값입니다. 메일이 `hong@pdi.co.kr` 이면 OC 는 `hong` 입니다.
발급 화면에서 긴 문자열을 찾으실 텐데 **없습니다.** 그게 정상입니다.

**② 신청만으로는 안 되고 「사용 승인」이 나야 합니다.**
신청 후 **1~2일** 걸립니다. 승인 전에 부르면 오류가 나는데, 그 오류가
**「OC 를 잘못 넣었다」와 똑같이 생겼습니다.** 그래서 열쇠를 다시 넣어 보게
되고, 넣어도 안 되니 또 넣게 됩니다. (Gemini 때 실제로 두 번 그랬습니다.)
→ 이 함정은 코드가 막습니다. `law.js` 가 **승인 / OC / 없음 / 형식** 넷으로
갈라 한국어로 말해 줍니다.

**③ 조문 번호는 6자리입니다.**
제46조는 `004600`, 제86조 제3항은 `008603` 입니다. 조 4자리 + 항 2자리.
0 을 안 채우면 **엉뚱한 조문이 조용히 옵니다.** 이것도 코드가 채웁니다.

## 2. 신청 절차 — 눌러야 할 자리

1. 브라우저에서 **`open.law.go.kr`** 을 엽니다 (국가법령정보 공동활용).
2. 오른쪽 위 **[로그인]** → 계정이 없으시면 **[회원가입]** 먼저 합니다.
   ★ **여기서 쓰신 이메일이 곧 OC 가 됩니다.** 회사 메일로 하십시오 —
   나중에 담당자가 바뀌면 개인 메일 계정이 그대로 남습니다.
3. 상단 메뉴 **[OPEN API]** → **[OPEN API 신청]** 을 누릅니다.
4. 신청서에서 **활용 대상**을 고릅니다. 최소 이 셋을 체크하십시오:
   - **법령** (법령 목록·본문)
   - **자치법규** (조례 — 이것이 빠지면 조례를 못 찾습니다)
   - **법령해석례** (선택 — 유권해석까지 보시려면)
5. **활용 목적**란에는 「부동산 개발사업 인허가 검토 자료 자동 수집」 정도로
   적으시면 됩니다. 상업적 이용 여부를 묻거든 **「내부 업무용」** 으로 답합니다.
6. 제출하면 **1~2일 뒤 승인 메일**이 옵니다.

## 3. 값을 넣는 곳 — 두 군데

승인 메일을 받으신 뒤에 하십시오. **승인 전에 넣어도 안 돕니다.**

### ① GitHub Secrets (배포가 NAS 로 실어 나릅니다)

1. `github.com` → 이 저장소 → 상단 **[Settings]**
2. 왼쪽 **[Secrets and variables]** → **[Actions]**
3. **[New repository secret]** 초록 버튼
4. **Name** 칸에 정확히 `LAW_OC`
5. **Secret** 칸에 **이메일의 @ 앞부분만** (예: `hong`).
   ★ 메일 주소 전체를 넣지 마십시오 — `@` 뒤가 들어가면 인증이 안 됩니다.
6. **[Add secret]**

### ② NAS 열쇠 파일 (배포가 자동으로 덮어씁니다)

`deploy-nas.yml` 이 이미 `LAW_OC` 를 실어 나르도록 되어 있습니다
(878번째 줄 근처 `NAMES` 목록). **①만 하시면 ②는 배포가 알아서 합니다.**

## 4. 되는지 확인하는 법

키가 있는 자리에서만 뜻이 있습니다 — **NAS 에서** 확인합니다.

- 배포가 끝나면 `deploy-nas` 워크플로의 **「Check map power」** 단계가
  이름과 길이만 찍어 줍니다 (값은 한 글자도 안 남깁니다).
- 커넥터가 실제로 응답을 읽는지는 NAS 에서 `npm run im:smoke` 를 돌려
  `LAW_OC` 줄을 봅니다.

★ **이 개발 컨테이너에서는 확인이 안 됩니다.** 두 가지 이유가 겹칩니다 —
운영 OC 가 여기 없고, `law.go.kr` 이 이 컨테이너의 네트워크에서 막혀 있습니다.
그래서 지금 커넥터는 **모양만 검증**되어 있습니다(시험 5개). 실제 응답 필드가
문서와 같은지는 **NAS 에서 한 번 재야** 확정됩니다 (CLAUDE.md §4.3).
