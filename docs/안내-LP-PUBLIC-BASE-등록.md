# 「앱이 쓰는 주소」를 배포에 알려 주기 — `LP_PUBLIC_BASE` 〈2026-08-27 사장님 확정〉

사람 손이 **한 번** 필요합니다. 5분이면 끝나고, 다시 만질 일이 없습니다.

## 무엇을 위해 하는가 — 먼저

「반영이 안 된다」는 **한 가지 증상이 아니라 셋**입니다.

| 무엇이 다른가 | 뜻 |
|---|---|
| 저장소 ≠ NAS 디스크 | **올리기가 실제로 안 됐다** |
| 디스크 ≠ 웹으로 받은 것 | **셋 중 하나** — 잰 길이 다르거나 / 다른 이가 덮었거나 / 캐시 |
| 셋이 다 같다 | 브라우저가 옛것을 들고 있다 |

지금 배포는 **NAS 안쪽 주소(포트 80)** 로만 받아 봅니다. 그런데 앱은 **바깥
주소(Funnel 443)** 로 들어옵니다. 둘은 서버에게 다른 문이라 **아예 다른 폴더**를
보고 있을 수 있습니다.

> **Funnel** — NAS 를 바깥 인터넷에서 열 수 있게 해 주는 통로입니다.
> 안쪽에서 부르는 주소와 바깥에서 부르는 주소가 서로 다릅니다.

그래서 지금은 「디스크 ≠ 웹」이 나와도 **캐시인지 다른 파일인지 갈리지 않습니다.**
이 값을 넣어 주시면 배포가 **사장님 앱이 실제로 받는 그 파일**을 그대로 받아
지문을 대 봅니다. 그러면 셋 중 무엇인지 **그 자리에서 갈립니다.**

## 넣는 값

앱이 보고서 화면을 불러오는 주소입니다 — `im-flow` 로 끝나는 그 주소입니다.
브라우저에서 「보고서 만들기」를 열었을 때 주소창에 뜨는 것에서 파일 이름
(`intake.html` 같은 것)만 뺀 부분입니다.

★ **끝에 빗금(`/`)이 있어도 됩니다.** 배포가 알아서 뗍니다.

## 넣는 법 — 마우스로 (5분)

1. 브라우저에서 **GitHub 의 이 저장소**를 엽니다 (`findKTH0415/linkpilot-cron`).
2. 위쪽 탭에서 **Settings** 를 누릅니다.
   - ★ **여기서 대개 막힙니다** — 위에 탭이 두 줄로 보일 수 있습니다.
     **저장소 이름 바로 아래 줄**의 Settings 입니다 (계정 설정이 아닙니다).
3. 왼쪽 목록에서 **Secrets and variables** 를 누르고, 그 아래 **Actions** 를 누릅니다.
4. 오른쪽 위 초록 단추 **New repository secret** 을 누릅니다.
5. 두 칸을 채웁니다.
   - **Name**: `LP_PUBLIC_BASE`
   - **Secret**: 위에서 정한 주소
6. **Add secret** 을 누릅니다.

### 확인

다음 배포의 실행 화면 맨 아래 요약에 **`앱 경로 확인: 17 개 일치`** 처럼 나옵니다.
지금은 그 자리가 **「건너뜀 (주소 없음)」** 으로 비어 있습니다.

## 안전한가

- **값은 어디에도 안 찍힙니다.** GitHub Secret 은 로그에서 `***` 로 가려집니다
  (CLAUDE.md §2). 이 저장소는 공개라서 **주소를 파일에 적지 않는** 것이 규칙이고,
  그래서 Secret 으로 받습니다.
- 배포는 그 주소로 **받기만** 합니다. 아무것도 쓰지 않습니다.

## 안 넣으면

배포는 그대로 돕니다. 다만 「앱이 쓰는 길로는 **못 쟀다**」가 매번 적힙니다 —
그것은 통과가 아니라 **못 쟀다는 사실**입니다 (§8).
