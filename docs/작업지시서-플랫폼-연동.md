## 1. 무엇을 하는가

앱의 [보고서 생성] 섹션에 **값 입력 단계를 들여온다.**

지금 그 화면은 기반정보를 내보내고, 값 입력은 바깥 AGENT 가 받는다. 그러면
**출처 필수 · 계산 항목 입력 금지 · 출력 사양 확정(LOCK)** 을 앱이 강제할 수 없다 —
검사가 전부 바깥에 있기 때문이다. 이 연동의 목적은 그 세 가지를 앱 안으로
들여오는 것이다.

> **외부 분석 경로는 유지한다.** 지우지 말 것. 화면 아래에 그대로 남겨 두었고,
> 둘 다 쓸 수 있어야 한다.

연동 후 섹션 구성:

```
[보고서 생성]
 ├ 1. 보고서 생성 입력      요청문 · 원본 자료 · 발행 주체
 ├ 2. 가이드 필드 입력      수치를 출처와 함께
 ├ 3. 출력 사양 확정        페이지 수 · 형식 · 언어 (LOCK)
 ├ 4. 생성                  확정 뒤에만 열린다
 └ 외부 분석 환경           기존 경로 (그대로 유지)
```

## 2. 범위

### 이번에 하는 것

- 서버에 라우터 2종 마운트 (읽기 / 쓰기)
- 실행 큐 연결
- 섹션 화면 배치 + 설정 주입
- 환경변수 등록
- 연동 확인 5항목 보고

### 이번에 하지 않는 것

| 항목 | 사유 |
|---|---|
| 서버에서 PDF·PPTX 생성 | 의존성 추가 미승인 (등록부 D-13). **브라우저 인쇄 경로는 이미 동작한다** |
| 결제 연동 | 결제대행사 미선정 (D-09) |

| SMP·REC · 임대료 시세 | 엔드포인트 사양 미확보 |

## 3. 전제 — 시작 전에 확보할 것

- [ ] `IM_AGENT_ROOT` 로 쓸 경로 확정 (예: `/volume1/linkpilot/im-projects`)
      → **나중에 바꾸면 기존 프로젝트를 못 찾는다**
- [ ] 세션에서 `{ name, planId, status }` 를 꺼내는 함수
      (`planId`: `free|basic|pro|business` · `status`: `active|expired`)
- [ ] 단계 화면을 **앱과 같은 출처**에 서빙할 경로 (예: `/im/`)
- [ ] 공공데이터 인증키 — 없으면 연동은 되지만 입력란이 8칸에서 9칸으로 는다

## 4. 작업

### 작업 1 — 서버 라우터 마운트

- [ ] 읽기 라우터 `ui/api-router.cjs` 를 `/api/linkpilot` 에 마운트
- [ ] 쓰기 라우터 `ui/report-api.cjs` 를 같은 경로에 마운트
- [ ] `ui/run-queue.cjs` 로 실행 큐를 만들어 `startRun` 에 연결
- [ ] `SIGTERM` 에서 `queue.stop()` 호출

**읽기와 쓰기를 한 라우터에 합치지 말 것.** 쓰기는 파일을 만들고 LLM 을 부르고
공공데이터 쿼터를 쓴다. 합치면 대시보드 폴링과 같은 권한으로 돈 드는 동작이 열린다.

**완료 판정** — `authenticate` 를 빼고 서버를 띄우면 **마운트 시점에 예외가 난다.**
예외가 안 나면 잘못 붙인 것이다.

### 작업 2 — `runningFor` 연결 ★

- [ ] `runningFor` 를 `queue.latestFor` 에 이어 준다

```js
runningFor: (projectId) => {
  const r = queue.latestFor(projectId);
  return r && (r.status === 'running' || r.status === 'queued') ? r : null;
},
```

**작업 1 안에 넣지 않고 따로 뺀 이유** — 이것을 빠뜨려도 **오류도 경고도 나지 않는다.**

`report-api` 는 생성이 도는 중에 값 저장을 거부한다. 파이프라인이 읽는 도중에 값이
바뀌면 산출물과 데이터가 어긋나기 때문이다. 그 판정을 `runningFor` 로 물어보는데,
안 넘기면 **검사를 통째로 건너뛴다.** 평소에는 아무 일 없이 돌다가, 생성 중에 누가
값을 고친 그날 산출물이 데이터와 다르게 나온다.

큐에는 `runningFor` 라는 이름의 메서드가 **없다** (`latestFor` 다). 위처럼 직접 잇는다.

**완료 판정** — 생성을 시작한 상태에서 값 저장을 시도하면 `409` 와
"생성이 진행 중입니다" 가 돌아온다.

### 작업 3 — 섹션 화면 배치

- [ ] 아래 파일을 앱과 **같은 출처**에 올린다

```
report-flow.html   flow-core.js   gate-core.js   catalog.js   inapp.js
intake.html        fields.html    reports.html
```

- [ ] `report-flow.html` 의 `window.LINKPILOT_REPORT_FLOW` 설정 블록만 채운다
      (`api` · `base` · `session` · `external`)
- [ ] 기존 [LinkPilot AGENT 저장소] · [보고서 생성 AGENT 열기] 주소를 `external` 에 옮긴다

**금지 — 단계 화면을 복사하지 말 것.** `report-flow.html` 이 `intake·fields·reports`
를 그대로 끼운다. 복사하면 「출처 없는 값은 저장할 수 없다」 같은 검사가 두 벌이 되고,
한쪽만 고치는 날 규칙이 갈린다.

**금지 — 단계 이름·순서를 화면에 적지 말 것.** 4단계는 `flow-core.js` 하나가 정한다.
바꿔야 하면 그 파일만 고친다.

사이드바·로고 중복과 안쪽 스크롤은 끼울 때 자동으로 처리된다 (`flow-core.js` 의
`EMBED_CSS`). **화면 소스는 건드리지 않는다.**

**완료 판정** — 섹션 안에 사이드바가 두 번 뜨지 않고, 창 안을 따로 스크롤하지 않는다.

### 작업 4 — 환경변수 등록

- [ ] `IM_AGENT_ROOT` (필수)
- [ ] `VWORLD_KEY` · `VWORLD_DOMAIN`
- [ ] `DATA_GO_KR_KEY` — **Decoding(일반) 인증키**
- [ ] `ECOS_API_KEY` · `DART_API_KEY` (둘 다 무료·즉시 발급)
- [ ] `GEMINI_API_KEY` (선택)

**값은 본체 프로세스에 넣는다.** GitHub Secrets 만으로는 아무 일도 일어나지 않는다 —
실제로 공공데이터를 쓰는 것은 NAS 에서 도는 프로세스다.

**빠뜨리기 쉬운 둘:**
- `VWORLD_DOMAIN` — 서버 호출에는 Referer 가 없어 이 값을 직접 넘겨야 한다.
  없으면 **키가 맞아도 인증 거부**된다
- `DATA_GO_KR_KEY` 의 Encoding/Decoding — 잘못 넣으면 인증만 실패하고 증상이
  "키가 틀렸다" 와 똑같다 (커넥터가 부르기 전에 막고 알려 준다)

**완료 판정** — `IM_AGENT_DEBUG_HTTP=1 npm run im:smoke` 출력에 모든 키가
`설정됨` 으로 뜬다.

### 작업 5 — 연동 확인

아래를 **순서대로** 실행하고 결과를 보고한다.

- [ ] `npm test` → 531 pass / 0 fail
- [ ] `npm run im:demo` → 파이프라인 1회 완주
- [ ] `IM_AGENT_DEBUG_HTTP=1 npm run im:smoke` → **출력 전문을 보고할 것**
- [ ] 앱에서 1단계 → 프로젝트 생성 → 2단계로 넘어가는지
- [ ] 3단계 [이 사양으로 확정] → 4단계 [생성] 이 열리는지

**세 번째를 건너뛰지 말 것.** 커넥터의 응답 필드명은 공식 문서 기준으로 작성했고
**실제 키로 검증한 적이 없다.** 다르면 조회는 성공하는데 값이 전부 비고, 화면에는
아무 경고도 안 뜬다 — 가장 잡기 어려운 종류의 오류다.

## 5. 인수 조건

전부 만족해야 완료로 본다.

| # | 조건 | 확인 방법 |
|---|---|---|
| 1 | 인증 없이는 생성 API 가 뜨지 않는다 | `authenticate` 를 빼면 마운트 시점에 예외 |
| 2 | 출처 없는 값이 저장되지 않는다 | 출처를 비우고 저장 → 거부 + 사유 표시 |
| 3 | 계산 항목은 입력란이 없다 | 2단계에서 IRR·NPV 입력란이 **아예 없다** |
| 4 | 사양 확정 전에는 생성이 안 열린다 | 3단계를 건너뛰고 4단계 시도 → 막힘 |
| 5 | 생성 중에는 값이 안 바뀐다 | 생성 시작 후 값 저장 → `409` |
| 6 | 검증 실패 산출물은 열리지 않는다 | RED FLAG 상태에서 파일 열기 → `403` |
| 7 | 키가 없으면 지어내지 않는다 | 키를 빼고 실행 → 해당 절이 **비고 사유가 뜬다** |
| 8 | 외부 분석 경로가 살아 있다 | 섹션 하단 버튼 2개가 기존 주소로 열린다 |

> **2·3·5·6 이 이 연동의 존재 이유다.** 나머지가 다 돼도 이 넷이 안 되면
> 붙이지 않은 것과 같다 — 그때는 바깥 AGENT 로 돌리는 편이 낫다.

## 6. 금지 사항

- **인증 없이 쓰기 라우터를 열지 말 것.** 브라우저 코드는 사용자가 고칠 수 있다.
  화면이 막는 것과 별개로 **서버가 세션·플랜을 다시 확인해야 한다**
- **단계 화면을 복사하지 말 것** (작업 3 참조)
- **키를 코드·로그·커밋에 남기지 말 것.** 이 저장소는 **public 이다**
- **`linkpilot-platform.html` 을 덮어쓰지 말 것.** 앱 본체 파일인데 이 저장소에
  원본이 없다 — 배포 워크플로가 거부하도록 막아 두었다

## 7. 막히면 보고할 것

화면이 사유를 적게 만들어 두었으므로, **그 문구만 그대로** 보내면 원인이 좁혀진다.

| 보이는 것 | 뜻 | 조치 |
|---|---|---|
| 단계 전부 잠김 · "서버(api)가 연결되어 있지 않습니다" | `api` 미설정 | 작업 3 설정 확인 |
| 2~4단계만 잠김 · "1단계에서 프로젝트를 먼저 만듭니다" | **정상** | 1단계부터 진행 |
| 화면 아래가 잘림 | 단계 화면이 다른 출처 | 같은 출처로 옮긴다 |
| "API 주소가 없어 만들 수 없습니다" | **정상 표시** | 눌리는 척하지 않는 것이다 |
| 서버가 안 뜨고 `authenticate` 예외 | **정상** | 인증 함수를 넘긴다 |
| 조회는 성공인데 값이 전부 빔 | 응답 필드명 불일치 | `im:smoke` 출력을 보낼 것 |

보고 형식: **어느 단계에서 · 무슨 문구가 · 어떤 조작 뒤에** 떴는지 세 줄.
