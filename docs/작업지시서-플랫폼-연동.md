## 1. 역할 분담 — **엔진이 주역이다** (본체 제안 수락)

**[보고서 생성] 섹션 안에서는 엔진이 정하고 본체가 따른다.** 화면·API·파이프라인·
산출물·품질 판정은 엔진이 갖고, 본체는 **그릇**(로그인·플랜·같은 출처·배포 통로)을
책임진다. 경계 밖(회원·결제·다른 섹션)은 본체가 정한다.

**경계 한 줄만 분명히 해 둔다** — `authenticate` 와 `runningFor` 는 **본체 몫이 맞다.**
「누가 로그인했나」는 회원 저장소가, 「지금 그 프로젝트가 돌고 있나」는 큐가 아는
사실이고 **둘 다 엔진이 모른다.**

> **왜 이 분담이 옳은지 증거가 있다.** NAS 서버가 라우팅 표를 손으로 옮겨 적고
> 있어서 **새 라우트 11개가 빠진 채 404** 가 났다. 엔진이 가진 사실을 본체가
> 복사해 들고 있었기 때문이다. 오류는 「없는 주소」로만 보여서, **두 목록을
> 나란히 세어 보기 전까지 원인이 안 보인다.**

## 4. 엔진이 내준 것 — **본체가 손으로 하던 넷을 없앴다**

| | 무엇 | 어디 |
|:--:|---|---|
| ① | 라우트 표를 **데이터로** | `im-agent/ui/routes.cjs` |
| ② | 배포용 사본을 **엔진이 낸다** | `npm run im:embed` (`build-embed.js` · `embed-bridge.js`) |
| ③ | NAS 반영 | `npm run deploy:nas` (`deploy/nas.sh`) |
| ④ | 확인 | `npm run verify:nas` |

### ① 라우트 — 손으로 옮기지 않는다

```js
const routes = require('/volume1/docker/linkpilot/im-agent/ui/routes.cjs');
const W = require('…/ui/report-api.cjs');   // W.ROUTES — 쓰기 22
const A = require('…/ui/api-router.cjs');   // A.ROUTES — 읽기 6

const hit = routes.match(W.ROUTES, req.method, pathname);   // {route, params} | null
if (hit) await hit.route.call(handlers, ctx, hit.params);
```

- **`express` 를 요구하지 않는다** — 순수 `http` 서버가 같은 표로 길을 찾는다.
- **표와 실제 등록이 갈릴 수 없다** — `createRouter()` 도 이 표에서 만든다.
- **차례가 규칙이다** — `/sources/verify` 가 `/sources/:name` 보다 먼저 잡힌다
  (안 그러면 「verify 라는 이름의 파일을 지워라」가 된다).
- 파일 라우트는 **`kind: 'file'`** 로 표가 말한다 — JSON 으로 읽으면 깨진다.

**실측** — express 없이 순수 http 서버에 표만 걸고 돌렸다.

```
GET  /intake            → 200
POST /projects (무인증)  → 401 「로그인이 필요합니다」
POST /projects (인증)    → 201
POST …/linked (미주입)   → 501 「저장소 내려받기가 붙어 있지 않습니다 …」
POST …/sources/purge    → 400 「olderThanDays 를 지정해야 합니다」   ← :name 으로 안 잡힌다
없는 주소               → 404
```

★ **본체가 할 일**: `im-engine-server.cjs` 의 손으로 적은 등록부를 지우고 위 세 줄로.
그러면 **엔진에 라우트가 늘어도 본체는 고칠 것이 없다.**

### ② 사본 — **치환이 없다**

화면들이 `embed-bridge.js` 를 스스로 달고 있고, 브리지가 부모(앱)의 전역을
**같은 출처로 읽어 병합한다.** 본체는 **파일을 복사만** 하면 된다.

```js
// 앱에서 — iframe 을 붙이기 **전에** 이 전역 하나만 채운다
window.LINKPILOT_EMBED = {
  common:   { api: '/api/linkpilot', inTab: true, token: lpToken, session: user },
  byScreen: { LINKPILOT_REPORT_FLOW: { base: '/im-flow/' } },
};
```

- **대입이 아니라 병합** — 화면이 심어 둔 기본값이 살아남는다.
- **토큰은 머무르지 않는다** — 헤더로만 쓰고 전역에서 지운다.
  `Authorization` 이 **이미 붙어 있으면 건드리지 않는다**(본체 래퍼와 안 싸운다).
- 세션이 도중에 바뀌면 기존 계약대로 `postMessage {type:'lp-session'}` 를 받는다.
- **다른 출처면 조용히 넘어가지 않는다** — `window.LinkPilotEmbed.reason` 에
  「같은 출처가 아닙니다」가 남는다.
- 단독으로 열면 **아무 일도 하지 않는다** (미리보기가 그대로 동작한다).

★ **브리지 자리가 어긋나면 사본을 만들지 않는다.** 설정 대입보다 앞에 두면
대입이 병합을 덮어써 **설정이 조용히 사라지는데 화면은 멀쩡히 뜬다** —
실제로 한 번 그렇게 만들었고 값만 기본값이었다.

### ③ NAS 반영 — 「전송 성공」을 성공으로 안 본다

백업(`im-agent.bak-<시각>`) → tar-over-ssh → **지문 대조** → 재시작 →
**healthz 10초 대기.** 하나라도 어긋나면 0 이 아닌 값으로 끝나고 **되돌리는
명령을 찍는다.**

### ④ 확인 — 못 잰 것을 통과로 안 센다

`npm run verify:nas -- --base …` 가 재는 것은 셋이다.

| 재는 것 | 판정 |
|---|---|
| 화면 사본 **14개** | 서버가 준 바이트의 **sha256 이 저장소와 같은가** |
| 라우트 **28개** | 앱을 거쳐 **닿는가** (404 가 아니면 통과 — 401·400 은 「있다」는 뜻) |
| 앱·인증 | `ver.txt` · 무인증 쓰기가 **401** 인가 |

주소가 없거나 막히면 `⚠️ 못 잼` 으로 나오고 **종료코드 2** 다.

> **`200` 을 「올라갔다」로 읽지 않는다.** 옛 사본도 200 을 준다. 그래서 지문을 댄다.
> 화면 전부를 3주 전 판으로 돌려주는 서버를 세워 재 봤더니, 지문을 안 대던
> 판은 **11통과 0실패**로 나왔다. 지금 판은 **15실패**로 잡는다 (§13).

> **라우트도 하나만 물어보지 않는다.** 프록시 목록에서 빠진 라우트는 그것만
> 404 가 나고 **화면은 멀쩡히 뜬다.** 그래서 28개를 전부 두드린다.
> 프로젝트가 없어 나는 404(엔진, **JSON**)와 길이 없어 나는 404(프록시, **HTML**)를
> 응답 형식으로 가른다 — 안 가르면 헛울음이 나고, 헛울음 한 번이면 아무도 안 믿는다.

## 5. 작업 — 다섯

### 5-1. 엔진 → NAS

```bash
cd ~/linkpilot-cron && git pull
npm run deploy:nas -- --dry-run     # 무엇을 할지만 본다
npm run deploy:nas
```

★ NAS 는 저장소를 clone 해 두지 않았다 — **git 이 아니라 tar-over-ssh** 다.
스크립트가 백업·지문 대조·healthz 까지 한다.

### 5-2. 배포용 사본

```bash
npm run im:embed -- --out /volume1/web/im-flow
```

**14개** + `manifest.json`(sha256) 이 나온다. 목록은 손으로 적은 것이 아니라 탭 셋과
4단계가 **실제로 참조하는 것**을 훑어 뽑았고, 테스트가 이 목록을 지킨다.

```
tokens.css                                          ← ★ 빠지면 색·글꼴이 통째로 빠진다
embed-bridge.js                                     ← ★ 빠지면 설정이 안 들어간다
outputs.html      report-flow.html   files.html     ← 탭 셋
intake.html       fields.html        reports.html   ← 4단계 (탭 바에 달지 않는다)
flow-core.js      fields-core.js     gate-core.js
live-core.js      catalog.js         inapp.js
```

★ **같은 출처여야 한다.** 다른 도메인이면 브리지가 부모를 못 읽고, iframe 높이
측정도 막혀 화면이 **잘린 채 정상처럼** 보인다.
★ `intake` · `fields` · `reports` 는 **탭 바에 달지 않는다** — `report-flow.html`
이 iframe 으로 부른다. 따로 달면 4단계가 6개 탭처럼 보인다.
★ **`im-flow/` 를 손으로 고치지 않는다** — 다음 사본 생성에서 조용히 사라진다.

### 5-3. 탭 하나 추가 — 정본 HTML 에

정본은 **사전 컴파일된 단일 HTML** 이라 `import` 로 목록을 읽는 구조가 아니다.
지금 탭 둘이 있는 자리에 **셋째를 같은 모양으로** 더한다. 값의 정본은 엔진의
`flow-core.js` (`FLOW.TABS`) 이고, 아래는 그것을 옮긴 것이다.

```js
{ id:'files', tab:'자료 업로드', note:'보관 · 연결 · 1회성',
  src:'/im-flow/files.html', plan:'free' }
```

탭 안에서 채우는 설정 전역은 셋이다 — **§4 ② 의 `LINKPILOT_EMBED` 하나만 채우면
브리지가 알아서 나눠 넣는다.**

```
window.LINKPILOT_OUTPUTS       ← 완성 보고서
window.LINKPILOT_REPORT_FLOW   ← 보고서 생성
window.LINKPILOT_FILES         ← 자료 업로드
```

★ **`plan` 이 `free` 다.** 다른 둘(`pro`)과 다르다 — 자료를 넣는 길이 유료면
Pro 를 살지 판단할 자료조차 못 넣는다. **잠금 규칙을 복사하면 안 된다.**
★★ **`inTab: true` 를 켠다.** 탭 이름과 화면 제목이 **같은 글자**라 안 켜면
「자료 업로드」 아래에 「자료 업로드」가 한 번 더 나온다. 거꾸로 **단독으로 열 때
켜 두면 이름 없는 화면**이 된다.
★ `external`(기존 외부 분석 경로)은 **지우지 않는다.**

## 7. 조용히 무너지는 것들 — **오류가 안 나서 더 위험하다**

| **설정 전역을 대입(`=`)** | 앱이 넣은 `api`·`session` 이 **데모값으로 되돌아간다** | 화면은 멀쩡하고 데이터만 가짜다 — **실제 사고** |

| `tokens.css` | 색·글꼴이 통째로 빠지는데 CSS 는 조용히 넘어간다 | 화면이 스스로 말한다 (§6 ⑧) |
| `embed-bridge.js` | 설정이 안 들어간다 | 위와 같다 |
| `inTab` | 같은 이름이 두 번 나온다 | 눈으로 |
| 다른 출처(도메인) | 브리지가 부모를 못 읽고 iframe 이 **잘린 채 정상처럼** 보인다 | 화면 아래가 잘린다 |

## 13. 이 지시서가 틀렸던 곳 — **지우지 않는다**

초판·2판은 **「일반적인 Express 앱에 라우터를 마운트한다」**를 가정했다. 실제
LinkPilot 은 그렇지 않았다. 지우면 다음 사람이 같은 착각을 그대로 한다.

| 지시서가 적었던 것 | 실제 |
|---|---|
| **`verify:nas` 가 붙었는지 확인해 준다** | 화면을 **`200` 인지만** 봤다. 옛 판을 그대로 주는 서버가 **11통과 0실패**로 나왔다. 막으라고 만든 것이 같은 사고를 냈다 (§14) |
| **라우트는 표에서 자동으로 나온다** | 저장소 안에서만 그렇다. **앱을 거쳐 닿는지는 안 물어봤다** — 28개 중 둘만 |
| `/volume1/linkpilot/…` | **`/volume1/docker/linkpilot/`**(엔진) · **`/volume1/web/im-flow/`**(화면) |
| 앱 `server.js` 에 라우터 둘 마운트 | 엔진은 **별개 프로세스** `im-engine-server.cjs`(8181)로 **이미 돈다** |
| 인증은 `req.session.user` | **HMAC 토큰 + `Authorization: Bearer`** |
| 탭 바에서 `import FLOW … FLOW.TABS` | 정본이 **사전 컴파일된 단일 HTML** 이라 import 가 아니다 |
| `.env` 를 만든다 | **이미 있다** |
| 글꼴을 넣고 PDF 를 확인한다 | 서버에 **크롬이 없어 PDF 를 안 만든다** |
| 설정 전역을 **대입**하는 예시 | **`Object.assign` 병합**이어야 한다 — 대입은 실제 사고를 냈다 |

**교훈**: 붙이는 쪽 환경을 재지 않고 쓴 지시서는 **그럴듯하게 틀린다.** 문장이
자연스러워서 읽는 사람이 의심하지 않고, 경로 하나 때문에 반나절이 간다.

## 14. 근거로 삼은 실제 사고 여덟 — **엔진에서 다시 나는가**

이 지시서의 규칙은 전부 실제로 난 사고에서 나왔다. 그러면 **엔진 쪽은 같은 일이
안 나는가** — 여덟을 하나씩 대 봤다. 2026-08-19 실측.

**셋이 뚫려 있었고, 셋 다 막았다.** 그중 하나는 이 지시서가 「막는 장치」라고
적어 둔 스크립트 자신이었다.

| | 사고 | 엔진에서 나는가 | 막는 것 |
|:--:|---|---|---|
| ① | **라우트 11개 누락 404** (08-18) | 🔴 **났다** — 28개 중 **둘만** 물어보고 있었다 | `verify:nas` 가 28개를 전부 두드린다 |
| ② | 설정 **대입이 병합을 덮음** | 🟢 막혀 있다 | `build-embed` 의 브리지 순서 확인 — 걸리면 **사본을 안 만든다** |
| ③ | **원본–사본 갈라짐** (소스 8/7 동결) | 🟡 반만 — 목록은 훑어서 만드는데 **올라간 것을 안 봤다** | 서빙 바이트를 **sha256 으로 대조** |
| ④ | **토큰 값 충돌** (6.5%·88) | 🟢 막혀 있다 | `tokens.css` 단일 출처 + 화면이 색을 직접 적으면 실패 |
| ⑤ | 게이트가 **소스만 보고 배포본을 안 봄** | 🔴 **났다** — 화면을 `200` 인지만 봤다 | 위 ③ 과 같은 장치 |
| ⑥ | **「초록인데 NAS 는 옛 판」** | 🔴 **났다** — 옛 판 서버가 **11통과 0실패** | `deploy:nas` 지문 + `verify:nas` 지문 |
| ⑦ | **버전 스탬프 누락** (폰만 옛 화면, 2회) | 🟡 서버 쪽은 막았다 · **폰 캐시는 본체 몫** | 아래 「남는 하나」 |
| ⑧ | **만들고 아무도 안 부른 모듈** (D-48·D-62·`materialize`) | 🟢 지금은 없다 — 다만 **지키는 것이 없었다** | `npm run check:reachable` (191개 전부 닿는다) |

### 어떻게 쟀나 — **말로 대조하지 않았다**

②④⑧ 은 저장소만 보면 되지만, ①③⑤⑥ 은 **서버가 있어야 알 수 있다.**
그래서 가짜 NAS 를 두 개 세워 스크립트를 **진짜 돌렸다.**

| 세운 것 | 옛 판 지문 검사 전 | 지금 |
|---|---|---|
| 화면을 전부 옛 판으로 주는 서버 | ✅ **11통과 0실패 · 종료 0** | ❌ **15실패 · 종료 1** |
| 라우트 셋이 빠진 서버 | ✅ 통과 | ❌ `3개가 404` |
| 제대로 올라간 서버 | ✅ 통과 | ✅ **21통과 0실패** (헛울음 없음) |

세 판 모두 `im-agent/test/nas-guard.test.js` 에 들어가 있다. **함수 반환값을 보는
검사로 두지 않았다** — 그렇게 했으면 위의 「11통과 0실패」를 똑같이 못 잡는다
(M-08).

### 남는 하나 — ⑦ 폰 캐시는 **본체가 해야 한다**

서버가 **지금 판을 주고 있는데도** 폰에는 옛 화면이 뜨는 경우가 남는다. 사본
주소가 늘 같아서 브라우저가 받아 둔 것을 그냥 쓴다. 엔진에서는 못 막는다 —
**주소를 만드는 쪽이 앱**이기 때문이다.

`npm run im:embed -- --out …` 이 내는 `manifest.json` 에 파일마다 sha256 이 들어
있다. 정본 HTML 이 사본을 부를 때 **그 앞 12자를 붙인다.**

```html
<iframe src="/im-flow/files.html?v=f9ca21429edf"></iframe>
```

내용이 안 바뀌면 지문도 안 바뀌므로 **바뀐 파일만** 다시 받는다. 날짜나 배포
시각을 붙이면 안 바뀐 파일까지 매번 다시 받는다.
