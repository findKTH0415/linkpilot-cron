## 4. 엔진이 내준 것 — **본체가 손으로 하던 넷을 없앴다**

| | 무엇 | 어디 |
|:--:|---|---|
| ① | 라우트 표를 **데이터로** | `im-agent/ui/routes.cjs` |
| ② | 배포용 사본을 **엔진이 낸다** | `npm run im:embed` |
| ③ | NAS 반영을 **스크립트로** | `npm run deploy:nas` |
| ④ | 인수 확인을 **한 번에** | `npm run verify:nas` |

### ① 라우트 — 손으로 옮기지 않는다

`ROUTES` 배열이 단일 출처이고 **라우터도 그 표에서 만든다.** 표와 실제 등록이
갈릴 수가 없다. `match()` 로 express 없이도 길을 찾을 수 있다 — 프레임워크를
강요하면 결국 또 베껴 적게 된다.

```js
const { ROUTES } = require('./im-agent/ui/report-api.cjs');   // 쓰기 22
const { ROUTES: READ } = require('./im-agent/ui/api-router.cjs'); // 읽기 6
```

전에는 이 목록이 **express 등록 코드 안에만** 있어서 다른 서버는 읽을 방법이
없었고, 그래서 베껴 적다가 **11개가 빠진 채 404** 가 났다.

### ② 사본 — **치환이 없다**

`npm run im:embed -- --out <경로>` 가 **15개** + `manifest.json`(sha256) 을 낸다.
목록은 손으로 적은 것이 아니라 탭 셋과 4단계가 **실제로 참조하는 것**을 훑어서
만든다. 화면이 늘면 목록이 저절로 따라온다.

```
catalog.js  embed-bridge.js  fields-core.js  fields.html  files.html
flow-core.js  gate-core.js  inapp.js  intake.html  live-core.js
outputs.html  report-flow.html  reports.html  tokens.css  upload-core.js
```

전에는 본체가 원본 글자를 찾아 끼워 넣고 있었다(설정 병합·세션·토큰 래퍼 셋).
앵커가 한 글자만 바뀌어도 치환이 빗나가 **배포가 멈추거나 설정이 안 들어간 사본이
나간다.** 지금은 화면들이 `embed-bridge.js` 를 스스로 달고, 브리지가 부모(앱)의
`window.LINKPILOT_EMBED` 를 **같은 출처로 읽어 병합한다.**

빌더는 **확인에 걸리면 사본을 만들지 않는다.** 설정이 안 들어간 사본이 나가는
것이 「빌드 실패」보다 훨씬 나쁘다 — 앱은 멀쩡히 뜨고 값만 비어 있다.

### ③ NAS 반영 — 「전송 성공」을 성공으로 안 본다

`npm run deploy:nas` 가 **백업 → 전송 → 지문 대조 → 재시작 → healthz** 를 하고,
셋 중 하나라도 어긋나면 0 이 아닌 값으로 끝난다. 되돌리는 명령을 마지막에 찍는다.

```bash
export LP_NAS_HOST='사용자@주소'      # 저장소에 두지 않는다 (D-10)
npm run deploy:nas -- --dry-run       # 무엇을 할지만 본다
```

### ④ 확인 — 못 잰 것을 통과로 안 센다

`npm run verify:nas -- --base $LP_BASE` 가 재는 것은 셋이다.

| 재는 것 | 판정 |
|---|---|
| 화면 사본 **15개** | 서버가 준 바이트의 **sha256 이 저장소와 같은가** |
| 라우트 **28개** | 앱을 거쳐 **닿는가** (404 가 아니면 통과 — 401·400 은 「있다」는 뜻) |
| 앱·인증 | `ver.txt` · 무인증 쓰기가 **401** 인가 |

주소가 없거나 막히면 `⚠️ 못 잼` 으로 나오고 **종료코드 2** 다.

> **`200` 을 「올라갔다」로 읽지 않는다.** 옛 사본도 200 을 준다. 그래서 지문을
> 댄다. 화면 전부를 3주 전 판으로 돌려주는 서버를 세워 재 봤더니, 지문을 안 대던
> 판은 **11통과 0실패**로 나왔다 (§7·§14).

> **라우트도 하나만 물어보지 않는다.** 프록시 목록에서 빠진 라우트는 그것만 404 가
> 나고 **화면은 멀쩡히 뜬다.** 프로젝트가 없어 나는 404(엔진, **JSON**)와 길이 없어
> 나는 404(프록시, **HTML**)를 응답 형식으로 가른다 — 안 가르면 헛울음이 나고,
> 헛울음 한 번이면 아무도 안 믿는다.

## 5. 작업 — 다섯

### 5-1. 엔진 → NAS

```bash
cd ~/linkpilot-cron && git pull
export LP_NAS_HOST='사용자@주소'
npm run deploy:nas -- --dry-run
npm run deploy:nas
```

커밋 안 된 변경이 있으면 멈춘다 — **NAS 에만 있는 판**은 어디에도 기록이 없다.
그래도 올려야 하면 `LP_ALLOW_DIRTY=1`.

### 5-2. 배포용 사본

```bash
npm run im:embed -- --out /volume1/web/im-flow
```

15개와 `manifest.json` 이 나온다. **`sync-im-flow.js` 는 쓰지 않는다 — 지운다.**

### 5-3. 탭 하나 추가 — 정본 HTML 에

정본은 사전 컴파일된 단일 파일이다. **재빌드하지 않고** 탭 하나를 더한다.
설정은 **대입이 아니라 병합**으로 넣는다.

```html
<script>
window.LINKPILOT_EMBED = Object.assign(window.LINKPILOT_EMBED || {}, {
  api: '/api/linkpilot',
  session: { plan: currentUser.plan, name: currentUser.name },
  token: lpToken,          // 브리지가 헤더로 옮기고 지운다
});
</script>
```

★ **`=` 로 덮어쓰지 않는다.** 대입은 브리지가 병합해 둔 것을 되돌려 놓는다 —
화면은 멀쩡하고 값만 데모로 돌아간다. 실제 사고다.

각 화면의 설정 전역은 이렇다 —
`window.LINKPILOT_REPORT_FLOW` · `window.LINKPILOT_OUTPUTS` ·
`window.LINKPILOT_FILES` · `window.LINKPILOT_INTAKE` ·
`window.LINKPILOT_FIELDS_CFG` · `window.LINKPILOT_REPORTS`.

탭 본문은 `/im-flow/<파일>` 을 iframe 으로 띄운다. 탭 안에서 열 때는 `inTab: true`
를 넣는다 — 안 넣으면 제목이 **두 번** 나온다.

### 5-4. 앱 배포

```bash
python3 deploy-filestation.py
```

★★ **`exit 0` 을 성공으로 읽지 않는다.** 로그 판정 줄과 **서버 `ver.txt`** 로 읽는다.
**배포 전과 값이 같으면 실패로 본다**(스탬프 누락). 앱 내장 `var V` 와도 같아야 한다.

### 5-5. 확인 — §6

```bash
npm run verify:nas -- --base $LP_BASE
```

## 7. 이 절차를 무엇으로 확인했나 — **사고 여덟을 다시 대 봤다**

이 지시서의 규칙은 전부 실제로 난 사고에서 나왔다. 그래서 **엔진 쪽도 같은 일이
나는지** 여덟을 하나씩 대 봤다 (2026-08-19 실측).

**셋이 뚫려 있었고, 셋 다 막았다.** 그중 하나는 이 지시서가 「막는 장치」라고
적어 둔 스크립트 자신이었다.

| | 사고 | 엔진에서 나는가 | 막는 것 |
|:--:|---|---|---|
| ① | **라우트 11개 누락 404** | 🔴 **났다** — 28개 중 **둘만** 물어보고 있었다 | `verify:nas` 가 28개를 전부 두드린다 |
| ② | 설정 **대입이 병합을 덮음** | 🟢 막혀 있다 | 브리지 순서 확인 — 걸리면 **사본을 안 만든다** |
| ③ | **원본–사본 갈라짐** | 🟡 반만 — 목록은 훑는데 **올라간 것을 안 봤다** | 서빙 바이트를 **sha256 으로 대조** |
| ④ | **토큰 값 충돌** | 🟢 막혀 있다 | `tokens.css` 단일 출처 + 화면이 색을 직접 적으면 실패 |
| ⑤ | 게이트가 **소스만 보고 배포본을 안 봄** | 🔴 **났다** — 화면을 `200` 인지만 봤다 | 위 ③ 과 같은 장치 |
| ⑥ | **「초록인데 NAS 는 옛 판」** | 🔴 **났다** — 옛 판 서버가 **11통과 0실패** | `deploy:nas` 지문 + `verify:nas` 지문 |
| ⑦ | **버전 스탬프 누락** (폰만 옛 화면) | 🟡 서버 쪽은 막았다 · **폰 캐시는 본체 몫** | 아래 「남는 하나」 |
| ⑧ | **만들고 아무도 안 부른 모듈** | 🟢 지금은 없다 — 다만 **지키는 것이 없었다** | `npm run check:reachable` |

### 어떻게 쟀나 — **말로 대조하지 않았다**

②④⑧ 은 저장소만 보면 되지만, ①③⑤⑥ 은 **서버가 있어야 알 수 있다.**
그래서 가짜 NAS 를 세워 스크립트를 **진짜 돌렸다.**

| 세운 것 | 지문 검사 전 | 지금 |
|---|---|---|
| 화면을 전부 옛 판으로 주는 서버 | ✅ **11통과 0실패 · 종료 0** | ❌ **15실패 · 종료 1** |
| 라우트 셋이 빠진 서버 | ✅ 통과 | ❌ `3개가 404` |
| 제대로 올라간 서버 | ✅ 통과 | ✅ **21통과 0실패** (헛울음 없음) |

세 판 모두 `im-agent/test/nas-guard.test.js` 에 들어가 있다. **함수 반환값을 보는
검사로 두지 않았다** — 그렇게 했으면 위의 「11통과 0실패」를 똑같이 못 잡는다.

### 남는 하나 — ⑦ 폰 캐시는 **본체가 해야 한다**

서버가 **지금 판을 주고 있는데도** 폰에는 옛 화면이 뜨는 경우가 남는다. 사본
주소가 늘 같아서 브라우저가 받아 둔 것을 그냥 쓴다. 엔진에서는 못 막는다 —
**주소를 만드는 쪽이 앱**이기 때문이다.

`manifest.json` 에 파일마다 sha256 이 있다. 정본 HTML 이 사본을 부를 때 **그 앞
12자를 붙인다.**

```html
<iframe src="/im-flow/files.html?v=f9ca21429edf"></iframe>
```

내용이 안 바뀌면 지문도 안 바뀌므로 **바뀐 파일만** 다시 받는다. 날짜나 배포
시각을 붙이면 안 바뀐 파일까지 매번 다시 받는다.

## 8. 조용히 무너지는 것들 — **오류가 안 나서 더 위험하다**

| 빠뜨리면 | 무슨 일이 | 어떻게 알아채나 |
|---|---|---|
| **설정 전역을 대입(`=`)** | 앱이 넣은 `api`·`session` 이 **데모값으로 되돌아간다** | 화면은 멀쩡하고 데이터만 가짜다 — **실제 사고** |
| **`LINKPILOT_EMBED` 미설정** | 브리지가 병합할 것이 없다 | 목록이 빈다 → 「자료가 없다」로 오해. `LinkPilotEmbed.reason` 을 본다 |
| **`runningFor`** | **오류도 경고도 없이** 「생성 중 값 저장 거부」가 꺼진다 | 아무 표시도 없다. §6 ⑩ 로만 잡힌다 |
| **`authenticate` 미주입** | 쓰기 API 를 **인증 없이** 열게 된다 | 마운트 시점에 예외로 막는다. §6 ① 의 「무인증 쓰기 → 401」로도 잡힌다 |
| `tokens.css` | 색·글꼴이 통째로 빠지는데 CSS 는 조용히 넘어간다 | 화면이 스스로 말한다 (§6 ⑧) |
| `embed-bridge.js` | 설정이 안 들어간다 | 위와 같다 |
| `inTab` | 같은 이름이 두 번 나온다 | 눈으로 |
| 다른 출처(도메인) | 브리지가 부모를 못 읽고 iframe 이 **잘린 채 정상처럼** 보인다 | 화면 아래가 잘린다 |
| `ver.txt` 스탬프 | **옛 화면이 그대로 뜬다** | §6 ③ |
| 사본이 옛 판 | 앱·CI 는 초록인데 **화면만 옛 판** | §6 ④ (지문 대조) |
| **라우트를 손으로 옮김** | 엔진에 라우트가 늘어도 서버가 모른다 → **404**. **11개가 빠졌었다** | §4 ① 로 없앴다 |

★ 큐에는 `runningFor` 라는 이름의 메서드가 **없다**(`latestFor` 다). 직접 이어 줘야
하고, 안 이으면 **아무 일도 안 일어난 것처럼 보인다.**

## 9. 금지 사항 — **실제 사고에서 나온 것만**

| | 왜 |
|---|---|
| 앱 **재빌드** | 정본이 사전 컴파일된 단일 파일이다. 재빌드하면 되돌릴 수 없다 |
| 라우트 목록을 **손으로 옮겨 적기** | 11개가 빠져 404 가 났다 (§4 ①) |
| 설정 전역을 **대입** | 병합을 덮어써 값이 데모로 돌아간다 (§5-3) |
| `sync-im-flow.js` 로 사본 만들기 | 치환이 빗나가면 설정 없는 사본이 나간다 (§4 ②) |
| **접속 주소·계정을 저장소에 적기** | **public 이다** (D-10). 환경변수로 준다 |
| `exit 0` 만 보고 배포 성공으로 읽기 | 스탬프가 안 찍혀도 0 이 나온다 (§5-4) |
| `200` 만 보고 반영됐다고 읽기 | 옛 사본도 200 을 준다 (§4 ④) |
| `git push --force` · `git reset --hard` | 되돌릴 수 없다 |

## 11. 지금은 해당 없지만 **정해야 하는 것** — 서버 PDF

서버에 크롬이 없어 최종본이 **HTML** 로 나간다. PDF 를 서버에서 만들기로 하면
크롬과 **한글 글꼴**(`Noto Sans CJK KR` · `Noto Serif CJK KR`)을 넣어야 하고,
확인은 **산출물로** 한다.

```bash
strings 12_Final/im-a4.pdf | grep CJK    # CJKkr 이 나와야 한다
# CJKjp · CJKsc · CJKtc · WenQuanYi 가 나오면 한글이 다른 나라 글꼴로 박힌 것
```

★ **한글이 화면에 멀쩡히 보이는 것은 근거가 아니다.** 일본어·중국어 변형도 한글은
그린다 — 다른 것은 한자 모양이라 눈으로는 안 잡힌다. 이 저장소의 PDF 에 실제로
한글이 중국어 글꼴로 박혀 나갔고, **「설치했다」는 검사는 통과하고 있었다**(D-52).

## 14. 이 지시서가 틀렸던 곳 — **지우지 않는다**

지우면 다음 사람이 같은 착각을 그대로 한다.

| 지시서가 적었던 것 | 실제 |
|---|---|
| **`verify:nas` 가 붙었는지 확인해 준다** | 화면을 **`200` 인지만** 봤다. 옛 판을 그대로 주는 서버가 **11통과 0실패**로 나왔다. 막으라고 만든 것이 같은 사고를 냈다 (§7) |
| **라우트는 표에서 자동으로 나온다** | 저장소 안에서만 그렇다. **앱을 거쳐 닿는지는 안 물어봤다** — 28개 중 둘만 |
| **접속 주소를 적어 두면 편하다** | **public 저장소다.** 편의 기본값이 곧 공개였다 (D-10). 지금은 `LP_NAS_HOST`·`LP_BASE` 로만 받는다 |
| `/volume1/linkpilot/…` | **`/volume1/docker/linkpilot/`**(엔진) · **`/volume1/web/im-flow/`**(화면) |
| 앱 `server.js` 에 라우터 둘 마운트 | 엔진은 **별개 프로세스** `im-engine-server.cjs`(8181)로 **이미 돈다** |
| 환경변수를 새로 넣어야 한다 | 엔진 `.env` 에 **이미 있다** |
| 한글 글꼴을 설치해야 한다 | 서버에 **크롬이 없어** PDF 를 안 만든다. 해당 없음 (§11) |
| 「일반적인 Express 앱」 가정 | 정본은 **사전 컴파일된 단일 파일 React** 다. 재빌드 금지 |
