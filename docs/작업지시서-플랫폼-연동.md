## 0-1. 역할 분담 — **수락한다** (본체 2판 §1-1 회신)

본체가 제안한 「**[보고서 생성] 섹션 안에서는 엔진이 주역**」을 그대로 받는다.
화면·API·파이프라인·산출물·품질 판정은 엔진이 정하고, 본체는 **그릇**
(로그인·플랜·같은 출처·배포 통로)을 책임진다.

**다르게 나누고 싶은 줄은 없다.** 다만 경계 한 줄만 분명히 해 둔다 —
**`authenticate` 와 `runningFor` 는 본체 몫이 맞다.** 그 둘은 「누가 로그인했나」와
「지금 그 프로젝트가 돌고 있나」인데, 앞은 회원 저장소가, 뒤는 큐가 알고 있고
**둘 다 엔진이 모르는 사실**이다.

### 왜 이 분담이 옳은지 — 이번에 증거가 나왔다

본체 2판이 이렇게 적었다: **NAS 서버가 라우팅 표를 손으로 옮겨 적고 있어서
새 라우트 11개가 빠진 채 404 가 났다.** 이것이 분담이 어긋났을 때 생기는 일의
전형이다 — **엔진이 가진 사실(라우트 목록)을 본체가 복사해 들고 있었다.**

> 오류 메시지는 「없는 주소」다. 두 목록을 나란히 놓고 세어 보기 전까지
> **「서버가 옛 표를 들고 있다」는 것이 보이지 않는다.**

## 0-2. 이관 4건 — **1건은 이번에 냈다** (본체 2판 §1-2)

| | 무엇 | 상태 |
|:--:|---|---|
| ① | **NAS 서버가 라우트를 손으로 옮기지 않게** | ✅ **엔진이 냈다** — 아래 |
| ② | 화면 사본을 엔진이 직접 낸다 (`build-embed.js`) | 🔴 남음 |
| ③ | NAS 반영 스크립트 `deploy/nas.sh` | 🔴 남음 |
| ④ | `npm run verify:nas` 한 번으로 확인 | 🔴 남음 |

### ① 라우트 표를 **데이터로 내준다** 〈2026-08-18 · `ui/routes.cjs`〉

```js
const routes = require('/volume1/docker/linkpilot/im-agent/ui/routes.cjs');
const W = require('…/ui/report-api.cjs');   // W.ROUTES — 쓰기 22
const A = require('…/ui/api-router.cjs');   // A.ROUTES — 읽기 6

const hit = routes.match(W.ROUTES, req.method, pathname);   // {route, params} | null
if (hit) await hit.route.call(handlers, ctx, hit.params);
```

- **`express` 를 요구하지 않는다.** 순수 `http` 서버가 같은 표로 길을 찾는다 —
  프레임워크를 강요하면 결국 또 손으로 옮기게 된다.
- **표와 실제 등록이 갈릴 수 없다.** `createRouter()` 도 이 표에서 만든다.
  가짜 라우터를 걸어 **무엇을 등록하는지 받아 적고 표와 대조**하는 검사가 있다.
- **차례가 규칙이다.** `/sources/verify` 가 `/sources/:name` 보다 먼저 잡힌다
  (안 그러면 「verify 라는 이름의 파일을 지워라」가 된다). 이것도 검사가 지킨다.
- **파일 라우트는 `kind: 'file'`** 로 표가 말한다 — JSON 으로 읽으면 깨진다.

**실측**(2026-08-18): express 없이 순수 http 서버를 세워 표만 걸고 돌렸다.

```
GET  /intake            → 200
POST /projects (무인증)  → 401 「로그인이 필요합니다」
POST /projects (인증)    → 201
POST …/linked (미주입)   → 501 「저장소 내려받기가 붙어 있지 않습니다 …」
POST …/sources/purge    → 400 「olderThanDays 를 지정해야 합니다」   ← :name 으로 안 잡힌다
없는 주소               → 404
```

★ **본체가 할 일**: `im-engine-server.cjs` 의 손으로 적은 라우트 등록을 지우고
위 세 줄로 바꾼다. 그러면 **엔진에 라우트가 늘어도 본체는 고칠 것이 없다.**

★ ②~④ 는 아직 엔진이 안 냈다. **그 전까지는 본체의 `sync-im-flow.js` ·
tar-over-ssh 가 계속 쓰인다** — 이 문서 §3 이 그것을 전제로 쓰여 있다.

## 3. 작업 — 다섯

### 작업 ① 엔진 최신판을 NAS 로 — **git 이 아니다**

NAS 는 저장소를 clone 해 두지 않았다. **tar-over-ssh** 로 올린다.

```bash
# 로컬(엔진 저장소)에서
cd ~/linkpilot-cron
git pull origin claude/linkpilot-agent-github-plan-0af7xs
tar czf - im-agent | ssh twomh0616@100.89.242.106 \
  'cd /volume1/docker/linkpilot && cp -a im-agent im-agent.bak-$(date +%Y%m%d%H%M) && tar xzf -'

# 올라갔는지 **파일로** 확인한다 (앱·CI 가 초록이어도 NAS 는 옛 판일 수 있다)
ssh twomh0616@100.89.242.106 'md5sum /volume1/docker/linkpilot/im-agent/ui/platform/files.html'
md5 -q im-agent/ui/platform/files.html            # 두 값이 같아야 한다
```

이번 판에 **새로 들어가는 파일은 `im-agent/ui/platform/files.html` 하나**다
(나머지는 이미 있고 내용만 바뀐다).

엔진을 다시 띄운다:

```bash
ssh twomh0616@100.89.242.106 'cd /volume1/docker/linkpilot && ./stop-engine.sh; ./start-engine.sh; \
  sleep 2; curl -s http://127.0.0.1:8181/healthz'
```

### 작업 ② 화면 사본 동기화 — `sync-im-flow.js`

```bash
node sync-im-flow.js     # im-agent/ui/platform/ → im-flow/
```

**`im-flow/` 를 손으로 고치지 않는다** — 다음 동기화에서 조용히 사라진다.
동기화기가 사본에 넣는 것은 셋이다.

| 주입 | 무엇 | 빠뜨리면 |
|---|---|---|
| ① 설정 병합 | `Object.assign(window.LINKPILOT_*, {api, session, inTab, …})` | **대입(`=`)하면 앱이 넣은 api·session 이 데모값으로 되돌아간다** (실제 사고) |
| ② 세션 | 부모 앱의 `postMessage {type:'lp-session', authenticated, pro}` 수신 | 화면이 등급을 모른다 (차단은 서버가 하므로 뚫리지는 않는다) |
| ③ 토큰 래퍼 | `fetch` 에 `Authorization: Bearer <lp_token>` | 모든 호출이 **401** 이 된다 |

★★ **`files.html` 은 이번에 처음 들어가는 화면이라 동기화기의 주입 목록에 없다.**
**전역 이름 `LINKPILOT_FILES` 를 셋 모두에 추가한다.** 안 하면 화면은 뜨는데
목록이 비고, 원인은 「자료가 없다」로 보인다.

| 화면 | 설정 전역 |
|---|---|
| `report-flow.html` | `window.LINKPILOT_REPORT_FLOW` |
| `outputs.html` | `window.LINKPILOT_OUTPUTS` |
| **`files.html`** | **`window.LINKPILOT_FILES`** ← 이번에 추가 |

```js
// ★ 대입이 아니라 병합이다 (대입하면 화면이 심어 둔 데모 기본값으로 되돌아간다)
Object.assign(window.LINKPILOT_FILES, {
  api: '/api/linkpilot', session: currentUser, inTab: true,
});
```

동기화가 끝나면 `im-flow/` 에 **13개**가 있어야 한다. (손으로 적은 목록이 아니라
탭 셋과 4단계가 **실제로 참조하는 것**을 훑어 뽑았고, 테스트가 이 목록을 지킨다)

```
tokens.css                                          ← ★ 빠지면 색·글꼴이 통째로 빠진다
outputs.html      report-flow.html   files.html     ← 탭 셋
intake.html       fields.html        reports.html   ← 4단계 (탭 바에 달지 않는다)
flow-core.js      fields-core.js     gate-core.js
live-core.js      catalog.js         inapp.js
```

★ `intake` · `fields` · `reports` 는 **탭 바에 달지 않는다** — `report-flow.html`
이 iframe 으로 부른다. 따로 달면 4단계가 6개 탭처럼 보인다.

### 작업 ③ 탭 추가 — 정본 HTML 에 직접

정본은 **사전 컴파일된 `linkpilot-platform.deploy.html`** 이다. `import` 로 목록을
읽어 오는 구조가 아니므로, 지금 탭 둘이 들어 있는 자리에 **셋째를 같은 모양으로**
더한다. 값은 엔진의 `flow-core.js` 가 정본이고, 아래는 그것을 그대로 옮긴 것이다.

```js
// 지금 있는 둘 옆에 하나 더
{ id:'files', tab:'자료 업로드', note:'보관 · 연결 · 1회성',
  src:'/im-flow/files.html', plan:'free' }
```

★ **`plan` 이 `free` 다.** 다른 둘(`pro`)과 다르다 — 자료를 넣는 길이 유료면
Pro 를 살지 판단할 자료조차 못 넣는다. 탭 잠금 규칙을 그대로 복사하면 안 된다.

★★ **`inTab: true` 를 켠다.** 탭 이름과 화면 제목이 **같은 글자**라(2026-08-18
개명) 안 켜면 「자료 업로드」 아래에 「자료 업로드」가 한 번 더 나온다.

## 11. 이 지시서가 틀렸던 곳 — **지우지 않는다**

초판·1차 개정은 **「일반적인 Express 앱에 라우터를 마운트한다」**를 가정했다.
실제 LinkPilot 은 그렇지 않았고, 아래가 어긋나 있었다. 지우면 다음 사람이 같은
착각을 그대로 한다.

| 지시서가 적었던 것 | 실제 |
|---|---|
| `/volume1/linkpilot/…` | **`/volume1/docker/linkpilot/…`** (엔진) · **`/volume1/web/im-flow/`** (화면) |
| 화면을 `/im/` 에 올린다 | **`/im-flow/`** — 그리고 손으로 올리는 것이 아니라 `sync-im-flow.js` 가 만든다 |
| 앱 `server.js` 에 라우터 둘을 마운트한다 | 엔진은 **별도 프로세스** `im-engine-server.cjs`(8181)로 **이미 돈다** |
| 인증은 `req.session.user` | **HMAC 토큰 + `Authorization: Bearer`** (사본의 fetch 래퍼가 붙인다) |
| 탭 바에서 `import FLOW … FLOW.TABS` | 정본이 **사전 컴파일된 단일 HTML** 이라 import 가 아니다. 값을 옮겨 적되 `flow-core.js` 를 정본으로 본다 |
| `.env` 를 만든다 | **이미 있다** |
| 글꼴을 넣고 PDF 를 확인한다 | 서버에 **크롬이 없어 PDF 를 안 만든다.** 지금은 해당 없음 (§5) |
| 설정 전역을 **대입**하는 예시 | **`Object.assign` 병합**이어야 한다 — 대입은 실제 사고를 냈다 |

**교훈**: 붙이는 쪽 환경을 재지 않고 쓴 지시서는 **그럴듯하게 틀린다.** 문장이
자연스러워서 읽는 사람이 의심하지 않고, 경로 하나 때문에 반나절이 간다.
