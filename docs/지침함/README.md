# 지침함 — 업무지침이 Orchestrator 에게 가는 길 〈2026-10-10 · D-428〉

사장님 지시: 「여기서 업무지침 전략이 만들어지면 챗지피티와 검증 자동화 해줘 · 분석자료를 여기로 백업해줘 ·
내가 직접 Orchestrator 에게 업무를 지시하거나 자동으로 연동하여 업무지침이 전달되도록 만들어줘」.

## 한눈에

```
① 지침을 만든다        claude.ai 프로젝트 「LinkPilot 리뉴얼 재구성」 (Claude)
        │  docs/지침함/<날짜>-<제목>.md 로 올리고, 같은 글을 그 프로젝트 문서에도 백업한다
        ▼
② ChatGPT 가 검증한다   GitHub Actions 「업무지침 교차검증 (ChatGPT·Gemini)」 (저절로 돈다)
        │  <지침>.gpt-review.md (판정·문제·고칠 점) · _검증현황.md (한 장 표)
        ▼
③ Orchestrator 가 반영   Claude Code 세션 「AI Project Manager Orchestrator」
           세션을 열 때 현황표를 읽고(CLAUDE.md §18), 반영하면 반영기록.md 에 지문을 남긴다
```

## 파일

| 파일 | 누가 쓰나 | 뜻 |
|---|---|---|
| `<날짜>-<제목>.md` | Claude(프로젝트) | 업무지침 원문 |
| `<같은 이름>.gpt-review.md` | 워크플로(자동) | ChatGPT 판정 — 통과 · 보완 필요 · 반영 보류 |
| `_검증현황.md` | 워크플로·`npm run guide:status` | 지침마다 검토·반영 상태 한 장 |
| `_검토요약.md` | 워크플로(자동) | 이번 실행의 판정 첫 줄과 건별 결과 |
| `_검증기준.md` | 사람 | ChatGPT 에게 함께 주는 «우리 규칙» 요약 |
| `반영기록.md` | Orchestrator | 반영한 지침의 지문(12자리) · 날짜 · 커밋 |

## 규칙 넷

1. **이 저장소는 공개다** — 지침에 열쇠·비밀번호·전화번호·개인정보를 적지 않는다. 적혀 있으면 스크립트가 보내지도 커밋하지도 않는다.
2. **ChatGPT 판정은 참고 의견이다** — 승인이 아니다(CLAUDE.md §11). 「반영 보류」는 고칠 때까지 반영하지 않는다.
3. **지침을 고치면 지문이 바뀌고 다시 검토된다** — 반영도 지문 단위다. 옛 지문의 반영 기록은 새 판에 안 이어진다.
4. **사장님은 언제든 Orchestrator 에게 직접 말씀하실 수 있다** — 그 세션에서 `/guideline-inbox` 를 치시면 지금 현황을 읽고 반영을 시작한다.
