# 업무지침 — 지침함 운영 (만들기 → ChatGPT 검증 → 백업 → Orchestrator 반영)

- 지침 번호: G-2026-10-10-01
- 작성: Claude (claude.ai 프로젝트 「LinkPilot 리뉴얼 재구성」)
- 지시: 김대표 · 2026-10-10
- 적용 대상: 프로젝트의 Claude · AI Project Manager Orchestrator · GitHub Actions

## 1. 목적

업무지침이 대화 속에만 남아 사라지지 않게 한다. 만든 지침은 다른 AI(ChatGPT)가 한 번 더 보고, 프로젝트에 백업되고, Orchestrator 가 받아 반영한다.

## 2. 만드는 쪽 (프로젝트의 Claude)

1. 업무지침·전략이 정해지면 `docs/지침함/<YYYY-MM-DD>-<제목>.md` 로 저장소에 올린다.
2. 같은 글을 claude.ai 프로젝트 문서 `claude/지침함/<같은 이름>` 에도 백업한다.
3. 지침 머리에 지침 번호 · 작성 · 지시 · 적용 대상을 적는다.
4. 열쇠·비밀번호·전화번호·개인정보는 적지 않는다. 저장소가 공개다.

## 3. 검증하는 쪽 (GitHub Actions · ChatGPT)

1. 지침함에 글이 올라오면 워크플로 「업무지침 ChatGPT 교차검증」이 저절로 돈다.
2. 바뀐 지침만 검토한다. 지문(12자리)이 같으면 다시 부르지 않는다.
3. 판정은 셋이다 — 통과 · 보완 필요 · 반영 보류. HIGH 문제가 있으면 통과로 적지 않는다.
4. 열쇠가 없거나 거부되면 그 까닭을 실행 요약 첫 줄에 적고 빨갛게 끝낸다.

## 4. 반영하는 쪽 (Orchestrator)

1. 세션을 열 때 `npm run guide:status` 로 현황표를 만든다.
2. «미반영»이면서 «통과»인 지침을 반영한다. 반영은 초안 PR 로 하고 검사가 초록이면 합친다.
3. «보완 필요»는 고칠 점을 사장님께 알리고, 답을 받은 뒤 반영한다.
4. «반영 보류»는 반영하지 않는다. 지침을 고쳐 다시 올리면 다시 검토된다.
5. 반영하면 `반영기록.md` 에 파일 · 지문 · 날짜 · 커밋을 한 줄로 적는다.

## 5. 완료 조건

- 지침마다 검토 파일이 있고, 그 지문이 지침의 지금 지문과 같다.
- 반영한 지침은 반영기록에 지문이 있다.
- 담당: 만들기·백업 = 프로젝트 Claude · 검증 = 워크플로 · 반영 = Orchestrator.
