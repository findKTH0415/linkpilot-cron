## 0. 결론
0. 컨셉 — «보고서의 품질은 모은 자료에서 정해진다.» LinkPilot 은 자료를 가장 잘 모으는 보고서 도구로 선다.
   사용자가 준 자료에 공공·시장 자료를 API 로 더 모은다. 자체 AI 가 둘을 맞대어 읽는다.
1. 7단계 순서·이름·건너뛰기 규칙은 그대로 둔다. 바뀌는 것은 여섯 자리다.
   ②는 «사업 파악·자료 수집»으로 넓힌다. ⑥은 «디자인 고르기»로 넓힌다.
2. 더하는 기능은 여섯이다. 출처 연결 · 지난 자료 불러오기 · 기관 양식 맞춤 · 디자인 고르기 · 출력 전 점검 · 보낸 뒤 열람 기록.
3. 「숫자를 지어내지 않는다 · 사람만 확정한다」 원칙은 바꾸지 않는다.
   더하는 기능은 이 원칙을 더 단단하게 하는 쪽만 골랐다.
4. 점수 리포트 · 재무 예측 · 공동 편집은 이번에 넣지 않는다(4절).

### 1-1. 화면과 대화 방식
화면 왼쪽은 대화창, 오른쪽은 지금까지 정한 것과 미리보기다.
AI 가 한 번에 질문 하나를 묻는다. 답은 고르기 칩 · [직접 입력] 중 하나다.
위쪽에 «3 / 7» 진행 줄과 [이전 단계로]를 둔다.
생성 뒤에도 대화로 고친다. «2장 더 짧게» «표를 그림으로»처럼 말하면 그 장만 다시 쓴다.
끝에는 확인사항 표를 붙인다. 구분은 넷이다 — 수정 완료 · 대표님 확인 필요 · 자료 추가 필요 · 법률·회계 확인 필요.

### 1-2. 건너뛰기 표 — 기본값이 있는 칸만 건너뛴다
| 단계 | 건너뛰기 | 건너뛰면 |
|---|---|---|
| ① 문서 종류 | 안 됨 | 고를 때까지 다음으로 가지 않는다 |
| ② 사업 파악·자료 수집 | 안 됨 | 수집 현황판에서 [맞습니다]를 눌러야 넘어간다 |
| ③ 받는 곳 | 안 됨 | 사업 사실이라 기본값이 없다. 정해지지 않으면 [자료 필요]로 남긴다 |
| ④ 작성 유형 | 안 됨 | 공개 범위·분량·목차는 사람이 고른다 |
| ⑤ 빈칸 | 안 됨 | [모름 — 자료 필요로 두기]만 있다. 값을 채우는 기본값은 없다 |
| ⑥ 디자인 | 됨 | 하우스 기본 판형·디자인 세트 |
| ⑦ 출력 | 됨 | `outputspec.js` PRESETS(쪽수·판형·형식·언어) |

### 1-3. «준비 중» 칩 — 요약 보고서 · 금융기관 제출본
1. 두 칩은 화면에 보인다. 누르면 «준비 중 — 갈래 규칙이 정해지면 엽니다»를 적고 다음 단계로 가지 않는다.
2. 갈래 규칙(공개 범위·분량·목차·서버 문서 종류 값)은 사장님 확인 뒤 다음 판에 적는다(6절 1번).
3. 규칙이 없는 갈래를 티저·IM 규칙으로 대신 돌리지 않는다.

### 1-4. ④ 작성 유형 — 티저와 IM 이 갈리는 자리
| | 투자 티저 | IM 풀버전 |
|---|---|---|
| 공개 범위 | 기본 [익명형 — 회사명 가림] · 사용자가 [실명형]을 고르면 실명으로 적는다 | 실명(NDA 뒤 제공) |
| 분량 | [1장] [2~3장] | [요약형 20쪽] [표준 40쪽] [상세 60쪽+] |
| 내용 | 핵심 지표 11개 중 넣을 것 고르기 | AI 가 «산업 맞춤 목차 제안서»를 먼저 낸다 → 장 추가·빼기·순서 바꾸기 → [이 목차로 진행] |
| 다음 단계 | 같은 자료로 [IM 으로 이어 만들기] | 같은 자료로 [티저 뽑기] |

### 1-5. 지키는 규칙
(AI 비용 규칙은 3-1 한 곳에 둔다. 여기 두 벌로 적지 않는다.)
1. AI 는 숫자를 지어내지 않는다. 모르는 값은 [자료 필요]·[수치 확인]으로 남긴다.
   투자자 배포판에서는 그 표시를 본문에서 빼고 별도 확인목록으로 옮긴다.
2. 사양 확정은 사람만 한다. 엔진은 확정자 이름에 ai·claude·gemini 가 있으면 거부한다(`outputspec.js`). 그대로 둔다.
3. 건너뛰기는 ⑥·⑦에만 있다. 건너뛴 칸에는 기본값을 쓰고, 고른 값을 화면에 적는다.
   사업 사실(②·③·⑤)에는 기본값을 쓰지 않는다.
4. 대화 기록과 고른 값은 프로젝트마다 저장한다. 중간에 나갔다 와도 그 자리에서 이어진다.
5. 서버 창구(프로젝트 만들기·자료·빈칸·사양 확정·생성)는 그대로 쓴다. 대화 한 턴을 받는 창구 하나만 더한다.
6. 화면은 linkpilot-cron 의 것이다. platform 은 그 화면을 띄워 보여 준다. 같은 화면을 두 벌로 만들지 않는다.
7. 이 지침 안에서도 같은 표·규칙을 두 벌로 적지 않는다. 단계 정의는 1절, 공사 차례는 3절 한 곳이다.

## 2. 더하는 기능 — 자세히
### 2-0. 컨셉 — 자료 수집이 품질을 정한다
1. 경쟁사는 자료를 받는 데서 멈춘다. 국내 서비스는 아이디어 몇 줄만 받는다.
   금융 IM 서비스는 고객이 올린 자료방만 읽는다.
2. LinkPilot 은 받은 자료에서 빈 곳을 찾는다. 그 빈 곳을 공공·시장 자료로 스스로 채운다.
   두 자료가 서로 맞는지는 AI 가 대어 본다.
3. 그래서 같은 딜이라도 LinkPilot 보고서에는 근거가 더 많이 붙는다.
   이것을 화면과 소개 문구의 중심에 둔다.
4. 소개 문구(안): «자료를 모으는 데서 보고서가 달라집니다.»

### 2-1. 사업 파악과 자료 수집 (②)
②는 네 걸음이다. Ⓐ 사업 파악 카드 → Ⓑ 자료 수집 세 갈래(㉠·㉡·㉢) → Ⓒ 수집 현황판 → [맞습니다].
Ⓐ 카드와 ㉠ 자료 올리기는 한 화면에서 함께 한다.
자료를 올리면 카드 칸이 채워진다. 빈 칸만 묻는다.
분야를 먼저 알아야 부를 API 가 정해진다. 추천할 목차·디자인도 분야로 정해진다.
그래서 카드가 맨 앞이다.

#### Ⓐ 사업 파악 카드 — 작성 목적 · 분야 · 딜 개요

| 칸 | 고르는 것·적는 것 | 반드시 | 이 값이 쓰이는 곳 |
|---|---|---|---|
| 작성 목적 | [투자 유치(지분)] [대출·PF 신청] [메자닌(CB·RCPS 등)] [매각] [인수 검토] [사업 제안·협력] | 예 | ③ 받는 곳 후보 · ④ 목차에서 앞세울 장 |
| 분야 | 큰 갈래 [부동산] [신재생] [인프라] [기업·회사채] [해외 사업] → 세부(예: 주거·상업·물류·호텔·데이터센터 / 태양광·풍력·ESS) | 예 | ㉡ 수집처 · ④ 산업 맞춤 목차 · ⑥ 디자인 세트 추천 |
| 나라·지역 | 나라 → 시·도 → 주소(국내는 지번까지) | 예 | ㉡ 지역 자료 · 브이월드 지도 |
| 사업명 | 직접 입력 | 예 | 표지 · 모든 장 머리 |
| 사업 단계 | [구상] [토지 확보] [인허가] [착공] [준공·운영] | 예 | ④ 목차 · ⑤ 빈칸 질문 순서 |
| 규모 | 면적·세대·용량(MW)·객실 수 등 분야별 단위 | 자료 있으면 | 요약 · ㉡ 비교 자료 |
| 당사자 | 시행사·차주·스폰서·시공사·운영사 이름과 역할 | 자료 있으면 | 사업 구도 그림 · NTS 사업자 확인 |
| 돈의 규모 | 총사업비 · 필요 자금 · 조달 구조(자기자본·대출·메자닌) | 자료 있으면 | 자금 조달 장 · ⑦ 숫자 점검 |
| 주요 일정 | 인허가·착공·준공·자금 집행 시점 | 자료 있으면 | 일정 장 |
| 한 줄 요약 | 이 딜을 한 문장으로 | 자료 있으면 | 티저 첫 줄 · 표지 리드문 |

채우는 방법
1. ㉠으로 올린 자료와 요청문에서 먼저 뽑아 칸을 채운다.
   뽑은 값 옆에는 어느 자료 몇 쪽에서 왔는지 붙인다.
2. 1단계에서는 정해 둔 규칙으로 뽑는다(지금 엔진의 요청문 읽기를 넓힌 것). 3단계부터는 ㉢ AI 가 읽어 채운다.
3. 못 채운 칸만 하나씩 묻는다. «반드시» 칸이 비면 ㉡ 수집으로 넘어가지 않는다.
4. «자료 있으면» 칸이 비면 [자료 필요]로 둔다. 이 칸들은 ⑤ 빈칸에서 다시 묻는다.
5. 사업 사실이므로 기본값을 넣지 않는다.
   고른 분야와 자료 내용이 어긋나면 카드에 알린다. 예: 분야 «태양광»인데 자료에 세대 수.

#### Ⓑ 자료 수집 세 갈래

#### ㉠ 사용자 자료

1. 파일(PDF·워드·엑셀·사진)·링크를 올린다. 지난 IM 의 장도 불러온다(같은 회사·같은 자산군 · 내 프로젝트와 공유받은 프로젝트만).
2. 가져온 지난 자료에는 «지난 자료 · 기준일»을 붙인다. 기준일이 지난 숫자는 ⑤에서 다시 묻는다.

#### ㉡ API 보완 수집

1. Ⓐ에서 정한 분야의 필수 항목(`assetclass.js`)과 ㉠을 맞대어 빈 항목을 찾는다. 빈 항목만 API 로 찾아온다.
2. 무엇을 어디서 가져올지 목록을 먼저 보여 주고, 사용자가 [수집 시작]을 누르면 돈다.
3. **수집처는 무료 자료만 쓴다.** 민간 시세·신용정보처럼 값을 내는 자료는 넣지 않는다(아래 «넣지 않는 수집처»).
4. 무료 API 라도 하루 호출 한도가 있다. 한도에 닿으면 다음 날 이어서 모으고, 유료로 넘어가지 않는다.
5. 수집처는 사장님 지정 목록과 Claude 추천 목록 두 표다. 각 API 의 실측 상태는 7절 «수집처 실측 표»에 적는다.
6. API 열쇠는 서버에만 둔다. 화면과 주소창에 두지 않는다.

#### 사장님 지정 수집처 (무료 · 48곳)

«열쇠 이름» 칸은 사장님이 서버에 넣으신 열쇠의 이름이다. 공공데이터포털 서비스 번호가 아니다.

| 신용정보 | 기업 신용등급 · 신용조회 · 기업 정보 유료 서비스 | DART 공시 재무로 채운다. 등급이 필요하면 사용자가 받은 평가서를 ㉠으로 올린다 |
| 유료 시장 보고서 | 민간 리서치·컨설팅 보고서 | 사용자가 가진 보고서를 ㉠으로 올리면 출처를 달아 쓴다 |

#### ㉢ 자체 AI 분석

1. ㉠과 ㉡을 함께 읽어 요약 카드를 만든다(«이렇게 이해했습니다»).
2. 자료끼리 어긋나는 곳을 찾는다. 예: 사용자 자료의 대지면적과 건축물대장 면적이 다름.
3. 아직 빈 항목 목록을 만든다. 이 목록이 ⑤ 빈칸 질문이 된다.
4. AI 는 숫자를 만들지 않는다. 출처가 있는 숫자를 옮기고, 해석 문장에는 «AI 분석» 표시를 붙인다.
5. AI 엔진은 3-2 의 3단 구성을 따른다(무료 Gemini → 유료회원 본사 엔진 → 사용자 열쇠).

#### Ⓒ 수집 현황판 (② 끝)

1. 맨 위에 Ⓐ 사업 파악 카드를 한 줄로 요약해 둔다(목적 · 분야 · 사업명 · 단계).
2. 필수 항목마다 출처를 한 칸에 보여 준다. [사용자 자료] [공공 자료] [AI 분석] [비어 있음].
3. «필수 항목 n개 중 m개 채움»을 적는다.
   딜을 평가하는 점수가 아니다. 자료가 얼마나 모였는지를 보여 주는 칸이다.
4. 사용자가 [맞습니다]를 눌러야 ③으로 간다. 건너뛰기는 v6 대로 없다.

### 2-2. 출처 연결 (⑤ · 생성 뒤)
1. ⑤에서 숫자를 넣으면 출처 칸이 따라 나온다. 올린 자료 목록에서 고르고 쪽 번호를 적는다.
2. 출처가 빈 숫자에는 [수치 확인] 표시가 붙는다. 투자자 배포판에서는 표시를 본문에서 빼고 확인목록으로 옮긴다(G-09 3절 1번 그대로).
3. 생성된 문서의 확인목록에서 숫자를 누르면 그 출처 자료와 쪽이 열린다.
4. AI 가 자료에서 읽어 온 숫자(② 요약 카드)도 같은 방식으로 출처를 단다. 이것은 3단계(AI 대화)에서 붙인다.

### 2-3. 기관 양식 맞춤 (③·④)
1. 금융기관 양식(목차 순서 · 표 이름 · 쪽 수 한도)을 기관마다 한 번 등록한다.
2. ③에서 받는 곳으로 그 기관을 고르면 ④의 목차 제안서가 양식 순서로 나온다.
3. 이것이 미결로 남은 «금융기관 제출본» 갈래의 답 후보다. 양식 등록이 생기면 ①의 [금융기관 제출본] 칩을 «준비 중»에서 연다. 여는 것은 사장님 확인 뒤다.

### 2-4. 출력 전 점검 (⑦)
점검 항목은 규칙으로 정한다. AI 비용이 없다.
1. 같은 이름의 숫자가 장마다 다르게 적힌 곳(예: 총사업비가 2장과 7장에서 다름)
2. 비어 있는 표 칸 · 남아 있는 [자료 필요]·[수치 확인] 표시 수
3. 기준일이 다른 숫자가 섞인 곳
4. 합계가 맞지 않는 표(행 합 ≠ 합계 행)
5. 도형·사진과 글씨가 겹친 곳 — 데스크탑 1600·1366 · 모바일 390·360 폭에서 잰다.
6. 글자와 배경의 대비가 낮아 읽기 어려운 곳 — 고른 디자인 세트·브랜드 색에서 생긴다.
7. 쪽 맨 아래에 제목만 홀로 걸린 곳
8. 결과는 «걸린 곳 n건» 목록이다. 점수나 등급으로 바꾸지 않는다.

### 2-5. 열람 기록 (보낸 뒤)
1. 생성한 티저·IM 을 공유 링크로 보낸다. 지금 있는 공유 링크·NDA 동의(`share.php`) 위에 얹는다.
2. 받는 사람별로 처음 연 때 · 마지막 연 때 · 본 장을 남긴다.
3. 경쟁사 비교에서 나온 기능 목록 G-08 ⑤(자료 열람 기록)와 같은 기능이다. 두 벌로 만들지 않는다.

6. 디자인을 바꿔도 [확정] 전이면 다시 고를 수 있다. 생성 뒤 바꾸면 내용은 그대로 두고 다시 입힌다.

### 3-1. AI 비용 승인 절차 (3단계)
0. 담당 — 승인 요청서는 AI Project Manager Orchestrator 가 쓰고, 승인은 사장님이 하신다.
1. 3단계는 무료 Gemini 열쇠 묶음만 쓴다. 유료 AI 호출은 넣지 않는다.
2. 유료로 넘어가는 길을 붙이는 것은 «새 유료 비용»이다. 사장님 승인 뒤에만 붙인다.
3. 승인을 여쭐 때 적는 것 — 한 건 생성에 드는 호출 수 · 하루·한 달 예상 금액 · 한도.
4. 한도의 80% 에 닿으면 Orchestrator 가 사장님께 미리 알린다. 넘긴 뒤 알리는 것은 보고가 아니다.
5. 승인 전에는 무료 열쇠가 막혀도 유료로 넘어가지 않는다.
   화면은 «AI 대화를 잠시 못 씁니다 — 질문 카드로 이어 갑니다»로 적고 1단계 방식으로 계속한다.
