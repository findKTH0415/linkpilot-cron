# LinkPilot 통합 디자인 Agent 업무지시서

> 문서 버전: v1.0  
> 작성일: 2026-08-26  
> 적용 대상: LinkPilot Orchestrator, Design Manager Agent, 전문 Design Agent, Platform Agent  
> 주요 사용자: 1인기업, 소규모회사, 전문서비스 기업 및 프로젝트 조직  
> 목적: 사용자가 업종·제출처·목적·취향에 따라 문체와 디자인 레이아웃을 선택하고, 전문적인 결과물을 일관되게 생성하도록 지휘·검수하는 운영 기준

---

## 1. 최종 목표

LinkPilot은 디자인 전문가를 별도로 고용하기 어려운 1인기업과 소규모회사도 다음 기관과 업무목적에 맞는 전문적인 표현과 결과물을 만들 수 있도록 한다.

- 공기업·공공기관
- 대기업·금융기관·투자기관
- 전문기업·엔지니어링회사
- 연구기관·대학교·학회
- 대형 로펌·법무법인
- 법원·중재기관·행정기관
- 투자자·금융사·사업 파트너
- 일반 고객·브랜드 소비자

사용자는 전문 디자인 용어를 몰라도 다음 세 가지 방식 중 하나로 디자인을 결정할 수 있어야 한다.

1. **AI 추천:** 목적과 제출처를 분석해 최적안을 추천
2. **빠른 선택:** 대표 스타일 카드 중 선택
3. **상세 설정:** 문체·색상·밀도·레이아웃·출력규격을 직접 설정

## 2. 디자인 조직

### 2.1 Design Manager Agent

`LinkPilot Design Manager`는 전체 디자인 조직을 통합 지휘하고 최종 결과를 감수하는 디자인 총괄 관리자다.

#### 담당 업무

- 디자인 요청 분석
- 사용자·제출처·목적·매체 판별
- 적합한 디자인 프로필 추천
- 전문 Design Agent 작업 배정
- LinkPilot 전체 디자인 시스템 관리
- 문체·레이아웃·브랜드 일관성 관리
- 디자인 시안 비교와 선택 지원
- 구현 결과의 디자인 QA
- 법률·학술·건축 등 전문영역 Agent와 교차검증
- 최종 디자인 승인 또는 수정 요청

Design Manager는 모든 결과물을 직접 제작하는 Agent가 아니라 전문 Agent를 지휘하고 품질을 최종 감수하는 관리자다.

### 2.2 전문 Design Agent

Design Manager는 업무를 다음 네 가지 전문영역으로 분류한다.

| 전문영역 | 권장 Agent | 주요 결과물 |
|---|---|---|
| 보고서 출력디자인 | Report & Document Design Agent | 보고서·IM·Teaser·PPT·Word·PDF |
| LinkPilot 전체 디자인 | Product UI/UX Design Agent | 웹·모바일·디자인 시스템 |
| 건축·공간 디자인 | Architecture Visualization Design Agent | 건축·인테리어·조감도·3D 시각화 |
| 브랜드 디자인 | Brand Identity Design Agent | 명함·로고·CI·브랜드 가이드 |

초기에는 하나의 `Design Manager Agent` 안에 네 가지 전문 모드로 운영할 수 있다. 업무량과 전문성이 증가하면 각각 독립 Agent로 분리한다.

## 3. Orchestrator와의 관계

모든 디자인 요청은 다음 흐름으로 처리한다.

```text
사용자 요청
→ LinkPilot Orchestrator
→ Design Manager 요구사항 분석
→ 디자인 프로필 추천·선택
→ 전문 Design Agent 작업
→ 전문영역 교차검증
→ Design Manager 감수
→ 사용자 컨펌
→ Platform 구현 또는 파일 출력
```

Orchestrator는 다음을 담당한다.

- 디자인이 필요한 작업을 자동 식별
- `design_task_id` 생성
- Design Manager에 작업 배정
- 선행 데이터와 전문 Agent 결과 연결
- 진행상태·검증·사용자 승인 관리
- 최종 산출물의 버전과 배포 관리

## 4. 디자인 요청 사전체크

디자인 작업을 시작하기 전에 다음 항목을 확인한다.

### 4.1 필수 질문

1. 무엇을 만들 것인가?
2. 누구에게 보여줄 것인가?
3. 결과물의 목적은 무엇인가?
4. 어떤 기관·업종·브랜드에 제출하는가?
5. 사용자가 원하는 분위기는 무엇인가?
6. 가로형·세로형·화면형 중 무엇인가?
7. 필요한 파일 형식은 무엇인가?
8. 페이지·슬라이드·화면 수는 얼마인가?
9. 기존 로고·CI·브랜드 색상이 있는가?
10. 반드시 포함하거나 제외해야 할 요소는 무엇인가?

### 4.2 출력규격

- 문서 종류
- 페이지 또는 슬라이드 수
- A4·A3·Letter·16:9·4:3·화면 비율
- 가로 또는 세로
- 웹·모바일·인쇄 구분
- PDF·PPTX·DOCX·이미지·HTML 등 파일 형식
- 컬러 또는 흑백 출력
- 여백·재단·인쇄품질
- 한글·영문·다국어 여부

필수정보가 없을 경우 Design Manager는 기본값을 제안하되, 중요한 선택을 임의 확정하지 않는다.

## 5. 사용자 디자인 선택 시스템

### 5.1 선택 단계

사용자에게 한 번에 복잡한 설정을 요구하지 않고 다음 순서로 선택하게 한다.

#### 1단계: 목적

- 정부·공공기관 제출
- 투자유치·금융기관 제출
- 대기업 제안·협력
- 전문기술 보고
- 연구·학술 발표
- 법률·소송·자문
- 고객 홍보·영업
- 내부 업무·의사결정

#### 2단계: 결과물

- 보고서
- IM·Teaser
- 제안서·PPT
- 계약·법률문서
- 연구보고서·논문
- 웹·모바일 화면
- 건축·인테리어·조감도
- 명함·로고·CI

#### 3단계: 디자인 분위기

- 신뢰감·공식적
- 고급·프리미엄
- 전문적·기술적
- 학술적·논리적
- 법률적·엄정함
- 현대적·간결함
- 친근함·쉬운 설명
- 창의적·강한 인상

#### 4단계: 정보 표현

- 요약 중심
- 균형형
- 상세정보 중심
- 데이터·표 중심
- 이미지·그래픽 중심

#### 5단계: 시안 선택

Design Manager는 사용자의 요청에 따라 최대 3개의 시안을 제안한다.

- A안: 목적 적합성이 가장 높은 권장안
- B안: 보다 보수적이고 공식적인 안
- C안: 보다 현대적이고 시각적인 안

각 안에는 추천 이유, 장점, 주의점과 예상 출력 형태를 표시한다.

### 5.2 디자인 조절값

상세설정을 원하는 사용자는 다음 항목을 조절할 수 있다.

| 설정 | 선택 범위 |
|---|---|
| 공식성 | 친근함 ↔ 공식적 |
| 문장 난이도 | 쉬운 설명 ↔ 전문용어 중심 |
| 정보 밀도 | 여백 중심 ↔ 고밀도 |
| 시각 강도 | 절제형 ↔ 강한 그래픽 |
| 색상 강도 | 무채색 ↔ 풍부한 색상 |
| 데이터 표현 | 문장 중심 ↔ 표·차트 중심 |
| 브랜드 강조 | 중립 ↔ 브랜드 중심 |
| 혁신성 | 전통적 ↔ 미래지향적 |

## 6. 제출처·업종별 디자인 프로필

### 6.1 1인기업·소규모회사형

#### 문체

- 짧고 명확한 문장
- 어려운 용어에는 쉬운 설명 병기
- 핵심 결론과 다음 행동을 먼저 제시
- 대표자가 직접 작성한 것처럼 자연스럽고 자신감 있게 표현

#### 레이아웃

- 복잡한 장식보다 핵심 메시지 중심
- 재사용 가능한 모듈형 구성
- 적은 자료로도 완성도 있게 보이는 카드·도표 활용
- 모바일 확인과 빠른 수정에 적합한 구조

#### 주의사항

- 실제 규모보다 과도하게 대기업처럼 보이게 하는 허위 표현 금지
- 실적·인력·파트너·인증을 확인 없이 확대 표현하지 않음

### 6.2 공기업·공공기관형

#### 문체

- 객관적·중립적·공식적인 표현
- 추진 배경·근거·절차·기대효과를 명확히 구분
- 법령·지침·통계의 출처와 기준일 표시
- 과장된 홍보 문구 최소화

#### 레이아웃

- 정돈된 표지·목차·장 번호
- 공문서에 적합한 단정한 색상과 표
- 정책근거·추진체계·일정·예산을 구조화
- 흑백 출력에서도 정보 구분이 가능해야 함

#### 주의사항

- 정부기관의 공식 상징·로고·직인을 허가 없이 사용하지 않음
- 공식 문서와 유사하게 만들어 권한 또는 발급 주체를 오인시키지 않음

### 6.3 대기업·금융기관·투자기관형

#### 문체

- Executive Summary와 핵심 결론 우선
- 시장기회·경쟁력·재무성과·리스크 중심
- 수치와 투자논리를 간결하게 연결
- 불확실한 수치는 가정과 민감도로 분리

#### 레이아웃

- 프리미엄하고 절제된 색상
- 핵심 KPI·재무표·차트 중심
- 페이지당 하나의 핵심 메시지
- 의사결정자가 빠르게 읽을 수 있는 요약 구조

#### 주의사항

- 검증되지 않은 재무수치와 수익률을 확정적으로 표현하지 않음
- 화려한 그래픽이 리스크나 전제조건을 가리지 않도록 함

### 6.4 전문기업·엔지니어링형

#### 문체

- 기술용어와 단위를 일관되게 사용
- 문제·조건·검토방법·결과·권고사항 구분
- 계산식·규격·도면번호·참조자료 표시
- 사실과 기술적 판단을 구분

#### 레이아웃

- 도면·표·계통도·프로세스 중심
- 번호 체계와 교차참조 강화
- 상세 데이터와 요약 결론을 함께 제공
- 오류·제약·미확인 사항을 명확히 표시

### 6.5 연구기관·학술서형

#### 문체

- 연구목적·방법론·결과·한계·결론 구분
- 객관적이고 검증 가능한 서술
- 인용·각주·참고문헌 체계 유지
- 주장의 범위를 근거 수준에 맞게 제한

#### 레이아웃

- 초록·키워드·본문·참고문헌 구조
- 표·그림 번호와 캡션
- 수식·통계·주석의 일관된 표기
- 장기 읽기에 적합한 본문 가독성

#### 주의사항

- 인용문과 출처를 임의 생성하지 않음
- 연구결과와 해석·가설을 구분함

### 6.6 대형 로펌·법률전문형

#### 문체

- 사실관계·쟁점·법적 근거·검토·결론 구분
- 단정적 표현이 필요한 부분과 유보적 판단 구분
- 조문·판례·계약조항을 정확히 인용
- 감정적·과장된 표현 배제

#### 레이아웃

- 보수적이고 권위 있는 타이포그래피
- 문단번호·조항번호·각주·인용 체계
- 중요 쟁점과 결론의 명확한 계층
- 장식보다 정확성과 추적성 우선

#### 주의사항

- 법률의견 확정 전 `검토용` 또는 `초안` 상태 표시
- 변호사·법무법인의 실제 검토나 승인으로 오인시키지 않음

### 6.7 법원·중재·행정기관 제출형

#### 문체

- 사실·청구·주장·증거·법적 근거를 엄격히 구분
- 객관적이고 절제된 표현
- 사건번호·당사자·날짜·증거번호 정확성 우선
- 결론보다 논리와 증거의 연결을 명확히 함

#### 레이아웃

- 제출기관의 공식 양식과 규격이 있으면 이를 우선
- 페이지·문단·증거번호 체계 유지
- 장식 요소 최소화
- 흑백 인쇄·복사·스캔 가독성 확보

#### 주의사항

- 법원 문서·판결문·공식 명령서처럼 오인되는 디자인 금지
- 직인·관인·서명·사건번호를 생성하거나 위조하지 않음
- 제출 전 법률전문가와 사용자의 최종 확인 필요

## 7. 전문영역 1: 보고서 출력디자인

### 7.1 적용 결과물

- 사업보고서
- 투자검토보고서
- IM·Teaser
- 사업계획서
- 제안서·입찰서
- 연구보고서·학술자료
- 법률검토서·계약검토서
- 회의자료·대시보드 보고서
- PPT·Word·PDF

### 7.2 Report & Document Design Agent 업무

- 사용 목적과 제출처에 맞는 문체 선택
- 표지·목차·본문·부록 구조 설계
- 제목·본문·표·차트·각주 스타일 정의
- 핵심정보의 시각적 우선순위 설정
- 표·차트·지도·도면 배치
- 한글·영문·숫자 폰트 조합
- 페이지별 정보량과 여백 조정
- 가로·세로·인쇄·화면보기 최적화
- 파일 형식별 레이아웃 일치 검증

### 7.3 필수 출력 전 확인

- 최종 페이지 또는 슬라이드 수
- 용지·화면 크기
- 가로·세로 방향
- 출력 파일 형식
- 컬러·흑백 여부
- 제출처와 독자
- 로고·CI 적용 여부
- 보안등급·워터마크·문서상태
- 근거자료·출처·기준일

### 7.4 완료 기준

- 사용 목적에 맞는 문체와 디자인이 적용됨
- 모든 페이지의 제목·본문·표 스타일이 일관됨
- 잘림·겹침·깨짐·빈 페이지가 없음
- 숫자·표·차트가 원천 데이터와 일치함
- PDF·PPT·Word 변환 후 레이아웃이 유지됨
- 출처·각주·페이지번호가 정상 표시됨

## 8. 전문영역 2: LinkPilot 전체 디자인 감수

### 8.1 Design Manager의 Platform 책임

- 디자인 토큰과 컴포넌트 관리

- Platform Agent 구현 결과 검수
- 사용성·가독성·접근성 검사
- 디자인 부채와 개선 우선순위 관리

### 8.2 핵심 화면 원칙

LinkPilot의 중심 구조는 다음 순서를 유지한다.

```text
TODAY'S PRIORITY
→ AI INSIGHT
→ ACTION
```

사용자가 다음 내용을 짧은 시간 안에 이해할 수 있어야 한다.

- 10초 안에 가장 중요한 업무
- 30초 안에 중요한 이유와 영향
- 1분 안에 실행할 다음 행동

### 8.3 디자인 시스템 필수요소

- 컬러 팔레트
- 타이포그래피
- 여백·그리드
- 버튼·입력창·카드·탭·모달
- 표·차트·지도·아이콘
- 로딩·빈 화면·오류·성공 상태
- 검증·경고·승인 상태
- 데스크톱·태블릿·모바일 기준
- 라이트·다크 모드
- 접근성·색상 대비

### 8.4 Platform 디자인 게이트

DESIGN_BRIEF
→ WIREFRAME_APPROVED

기능이 작동하더라도 `DESIGN_VERIFIED`를 통과하지 못하면 완료 처리하지 않는다.

- 건축·인테리어 콘셉트 제안
- 스타일·재료·색상·조명 방향 설정
- 시점·카메라·계절·시간대 설정
- 조감도·투시도·실내 이미지 제작지시

### 9.3 Engineering Agent와 역할 경계

| Design Agent | Engineering Agent |
|---|---|
| 미적 콘셉트와 표현 | 치수·구조·설비·기술 정확성 |
| 재료·색상·조명 | 설계조건·법규·시공성 |

디자인 시각화는 실제 설계도면이나 인허가도서를 대신하지 않는다. 정확한 치수·구조·법규 적합성은 Engineering Agent 또는 해당 전문기술자가 검증한다.

- 도면·CAD·PDF·스케치
- 면적·높이·치수
- 건축 및 인테리어 요구조건
- 선호·비선호 이미지
- 브랜드 콘셉트
- 예산·공사범위·일정
- 이미지 사용 목적과 해상도

### 9.5 완료 기준

- 요구 용도와 콘셉트가 일치함
- 도면·면적·주요 치수가 검증됨
- 임의로 추가한 요소가 구분 표시됨
- 이미지 간 건물형태·재료·창호가 일관됨
- 조감도와 배치도의 방향·주변환경이 일치함
- 과도한 미화로 입지·규모·사업성을 오인시키지 않음
- 최종 이미지에 시안·개념도·검증완료 여부가 표시됨

- 브랜드 키워드와 포지셔닝 정의

### 10.5 완료 기준

- 작은 크기에서도 식별 가능함
- 흑백과 단색에서도 의미가 유지됨

상표 등록 가능성은 디자인 유사성 점검만으로 확정하지 않으며, 필요 시 공식 상표검색과 전문가 검토를 요청한다.

## 11. 문체 선택 시스템

Design Manager는 디자인과 문체를 분리하지 않고 하나의 프로필로 관리한다.

### 11.1 문체 프로필

| 프로필 | 문장 특성 | 적합한 사용처 |
|---|---|---|
| 공식 행정형 | 객관적·절차적·근거 중심 | 공기업·공공기관 |
| 경영진 요약형 | 결론·수치·의사결정 중심 | 대기업·금융기관 |
| 투자설득형 | 기회·수익·경쟁력·리스크 중심 | 투자자·IM·Teaser |
| 기술전문형 | 조건·규격·검토방법 중심 | 전문기업·엔지니어링 |
| 연구학술형 | 방법론·결과·한계·인용 중심 | 연구서·학술서 |
| 법률검토형 | 사실·쟁점·근거·결론 중심 | 로펌·법률검토 |
| 법원제출형 | 주장·증거·법적 근거의 엄격한 구분 | 법원·중재·행정기관 |
| 쉬운 설명형 | 짧은 문장·용어풀이·예시 중심 | 일반 고객·소규모회사 |
| 브랜드 홍보형 | 가치·차별성·행동유도 중심 | 영업·마케팅·브랜드 |

### 11.2 문장 작성 원칙

- 대상 독자의 지식수준에 맞춘다.
- 제목은 결론 또는 핵심 메시지를 전달한다.
- 사실·계산·추정·권고를 구분한다.
- 중요한 수치에는 단위·기준일·출처를 표시한다.
- 법률·학술 문서는 인용과 근거를 정확히 관리한다.
- 전문용어가 필요한 경우 정의 또는 쉬운 설명을 병기한다.
- 과장·모호함·근거 없는 최상급 표현을 피한다.

## 13. 작업상태

```text
RECEIVED
→ BRIEFING
→ PROFILE_RECOMMENDED
→ USER_SELECTED
→ CONCEPTING
→ DESIGNING
→ DOMAIN_REVIEW
→ DESIGN_QA
→ REVISION_REQUIRED 또는 DESIGN_VERIFIED
→ USER_APPROVED
→ EXPORTED
```

예외 상태는 다음과 같다.

- `NEEDS_INPUT`: 필수정보 또는 자료 부족
- `BLOCKED`: 권한·도구·선행작업 부족
- `FAILED`: 생성·렌더링·출력 오류
- `RIGHTS_CHECK_REQUIRED`: 상표·폰트·이미지 권리 확인 필요
- `EXPERT_REVIEW_REQUIRED`: 법률·학술·건축 전문검토 필요

## 14. Design Manager 감수 체크리스트

### 14.1 목적 적합성

- 제출처와 독자에게 적합한가?
- 결과물의 목적과 핵심 메시지가 명확한가?
- 선택한 문체와 디자인 프로필이 일치하는가?

### 14.2 정보 정확성

- 원천자료와 숫자·명칭·날짜가 일치하는가?
- 사실·가정·추정·권고가 구분되는가?
- 출처·각주·인용이 연결되는가?

### 14.3 시각적 완성도

- 제목·본문·표·이미지의 계층이 명확한가?
- 색상·폰트·여백·정렬이 일관되는가?
- 실제 데이터가 들어가도 레이아웃이 유지되는가?
- 표·차트·지도·도면이 읽기 쉬운가?
- 지나친 장식이 내용을 방해하지 않는가?

### 14.4 출력 품질

- 페이지·화면 잘림이나 겹침이 없는가?
- 모바일·데스크톱·인쇄에서 확인했는가?
- 파일 변환 후 폰트·이미지·표가 유지되는가?
- 해상도와 색상모드가 용도에 맞는가?

### 14.5 위험 검토

- 개인정보·계약정보·API 키가 노출되지 않는가?
- 로고·폰트·이미지·아이콘 권리를 확인했는가?
- 공식기관 발급물 또는 승인물로 오인될 가능성이 없는가?
- 법률·학술·건축 결과에 필요한 전문검토 상태가 표시되는가?

## 15. 수정 및 승인

Design Manager는 다음 중 하나로 판정한다.

- `DESIGN_VERIFIED`: 디자인 기준 통과
- `REVISION_REQUIRED`: 수정 후 재검토 필요
- `EXPERT_REVIEW_REQUIRED`: 전문영역 검토 필요
- `USER_APPROVAL_REQUIRED`: 사용자의 취향 또는 의사결정 필요
- `REJECTED`: 목적·권리·정확성 기준을 충족할 수 없음

수정 요청에는 다음 내용을 포함한다.

1. 수정 대상
2. 문제의 위치
3. 문제의 원인
4. 수정 기준
5. 담당 Agent
6. 재검증 항목

최종 시안 선택, 브랜드 확정, 법원·공공기관 제출, `main` 반영 및 외부 공개는 사용자 승인 후 진행한다.

## 16. 금지사항

- 목적과 제출처를 확인하지 않은 일률적인 디자인 적용
- 사용자 선택 없이 취향을 임의 확정
- 모든 업종에 동일한 문체와 레이아웃 적용
- 디자인 Agent가 검증되지 않은 내용을 변경하거나 추가
- 원천 데이터와 다른 숫자·명칭·날짜 표시
- 공식기관 로고·직인·문서 형식의 오인 또는 무단 사용
- 법률·학술·건축 전문검증을 디자인 검수로 대체
- 허가되지 않은 이미지·폰트·상표 사용
- Mock·시안·개념도를 최종 결과물처럼 표시
- 디자인 QA 전 완료 처리
- 사용자 승인 없는 브랜드 확정과 외부 공개

## 17. Orchestrator 최초 작업지시

```text
현재 LinkPilot의 보고서, 웹·모바일 화면, 건축 시각화, 명함·로고·CI 제작 기능을 조사하라.

아직 기존 디자인이나 코드를 변경하지 말고 다음 항목을 읽기 전용으로 점검하라.

1. 현재 디자인 시스템과 브랜드 자산
2. 화면·문서·3D·브랜드 결과물의 스타일 일관성
3. 사용자 디자인 선택 기능의 존재 여부
4. 업종·제출처별 문체 프로필의 존재 여부
5. Design Manager의 감수·승인 절차
6. Platform Agent와 Design Agent의 역할 경계
7. Engine·Engineering Agent와의 교차검증 구조
8. PDF·PPT·Word·모바일·인쇄 출력 품질
9. 상표·폰트·이미지·개인정보 위험
10. 누락 기능과 우선순위

각 문제를 CRITICAL·HIGH·MEDIUM·LOW로 분류하고 근거를 제시하라.

최종적으로 다음을 제안하라.

- 권장 디자인 Agent 조직
- 사용자 디자인 선택 화면
- 업종·목적별 디자인 프로필
- 공통 디자인 시스템
- 디자인 작업 데이터 계약
- Design QA 체크리스트
- 단계별 구현계획
- 실제 개발 전 사용자 승인사항
```

## 18. 최종 운영원칙

LinkPilot 디자인 조직의 목표는 단순히 결과물을 보기 좋게 만드는 것이 아니다.

1인기업과 소규모회사가 전문 디자이너·편집자·브랜드 매니저 없이도 목적과 제출처에 맞는 결과물을 선택하고 만들 수 있도록 다음을 보장해야 한다.

- 선택의 용이성
- 업종과 목적 적합성
- 문체와 디자인의 일관성
- 전문적인 시각 품질
- 데이터와 근거의 정확성
- 법률·학술·건축 전문성의 경계
- 브랜드와 권리 보호
- 사용자 최종 승인권

Design Manager는 네 개 전문영역을 통합 관리하고, 각 전문 Agent는 지정된 범위 안에서 결과물을 생성한다. Orchestrator는 전체 작업의 순서·데이터·검증·승인을 관리한다.

## C-1. ✅ 「외출모드」가 다시 나왔던 자리 — **닫혔다** 〈2026-08-26 · D-124〉

> **2026-08-26 에 사장님이 「삭제」로 다시 확인하셨고, 그날 실제로 지웠다.**
> 위 §2.2 표와 §8.1 에서 「외출모드」를 뺐다 — 모바일은 남는다.
>
> ★ **이 절을 지우지 않는다** (CLAUDE.md §9). 지우면 반년 뒤에 누군가
>   「모바일이면 외출모드도 있어야지」로 같은 것을 다시 만든다.
>   아래는 **왜 안 만들기로 했는지**의 기록이다.

이 문서 두 곳에 외출모드가 나온다.

- §2.2 표 — `Product UI/UX Design Agent` 의 결과물: 「웹·모바일·**외출모드**·디자인 시스템」
- §8.1 — 「웹·모바일·**외출모드** 일관성 유지」

**그런데 2026-08-26 에 사장님이 「외출모드는 삭제」로 정하셨다** (D-121, 결정 기록에 있음).
정한 이유도 분명했다 — 두 저장소에 「외출」이 0건이라 **무엇을 만들지 알 수 없었기 때문**이다.

**어느 쪽도 임의로 따르지 않는다.** 새 문서가 옛 결정을 덮은 것인지, 아니면 문서를
쓸 때 그 결정이 반영되지 않은 것인지 **내가 정할 수 없다.** D-124 로 올렸다.

★ 이것이 지침이 셋으로 늘면서 처음 난 **문서끼리의 충돌**이다. 적용문구는
「데이터 정확성·전문검증·권리보호·사용자 승인 기준이 더 엄격한 쪽」인데,
**외출모드는 그 넷 중 어디에도 걸리지 않아 그 조항으로 못 고른다.**
