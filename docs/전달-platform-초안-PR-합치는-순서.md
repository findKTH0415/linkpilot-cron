# 초안 PR 여섯을 합치는 순서 — 실측판

〈2026-08-31 · 여섯을 **실제로 합쳐 보고** 적은 것입니다〉

## 한 줄

**여섯은 서로 깨뜨리지 않습니다.** 전부 합친 상태에서 `npm run gate` 열아홉 가지가
모두 통과했습니다(초록 69줄 · 빨간 줄 0 · exit 0).

막히는 자리는 **`package.json` 한 파일 한 줄**뿐이고, 답은 정해져 있습니다.

## 순서

| 단계 | PR | 무엇 | 충돌 |
|---|---|---|---|
| 1 | 4번 | PR 마다 게이트를 돌린다 | 없음 |
| 2 | 1번 | 웹앱 아이콘 (maskable) | 없음 |
| 3 | 3번 | 서비스워커가 주소를 안 보고 있었다 | 없음 |
| 4 | 5번 | 보고서 배너 삭제 + 화면이 머리를 단다 | `package.json` |
| 5 | 6번 | 연도별 통화량 최근 5개년 | `package.json` |
| 6 | 2번 | 기기 한도에서 자리 비우기 | `package.json` |

**왜 이 순서인가**

- 1·2단계는 다른 파일만 건드려 어디에 놓아도 안 부딪힙니다. 그중 **4번을 맨 앞에** 둔 것은
  그것이 합쳐져야 나머지 PR 에도 검사가 걸리기 때문입니다.
- **3번을 셋째에** 둔 것은 그것이 사장님이 겪으신 「배너 두 벌 · 앱 열기 안 됨」의 고침이라
  가장 급하기 때문입니다.
- 4~6단계의 충돌은 **순서를 바꿔도 셋입니다.** `package.json` 을 건드리는 PR 이 넷이라,
  첫째만 무충돌이고 나머지 셋은 반드시 부딪힙니다. 피하는 순서는 없습니다.

## 충돌은 왜 나나

검사 목록을 적는 `"gate"` 줄에 **각 PR 이 자기 검사를 덧붙였습니다.** 같은 줄의 같은 끝을
넷이 서로 다르게 고쳤으니 git 이 어느 쪽인지 못 정합니다.

★ 내용이 다투는 것이 아닙니다 — **둘 다 남기면 맞습니다.**

## 무엇을 하면 되나

GitHub 의 충돌 화면에서 `<<<<<<<` 로 시작해 `>>>>>>>` 로 끝나는 덩어리를 통째로 지우고,
그 단계의 줄을 넣으십시오. 줄은 **[`docs/전달-platform-gate-단계별-한-줄.txt`](전달-platform-gate-단계별-한-줄.txt)** 에 있습니다.

★★ **단계마다 줄이 다릅니다.** 아직 없는 검사 파일을 부르면 게이트가 깨집니다 —
반드시 그 단계의 줄을 쓰십시오.

## 합치신 뒤 — 한 번 더 하실 일

앱 본체는 GitHub 이 **자동으로 안 올립니다.** 맥에서 두 줄입니다:

    git pull
    python3 deploy-filestation.py

여기서 대개 막히는 곳: NAS 로그인 토큰(`~/.linkpilot-nas-token`)이 없으면 비밀번호와
OTP 를 묻습니다.

그리고 브라우저가 옛 서비스워커를 들고 있어 **한 박자 늦게** 바뀝니다. 탭을 모두
닫았다 다시 여시면 됩니다.

## 어떻게 쟀나

`platform` 갈래에서 시작해 위 순서로 여섯을 실제로 합쳤습니다. 충돌 셋을 합집합으로
풀고 `npm run gate` 를 돌렸습니다.

★ 도중에 제 실수를 하나 잡았습니다 — 처음 합집합을 계산할 때 `verify-build.js` 뒤의
**인자(`linkpilot-platform.deploy.html`)를 떨어뜨렸습니다.** 그래도 게이트는 초록이었습니다.
「통과했으니 맞다」가 아니라 첫 항목을 눈으로 본 덕에 잡혔습니다. 위 파일의 줄은
인자를 살린 판입니다.
