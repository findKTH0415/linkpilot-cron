# LinkPilot HWPX 보고서 생성·기존 양식 편집 반영 작업지침서

- 버전: v1.0
- 작성일·저장소 확인일: 2026-10-29 · Asia/Seoul
- 적용 위치: LinkPilot → 보고서 만들기
- 적용 대상: 새 한글 보고서 생성, 기존 HWPX 양식의 내용 수정·채우기·검증
- 대상 저장소: `kist-aix/hwpx`, `kangdacool/hwpx-editing-skill`
- 문서 상태: 기획·개발·검수 인수인계용 구현 규격이다. 실제 스킬 설치·앱 코드 변경·HWPX 생성·한글 렌더 검증은 수행하지 않았다.

## 1. 적용 결정과 작업 목표

**새 보고서 생성은 첫 번째 스킬을 기반으로 구성하고, 기존 양식 편집은 두 번째 스킬의 편집·검증 도구를 기반으로 구성한다.** 두 경로를 화면과 서버 작업에서 구분한다.

| 경로 | 기반 저장소 | 맡길 역할 | 주의할 범위 |
|---|---|---|---|
| 새 HWPX 보고서 | [kist-aix/hwpx](https://github.com/kist-aix/hwpx) | 기본 보고서 양식·표 생성의 제작 기반 | 원본 양식 복원·10종 디자인 자동 지원 도구로 간주하지 않음 |
| 기존 HWPX 편집 | [kangdacool/hwpx-editing-skill](https://github.com/kangdacool/hwpx-editing-skill) | 기존 문서의 대상 구간 수정·패키지 보존·검증 기반 | 모든 문서의 서식 무손실을 시험 없이 보장하지 않음 |
| 공통 검증 | 생성 경로의 구조 검사 + 편집 경로의 점검 도구 | 구조·내용·서식·실제 화면 검수 | XML 검사 통과를 시각 검증 완료로 대체하지 않음 |

GitHub의 스킬은 에이전트 지침과 보조 스크립트이다. LinkPilot 회원용 웹 API·권한·작업 큐·편집 화면은 별도로 구현한다. 저장소를 내려받거나 개발자 에이전트에 등록하는 작업만으로 플랫폼 연동 완료라고 표시하지 않는다.

## 2. 확인한 기능과 신규 개발의 경계

첫 번째 저장소는 공공기관 형식의 보고서·표 생성과 보조 도구를 안내하며, 기본 `report` 양식을 사용한다. 첨부 HWPX를 받아도 같은 원본 양식으로 복원하는 기능은 아니다. 두 번째 저장소는 기존 HWPX 편집·구조/서식 점검을 안내하며, 실제 렌더 감사에는 한글 실행 환경이 필요한 도구가 포함돼 있다. 두 저장소의 라이선스 표시는 MIT이다. [S1][S2][S3][S4]

위 내용은 저장소 문서 확인 결과이다. 실제 서버 호환성·성능·완성도는 LinkPilot 환경에서 시험해야 한다. 아래의 화면·데이터·API·템플릿 확장은 **새로 구현할 규격**이다.

### 적용 범위

- 신규 업무보고·회의록·사업 개요·일반 보고서의 HWPX 출력 기반.
- 기관 제출용 HWPX 양식의 지정 필드 채우기와 문장·표 값 변경.
- 결과 파일의 구조·내용·시각 검증 및 원본/변경본 관리.
- 기존 보고서 작성·자료 가져오기·회원 디자인 설정과의 연결.

### 초기 제외·조건부 기능

- 바이너리 `.hwp`를 `.hwpx`로 이름만 바꿔 처리하지 않는다. 초기에는 한글에서 HWPX로 저장한 파일을 받는다.
- 비밀번호·보호·서명·손상·지원하지 않는 개체가 있는 파일은 상태를 진단하고 가능한 편집 범위를 표시한다. 지원 전에는 자동 복구·서명 유지를 약속하지 않는다.
- 브라우저에서 한글 전체 기능을 재현하는 자유 편집기는 초기 범위가 아니다. 필드·본문·표 중심의 편집 화면을 우선한다.
- HWPX→PDF·DOCX 등 변환은 실제 출력 환경의 지원과 검증을 확인한 기능만 노출한다.

## 3. 메뉴·화면 구성

**보고서 만들기 → 한글 문서(HWPX)** 아래에 다음 두 시작 버튼을 둔다.

| 시작 버튼 | 안내 문구 | 이후 화면 |
|---|---|---|
| 새 보고서 만들기 | 보고서 유형과 지원 양식을 선택해 새 문서 작성 | 유형·양식·자료·본문·미리보기 |
| 기존 양식 가져오기 | 내 HWPX 양식을 불러와 필요한 부분만 수정 | 업로드·문서 분석·수정 대상·비교·미리보기 |

- ‘첨부 내용을 참고해 새 보고서 작성’은 첫 번째 경로이다. 원본 양식 유지 기능으로 표시하지 않는다.
- ‘원본 양식 유지’는 두 번째 경로에서 지원 범위와 실제 검수 결과에 따라 안내한다.
- 상단에는 문서명·회원/조직·작업 유형·버전·저장 상태를 둔다.
- 왼쪽에는 목차 또는 수정 대상 목록, 중앙에는 페이지 미리보기, 오른쪽에는 선택 필드·표·스타일 속성을 배치한다.
- 기본 버튼은 자료 가져오기·초안 생성·수정 저장·검사·미리보기·HWPX 다운로드이다.
- 개발 도구명·XML·내부 프롬프트는 일반 회원 화면에 기본 노출하지 않는다.
- 미지원 양식·출력 환경 부재는 선택 불가 사유와 필요한 다음 행동으로 표시한다.

## 4. 경로 선택·오작동 방지

| 회원 의도 | 선택 경로 | 금지 동작 |
|---|---|---|
| 내용으로 새 보고서 작성 | 신규 생성 | 첨부 파일과 같은 양식이라고 오인시키기 |
| 기존 공문 양식의 항목 채우기 | 기존 문서 편집 | 원본을 첫 번째 스킬의 기본 report 양식으로 교체 |
| 표의 금액·기한 수정 | 기존 문서 편집 | 표·머리말·전체 글꼴을 불필요하게 재작성 |
| 회원 디자인으로 전체 재구성 | 별도의 새 문서 생성·지원 템플릿 확인 | 원본 보존 편집으로 표시 |
| HWP 파일 업로드 | 형식 안내·지원되는 변환 경로 확인 | 확장자 변경으로 처리 |

서버는 작업 유형을 `create_new`와 `edit_existing`으로 구분한다. 경로를 바꾸면 새 작업·버전으로 저장하고 양식·내용 영향 범위를 보여준다. 실패 시 다른 경로로 조용히 전환하지 않는다.

## 5. 신규 보고서 생성 절차

1. 문서 유형·제목·작성일·작성 부서·언어·공개 범위를 입력한다.
2. 현재 HWPX 출력이 검증된 양식만 선택하게 한다. 초기 기본 report 양식과 신규 디자인 양식을 구분한다.
3. 프로젝트 정보·자료·표 데이터를 가져오고 사용 필드를 확인한다.
4. 목차·본문·표·주석·출처·회원 브랜딩을 구조화한다.
5. 회원이 확인한 입력을 해당 양식의 문서 요소·스타일에 매핑한다.
6. 첫 번째 저장소 기반 생성 어댑터로 새 HWPX를 만든다.
7. 구조·내용 검사를 실행하고 실제 렌더로 페이지·표·글꼴·줄바꿈을 확인한다.
8. 검사 결과와 미리보기를 제시하고 확정 버전의 파일을 제공한다.

- 날짜는 회원이 선택한 날짜를 우선한다. 자동값을 사용하면 Asia/Seoul 기준의 작성일을 명시한다.
- 제목·날짜·부서 등 템플릿의 샘플 자리표시자가 결과에 남지 않도록 검사한다.
- 파일 내부 스타일 ID는 선택 양식의 정의와 대조해 사용한다. 기존 예시 ID를 모든 양식에 그대로 적용하지 않는다.
- 임의 표·이미지·장문을 넣어도 자동으로 잘 배치된다고 가정하지 않는다. 내용 길이·셀 병합·쪽 나눔을 검수한다.
- 회원 입력이 부족하면 미정값을 구분한다. 실제 수치·기관명·인용문을 만들어 채우지 않는다.

## 6. 기존 양식 편집 절차

1. 업로드 파일의 실제 형식·무결성·회원 접근 권한을 확인한다.
2. 원본을 변경 불가 버전으로 저장하고 해시·파일명·문서 정보를 기록한다.
3. 문서의 구역·문단·표·이미지·각주/미주·머리말/꼬리말·필드 등 편집에 필요한 구조를 분석한다.
4. 수정할 항목을 문서 위치와 연결한다. 중복 문구는 실제 대상 구역·표·셀을 선택하게 한다.
5. 변경 전/후 값과 영향 범위를 보여준다. 대상이 불명확하면 편집을 보류한다.
6. 두 번째 저장소 기반 편집 어댑터로 필요한 요소만 수정하고 새 버전으로 저장한다.
7. 변경 부위와 비변경 부위를 대조하고 구조·참조·내용을 검사한다.
8. 실제 한글 렌더로 표·쪽 나눔·폰트·개체 배치를 확인한다.
9. 변경 요약·검사 결과·미리보기·편집본을 제공한다. 원본을 덮어쓰지 않는다.

### 편집 기준

- 문단·표·셀·필드의 내부 식별자와 문맥을 함께 사용한다. 전역 문자열 치환만으로 편집하지 않는다.
- 단어가 여러 텍스트 요소로 나뉜 경우 표시 문자열과 실제 요소의 관계를 확인한다. 글꼴·서식이 다른 구간을 불필요하게 합치지 않는다.
- 표 값을 바꿀 때 행·열·병합·셀 크기·테두리·배경을 보존한다. 구조를 바꾸는 요청은 별도 변경으로 표시한다.
- 기존 양식 편집에는 신규 디자인의 글꼴·색상·표지 규칙을 일괄 덮어쓰지 않는다. 회원이 요청한 변경만 적용한다.
- 이미지·수식·머리말·각주 등 미변경 자산과 참조를 보존한다. 단순 본문 텍스트만 추출해 전체 문서를 재생성하지 않는다.
- 편집으로 줄배치·참조·번호 캐시의 갱신이 필요한지 채택 버전 지침에 따라 판단한다. 모든 캐시를 조건 없이 삭제하거나 이전 캐시를 무조건 유지하지 않는다.
- 아무 변경도 하지 않은 재저장과 실제 편집의 검수 기준을 구분한다. 실제 편집 후 전체 파일 해시가 원본과 달라지는 것은 정상이며, 변경하지 않은 내용·자산의 보존을 확인한다.

## 7. 기존 10종 디자인 시스템 연결

**10종 디자인 선택과 10종 HWPX 지원은 같은 의미가 아니다.** 기존 앱의 디자인 선택 화면을 연결하되 출력 형식별 실제 지원 상태를 저장한다.

| 디자인 유형 | HWPX 적용 작업 |
|---|---|
| 기업 표준 그리드 | 표준 제목·본문·표·각주 스타일 구현 |
| 부동산·투자 IM | 회원 표지·사업 개요·숫자·출처·도표 배치 구현 |
| 사업계획 캔버스 | 구획·요약 표·사업모델 배치 검증 |
| 공공·정책 보고 | 기본 report 기반 적용과 사용자 문체·폰트 매핑 |
| 데이터 분석 대시보드 | 차트·표의 이미지/편집 개체 제공 범위 구분 |
| 인프라·사업 구도 | 다이어그램·지도·범례·출처 배치 검증 |
| 로드맵·추진 일정 | 일정표·쪽 나눔·반복 머리글 검증 |
| 분양·프로모션 | 강조 숫자·사진·가격/조건 배치 검증 |
| 사진·브로슈어 | 사진 자르기·품질·문자 가독성·개체 배치 검증 |
| 프리미엄 투자제안 | 표지·챕터·고급 제목 스타일·사진 배치 검증 |

- 첫 번째 저장소의 기본 양식은 위 목록 전체를 기본 제공하지 않는다. 추가 양식은 LinkPilot 템플릿 확장과 실제 출력 시험이 필요하다.
- 초기에는 기본 report 경로부터 검증하고, 지원 완료된 유형만 HWPX 선택에 활성화한다. 나머지는 ‘준비 중/미지원’으로 표시한다.
- 미지원 유형을 선택했다고 기본 report로 바꿔 출력하지 않는다. 회원이 지원 양식을 선택하거나 다른 출력 형식을 선택하게 한다.
- 템플릿마다 버전·지원 요소·폰트·검증 샘플·필수 입력·출력 제한을 등록한다.
- 기존 양식 편집에서는 원본 양식이 우선이다. 전체 디자인 변경은 신규 생성 경로로 구분한다.

## 8. 회원 디자인·글꼴·작성 규칙

### 신규 문서·사용자 지정 양식

- 표지·로고는 **[회원 사용자]**의 승인 프로필을 사용한다. PDI를 모든 회원의 공통 브랜드로 넣지 않는다.
- 로고 원본과 투명 배경·어두운 바탕용 변형을 관리한다. 없는 변형을 확보했다고 표시하지 않는다.
- 해당 디자인의 표지는 회색 사진을 기본으로 하고 부분 컬러 강조를 적용한다. 챕터·마지막 페이지의 어두운 배경에서는 글자·로고 대비를 확인한다.
- 설명이 복잡한 구간은 도식화한다. Figma에서 제작한 도표를 쓰면 편집 원본·버전과 출력 자산을 연결한다. 지시선은 겹치지 않게 각도와 간격을 둔다.
- HWPX에 삽입한 도표가 이미지이면 편집 가능한 네이티브 개체라고 표시하지 않는다. 편집 원본을 별도 연결한다.
- 강조할 표 셀은 승인한 배경색·굵기를 적용한다. 문구를 자동 추가해 투자 성과를 과장하지 않는다.

### IM 글꼴 기준

| 요소 | 사용자 지정 기본 크기 |
|---|---|
| 표지 제목 | 18pt |
| 페이지·슬라이드 제목 | 14pt |
| 핵심 숫자 | 10pt |
| 본문 | 12pt |
| 표 안의 글자 | 10pt |
| 각주·표 아래 설명 | 8pt |
| 주석·출처 줄 | 7pt |

- 위 크기는 사용자 IM 기본 규격이다. 모든 공문·외부 양식에 일괄 강제하지 않는다.
- 기본 한국어·숫자·영문은 Paperlogy를 적용하되 실제 폰트 파일·지원 문자·이용 조건·렌더 환경을 확인한다.
- 용도별 영문 강조 후보인 DIN Condensed Bold, Bebas Neue, Anton, Roboto Condensed Bold, Oswald Bold, Montserrat ExtraBold는 실제 확보·라이선스·글리프를 확인한 스타일에만 적용한다.
- 웹 CSS 폰트 선언과 HWPX 내부 스타일은 별도이다. CSS만 지정해 한글 문서에도 적용됐다고 판단하지 않는다.
- PDF의 CIDFont 표기나 별칭을 실제 설치 폰트 파일명으로 간주하지 않는다. 출력 환경에서 실제 사용 글꼴을 확인한다.

### 문체·표 규칙

- 결론–근거–실행–결정 순서와 쉬운 말·간결체를 기본으로 한다. 사용자가 원하는 ‘이다/한다’ 체계를 적용한다.
- 외부 스킬 기본 문체 검사와 사용자 문체가 다르면 LinkPilot 문서 유형별 규칙을 우선한다. 명사형 종결로 강제 바꾸지 않는다.
- 표의 문자·날짜 혼합값·숫자는 **모두 좌측 정렬**을 기본으로 한다. 기존 양식은 원본 유지 요청과 지정된 변경 범위를 따른다.
- 표 안의 문장은 1줄을 우선하고 가용 폭을 사용한 뒤 2줄을 허용한다. 글자 축소로 강제로 넣지 않는다.
- 보고서 본문에서 제작 도구·AI 작업 과정 설명은 제거한다. 도구·검수 기록은 별도 관리한다.
- 자료의 미확인 사실은 지어내지 않는다. 공개용 본문 표현과 내부 검수 기록은 구분하되 중요한 조건·근거를 숨기지 않는다.

- 문서별 격리된 작업 디렉터리·입출력 제한·시간 제한을 둔다. ZIP 경로 탈출·과도한 압축 해제·외부 XML 엔터티를 차단한다.

- 한글 COM 기반 검사는 해당 기능을 지원하는 실행 환경을 별도로 확보한다. 브라우저 미리보기로 자동 대체하지 않는다.

## 10. 구조·내용·시각 검증

### 10.1 구조 검사

HWPX 패키지 규칙과 채택 버전 검사기를 기준으로 필수 파일·XML 유효성·스타일/개체 ID·참조·표 구조를 확인한다. 새 패키지 생성 시 `mimetype`의 위치·압축 방식도 검사한다. 스크립트 이름·옵션은 고정한 실제 버전에서 대조한다.

### 10.2 내용 검사

- 제목·날짜·부서·회원 정보·로고 선택값과 결과가 일치해야 한다.
- 지정한 문장·표 값·단위·출처가 반영됐는지 확인한다.
- 기존 문서의 미수정 문단·이미지·각주·미주·필드가 의도치 않게 사라지지 않아야 한다.
- 템플릿 샘플 문구·자리표시자·편집 지시·원고 중복이 남지 않아야 한다.
- 계산값·합계는 검증된 계산 모듈 결과와 대조한다. 텍스트 모델의 수치 생성으로 대체하지 않는다.

### 10.3 시각 검사

실제 출력된 페이지에서 글꼴 대체·문자 잘림·셀 넘침·행 높이·병합·표 너비·쪽 나눔·빈 페이지·제목 고립·로고/그림 위치·각주·목차 번호를 확인한다. 원본과 편집본의 대응 페이지를 비교하되 수정 때문에 페이지 수가 변할 수 있음을 구분한다.

### 검증 결과 상태

| 상태 | 의미·허용 행동 |
|---|---|
| 구조 검사 실패 | 완료 표시 금지. 오류 위치·원인·수정 필요 항목 제시 |
| 구조 통과·시각 미검증 | 구조 검사 결과만 표시. 실제 화면 검증 완료로 표시 금지 |
| 시각 문제 발견 | 수정 대상으로 표시하고 확정본 배포 보류 |
| 전체 검사 통과 | 검사한 버전과 범위에 한해 다운로드 제공 |

시각 검증 환경이 없으면 ‘시각 미검증’임을 명확히 알린다. 내부 시험본은 권한 있는 담당자에게 구분 제공할 수 있지만, 미검증 결과를 검증된 제출본으로 자동 발행하지 않는다. 무기한 대기 대신 원본·편집 계획·오류 상태·재개 조건을 제공한다.

## 11. 변경 비교·저장·다운로드

- 원본은 변경 불가 버전으로 유지한다. 결과는 새 버전·새 파일로 저장한다.
- 변경 목록에는 문서 위치·변경 전/후·요청자·입력/양식 버전·작업 시각을 기록한다.
- 미리보기는 다운로드 대상과 같은 HWPX 버전에서 생성한다. 수정 후 이전 미리보기를 최신으로 보여주지 않는다.
- 파일명은 문서명·버전·날짜로 구분하고 회원 개인 정보의 불필요한 포함을 피한다.
- 기본 제공 항목은 편집 가능한 HWPX와 변경 요약·검사 결과이다. PDF·페이지 이미지는 실제 생성·검증됐을 때 제공한다.
- HWPX만 성공하고 요청한 PDF가 실패하면 파일별 완료/실패를 구분한다. 전체 산출물 완료로 표시하지 않는다.
- 다른 회원의 원본·결과·임시 파일·다운로드 링크에 접근할 수 없게 한다. 공유 문서는 실제 공유 권한을 따른다.
- 재시도는 입력·원본·템플릿 버전과 작업 식별자를 확인한 뒤 실행한다. 늦은 응답이 최신 결과를 덮어쓰지 않게 한다.

| HX-21 | 목차·상호참조·쪽 번호 | 실제 출력에서 참조와 번호 일치 |
| HX-22 | 취소·재시도·동시 수정 | 중복 실행·최신 결과 덮어쓰기·원본 손상 없음 |
| HX-23 | 회원 간 파일 접근 | 원본·결과·임시 자산·다운로드 권한 분리 |
| HX-24 | 산출물 부분 실패 | HWPX/PDF 등 파일별 상태와 재개 방법 표시 |

각 시험은 문서 샘플·도구/템플릿·한글 버전·OS·폰트·수행자·일시·결과·미해결 문제를 기록한다. 샘플은 단순 문서·병합 표·다중 구역·그림/각주·장문 등 실제 지원 범위를 대표하도록 정한다. 이 문서 작성으로 24개 시험이 실행된 것은 아니다.

## 15. 완료 기준·현재 작업 범위

### 개발 완료 기준

1. 새 보고서와 기존 양식 편집이 다른 경로로 동작해야 한다.
2. 기본 양식의 새 HWPX를 생성하고, 기존 문서의 지정 항목을 원본 보존 방식으로 수정할 수 있어야 한다.
3. 구조·내용·시각 결과를 구분하며, 검사한 파일과 다운로드 파일이 같은 버전이어야 한다.
4. 회원 로고·글꼴·문체·표 정렬과 기존 양식 보존 규칙을 요청 범위에 맞게 적용해야 한다.
5. 미지원 양식·미검증 출력·오류·부분 실패를 숨기지 않고 재개 조건을 제공해야 한다.
6. 원본·변경 비교·검사 결과·권한·도구 버전을 추적할 수 있어야 한다.

### 본 지침서 작성 시 완료한 범위

GitHub 공개 문서·스킬 안내의 적용 범위를 대조하고, LinkPilot의 신규 생성/편집·디자인·검증·개발 순서·검수 규격을 정리했다. 스킬을 설치하거나 실제 HWPX 파일을 제작·편집한 것은 아니다. 현재 앱 소스·회원 양식·폰트·한글 실행 환경이 제공되지 않았으므로 구체 구현 경로와 실제 호환성은 개발 착수 시 확인한다.
