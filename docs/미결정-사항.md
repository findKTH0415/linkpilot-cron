## C. 보안 · 운영

### 🔴 D-10. 저장소 공개 범위

**현재 public.** 본문의 내부 NAS 주소는 크론 삭제(D-18)로 함께 사라졌으나
**git 이력에는 그대로 남아 있다.** CLAUDE.md §2 위반 상태가 해소되지 않았다.

- [ ] private 전환 (가장 확실)
- [ ] public 유지 (이력은 남음 — 위험 감수)
- [ ] public 유지 + 이력 재작성 (되돌릴 수 없음, 협업자 재클론 필요)

> 이력에는 tailnet 주소·내부 IP뿐 아니라 **개인 휴대폰 번호와 실명**도 남아 있다

### 🔴 D-12. Secret 등록

`TS_OAUTH_CLIENT_ID`/`TS_OAUTH_SECRET` · `NAS_SSH_HOST`/`NAS_SSH_USER`/`NAS_SSH_KEY` ·
`ALERT_PHONE` · `VWORLD_KEY` · `DATA_GO_KR_KEY` — 전부 미등록.
값은 **GitHub Secrets 에만** 넣는다. 채팅·문서·커밋에 붙여넣지 않는다.

> 크론 삭제로 `GEMINI_API_KEY`·`SOLAPI_*`·`FRIENDS_URL`·`RECIPIENTS`·`ONLY_TO`·
> `NAS_BASE_URL`·`CARD_*`·`SENDER_PHONE`·`LAW_*` 는 **이 저장소에서 불필요해졌다.**
> 크론을 옮길 저장소가 정해지면 그쪽으로 옮기고 여기서는 삭제한다.

## F. 크론 이관

### 🔴 D-20. 배포된 지침이 약속한 기능이 저장소에서 사라졌다

`catalog.js` 와 **협력사 배포 지침 §2** 는 `오늘의 한줄생각`·`아침브리핑` 을
유료 기능으로 적어 두었다. 구현은 D-18 로 이 저장소에서 삭제되었다.

지금은 `main` 의 크론이 돌고 있어 기능이 살아 있다. **PR #3 이 병합되는 순간
지침과 실제가 갈린다** — 협력사가 "된다고 적혀 있는데 안 된다"고 문의한다.

- [ ] D-19 에서 이관 → 카탈로그·지침 그대로 둔다
- [ ] 이관하지 않는다 → **카탈로그에서 두 기능을 빼고 지침을 재발행한다**
      (화면에서 지우는 것만으로는 끝나지 않는다 — 지침은 이미 협력사 손에 있다)

### 🟠 D-19. 아침 크론을 어디로 옮기는가

D-18 로 이 저장소에서 삭제했다. **삭제일 뿐 이관이 아니다** — 옮길 곳이 없으면
브리핑 기능 자체가 사라진다.

- [ ] 새 저장소로 이관 → 이름: ________________
- [ ] 이관하지 않는다 (브리핑 서비스 종료)
- [ ] 본체(NAS n8n)로 되돌린다

옮길 때 함께 가져가야 하는 것: CLAUDE.md §1·§3·§4(참고용으로 남겨 두었다) ·
Secret 10종 · `git log --diff-filter=D` 로 복원한 파일 6개 · 워크플로 4개.
