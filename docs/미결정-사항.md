### 🟠 D-22. 차입금리를 기준금리 + 스프레드로 만들 것인가

| 지금 | 바꾼다면 |
|---|---|
| `debt.rate` = 산업 통상치 (출처 없음) | `debt.rate` = 기준금리(출처 있음) + 스프레드(가정치) |

### 🟡 D-39. 조감도에 주변 맥락을 넣을 것인가

지금 조감도는 **대상 필지와 매스만** 그린다. 인접 필지·도로·기존 건물은 그리지 않는다.

- 넣으면 입지가 훨씬 잘 읽힌다 (연속지적도로 인접 필지를 받을 수 있다).
- 대신 **호출이 는다** (§4.5) — 필지 하나가 아니라 주변 반경을 받아야 한다.
- 그리고 **기존 건물 높이는 우리가 모른다.** 건축물대장을 인접 필지마다 부르면
  호출이 몇십 배가 된다. 높이를 짐작해서 그리면 그 순간 조감도가 지어낸 그림이 된다.

- [ ] 대상 필지만 (지금) · [ ] 인접 필지 경계선까지 (높이 없이) · [ ] 주변 건물 높이까지

> **두 번째가 절충안이다.** 인접 필지 **경계선만** 회색으로 깔면 입지는 읽히고
> 높이를 지어내지 않는다. 호출은 연속지적도 한 번 더면 된다.

### 🟠 D-40. 제조 재무 템플릿의 기본값이 추측이다

「제조 = 일반 프로젝트」가 틀렸다는 지적(2026-08-16)을 받고 `manufacturing`
템플릿을 새로 만들었다. **부동산과 갈리는 지점은 분명하다** — 부동산은 임대료를
받고 Cap Rate 로 팔지만, 제조는 물건을 팔고 나가는 돈의 대부분이 원재료비다.

**그런데 숫자는 확인받지 못했다.** 업종마다 크게 갈린다 (조립 vs 장치산업).

|---|---|---|---|

### 🔴 D-43. 생산자물가 통계표코드·항목코드를 실제 키로 대조하지 못했다

D-42 의 1번을 붙이면서 `404Y014`(생산자물가지수 기본분류)·주기 `M` 을
**공식 문서 기준으로** 넣었다. 실제 키로 부른 적이 없다.

**틀리면 어떻게 나타나는가**는 두 갈래인데, 한쪽이 훨씬 위험하다.

| 무엇이 틀렸나 | 증상 |
|---|---|
| 통계표코드가 없거나 폐기됨 | `ppiItems()` 가 「항목이 없다」로 막는다 — **눈에 띈다** |
| 코드는 살아 있는데 **분류가 다름** | 업종 목록이 나오고 계수도 나온다. 사람이 「기타 기계 및 장비」인 줄 알고 고른 항목이 실제로는 다른 분류일 수 있다 — **문서에는 「시점수정 적용」만 남는다** |

두 번째는 조용히 틀린다. 그래서 실측 전까지 이 계수를 IM 에 자동으로 싣지 않는다
(§4.8 의 반대편 — 공표 통계라도 어느 통계표인지 확실하지 않으면 근거가 아니다).

- [ ] `npm run im:smoke` 출력 (업종 목록에 기대한 업종명이 실제로 있는지)
- [ ] `npm run im:smoke -- --ppi-item <항목코드>` 출력 (계수·기준시점)

> 확인 순서: 업종 목록에서 **딜 업종에 해당하는 이름**을 찾는다 → 그 코드로
> 계수를 뽑는다 → ECOS 웹 화면의 같은 표와 **양 끝 지수 두 개를 눈으로 대조한다.**
> 계수만 보면 맞는지 알 수 없다 — 그럴듯한 값이 나오기 때문이다.

### 🔴 D-44. KOSIS 키가 없고, 엔드포인트·통계표를 실측하지 못했다

D-42 의 2번(제조업 가동률)을 붙였다. **가동률은 지금 재무모델에서 근거가 0인
숫자**다 — 사업계획서가 「85%」라고 하면 그대로 들어가고, 85% 와 70% 는 매출을
20% 넘게 흔든다.

**막힌 것이 둘이다.**

**① 키가 없다.** `KOSIS_API_KEY` 는 kosis.kr 공유서비스에서 **따로 신청·발급**
받는다. ECOS·부동산원·data.go.kr 키와 통용되지 않는다 (§4.1).

- [ ] kosis.kr 공유서비스 신청 → 발급된 키를 Secrets 에 등록 (D-12 와 함께)

**② 엔드포인트·통계표가 문서 기준이다.** KOSIS 는 표가 수천 개고 이름이 겹친다.
그래서 표를 코드에 박지 않고 `tables()` 로 후보를 내 사람이 고르게 했다.
검색·메타·자료 세 엔드포인트의 응답 필드가 아직 실제 응답과 대조되지 않았다.

- [ ] `npm run im:smoke` (통계표 검색이 도는가)
- [ ] `npm run im:smoke -- --kosis-tbl <통계표ID>` (항목 목록 + **단위**)
- [ ] `npm run im:smoke -- --kosis-tbl <ID> --kosis-item <항목코드>` (평균 대조)

> ⚠️ **이 작업이 돌아간 환경에서는 kosis.kr 이 망 정책으로 막혀 있다.** 더미 키로
> 스모크를 돌리면 `HTTP 403 (재시도 무의미)` 이 나오는데, 이것은 **KOSIS 의 응답이
> 아니라 프록시의 차단**이다. 둘을 구분하지 않으면 「키가 틀렸다」로 읽고 엉뚱한
> 곳을 고치게 된다. 실측은 **사용자 쪽 환경에서만** 가능하다.
> (확인된 것: 실패해도 예외를 던지지 않고 `{ok:false}` 로 격리된다 — §4.6)

**③ 고를 때 반드시 볼 것 — 「지수」인가 「%」인가.**

광업제조업동향조사는 **가동률지수(2020=100)** 와 **제조업 평균가동률(%)** 을
둘 다 낸다. 이름이 비슷하고 **숫자도 같은 자리(70~110)에 있다.**

| 고른 것 | 결과 |
|---|---|
| 평균가동률 (%) | 「이 딜의 85% 는 업종 평균 73% 보다 12%p 높다」 — 맞다 |
| 가동률지수 (2020=100) | 「가동률 102%」. **물리적으로 불가능한데 표에서는 그럴듯하다** |

커넥터가 단위를 읽어 성격이 다르면 **견주기를 거부**하지만, 그 판정은 응답의
`UNIT_NM` 에 의존한다. 단위 표기가 예상과 다르면 `unknown` 이 되어 대조가 통째로
빠진다 — **조용히 틀리지는 않지만 조용히 비긴 한다.** 스모크 출력의
`[단위→성격]` 이 전부 `unknown` 이면 그 판정 규칙을 실제 표기에 맞춰야 한다.

> **개별 공장의 가동률은 공적으로 나오지 않는다.** 나오는 것은 업종 평균뿐이다.
> 그래서 이 커넥터는 **값을 채우지 않고 대조만 한다** — fact 로 등록하지 않는다.
> 「가동률은 73% 다」로 쓰면 딜의 고유 조건이 사라진다.

### 🔴 D-45. 공장등록 — 제공 기관이 미확정이고 활용신청이 안 되어 있다

D-42 의 3번을 붙였다. 제조 딜에서 **건축물대장 격**이다 — 「연 12만톤을 만든다」는
주장이 앉을 수 있는 물리적 상한이 여기서 나온다.

**막힌 것이 셋이다.**

**① 어느 기관 자료인가.** 유사 자료가 두 곳에 있다 — **공장설립온라인지원시스템
(팩토리온)** 과 **한국산업단지공단**. 수록 범위와 필드가 다를 수 있다.

- [ ] data.go.kr 에서 실제 제공 API 확인 → 기관·엔드포인트 확정

**② 활용신청.** `DATA_GO_KR_KEY` 는 이미 있지만, **키가 유효해도 신청하지 않은
API 는 거부된다** (§4.2). 증상이 「키가 틀렸다」와 구분되지 않으므로 응답 본문을 본다.

| 응답 | 뜻 |
|---|---|
| `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` (30) | 그 API 에 활용신청이 안 됨 |
| `NO_OPENAPI_SERVICE_ERROR` (12) | 엔드포인트가 없거나 폐기됨 |

- [ ] 해당 API 활용신청 → `npm run im:smoke -- --factory-name <상호>`

**③ 응답 필드가 문서 기준이다.** 특히 **면적 필드명**이 그렇다.

**면적을 뭉치지 않는 것이 이 커넥터의 전부다.** 공장등록에는 면적이 넷 실린다.

| 면적 | 무엇 | 쓰임 |
|---|---|---|
| 용지(부지)면적 | 공장이 앉은 땅 전체 (주차장·녹지 포함) | **생산능력 근거로 쓰면 안 된다** |
| 건축면적 | 건물이 땅을 덮은 넓이 | 건폐 확인 |
| **제조시설면적** | 실제로 제조가 일어나는 시설 | **생산능력은 이것으로 논한다** |
| 부대시설면적 | 창고·사무동·후생시설 | 더해서 「공장면적」으로 뭉치지 않는다 |

용지면적은 제조시설면적의 **보통 두세 배**다. 바꿔 쓰면 상한이 세 배로 부풀고
문서에는 「공장등록 기준」이라고만 남는다. 그래서 코드는 `area` 라는 이름의 필드를
아예 만들지 않고, 종류를 지정하지 않으면 꺼내 주지 않는다.

**필드명이 실제와 다르면 면적이 통째로 `없음` 으로 나온다.** 조용히 틀리지는
않지만(0 으로 그리지 않는다) **조용히 비긴 한다** — 스모크 출력에서 네 면적이
전부 `없음` 이면 필드명을 실제 응답에 맞춰야 한다.

> **부수 효과 — 공부끼리의 대조.** 공장등록 용지면적과 건축물대장 대지면적은
> 같은 필지를 말하는데 값이 다를 수 있다. `crossCheckLand()` 가 그 차이를
> 드러내되 **어느 쪽이 맞다고 말하지 않는다** (§4 첫머리·§4.9).
>
> **업종코드(한국표준산업분류)도 함께 받는다** — D-44 의 KOSIS 업종을 고를 때
> 근거가 된다. 다만 **자동으로 연결하지 않는다.** 분류 체계가 같다는 보장이 없다.

### 🔴 D-46. 수출입 단가 — 월별 값이 단월인가 연초 누적인가

D-42 의 4번을 붙였다. 단가에 붙는 **두 번째** 출처다 — 생산자물가(D-43)는

### 🔴 D-47. 환경 인허가 — 세 자료 미검증, 배출권 명단은 API 가 아닐 수 있다

D-42 의 5번을 붙였다. **D-42 는 이로써 전부 붙었다.**

앞의 넷은 숫자를 견줬다. 이것은 **사업이 성립하는지**를 본다 — 통합환경허가가
없으면 가동을 못 하고, 배출권 할당대상인데 그 비용이 원가에 없으면 재무모델이
통째로 낙관적이다.

**① 이 항목의 위험은 앞의 넷과 반대 방향이다.**

숫자는 없으면 비우면 된다 — 빈칸은 빈칸으로 보인다.
**딜브레이커는 없는 것이 「문제 없음」처럼 보인다.**

| 조회 결과가 빈 것을 | 결과 |
|---|---|
| 통과로 읽으면 | 진짜 결격을 놓친다 |
| 결격으로 읽으면 | 멀쩡한 딜을 죽인다 |

둘 다 조용히 일어난다. 그래서 판정을 **넷**으로 두었다 — 「확인됨」·「기록 없음」·
**「확인되지 않음」**·「대상 아님」. 뒤의 둘 중 「확인되지 않음」을 통과로 세지 않고,
「대상 아님」은 **사람만 붙일 수 있다**(대상 여부는 업종·규모로 정해지는데 그
판단을 커넥터가 할 수 없다).

**② 배출권 명단은 고시(告示)로만 나올 수 있다.**

할당대상업체 명단이 API 로 제공되지 않으면 이 항목은 **영구히 「확인되지 않음」**
이다. 그것을 모른 채 두면 「왜 항상 모름이지」를 반복해서 조사하게 된다.

- [ ] data.go.kr·환경부에 배출권 할당대상 API 가 있는지 확인
- [ ] 없으면 → 고시 PDF 를 사람이 확인하는 절차로 둘지 결정

**③ 나머지 두 자료도 미검증이다.**

- [ ] 통합환경허가 (통합환경허가시스템) API 제공 여부·엔드포인트
- [ ] 대기·수질 배출시설 신고 API 활용신청 + 응답 필드
- [ ] `npm run im:smoke -- --enviro-name <상호>` 출력

> **낼 수 있는 말은 「사람이 확인해야 한다」까지다.** 조회 결과가 비는 이유가
> 넷인데(① 정말 미허가 ② 대상 아님 ③ 다른 법인명 ④ 자료 수록 범위 밖) 우리는
> 가리지 못한다. **「결격」이라고 단정하지 않는다.**
>
> **배출권 비용은 내지 않는다** — 부족분과 배출권 가격이 둘 다 가정이다.
> 「할당대상이다」까지만 낸다 (§4.8 · D-25 와 같은 자리).

| `rule` | institutional · private_equity · corporate · minimal · infrastructure · government · custom |
| `split` | global_ib · technology |
| `fullImage` | real_estate · premium · renewable · luxury |

밀도도 `normal`·`compact`·`airy` 로 갈라 두었다. **그런데 `design/a4.js` 는 `T.cover`
도 `T.density` 도 읽지 않는다** (`layouts`·`emphasisKpis`·`chart` 도 마찬가지).
쓰는 것은 색과 글꼴뿐이다.

즉 **고를 수 있는 것은 색 팔레트 13개이지 디자인 13개가 아니다.**
지금은 그 사실을 화면에 적어 두었다 — 안 적으면 사람은 13종 중에 골랐다고 믿는다.

- [ ] 표지 3종(rule·split·fullImage)을 실제로 갈리게 한다
      (`fullImage` 는 표지 이미지 슬롯이 필요하다 — Pexels 와 이어진다)
- [ ] 밀도 3종을 여백·자간에 반영한다
- [ ] 지금대로 색만 갈리게 두고, 테마 선언에서 `cover`·`density` 를 **뺀다**
      (선언만 있고 안 쓰이는 것이 더 나쁘다)

**② 한글 글꼴이 없어 견본 활자가 최종본과 다르다.** → D-52

**③ 표지에 이미지를 넣을 자리가 없다.** `a4.cover()` 의 인자에 이미지가 없다.
`fullImage` 테마 4종은 그래서 구조상 불가능하다. Pexels 로 받은 참고 이미지도
표지에 못 들어간다.

- [ ] 표지 이미지 슬롯을 만든다 (D-50 의 「내부 검토본까지만」이 함께 걸린다)

> **추천은 강제하지 않는다.** 화면은 딜(자산유형)을 줄 때만 추천 순위와 **근거**를
> 붙이고, 안 주면 아예 안 붙인다 — 딜을 모르는 채 특정 추천을 박아 두면
> **다른 딜에서 틀린 추천이 그럴듯하게 붙는다.**

### ✅ D-52. 한글 글꼴이 없어 문서가 서버마다 다르게 나온다 〈2026-08-16 — 조용한 대체를 없앴다〉

임베드된 폰트: LiberationSans · WenQuanYiZenHei · LiberationSerif · DejaVuSansMono

**디자인 검사는 통과한다.** `design/check.js` 는 HTML 의 `font-family` 문자열만

### ✅ D-53. `formats: ['pdf']` 라고 선언하는데 PDF 가 안 나온다 〈2026-08-16 — 붙였다〉

`core/outputspec.js` 는 모든 문서 종류에 `formats: ['pdf']` 를 선언한다. 그런데
실제 산출물은 `09_IM/im.md` 와 `12_Final/im-a4.html` 까지다 — **PDF 는 어디서도
만들어지지 않는다.**

**이미 있는 것으로 된다.** 헤드리스 크로미움(`core/raster.js` 가 이미 쓴다)에
`--print-to-pdf` 를 주면 그만이고, `design/a4.js` 는 이미 `@page` 로 인쇄 기하를
소유한다. 실측했다 — **24페이지 PDF 가 그대로 나왔다. 새 의존성 0.**

- [x] **`core/pdf.js` + 파이프라인 배선.** `12_Final/im-a4.pdf` 가 나온다.
      **새 의존성 0** — 이미 쓰는 헤드리스 크로미움이다
- [x] **쪽수를 세어 사양과 견준다.** 막지는 않는다 — 사양은 목표이고 쪽수는
      내용이 정한다. 다만 크게 벗어나면 빠진 절이 있다는 신호다
      (지금 데모: 24p / 최소 30p → 경고)
- [x] **브라우저 기본 머리말·꼬리말을 끈다.** 기본값은 **파일 경로와 날짜**를
      페이지마다 찍는다 — 대외 문서에 로컬 경로가 나가면 안 된다 (§2 와 같은 줄)

**붙이면서 잡은 것:** 로그가 `→ 12_Final/im.pdf` 라고 **손으로 적은 이름**을
찍고 있었는데 실제 산출은 `im-a4.pdf` 였다. 경로를 실제 결과에서 만들게 고쳤다 —
화면만 옛말을 하는 자리다.

### ✅ D-54. 변전소 거리를 낼 좌표가 공개되지 않는다 〈결정됨 2026-08-16 — (다) 둘 다〉

데이터센터·풍력·태양광 딜에서 요구된 것은 **「사업지 ↔ 한전 변전소 거리」와
「전력계통 여유」** 두 가지다. 한전 쪽을 조사한 결과 **둘의 사정이 서로 다르다.**

**① 여유용량은 나온다.** `한국전력공사_분산전원연계정보`(공공데이터포털
15147381)가 **선로별 여유용량·접속정보**를 준다. 다만 **인증키가 다르다** —
공공데이터포털에 올라와 있어도 실제 인증은 **전력데이터개방포털
(`bigdata.kepco.co.kr`) 자체 발급키**다. `DATA_GO_KR_KEY` 로는 안 된다(§4.1
「기관마다 키가 다르고 서로 통용되지 않는다」에 새 행이 는다).

**② 거리는 못 낸다.** `한국전력공사_지역별 공급가능 변전소 정보`(15128065)는
**변전소 좌표를 비식별 처리한다** — 국가중요시설이라는 이유다. 공개되는 것은
**행정구역 단위로 「공급 가능한 변전소가 있다/없다」**까지다. 즉 **거리를 계산할
좌표 자체가 없다.** `변전설비현황`(15101530)도 지역본부별 **집계**라 개별 변전소가
아니다.

**그래서 「N km」를 자동으로 적을 방법이 없다.** 여기서 갈린다:

- [ ] (가) 거리를 포기하고 행정구역 단위로만 적는다
- [ ] (나) 거리만 사람이 넣고 여유용량 조회는 안 붙인다
- [x] **(다) 둘 다 — 나오는 것은 자동으로, 거리는 사람이** (2026-08-16 사용자 결정)

**붙였다** (`connectors/kepco.js`):

- [x] **`capacity({region})`** — 선로별 여유용량. 지역을 특정하지 못하면 **부르지
      않는다** (전국 값으로 대체하면 문서에는 「적용됨」만 남는다, §4.9)
- [x] **`headroom(rows, needMw)`** — 변전소·주변압기·배전선로 **셋 중 최소값**과
      견준다. 가장 큰 것만 보면 통과처럼 보인다
- [x] **`substationDistance()` 는 거절한다.** 값을 내려고 둔 함수가 아니라
      **못 내는 이유를 코드가 들고 있으려고** 둔 것이다 — 없으면 「아직 안
      붙였나 보다」로 읽히고 언젠가 누가 좌표를 짐작해 채운다
- [x] **`humanDistance()`** — 사전검토 회신값을 받되 **직선/선로 기준을 밝히지
      않으면 받지 않는다**
- [x] 가이드 필드 5개 (`crosscheck.grid_region` · `substation_name` ·
      `substation_km` · `substation_km_basis` · `grid_reviewed_at`)
- [x] **데이터센터 자산군 + 태양광 템플릿** 양쪽에 배선. 태양광은 자산군이
      아예 없어(`CLASSES` 에 없다) 자산군에만 달면 **정작 계통이 가장 중요한
      딜에서 안내가 빠진다** — `TEMPLATE_CROSSCHECKS` 를 새로 뒀다

⚠️ **풍력은 아직 안 된다.** 자산군도 재무 템플릿도 없어 `generic` 으로 떨어지고,
붙이려면 재무 템플릿부터 만들어야 해서 이번 범위 밖이다. `crosscheck-wiring.test.js`
가 **「풍력은 아직 묻지 않는다」를 테스트로 박아** 두었다 — 「붙였다」고 적어 두고
실제로는 안 뜨는 것을 이 저장소가 이미 한 번 겪었다 (D-48).

**어느 쪽이든 지켜야 하는 것 셋** (코드에 박았다):

1. **직선거리 ≠ 선로거리** (실무상 1.3~2배). 거리를 적더라도 **인입 공사비는
   내지 않는다** — 단가가 가정이다 (§4.8, D-25 태양광 발전량과 같은 자리).
   `humanDistance()` 가 `cost: null` 과 그 사유를 함께 돌려준다
2. **여유용량은 시점 스냅샷이다.** 접속 대기열이 실재한다 — 보령 해상풍력은
   **2032년 이전 접속 불가** 통보를 받았다. 조회 시점의 여유가 「접속 가능」을
   뜻하지 않는다. **대조값이지 확정값이 아니다** — 판정 문구에 그 말을 박았고
   캐시 TTL 도 하루로 짧게 잡았다(접속 신청이 들어오면 줄어든다)
3. **「확인 안 됨」이 「문제 없음」이 되면 안 된다.** `enviro.js` 의 네 갈래
   판정을 그대로 쓴다 (CONFIRMED / SHORT / UNKNOWN / NOT_APPLICABLE).
   여유가 모자란 것은 **실패가 아니라 결과**라 `needs_review` 로 남긴다 —
   `failed` 로 두면 딜브레이커가 통신 오류처럼 보인다

> **이 환경에서는 실측할 수 없다.** `home.kepco.co.kr` · `bigdata.kepco.co.kr` ·
> `www.kepco.co.kr` · `www.data.go.kr` 전부 **망 정책으로 차단**(000/EGRESS_BLOCKED)
> 이다. 위는 공개 문서로 확인한 것이고, **응답 필드는 아직 실측 전이다** (§4.3).
