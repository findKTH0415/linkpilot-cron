# 한국어 AI 표현 교정 업무지침서
## im-not-ai 참고 · 사업제안서·IM·보고서 적용판 v1.0

- 작성일: 2026-10-27
- 적용 대상: 사업제안서, 투자설명서(IM), 금융기관 제출자료, 사업성 검토보고서, 업무협의문
- 문서 성격: im-not-ai의 윤문 취지를 참고해 별도로 작성한 실무 지침
- 적용 방식: 작성·교정 담당자 및 AI에 본 지침과 검토 원문을 함께 제공
- 유의사항: 공식 스킬 원문·설치 패키지가 아니며, 파일 다운로드만으로 스킬이 설치되지는 않는다.

## 1. 업무 목적

읽는 사람이 사업구조와 판단사항을 바로 파악하도록 한국어 문장을 정리한다. 불필요한 수식어와 반복을 줄이고, 사업주체·행위·조건·시점을 명확히 쓴다.

문체 교정과 내용 보완은 구분한다. 근거 확인이나 계산이 필요한 사항은 별도 검토항목으로 남긴다.

## 2. 적용 우선순위

1. 원문에 기재된 권리·의무·조건과 사실관계
2. 금액·단위·기간·수익률·계산식·출처
3. 사용자가 지정한 제출처·문서 목적·문체
4. 문장 간 논리와 전문용어 일관성
5. 자연스러운 표현과 간결성

표현을 줄이면서 조건이나 예외가 사라지면 원문을 유지한다. 계약상 문구를 바꿔야 할 때는 교정안에 바로 반영하지 않고 확인사항으로 분리한다.

## 3. 교정 대상

| 점검 항목 | 처리 기준 |
|---|---|
| 추상적 표현 | 실제 사업·업무 내용으로 구체화하되 원문에 근거가 없으면 확인 요청 |
| 과도한 수식 | 최고의, 혁신적인 등 객관적 근거 없는 표현 삭제 또는 조정 |
| 반복 문장 | 같은 내용을 반복하는 문장만 통합 |
| 번역투 | 조사·어순·주술관계를 한국어 문맥에 맞게 정리 |
| 명사 나열 | 누가 무엇을 하는지 드러나는 문장으로 전환 |
| 불명확한 주어 | 원문에서 주체를 확인할 수 있을 때만 명시 |
| 연결어 과다 | 또한·아울러·더불어 등을 필요한 위치에만 사용 |
| 기계적인 구성 | 의미 없는 동일 형식의 나열을 줄이고 정보의 관계에 맞게 배치 |
| 전문용어 혼용 | 같은 개념은 같은 용어로 표기 |
| 불필요한 자체 설명 | 작성 과정·AI 역할 설명을 본문에서 제외 |

특정 단어를 일괄 삭제하지 않는다. 문맥상 필요한 전문용어와 자연스러운 표현은 유지한다.

## 4. 사업·금융 문서의 보존사항

다음 항목은 교정 전후 대조표에 등록한다.

- 법인명, 사업명, 소재지, 지번, 인허가 명칭
- 금액, 통화, 부가세 포함 여부, 면적, 전력용량, 비율
- 계약금·중도금·잔금, 지급시점, 지급조건, 해제조건
- PF, LTV, LTC, DSCR, IRR, NPV, CAPEX, OPEX 등 약어와 산정 기준
- 가정값·추정값·확정값의 구분
- 선행조건, 담보순위, 보증범위, 상환재원
- 법령 인용, 출처, 기준일, 직접 인용문

‘협의 중’을 ‘확보’로, ‘검토 가능’을 ‘승인 예정’으로 바꾸지 않는다. ‘목표 수익률’을 ‘보장 수익률’로 바꾸지 않는다. 불확실성을 나타내는 표현은 판단에 영향을 주므로 임의로 삭제하지 않는다.

## 5. 문서별 작성 기준

| 문서 | 권장 표현 |
|---|---|
| 사업제안서 | 제안사항·사업구조·협의조건·요청사항 중심 |
| IM | 투자대상·자금용도·수익구조·회수방안·주요 전제 중심 |
| 금융기관 제출자료 | 차주·대출금액·상환재원·담보·선행조건 중심 |
| 검토보고서 | 판단·근거·확인 필요사항·후속조치 중심 |
| 업무협의문 | 상대방 조치사항·담당자·회신기한 중심 |

본문은 ‘한다’ 또는 ‘합니다’ 중 한 형식을 선택한다. 표·요약문은 ‘검토 필요’, ‘협의 진행 중’ 등의 간결한 표현을 사용할 수 있다. 간결성을 이유로 모든 문장을 명사형으로 바꾸지 않는다.

## 6. 문단 구성

새로 작성하는 요약문은 아래 순서를 기본으로 한다.

1. 결론: 제안하거나 판단할 사항
2. 근거: 판단을 뒷받침하는 확인된 자료
3. 실행: 필요한 조치와 담당 주체
4. 결정: 승인·협의·확인할 사항과 시점

기존 문서의 윤문에서는 원문의 목차와 논리 순서를 우선한다. 구조를 바꿔야 할 경우 별도 재구성안으로 제시한다. 근거가 없는 결론·실행계획·기한을 새로 만들지 않는다.

## 7. 업무 절차

### 7.1 접수

- 원문을 보존하고 작업본을 별도로 만든다.
- 제출처, 목적, 문체, 교정 범위를 확인한다.
- 표·각주·별첨도 검토 범위에 포함되는지 기록한다.

### 7.2 진단

문제 문장마다 위치, 문제 유형, 수정 이유를 기록한다. 수정할 필요가 없는 문장은 유지한다.

### 7.3 교정

- 한 문장에는 핵심 판단이나 행위를 분명히 담는다.
- 긴 문장을 나눌 때 조건과 적용 대상을 함께 옮긴다.
- 열거사항의 상하관계와 조건·결과 관계를 보존한다.
- 오탈자처럼 보여도 금액·회사명·날짜는 근거 없이 수정하지 않는다.

### 7.4 대조 검증

교정본을 원문과 문장 단위로 비교한다. 숫자뿐 아니라 부정문, 조건문, 예외, 가능성 표현을 함께 확인한다. 판단이 달라지면 해당 문장을 원복하고 확인사항으로 남긴다.

### 7.5 제출

최종 교정본, 주요 변경표, 확인 필요사항을 구분해 제출한다. 변경내역과 검토 메모는 외부 제출용 본문 밖에 둔다.

## 8. 교정 예시

아래는 지침 설명을 위해 작성한 예시이며 실제 사업조건을 의미하지 않는다.

| 교정 전 | 교정 후 |
|---|---|
| 본 사업은 다양한 측면에서 검토가 이루어질 필요성이 있습니다. | 본 사업은 추가 검토가 필요하다. |
| 당사는 혁신적인 솔루션을 통해 금융조달의 새로운 지평을 열고자 합니다. | 당사는 금융조달 방안을 제안한다. |
| 사업비 절감이 가능할 것으로 예상되고 있는 상황입니다. | 사업비 절감이 가능할 것으로 예상된다. |
| 인허가 완료 이후 PF 실행이라는 조건이 충족되는 경우 잔금을 지급합니다. | 인허가 완료 후 PF가 실행되면 잔금을 지급한다. |
| PF 실행 여부와 관계없이 계약일로부터 3년 후 잔금을 지급한다. | PF 실행 여부와 관계없이 계약일로부터 3년 후 잔금을 지급한다. |

마지막 예시는 수정 불필요 문장이다. ‘3년 후 지급’과 ‘PF 실행 시 지급’은 서로 다른 조건이므로 임의로 통합하거나 대체하지 않는다.

## 9. 최종 검수표

- [ ] 원문과 교정본의 사업조건이 동일하다.
- [ ] 금액·단위·기간·날짜·비율이 동일하다.
- [ ] 확정·추정·협의·미확인 상태가 유지되었다.
- [ ] 계약상 주체와 의무의 범위가 바뀌지 않았다.
- [ ] 전문용어와 약어의 의미가 유지되었다.
- [ ] 새 주장·새 근거·새 일정이 추가되지 않았다.
- [ ] 불필요한 반복과 어색한 문장이 정리되었다.
- [ ] 표·각주·별첨의 조건이 본문과 충돌하지 않는다.
- [ ] 수정 필요사항과 사실 확인사항이 구분되어 있다.
- [ ] 실제 수행하지 않은 검증을 완료로 표시하지 않았다.

핵심 조건에 차이가 있으면 제출을 보류한다. 확인할 수 없는 항목은 ‘미확인’으로 남긴다. 실제 측정하지 않은 변경률이나 AI 탐지점수를 기재하지 않는다. 자연스러운 문체만으로 AI 작성 여부를 판정하지 않는다.

## 10. 복사하여 사용하는 실행 프롬프트

```text
아래 원문을 한국어 사업·금융 문서에 맞게 교정하라.

[작업 정보]
- 문서 유형: [사업제안서 / IM / 금융기관 제출자료 / 검토보고서]
- 제출처: [입력]
- 문체: [한다 / 합니다]
- 교정 범위: [문장 교정 / 별도 구조 재구성 제안]
- 고정 용어: [입력]
- 원문: [입력]

[수행 기준]
1. 번역투, 불필요한 반복, 추상적 수식어, 어색한 주술관계를 정리한다.
2. 사실·주장·금액·단위·날짜·고유명사·약어·출처를 유지한다.
3. 지급조건, 선행조건, 예외, 부정문과 불확실성의 정도를 유지한다.
4. 의미가 분명하고 자연스러운 문장은 수정하지 않는다.
5. 원문에 없는 정보나 주체·기한·근거를 보충하지 않는다.
6. 전문용어는 일관되게 쓰되 계약상 정의는 바꾸지 않는다.
7. 내용상 오류가 의심되면 임의 수정하지 않고 확인사항에 적는다.
8. 최종 제출용 본문에 AI 역할·작업 과정·자체 평가를 넣지 않는다.

[출력]
A. 최종 교정본
B. 주요 변경표: 위치 / 원문 / 교정문 / 수정 이유
C. 확인 필요사항
D. 대조 검증: 수치·조건·고유명사·추정상태별 확인 결과

실제로 대조한 항목만 확인 완료로 표시하라.
```
