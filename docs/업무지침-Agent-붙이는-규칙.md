# 업무지침 — Agent 를 하나 더 붙일 때

제정 2026-08-25 · 대상 저장소 `findKTH0415/linkpilot-cron`
검사 `npm run agent:check` (`im-agent/tools/agent-doctor.js`) · `test/agent-wiring.test.js`

> **이 문서는 규칙이고, 기계가 잴 수 있는 것은 이미 검사가 잰다.**
> 규칙을 문서에만 적으면 그 규칙은 **사람의 기억에 얹힌다** (M-31).
> 그래서 아래 규칙 중 여섯은 `npm run agent:check` 가 세고, 사람이 읽어야
> 하는 것만 글로 남긴다. **어느 쪽인지 규칙마다 표시했다.**

---

## 0. 왜 이 지침이 있나 — 두 번 당했다

| | 무슨 일이 났나 | 그때 아무 오류도 안 났다 |
|---|---|---|
| **D-48** | 커넥터 여섯이 **등록만 되고 한 번도 안 불렸다** | 등록돼 있으니 목록에는 보였다 |
| **D-101** | 두 작업선이 **같은 이름의 Agent 를 각자** 만들었다 | 병합이 한쪽을 고르는 것으로 끝나 진 쪽이 **오류 하나 없이** 사라질 뻔했다 |

**둘 다 「빠뜨려서」 났지 「할 줄 몰라서」 난 것이 아니다.** 그리고 둘 다
**조용했다** — 그것이 이 저장소에서 가장 비싼 실패다.

---

## 1. 붙이기 전에 — 사람이 읽어야 하는 것 〈기계가 못 잰다〉

### 1-1. ★★★ 이름과 번호를 **열려 있는 다른 갈래와 함께** 본다

D-101 이 난 자리다. 두 작업선이 같은 갈림점에서 나와 같은 이름의 Agent 를
각자 만들었고, **같은 파일을 쓰고 있었다.**

- 새 **Agent 이름**, 새 **D 번호**(미결정), 새 **M 번호**(사고 기록)를 딸 때
  **열려 있는 PR 의 변경 파일 목록을 본다.**
- **번호를 비워 두는 약속으로는 못 막힌다.** 실제로 한쪽이 D-85~D-94 를
  비워 뒀는데 다른 쪽이 그 뒤 번호를 또 땄고, 결국 **여섯이 두 뜻**을 갖게 됐다
  (D-96 · D-97 · D-98 · D-99 · M-33 · M-34).
- 부딪히면 **코드가 참조하는 쪽이 번호를 지킨다** (D-77 의 기준).

### 1-2. 이 Agent 가 **값(fact)을 내는가**를 먼저 정한다

- 자료·공부(公簿)에서 **읽은 것**이면 낸다.
- 우리가 **계산하거나 만든 것**이면 **안 낸다** (D-33 · D-96).
  우리가 만든 값으로 우리 주장을 증명하면 안 된다.
- 안 내기로 정했으면 **스키마가 강제하게 한다** — `facts: { type: 'array', maxItems: 0 }`.
  주석으로만 적으면 다음 사람이 채운다.

### 1-3. 같은 수를 **두 곳에서 계산하지 않는다** (D-99)

이미 다른 Agent 가 내는 수를 새 Agent 가 다시 계산하지 않는다. 두 공식이
갈라지는 날이 오고, **그날 두 산출물이 서로 다른 것을 말한다.**
받아서 **옮겨 적기만** 한다.

### 1-4. 가정이 섞이면 **자동으로 내지 않는다** (CLAUDE.md §4.8)

출처 있는 값끼리의 계산만 자동화한다. 가정계수가 하나라도 들어가면
그 사실을 산출물에 **적고**, 값으로 올리지 않는다.

## 2. 배선 다섯 곳 — 하나만 빠져도 조용히 안 돈다 〈검사가 센다〉

| # | 곳 | 무엇을 | 빠지면 |
|---|---|---|---|
| ① | `core/registry.js` | 등록 · `order` · 승인규칙 · 모듈 경로 | **아예 안 돈다** |
| ② | `core/monitor.js` `WEIGHTS` | 진행률 비중 | 기본값으로 잡혀 **진행률이 슬쩍 틀어진다** |
| ③ | `core/monitor.js` `DEPENDS` | 선행 Agent | **병목 판정이 엉뚱한 곳을 가리킨다** |
| ④ | `pipeline.js` | 실제로 부르는 자리 | **등록만 하고 안 부르면 없는 것과 같다** (D-48) |
| ⑤ | `ui/platform/live-core.js` | 화면의 단계 묶음 | **진행 화면이 이 단계를 영영 안 그린다** |

★ **`npm run agent:check` 가 등록된 전부에 대해 이 다섯을 센다.**
앞 판은 이 검사가 **한 Agent 에만** 있었다 — 그러면 다음에 붙는 Agent 는
또 아무도 안 센다. 그것이 D-48 이 났던 자리다.

### 2-1. 진행률 비중 **합계 100** 〈검사가 센다〉

합계 100 은 **뜻을 읽기 위한 기준**이다. 100 이 아니면 「이 Agent 가 전체의
몇 퍼센트인가」를 사람이 읽을 수 없다.

★ **새 Agent 를 더할 때는 「어디서 덜어 올지」를 함께 정한다.**
예: 매스를 세우는 일과 그것을 계획으로 적는 일은 **한 일의 앞뒤**라
09 의 몫을 나눠 가졌다.

### 2-2. 실행 차례(`order`)가 겹치지 않는다 〈검사가 센다〉

겹치면 **어느 쪽이 먼저인지 코드가 정하게 된다.**
차례는 **정수**로 매긴다 — 소수 `order` 는 읽는 사람이 「임시」로 읽는다.

## 3. 모듈이 지켜야 하는 계약 〈검사가 센다〉

```
module.exports = { id, label, inputSchema, outputSchema, run(input, ctx) }
```

실행기(`core/runtime.js`)가 강제하는 것 다섯:

1. **입력 스키마 검증** → 위반하면 실행 안 함
2. **출력 스키마 검증** → 위반하면 error 로 격리 (다음 Agent 에 오염 전달 금지)
3. confidence 임계 미달이면 `needs_review`
4. `approvalRule: 'human'` 이면 승인 전까지 downstream 차단
5. **실패는 격리한다** — 한 Agent 가 죽어도 파이프라인 전체를 죽이지 않는다

★ `id` 는 registry 의 키와 **글자 그대로 같아야 한다.** 다르면 등록과 모듈이
서로 다른 것을 가리키는데 오류는 안 난다.

## 4. 없는 값을 만났을 때 — 셋을 지킨다 〈사람이 읽는다〉

| 상황 | 어떻게 |
|---|---|
| 근거가 없다 | **만들지 않는다.** 그리고 **왜 못 만드는지**를 산출물과 화면에 적는다 |
| 자동으로 하나를 고를 수 있다 | **고르지 않는다.** 후보를 내고 사람이 특정한다 (CLAUDE.md §4.9) |
| 대체값으로 메울 수 있다 | **메우지 않는다.** 메우면 「적용됨」만 남고 무엇이 빠졌는지 사라진다 |

★ **조용히 빠지는 것이 이 저장소에서 가장 비싼 실패다.** 켰는데 아무 말 없이
안 나오면 사람은 **고장으로 읽고, 없는 고장을 찾으러 간다.**

★ **0 이 정상 결과이기도 한 자리는 특히 위험하다.** 그때는 0 옆에
**「왜 0 인가」**를 함께 남긴다 (M-37).

---

## 5. 검사 — 무엇을 재야 하나 〈검사가 존재 여부만 센다〉

새 Agent 에는 **이름으로 그것을 재는 검사가 하나 이상** 있어야 한다.
`agent:check` 가 그 존재를 세고, 무엇을 재는지는 사람이 정한다.

권하는 넷:

1. **값을 안 내기로 했으면 정말 안 내는가** (스키마가 강제하는지까지)
2. **없는 값을 짐작해 채우지 않는가** — 이름을 적는가
3. **근사한 것을 근사라고 적는가** — 안 적으면 실제처럼 보인다
4. **막는 장치를 빼고 돌려 빨개지는가** — 통과가 아니라 **실패를 잰다**

★ 4번이 없으면 **아무것도 안 재는 검사가 초록으로 앉아 있게 된다.**
`agent-wiring.test.js` 자신도 일부러 배선을 빼 보고 빨개지는 것을 확인한다.

## 6. 내보내기 전 — 순서 그대로

1. `npm run agent:check` — **빠진 곳이 없다** 를 본다
2. `npm run guard` — 여섯 칸이 전부 초록
3. `npm run im:demo` — 끝까지 돌려 **그 Agent 의 줄이 실제로 찍히는지** 본다
   (등록·호출이 맞아도 입력이 안 닿으면 조용히 건너뛴다)
4. 배포는 **`dry_run=false` · `engine=yes`** 를 준다 —
   안 주면 **초록으로 끝나는데 아무것도 안 올라간다** (M-31)
5. `Verify deployed` 가 초록인 것을 **보고** 말한다.
   「걸었다」와 「닿았다」는 다른 사실이다 (M-25)

## 7. 하지 않는 것 — 다섯

- **`facts` 를 함부로 내지 않는다** (§1-2)
- **같은 수를 두 곳에서 계산하지 않는다** (§1-3)
- **없는 값을 대체값으로 메우지 않는다** (§4)
- **새 라이브러리를 들이지 않는다** — 표준 라이브러리와 기존 의존성이 먼저다
  (CLAUDE.md §5). 네이티브 의존성은 특히 안 된다
- **등록만 하고 안 부르지 않는다** — 그것이 D-48 이다
