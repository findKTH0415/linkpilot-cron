### ① 개별공시지가가 11년 낡은 값이었다 — 30% 오차

```
받아온 값  2015년 46,100,000 원/㎡
실제 최신  2026년 65,730,000 원/㎡
```

**원인** — NED 응답이 **오름차순**인데 `numOfRows: 10` 이라 2006~2015 만 받았다.
코드는 그중 최신을 골랐으니 "최신 = 2015년" 이 됐다.
**고침** — `latestFirst()` 로 정렬을 한 곳에 모으고 `numOfRows: 100`.

### ② 지역·지구 19건 중 18건을 버리고 있었다

버려지던 것에 **토지거래계약에관한허가구역**(매매에 관청 허가 필요)과 **고도제한
두 겹**이 있었다. 문서에는 "일반상업지역, 용적률 상한 1300%" 만 남는데, 그 1300%
를 실제로 못 쓰는 부지였다.
**고침** — `land.use_districts` 전량 등록 + `classifyZones()` 로 딜 조건 분류.
**미확정** — 분류표는 회사 기준이 아니다 → **D-24**

### ③ 시점수정이 한 달 과다였다 — 표본 필지 28억원

```
변동률 누적 (틀림)  1.022834 (+2.28%)
지수 비   (맞음)    1.019436 (+1.94%)
       1.022834 ÷ 1.00333 = 1.019436   ← 기준월 변동률을 한 번 더 셌다
```

**원인** — `202601` 변동률은 2025-12 → 2026-01 구간인데 공시지가 기준일이
2026-01-01 이라 그건 기준일 **이전**이다.
**고침** — **지수의 비**로 계산. 경계가 값 자체에 박혀 있어 같은 실수가 안 난다.

### ④ 엉뚱한 지역의 지수로 보정하고 있었다

인천 남동구 부지인데 근거에 **`울산>북구`** 가 찍혔다.

```
CLS_ID = 510088
  변동률표 (A_2024_00903) → 인천>남동구
  지수표   (A_2024_00901) → 울산>북구
```

**원인** — **통계표마다 지역코드 체계가 다르다.** 색인은 변동률표로 만들고 조회는
지수표에 했다.
**고침** — 색인을 조회할 표와 같은 표에서 만든다. 그리고 **고른 지역과 조회된
지역이 다르면 적용하지 않는다**(`expectRegion`). 이 대조가 없으면 표가 하나 더
늘 때 같은 일이 또 난다.

### ⑤ 값이 데이터셋에만 있고 IM 에는 없었다

`land.use_districts` 가 `facts` 에는 들어가는데 `im-outline.js` 의 `dataKeys` 에
없어 본문·출처표 어디에도 안 실렸다. **토지거래허가구역이 RED FLAG 로만 뜨고
본문 근거는 비어 있었다.**

## 4.2 키를 넣을 때 걸리는 함정 셋 — 겪은 것만

- **`DATA_GO_KR_KEY` 는 Decoding(일반) 쪽이다.** Encoding 키는 한 번 더 인코딩되어
  인증만 실패하고, 증상이 "키가 틀렸다"와 같다 → 커넥터가 부르기 전에 막는다
- **기상청 키 첫 글자의 대문자 `I` 와 소문자 `l`** 이 화면 글꼴로 구분되지 않는다.
  틀리면 `401` 만 나온다 — 눈으로 옮기지 말고 복사한다
- **`VWORLD_DOMAIN` 은 콘솔 서비스URL 을 글자 그대로.** 가공하면 간헐적으로 깨진다

