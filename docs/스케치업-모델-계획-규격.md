# 스케치업 모델 계획 규격 — `model-plan.json`

〈2026-08-25 확정 · D-95 「평면 A 만 GitHub 에서 돌린다」〉

---

## 0. 이 파일이 있는 이유

엔진은 **SketchUp 을 부르지 않는다.** 부르면 반드시 깨진다 — `build_model` 은
살아 있는 SketchUp 앱에 파이썬을 밀어 넣는데 NAS(리눅스)에도 GitHub Actions
러너에도 그런 것이 없다.

그래서 엔진이 내는 것은 **「무엇을 어디에 만들어라」**까지다. 그것이 이 파일이다.

```text
평면 A · 엔진 (NAS · GitHub · 자동)     평면 B · 사람 자리 (보류)
  대지·용적률·층수                        SketchUp + MCP
        ↓                                        ↑
   model-plan.json  ──────────────────────────────┘
```

★ **평면 B 는 아직 자리가 없다** (D-95). `model-plan.json` 은 지금은 **읽을 사람이
없는 채로** 만들어진다 — 그래도 만든다. 나중에 자리가 생기면 그날 바로 쓰이고,
그때 규격을 정하면 이미 만들어 둔 것과 안 맞는다.

★ 이 규격은 **SketchUp 전용이 아니다.** 중간표현이라 Rhino·Blender 로 바꿔도
평면 A 는 그대로다.

---

## 1. 단위와 좌표 — mm 고정

- **길이는 전부 밀리미터(mm) 정수**다. `heightMm: 36000` 은 36m 다.
- **면적만 ㎡** 로 둔다 (`areaSqm`). 도면에서 오는 값이 아니라 사업계획서에서
  오는 값이라 ㎡가 원본 단위다. 억지로 mm² 로 바꾸면 자릿수만 늘고 틀리기 쉽다.
- 좌표계는 **오른손 · Z 위**. 원점은 대지 경계의 왼쪽 아래 모서리.
- SketchUp 내부 단위는 inch 다. **변환은 어댑터 한 곳에서만** 한다 —
  두 곳에서 하면 어느 쪽이 이미 바꿨는지 알 수 없게 된다.

## 3. `model-plan.json` 스키마

```json
{
  "version": 1,
  "projectId": "LP-RE-2026-016",
  "generatedAt": "2026-08-25T09:00:00+09:00",
  "unit": "mm",
  "purpose": "massing",

  "site": {
    "areaSqm": 5000,
    "polygonMm": [[0,0],[80000,0],[80000,62500],[0,62500]],
    "polygonSource": "지적공부(VWorld) 연속지적도",
    "polygonIsApproximate": false
  },

  "building": {
    "floors": 12,
    "floorHeightMm": 4500,
    "heightMm": 54000,
    "footprintAreaSqm": 4000,
    "gfaSqm": 24000
  },

  "objects": [
    {
      "objectId": "MASS-01",
      "type": "mass",
      "name": "본동 매스",
      "originMm": [0, 0, 0],
      "footprintMm": [[0,0],[80000,0],[80000,50000],[0,50000]],
      "heightMm": 54000,
      "source": { "keys": ["land.area_sqm", "building.gfa_sqm"], "from": "09_massing" }
    }
  ],

  "missing": ["land.far_limit"],
  "assumptions": [
    { "what": "floorHeightMm", "value": 4500, "why": "층고가 자료에 없어 자산군 기본값을 썼다" }
  ],
  "notes": "용적률·건폐율 검토용 매스이며 설계안이 아니다"
}
```

### 칸마다의 규칙

| 칸 | 규칙 |
|---|---|
| `site.polygonMm` | **지적 필지 형상이 있을 때만** 실제 모양. 없으면 직사각형 근사이고 `polygonIsApproximate: true` 를 반드시 세운다 |
| `building.*` | 하나라도 없으면 **`missing` 에 이름을 적고 그 칸을 비운다.** 짐작해 채우지 않는다 |
| `objects[].source` | 그 물체가 **어느 값에서 나왔는지**. 없으면 물체를 만들지 않는다 |
| `assumptions` | 자료에 없어 기본값을 쓴 것. **비어 있는 것이 정상이 아니다** — 층고는 대개 여기 온다 |
| `missing` | 비어 있어야 좋은 것이 아니다. **무엇이 없는지가 보이는 것**이 이 칸의 일이다 |

★ **`objects` 가 비어도 파일은 낸다.** 「계획을 못 냈다」와 「계획이 없다」는
다른 사실이고, `missing` 이 그 이유를 말한다.

## 3-1. `deliverables` — **SketchUp 쪽에 만들어 달라고 적는 목록**

〈2026-08-25 사장님 지시: 「출력시 옵션이 [지적도면], [조감도] 반영할시
SketchUp Engineering Agent 로부터 불러오도록」〉

출력 사양(4단계 화면)의 **시각자료** 칸을 켜면 여기에 줄이 선다.

```json
"deliverables": [
  { "id": "cadastral", "label": "지적도면", "sceneId": "SC-CAD-01",
    "status": "requested", "needs": "지적 필지 형상", "why": null },
  { "id": "birdseye", "label": "조감도", "sceneId": "SC-AERIAL-01",
    "status": "blocked", "needs": "지적 필지 형상 + 매스",
    "why": "지적 필지 형상 + 매스을 못 받았다 — …" }
]
```

| 칸 | 뜻 |
|---|---|
| `status: "requested"` | **SketchUp 쪽에서 만들어야 한다.** 근거가 다 있다 |
| `status: "blocked"` | 켜져 있지만 **못 만든다.** `why` 에 까닭이 있다 |
| `sceneId` | 마스터 프롬프트 §23·§24 의 Scene 이름 |

### 규칙 셋

1. **엔진이 대신 그리지 않는다.** 엔진이 그리면 SketchUp 판과 **두 벌**이 되고,
   그때 어느 것이 문서에 실렸는지 알 수 없게 된다.
2. **켰다고 나오는 것이 아니다.** 근거가 없으면 `blocked` 로 적고 **왜**를 남긴다 —
   켰는데 조용히 안 나오면 사람은 고장으로 읽고 없는 고장을 찾으러 간다.
3. **지적도면과 조감도는 다른 것이다.** 조감도는 건물이 선 그림이고 지적도면은
   **땅만** 그린 것이다. 하나로 묶으면 「땅만 필요한데 건물까지 그려진」 문서가 나온다.

## 4. `model-result.json` — 되돌려 놓는 것 〈평면 B · 아직 안 쓴다〉

```json
{
  "version": 1,
  "projectId": "LP-RE-2026-016",
  "planGeneratedAt": "2026-08-25T09:00:00+09:00",
  "builtAt": "2026-08-26T14:00:00+09:00",
  "builtBy": "SketchUp 2025 + MCP",
  "model": { "floors": 12, "heightMm": 54000, "objectCount": 1 },
  "files": ["project.skp", "scene_001.png"],
  "notes": ""
}
```

★ 되받을 때 **계획과 대조한다.** 층수·높이가 다르면 플래그를 세운다 —
사람이 손으로 고친 것이 문서에 조용히 실리면 안 된다.

★ `.skp` 는 **파싱하지 않는다.** 이진 포맷이고 SDK 가 필요하다 (D-38 과 같은 이유).
**있다는 사실만** 기록한다.

---

## 5. 하지 않는 것

1. **엔진이 SketchUp 을 부르지 않는다.**
2. **계획값을 `Dataset` 에 fact 로 등록하지 않는다** (D-33 · D-96 권고).
   우리가 만든 값으로 우리 주장을 증명하는 셈이 된다.
3. **없는 값을 짐작해 채우지 않는다.** `missing` 에 적는다.
4. **도면을 읽지 않는다** (D-98 미정). 대지·용적률 값만으로 만든다.
