# 자료를 더 읽게 하는 법 — 읽기 힘(OCR) 켜기

> **왜 이 문서가 필요한가** 2026-08-23, 잠원동 딜 자료 11건 중 **7건이 안 읽혔습니다.**
> 그중에는 시행사 투자자료와 필지개발계획 PDF 가 있었습니다 — **딜의 핵심이 그쪽**입니다.
> 안 읽히면 그 자료의 값은 보고서에 안 실리고, 재무 항목은 「통상치」로 대체됩니다.
> 화면은 초록이고 보고서도 나옵니다. **달라지는 것은 숫자의 근거뿐**이라 눈에 안 띕니다.

---

## 1. 지금 무슨 일이 일어났나

3단계에서 자료를 올리면 화면이 파일마다 한 줄로 답합니다. 이번에는 이렇게 나왔습니다.

| 자료 | 결과 |
|---|---|
| 대상사업지_네이버 뉴스.pdf | 본문을 읽음 |
| 서초구 잠원동 38-23외 매각 자료 793평 동의서.pdf | 본문을 읽음 |
| 잠원동 38-23 주상복합 신축사업…코리아에셋자증권.xlsx | 본문을 읽음 |
| **시행사 잠원동 블럭개발 투자 (1).pdf** | **못 읽음** — 글자의 58% 가 코드값 |
| **잠원동 38-23외필지개발계획_(주)부강디앤씨.pdf** | **못 읽음** — 글자의 87% 가 코드값 |
| 스크린샷 4장 (.png) | **못 읽음** — 이미지 |
| 잠원동 역세권 활성화사업 용적율 인세티브 (1)(2).png | **못 읽음** — 이미지 |

읽힌 것은 **4건**이고, 거기서 값 15개가 나왔습니다.

### 「글자의 87% 가 코드값」이 무슨 말인가

PDF 안의 글자는 **글자 그 자체가 아니라 번호**로 들어 있을 때가 있습니다.
그 번호를 글자로 되돌리는 표(`ToUnicode`)를 같이 넣어 주지 않으면, 컴퓨터가
읽어도 **뜻 없는 기호만** 나옵니다. 한글 문서를 PDF 로 내보낼 때 자주 그렇습니다.

★ 이때 **억지로 뽑지 않습니다.** 깨진 글자를 그대로 뽑으면 그 안의 숫자가
**멀쩡한 값처럼** 들어가고, 그건 못 읽은 것보다 나쁩니다.

## 2. 무엇을 하면 되나 — 한 줄

**엔진에 「읽기 힘(OCR)」 키를 하나 넣으면 위 7건이 전부 읽힙니다.**

이미 그 기능은 만들어져 있습니다. 켜는 열쇠만 없습니다.

- 이미지(.png)는 글자로 옮겨 읽습니다.
- **코드값만 든 PDF 도 같은 길로 읽습니다** — 그림처럼 놓고 글자를 옮겨 적습니다.
- 옮겨 적은 값은 **신뢰도를 낮춰** 표시하고, 출처에 「옮겨 적은 것」이라고 남깁니다.
  사람이 나중에 원본을 다시 봐야 한다는 뜻입니다.

## 3. 열쇠 받기 (5분)

Google 계정이 있으면 무료로 받습니다.

1. 브라우저에서 **aistudio.google.com/apikey** 를 엽니다.
2. Google 계정으로 로그인합니다.
3. 파란 단추 **[Create API key]** 를 누릅니다.
4. 프로젝트를 고르라고 하면 아무거나 골라도 됩니다 (없으면 만들라고 나옵니다).
5. `AIza…` 로 시작하는 긴 글자가 나옵니다. **복사 단추**를 눌러 둡니다.

### 여기서 대개 막힙니다

- **결제 정보를 묻는 화면이 나오면** 무료 등급으로도 됩니다 — 넘어가도 됩니다.
- 열쇠는 **한 번만 통째로 보여 줍니다.** 창을 닫기 전에 복사해 두십시오.
  잃어버려도 새로 만들면 되니 겁내실 것은 없습니다.

## 4. 열쇠를 GitHub Secret 에 넣기 — 이제 이 길 하나입니다

〈2026-08-23 개정 · **손으로 파일을 만드는 길은 폐기했습니다**〉

### 왜 바꿨나 — 세 번 다 실패했습니다

앞 판은 열쇠를 적은 파일을 NAS 에 직접 놓으시게 했습니다. **세 번 시도해서 세 번 다 다른 자리에서 막혔습니다.**

| 시도 | 무슨 일이 났나 |
|---|---|
| 1 | `.env` 라는 **폴더**가 만들어졌습니다 — File Station 의 [생성] 에는 폴더밖에 없는데 제가 없는 메뉴를 안내했습니다 |
| 2 | 이름이 `linkpilot.env.env` 가 됐습니다 — 맥이 확장자를 한 번 더 붙입니다 |
| 3 | **서식 있는 텍스트로 저장됐습니다.** 그리고 고치신 뒤에도 NAS 의 파일은 지문까지 그대로였습니다 — 새 파일이 아예 안 올라갔습니다 |

★ 막힌 자리가 매번 달랐습니다. **그 길에 함정이 넷**이기 때문입니다 — 서식 모드, 확장자, 업로드 건너뛰기, 숨김 파일. 안내를 더 잘 쓰는 것으로 될 일이 아니라 **그 길을 안 쓰는 것이 고치는 것**입니다.

### 지금은 이렇게 합니다 (2분)

GitHub 의 Secret 칸은 **그냥 글자를 붙여 넣는 상자**입니다. 서식도, 확장자도, 업로드 대화상자도 없습니다. 거기 넣어 두시면 **배포가 NAS 에 파일을 대신 만들어 놓습니다.**

1. 브라우저에서 저장소를 엽니다 — **github.com/findKTH0415/linkpilot-cron**
2. 위쪽 **[Settings]** 탭 (톱니바퀴 모양 아이콘 옆 글자)
3. 왼쪽 목록에서 **[Secrets and variables]** → 그 아래 **[Actions]**
4. 오른쪽 위 초록 단추 **[New repository secret]**
5. **Name** 칸에 정확히: `GEMINI_API_KEY`
   - 대문자와 밑줄까지 그대로입니다. 한 글자만 달라도 안 읽힙니다.
6. **Secret** 칸에 열쇠를 붙여 넣습니다.
   - **따옴표로 감싸지 않습니다.** 앞뒤에 빈칸도 넣지 않습니다.
   - 색을 칠하거나 꾸밀 방법이 아예 없습니다 — 그래서 안전합니다.
7. **[Add secret]**

### 여기서 대개 막힙니다

- **[Settings] 탭이 안 보이면** 그 저장소의 관리 권한이 없는 계정으로 로그인된 것입니다. 오른쪽 위 사람 아이콘을 눌러 계정을 확인하십시오.
- 한 번 넣으면 **다시는 볼 수 없습니다** (GitHub 이 안 보여 줍니다). 바꾸려면 덮어쓰면 됩니다 — 지금 값이 무엇인지 몰라도 됩니다.
- 넣은 뒤에는 **배포를 한 번 돌려야** NAS 에 닿습니다 (§5).

### 넣고 나면 무슨 일이 나나

배포가 돌 때 이 순서로 움직입니다.

1. 엔진 루트의 기존 `linkpilot.env` 를 `linkpilot.env.bak-<시각>` 으로 **먼저 옮겨 둡니다** (되돌릴 자리)
2. Secret 값으로 `linkpilot.env` 를 **새로 씁니다** — 한 줄짜리 일반 텍스트입니다
3. 엔진을 다시 띄웁니다 → 뜨면서 그 열쇠를 읽습니다
4. 진단이 `읽힌 키: GEMINI_API_KEY` · `엔진이 보는 상태: OCR 켜짐` 이라고 적습니다

★ **Secret 이 비어 있으면 아무것도 안 건드립니다.** 손으로 놓아 두신 파일을 빈 값으로 덮는 일은 없습니다.

★ 열쇠 값은 **로그에 한 글자도 안 남습니다.** 배포 기록에 적히는 것은 길이와 앞머리 모양(`AIza…` 인지 `AQ.…` 인지)뿐입니다.

### 〈참고〉 그래도 손으로 놓고 싶으시면

엔진은 **자기 폴더 바로 위**에서 `.env` 또는 `linkpilot.env` 를 찾습니다 — `im-agent` 가 들어 있는 그 폴더입니다. 한 칸 위나 아래에 두면 안 읽고, 그때도 오류는 안 나고 그냥 「꺼짐」입니다.

반드시 **일반 텍스트**여야 합니다. NAS 안에서 File Station → 파일 오른쪽 클릭 → **[Text Editor 로 열기]** 로 만드시면 서식이 섞일 방법이 없습니다.

**둘 다 있으면 `.env` 가 이깁니다.** Secret 을 넣으신 뒤에는 배포가 `linkpilot.env` 를 쓰므로, `.env` 를 손으로 만들어 두면 **그쪽이 이겨서 Secret 이 무시됩니다.**

## 5. 엔진 다시 띄우기

열쇠는 엔진이 **뜰 때** 읽습니다. 그래서 한 번 다시 띄워야 합니다.

Secret 을 넣으신 뒤 **배포를 한 번 돌리면** 파일 놓기와 엔진 재시작이 함께 끝납니다.

1. GitHub 저장소 → 위쪽 **Actions** 탭
2. 왼쪽 목록에서 **deploy-nas**
3. 오른쪽 **[Run workflow]**
4. **`dry_run` 을 `false` 로 바꾸십시오** — 기본값은 `true` 라서 그냥 누르면
   **아무것도 안 올라갑니다.** (재기만 하고 끝납니다 — 실제로 한 번 그랬습니다.)
5. `engine` 을 **yes** 로 두고 초록 단추

## 6. 켜졌는지 확인하는 법 — 두 가지

**① 배포 기록에서**

배포가 끝나면 요약에 한 줄이 적힙니다.

- `OCR: 켜짐 — 스캔본·이미지·코드값 PDF 를 글자로 옮겨 읽는다` → 된 것입니다.
- `OCR: **꺼짐**` → 아직입니다. 바로 아래 진단 줄이 원인을 말합니다.

**★ 「꺼짐」이 나오면 — 그 바로 아래 줄에 원인이 적힙니다** 〈2026-08-23 추가〉

앞 판은 「꺼짐」 한 마디로 끝났습니다. 그런데 그 말로는 **다음에 무엇을 봐야
할지 알 수가 없습니다** — 아래 다섯이 전부 똑같이 「꺼짐」으로 보입니다.

| 실제로 일어난 일 | 이제 로그에 나오는 말 |
|---|---|
| 이름이 파일이 아니라 폴더다 | `.env — **폴더다.** 파일이어야 한다` |
| 서식 있는 텍스트로 저장됐다 ← **이번에 이것이었습니다** | `**서식 문서(RTF)** — [일반 텍스트로 만들기] 를 안 눌렀다` |
| 줄이 `KEY=값` 모양이 아니다 | `못 읽은 줄 1개 (KEY=값 모양이 아니다)` |
| 값에 따옴표·빈칸이 섞였다 | `**따옴표가 값에 섞였다**` |
| 자리표시자를 안 바꿨다 | `**자리표시자가 그대로 들어 있다**` |

제대로 됐으면 `읽힌 키: GEMINI_API_KEY` 와 `엔진이 보는 상태: OCR 켜짐` 이
나옵니다. **열쇠 값 자체는 로그에 한 글자도 안 남습니다** — 길이와 앞 네 글자가
`AIza` 인지 여부만 적습니다.

**② 화면에서**

3단계에서 **안 읽혔던 파일을 다시 올려** 봅니다.
「못 읽었습니다 — GEMINI_API_KEY 가 필요합니다」가 사라지고
「글자로 옮겨 읽음」으로 바뀌면 된 것입니다.

## 7. 켠 뒤에 달라지는 것

| | 지금 | 켠 뒤 |
|---|---|---|
| 읽히는 자료 | 11건 중 4건 | **11건 전부** |
| 재무 필수 항목 | 8건이 **통상치로 대체됨** | 자료에서 읽은 값 |
| 시장분석 절 | 자리표시자 | 자료 기반 서술 |

★ **숫자가 지어지는 것이 아닙니다.** 옮겨 적은 글자에 평소의 규칙 추출을 그대로
돌립니다. 근거 문구를 원문과 대조하는 장치도 그대로 돕니다 — 다만 **신뢰도를
낮춰** 표시하므로, 출처표에서 「이 값은 원본을 다시 봐야 한다」가 보입니다.

## 8. 이것 말고 남은 것 하나

시장금리를 아직 **가정치**로 두고 있습니다 (`ECOS_API_KEY 미설정`).
한국은행 열쇠를 넣으면 실제 고시 금리로 바뀝니다. 급하지는 않습니다 —
그 값은 「가정」이라고 문서에 적히고 있어서 조용히 틀리지는 않습니다.
