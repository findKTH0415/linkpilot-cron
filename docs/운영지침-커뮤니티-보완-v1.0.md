## 1. 적용 범위와 현황 확인

### 1.1 검토 근거

2026-10-21 오후 10:12:40 및 10:12:49 첨부 화면을 기준으로 한다.

확인된 구성:

- 프로젝트[공유] 배포, 전문가 연결, 실시간 공유, 쪽지 탭.
- 투자자 구함, 자금조달, 용역·견적 요청, 파트너 구함, 사업·매물 소개 분류.
- 관심 산업 선택 및 계정별 저장 안내.
- 자금조달 글의 필요 금액, 기간, 자금 용도, 담보·보증 필드.
- 공개·나만 보기 선택, 작성자 수정·삭제 기능.

화면만으로 확인되지 않은 항목:

- 전문가 연결·쪽지 탭 내부 기능.
- 국가별 공개 범위, 번역, 자료 승인, 신고·차단, 서버 권한 검증.
- 기존 프로젝트 섹션과 커뮤니티의 실제 연결 상태.

개발 착수 시 작성자·일반 회원 계정으로 기존 기능을 먼저 확인한다. 확인되지 않은 기능을 미구현으로 단정하지 않으며, 동일 기능이 있으면 기존 기능을 연결·개선한다.

### 1.2 구현 원칙

1. 커뮤니티는 발견·모집·연결을 담당한다.
2. 참여 확정 후 업무·일정·담당자 관리는 기존 프로젝트 섹션으로 연결한다.
3. 공개 요약, 신청자 정보, 승인 자료, 프로젝트 내부 업무의 접근 권한을 각각 구분한다.
4. 게시글 공개 여부와 모집 진행 상태를 분리한다.
5. 국가·언어·통화·시간대를 구분하여 글로벌 거래 조건을 명확히 표시한다.
6. 신규 기능으로 기존 게시글·쪽지·프로젝트 연결이 유실되지 않도록 한다.
7. 이 지침으로 회원 요금제나 이용 한도를 새로 변경하지 않는다. 실제 적용된 정책을 확인하여 사용한다.

## 3. 메뉴와 이동 경로

### 3.1 권장 메뉴

| 메뉴 | 주요 기능 | 기존 구성과의 관계 |
|---|---|---|
| 프로젝트 찾기 | 공개 프로젝트 검색·상세·문의·신청 | 실시간 공유의 탐색 기능을 연결 |
| 전문가 찾기 | 전문 분야·활동 국가·언어별 검색 | 전문가 연결을 개선 |
| 내 활동 | 내 글·관심 저장·보낸 신청·받은 신청 | 프로젝트[공유] 배포의 관리 기능을 연결 |
| 쪽지·문의 | 프로젝트 관련 대화·미확인 알림 | 기존 쪽지 기능 활용 |
| 자료 승인 | 받은 열람 요청·승인·거절·철회 | 기존 기능 확인 후 연결 또는 추가 |

상위 메뉴를 즉시 모두 변경할 필요는 없다. 우선 공개 탐색과 내 글 관리를 명확히 나누고, 관련 기능은 하위 탭으로 배치할 수 있다. 메뉴명이 변경되어도 기존 링크는 대응 화면으로 연결한다.

### 3.2 용어 정리

- 게시글 생성 버튼: `+ 모집 글 등록`.
- 게시글에 관한 질문: `문의하기`.
- 참여 의사와 역할 제안: `참여 신청`.
- 운영자에게 보내는 질문: `고객지원`.
- 관심 프로젝트 보관: `관심 저장`.
- 작성자가 모집을 끝내는 기능: `모집 종료`.

현재 `+ 문의 추가`가 수행하는 기능을 확인한 뒤 목적에 맞게 이름을 변경한다. 게시글과 고객지원 문의를 같은 이름으로 표시하지 않는다.

## 4. 화면별 보완

### 4.1 공개 프로젝트 목록

상단에는 검색, 모집 유형, 국가, 산업, 모집 상태를 배치한다. 추가 조건은 상세 필터로 접는다.

- 검색 대상: 제목, 공개 요약, 산업, 사업 국가, 찾는 역할.
- 필터: 모집 유형, 사업 국가, 파트너 희망 국가, 산업, 금액·통화, 사업 단계, 마감일, 언어.
- 정렬: 최신 등록, 최근 수정, 마감 임박. 추천순은 추천 근거를 마련한 뒤 추가한다.
- 관심 산업: 검색 필터인지 추천 설정인지 구분하고 `전체 선택·초기화` 제공.
- 결과가 없으면 조건 초기화, 모집 글 등록, 저장 검색 알림을 안내한다.
- 공개 목록에서 `내 글·다른 회원 글`보다 전체 결과와 현재 검색 조건을 먼저 보여준다.

카드 필수 표시:

- 모집 유형, 제목, 공개 요약.
- 사업 국가·지역, 산업, 찾는 역할.
- 금액·통화 또는 협의 여부.
- 모집 상태, 마감일, 최근 확인일.
- 작성자 공개명과 확인된 소속 여부. 익명 설정이면 소속을 유추할 정보는 숨긴다.
- 상세 보기, 관심 저장.

### 4.2 상세 화면

- 상단: 제목·모집 상태·국가·산업·최근 확인일.
- 본문: 사업 요약, 필요한 협력, 조건, 일정, 공개 가능한 근거·자료.
- 다른 회원: `문의하기·참여 신청·관심 저장·신고`.
- 작성자: `수정·공개 범위 변경·공개 중단·모집 종료·받은 신청`.
- 작성자는 자신의 글에 참여 신청할 수 없다.
- 마감된 글에는 신규 신청을 차단하고 종료 상태를 안내한다.
- 비로그인 열람은 현재 서비스 정책을 확인한다. 정책이 정해지기 전 외부 공개로 자동 확대하지 않는다.

작성자가 현재 탭에서 수정할 수 있도록 한다. 수정 때문에 다른 탭으로 이동해야 하는 구조를 개선한다.

### 4.3 내 활동

- 내 글: 초안, 공개 중, 공개 중단, 모집 종료 구분.
- 보낸 신청: 신청 대상, 신청 역할, 처리 상태, 최근 답변, 철회.
- 받은 신청: 신청자, 제안 요약, 상태, 처리 담당자, 답변.
- 관심 저장: 모집 상태 변경과 마감 표시.
- 프로젝트 연결: 연결된 프로젝트로 이동.

### 4.4 배치·모바일·접근성

- 대표 배너 높이를 줄여 첫 화면에 실제 프로젝트와 주요 버튼이 보이게 한다.
- 관심 산업 영역은 접기·펼치기를 지원한다.
- 데스크톱 목록·상세 분할 구성을 모바일에서는 목록→상세로 전환한다.
- 모바일 상세의 주요 신청 버튼은 본문을 가리지 않는 위치에 둔다.
- 버튼은 터치 가능한 크기로 제공하고 키보드 포커스와 스크린리더 이름을 지정한다.
- 선택·종료·승인 상태는 색상과 텍스트를 함께 사용한다.
- 긴 제목·금액·다국어 문장·오류 안내가 잘리거나 버튼과 겹치지 않게 한다.
- 판 번호 등 운영 정보는 이용자 콘텐츠와 겹치지 않는 관리 영역으로 옮긴다.

## 5. 모집 글 입력 필드

### 5.1 공통 필드

| 필드 | 입력 기준 |
|---|---|
| 제목 | 사업과 찾는 역할이 드러나게 작성 |
| 모집 유형 | 투자자·자금조달·용역/견적·파트너·사업/매물 중 선택 |
| 공개 요약 | 공개해도 되는 내용만 입력 |
| 사업 국가·지역 | 실제 사업이 소재하거나 수행되는 곳 |
| 파트너 희망 국가 | 상대방을 찾는 국가, 복수 선택 가능 |
| 산업 | 기존 산업 분류 활용, 세부 분야 선택 지원 |
| 사업 단계 | 기획·사전검토·인허가·개발/구축·운영·거래 협의 등 |
| 찾는 역할 | 투자·금융·시공·운영·유통·자문 등 |
| 금액·통화 | 숫자와 통화를 별도 저장, 미정·협의 구분 |
| 모집 마감 | 날짜·시간대 또는 상시 모집 선택 |
| 작성자 입장 | 사업주·직접 투자자·수임 자문사·소개자·기타 |
| 작성 언어·대응 언어 | 원문 언어와 실제 협의 가능한 언어 구분 |
| 공개 범위 | 나만 보기·회원 공개·선택 국가·전 세계 |
| 신원 공개 | 익명 기본, 실명·소속 공개는 작성자 선택 |
| 자료 제공 조건 | 공개 요약만·신청 승인 후·NDA 및 승인 후 |

초안은 미완성 저장을 허용한다. 공개 시에는 제목·모집 유형·공개 요약·사업 국가·산업·찾는 역할·모집 기간·공개 범위·작성자 입장을 필수로 확인한다. 거래 금액을 확정할 수 없으면 `협의`를 허용한다.

### 5.2 모집 유형별 추가 필드

| 모집 유형 | 세부 입력 |
|---|---|
| 투자자 구함 | 투자 방식, 모집 금액, 최소 참여금액, 자금 용도, 찾는 투자자, 주요 조건 |
| 자금조달 | 조달 방식, 필요 시점, 만기, 상환 재원, 담보·보증, 기존 채무의 공개 가능 범위 |
| 용역·견적 요청 | 업무 범위, 결과물, 수행 기간, 예산 범위, 제안 마감, 선정 기준 |
| 파트너 구함 | 필요한 역량, 제공 가능한 자원, 역할 분담, 협력 방식, 활동 지역 |
| 사업·매물 소개 | 매수/매도 구분, 대상 종류, 가격 범위, 거래 구조, 자료 제공 조건 |

소개자·수임 자문사가 작성한 글은 직접 당사자인 것처럼 표시하지 않는다. 수임 여부나 자료 확인 여부는 확인한 범위만 표시한다.

### 5.3 입력·표시 품질

- 금액에 단위를 중복 입력하지 않도록 숫자·통화·표시 단위를 구분한다.
- 자동 환산을 제공하면 원화폐 금액, 환율 기준일, 환산값을 함께 표시한다.
- 연락처·이메일·기밀 정보가 공개 요약에 들어가면 공개 전 작성자에게 확인시킨다.
- 날짜 형식을 통일하고 마감 시각은 이용자 시간대와 원래 시간대를 확인할 수 있게 한다.
- 투자수익이나 사실 확인이 안 된 내용을 플랫폼이 검증한 것처럼 자동 생성하지 않는다.

## 6. 문의·참여 신청 처리

### 6.1 문의와 신청의 구분

- 문의: 조건을 확인하는 대화. 문의만으로 참여자 등록이나 자료 열람 권한이 생기지 않는다.
- 참여 신청: 역할·경력·제안 내용을 제출하는 공식 의사 표시.

신청 필드:

1. 신청 역할.
2. 관련 경력·보유 역량.
3. 제안 요약과 제공 가능한 자원.
4. 참여 가능 시점.
5. 활동 국가·대응 언어.
6. 작성자에게 제공할 프로필 정보의 확인.

필요하지 않은 민감정보는 받지 않는다. 신청 내용은 작성자와 권한 있는 담당자만 볼 수 있다.

### 6.2 상태와 처리 권한

| 상태 | 변경 주체 | 다음 처리 |
|---|---|---|
| 접수 | 신청 제출로 생성 | 작성자 검토 시작 |
| 검토 중 | 작성자·지정 담당자 | 추가 정보 요청·수락·거절 |
| 추가 정보 요청 | 작성자·지정 담당자 | 신청자 보완 후 검토 재개 |
| 수락 | 작성자·승인 권한 담당자 | NDA·자료 승인·프로젝트 초대 절차 |
| 거절 | 작성자·승인 권한 담당자 | 신청자에게 결과 통지 |
| 철회 | 신청자 | 미확정 신청 종료 |

중복 클릭으로 신청이 여러 건 생성되지 않게 한다. 동일 글의 진행 중 신청은 1건으로 관리하고 수정 이력을 남긴다. 거절·철회 후 재신청 허용 여부는 운영 정책으로 설정한다.

### 6.3 수락 이후 프로젝트 연결

1. 신청 수락.
2. 글의 자료 제공 조건에 따라 NDA 또는 열람 승인 진행.
3. 기존 프로젝트 선택 또는 새 프로젝트 생성.
4. 참여자에게 역할과 접근 범위를 명시한 초대 발송.
5. 참여자가 초대를 수락한 뒤 해당 범위의 협업 시작.

신청 수락은 협업 검토 수락이며 계약 체결·투자 확약·자료 전체 공개를 의미하지 않는다. 프로젝트 초대는 실제 프로젝트 관리 권한을 가진 회원만 수행한다. 자료 열람이 필요 없는 협업은 NDA·자료 단계를 생략할 수 있다.

## 7. 기존 프로젝트 섹션과 업무 공유

커뮤니티의 공개 글과 프로젝트 내부 업무를 연결하되 공개 범위를 서로 상속하지 않는다.

프로젝트 업무 필드:

- 단계·업무명·업무 설명.
- 업무 책임자·참여자·검토자.
- 시작일·마감일·시간대.
- 상태: 예정·진행 중·검토 요청·완료·보류.
- 선행 업무·완료 조건·필요한 승인.
- 산출물 외부 링크·댓글·멘션·수정 이력.
- 공개 범위: 프로젝트 전체·지정 참여자.

커뮤니티 글의 내용 수정이 프로젝트 내부 조건이나 계약 내용을 자동으로 변경하지 않게 한다. 프로젝트 생성 시 전달한 요약과 원문 연결을 남기고, 이후 변경은 담당자가 검토한다. 프로젝트 내부 진행 상황을 공개 글에 표시할 때는 공개용 요약을 별도로 승인한다.

## 8. 공개 범위와 권한

### 8.1 범위를 분리해서 설정

- 사업 국가: 사업이 있는 곳.
- 파트너 희망 국가: 찾는 상대방의 활동 국가.
- 공개 대상 국가: 글을 보여줄 대상으로 선택한 국가.
- 작성자 신원 공개: 익명·실명·소속 표시 선택.

국가 공개 범위는 확인된 계정의 활동 국가를 기준으로 적용한다. 국가 설정은 서버에서 검사하며, IP 위치만으로 국가를 확정하지 않는다. 이 기능은 열람 대상을 정하는 기능으로 안내하고 실제 물리적 위치를 보장한다고 표시하지 않는다.

`전 세계`는 모든 대상 국가의 회원을 의미하도록 우선 설계한다. 검색엔진·비로그인 외부 공개는 별도 설정으로 분리하고, 기본값은 끈 상태로 둔다.

### 8.2 권한 기준

| 정보·행동 | 허용 대상 |
|---|---|
| 공개 요약 열람 | 해당 글의 공개 범위에 포함되는 이용자 |
| 문의·참여 신청 | 로그인·계정 상태·차단 조건을 충족한 다른 회원 |
| 신청자 정보 열람 | 신청자 본인, 작성자, 승인된 담당자 |
| 글 수정·공개 변경 | 작성자와 위임받은 관리 담당자 |
| 신청 수락·자료 승인 | 작성자와 해당 승인 권한 담당자 |
| 기밀 자료 열람 | 자료별 승인 조건을 충족한 이용자 |
| 프로젝트 내부 업무 | 초대 수락 후 부여된 역할 범위의 참여자 |
| 신고 처리 | 업무상 필요한 범위의 운영 담당자 |

화면 버튼 숨김과 별도로 서버에서 권한을 확인한다. 직접 주소 접근·검색 결과·알림·번역 요청·내보내기에서도 동일한 권한을 적용한다. 차단·공개 중단·권한 회수 후에는 관련 캐시와 연결 화면에서도 노출이 중단되어야 한다.

공개 중단·모집 종료·프로젝트 참여 권한 해지는 서로 다른 행동으로 처리한다. 하나를 변경할 때 다른 권한까지 자동 변경되는 경우 영향 범위를 안내한다.

## 9. 신뢰 확인·전문가 연결·운영

### 9.1 확인 배지

- 이메일 확인, 소속 확인, 자격 확인을 각각 구분한다.
- 배지에 확인 항목·확인일·만료 여부를 표시한다.
- 자기소개와 운영자가 확인한 정보를 구분한다.
- 명함 등록만으로 기업 실체·전문 자격·투자 능력이 확인되었다고 표시하지 않는다.
- 사업성·수익성·거래 안전성을 보증하는 것처럼 보이는 배지를 사용하지 않는다.

### 9.2 전문가 연결

- 전문 분야, 활동 국가, 대응 언어, 수행 경력, 상담 가능 여부 표시.
- 의뢰서→제안서→수락→프로젝트 역할 초대 과정 연결.
- 후기 작성은 실제 연결·수행 이력이 있는 회원을 기준으로 제한.
- 프로필 확인과 후기 평점을 구분. 후기 이의 제기·운영 검토 절차 마련.
- 전문가 등록·노출 기준은 현재 정책을 확인해 적용. 새 가격이나 결제 구조는 이 문서에서 확정하지 않는다.

### 9.3 신고·차단·게시 관리

- 신고 유형: 허위 정보 의심, 무단 자료, 스팸, 사칭, 부적절한 연락 등.
- 신고 접수·검토·조치 결과와 처리 이력 기록.
- 차단 후 새 쪽지·새 신청 제한. 기존 프로젝트 관계는 별도로 정리할 수 있게 안내.
- 모집 마감 후 자동 종료, 상시 모집 글의 정기 재확인.
- 재확인 주기와 알림 횟수는 운영 설정으로 관리.
- 글 삭제와 공개 중단을 구분하고, 실수 방지를 위한 확인과 복구 정책 마련.

## 10. 글로벌 번역과 추천

### 10.1 번역

- 원문 보기·번역 보기 제공, 자동 번역임을 표시.
- 원문 수정 후 이전 번역을 최신 번역처럼 보여주지 않음.
- 금액·통화·지분율·단위·날짜·회사명은 원문과 대조 가능하게 표시.
- 번역 오류 신고와 작성자 확인 기능 마련.
- 공개되지 않은 자료·신청서·쪽지를 번역 처리할 때도 해당 접근 권한을 유지.
- 지원 언어는 실제 번역 연동과 검수 가능 범위를 확인한 뒤 표시. 구현되지 않은 언어를 지원한다고 안내하지 않음.

### 10.2 추천·저장 검색

- 관심 산업, 사업 국가, 파트너 희망 국가, 역할, 금액 범위, 언어를 활용.
- `에너지 분야·동남아 사업·금융 파트너 모집 조건과 일치`처럼 추천 이유 표시.
- 조건이 맞지 않는 대상을 억지로 추천하거나 근거 없는 적합도 수치를 생성하지 않음.
- 미확인 프로필을 확인된 투자자나 전문가로 표시하지 않음.
- 종료·공개 중단·차단 글을 신규 추천에서 제외.
- 저장 검색과 알림 수신 여부·빈도를 회원이 선택.

## 11. 자료 승인과 외부 클라우드

비밀문서는 기존 방침에 따라 외부 저장소 링크를 활용한다. 플랫폼에는 자료 설명·접근 요청·승인 상태를 관리한다.

- 자료별로 열람 요청, 승인, 거절, 만료, 철회 상태 제공.
- NDA 조건이 있으면 동의한 문서 버전·동의자·시각을 기록. 이를 법적 효력 보증으로 표현하지 않음.
- 쪽지는 기존 방침에 따라 파일 첨부 없이 프로젝트·자료 요청 화면으로 연결.
- 외부 링크는 공개 요약·알림·공유 미리보기에 자동 포함하지 않음.
- LinkPilot 승인과 외부 저장소 권한 설정을 구분해 표시.
- 외부 저장소 연동이 없으면 `외부 권한 설정 확인 필요`로 안내.
- 외부 접근 권한을 실제로 제한하지 못하면 `다운로드 차단`이나 `접근 회수 완료`로 표시하지 않음.
- 링크 철회·NDA 동의만으로 이미 내려받은 파일까지 회수할 수 있다고 안내하지 않음.

## 12. 알림과 쪽지

알림 대상: 새 문의, 신청 접수, 추가 정보 요청, 신청 결과, 프로젝트 초대, 자료 승인 결과, 모집 마감, 관심 글 변경.

- 프로젝트명과 사건의 요약을 표시하고 해당 화면으로 연결.
- 민감한 신청 내용과 기밀 금액을 푸시·이메일 제목에 넣지 않음.
- 중복 알림 방지, 읽음 상태, 알림 빈도·채널 선택 제공.
- 대화에 원래 프로젝트 링크를 자동 연결.
- 실제로 동작하는 발송·수신 기능이 있는 경우에만 실시간 알림으로 안내.
- 운영 메시지와 회원 간 쪽지를 구분.

## 13. 데이터 보존과 전환

1. 기존 글·분류·작성자·공개 여부·쪽지·프로젝트 연결 관계를 확인한다.
2. 변경 전 백업과 복구 절차를 마련한다.
3. 신규 필드는 기존 글에서 `미입력`으로 구분하고 국가·통화 등을 임의 추정해 채우지 않는다.
4. 기존 비공개 글은 비공개 상태를 유지한다. 공개 대상이 불분명한 기존 글은 작성자 확인 전 범위를 확대하지 않는다.
5. 신규 필수 필드가 누락된 기존 글은 다음 편집·재공개 시 보완하도록 안내한다.
6. 기존 주소와 저장 링크의 이동 경로를 보존한다.
7. 게시글, 신청, 프로젝트, 자료 요청을 연결할 수 있는 식별자를 유지한다.
8. 상태·권한 변경은 변경 주체·시각·이전 값·이후 값을 기록한다.
9. 신청자 정보와 신고 자료의 보유 기간·삭제 기준은 실제 운영 정책으로 정하고 무기한 저장을 기본으로 두지 않는다.

## 14. 검수 시나리오

실제 서비스 수정 후 아래 항목을 검수한다. 이 문서 작성 시점에는 구현 테스트를 수행한 것이 아니다.

- [ ] 작성자는 자신의 글에 신청할 수 없고, 다른 회원에게는 문의·신청 버튼이 보인다.
- [ ] 신청 중복 제출이 차단되고 접수·검토·보완·수락·거절·철회 과정이 일관된다.
- [ ] 작성자 계정 외에는 다른 신청자의 개인정보와 제안 내용을 볼 수 없다.
- [ ] 비공개·선택 국가 글은 직접 주소·검색·알림·번역에서도 권한 밖에 노출되지 않는다.
- [ ] 공개 대상 국가와 사업 국가, 파트너 희망 국가가 서로 혼용되지 않는다.
- [ ] 익명 작성자를 카드·자료 링크·번역 결과에서 우회적으로 식별시키지 않는다.
- [ ] 모집 종료 후 신규 신청이 차단되며 기존 대화·프로젝트는 정해진 정책에 따라 유지된다.
- [ ] 신청 수락만으로 전체 자료나 프로젝트 업무 권한이 생기지 않는다.
- [ ] 프로젝트 관리 권한이 없는 소개자는 다른 회원을 내부 프로젝트에 임의 초대할 수 없다.
- [ ] 초대 수락 이후 지정된 역할·업무·자료에만 접근한다.
- [ ] 공개 중단·차단·권한 회수 후 목록·상세·추천·알림 링크에서 상태가 일치한다.
- [ ] 원문 변경 시 번역이 갱신되며 금액·통화·지분율·마감 시각이 왜곡되지 않는다.
- [ ] 서버 시간대와 다른 회원 시간대에서도 마감 판정이 같다.
- [ ] 외부 자료 권한이 설정되지 않았는데 플랫폼이 보호 완료로 표시하지 않는다.
- [ ] 모바일에서 긴 제목·다국어·키보드 입력·하단 버튼이 겹치지 않는다.
- [ ] 기존 글과 쪽지·프로젝트 연결 관계가 전환 후 유지된다.
- [ ] 알림이 중복 발송되지 않고 수신 설정이 적용된다.
- [ ] 신고·차단·오류·빈 검색 결과에서 다음 행동을 안내한다.
- [ ] 기존 메뉴의 링크와 새 메뉴의 이동 경로가 연결된다.

## 15. 운영 성과 확인

조회수와 함께 실제 참여 과정을 측정한다. 초기 운영 데이터를 확인한 뒤 목표값을 정한다.

| 지표 | 정의 |
|---|---|
| 문의 전환율 | 측정 기간 중 상세를 본 회원 중 문의를 보낸 회원의 비율 |
| 신청 전환율 | 측정 기간 중 상세를 본 회원 중 신청을 제출한 회원의 비율 |
| 첫 응답 시간 | 문의·신청 접수부터 첫 응답까지의 시간 |
| 신청 수락률 | 신청 건 중 수락된 건의 비율, 접수 기간과 관찰 기간 명시 |
| 프로젝트 연결률 | 수락된 신청 중 프로젝트 초대 수락까지 이어진 건의 비율 |
| 해외 연결 비중 | 국가 정보를 확인한 연결 중 서로 다른 국가 회원 간 연결의 비율 |
| 정보 최신성 | 모집 중 글 중 정해진 기간 내 재확인된 글의 비율 |

작성자 본인 조회·운영 테스트·중복 클릭을 구분한다. 측정 기간, 중복 제거 기준, 취소·철회 처리 기준을 함께 정한다. 제시된 지표를 매출·투자 유치 성과로 자동 해석하지 않는다.

## 17. 개발 담당자 실행 지시

첨부 화면과 실제 커뮤니티 기능을 대조하여 기존 구현·보완 필요·신규 개발 항목을 구분한다. P0부터 적용하고, 공개 범위와 권한 검증은 화면 수정과 함께 구현한다. 참여 신청 수락 후에는 기존 프로젝트 섹션의 초대·업무·일정 기능을 연결한다. 기존 데이터와 링크를 보존하고, 다른 회원 계정과 국가·언어가 다른 계정으로 검수한다.

완료 보고에는 다음을 제출한다.

1. 반영한 화면과 변경 사항.
2. 기존 기능을 재사용한 부분과 새로 구현한 부분.
3. 작성자·일반 회원·승인 담당자별 검수 결과.
4. 공개 범위·자료 권한·마감 처리 검수 결과.
5. 모바일·다국어 확인 결과.
6. 기존 데이터 보존 결과와 복구 방법.
7. 미반영 항목·이유·다음 단계.

작업 착수 순서: 문의·참여 신청 → 내 활동과 공개 탐색 구분 → 공개 권한 검증 → 국가·통화·마감·모집 상태 → 신청 관리와 프로젝트 연결 → 번역·추천·운영 지표.
