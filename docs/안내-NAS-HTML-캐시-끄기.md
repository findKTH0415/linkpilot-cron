# NAS 에게 「화면은 매번 다시 주라」고 일러두기 〈2026-08-27 · D-150〉

사람 손이 **한 번** 필요합니다. 한 번 켜 두면 다시 만질 일이 없습니다.

## 무엇을 위해 하는가 — 먼저

앱에서 보고서 화면을 여실 때 **빨간 띠**(「화면과 스크립트의 판이 다릅니다」)가
뜬 적이 있습니다. 그 띠가 뜨는 이유는 거의 언제나 하나입니다.

- 화면이 부르는 **형제 파일**(`flow-core.js` 같은 것)은 주소 뒤에 판 표시가
  붙어 있어서, 판이 바뀌면 **주소가 바뀝니다.** 그러면 브라우저가 새로 받습니다.
- 그런데 **화면 자체**(`intake.html` 같은 HTML)에는 그런 표시가 없습니다.
  브라우저는 「전에 받아 둔 게 있으니 그냥 쓰지」 하고 **옛 화면**을 씁니다.

그래서 **옛 화면이 새 형제를 부르는** 상태가 되고, 그때 띠가 뜹니다.

지금은 화면이 그 띠를 만나면 **스스로 한 번 다시 받습니다**(2026-08-27 에 넣었습니다).
그래도 그건 **띠가 뜬 뒤**에 고치는 것입니다. 아래를 켜면 **애초에 옛 화면을
안 받습니다.**

> **캐시(cache)** — 브라우저가 「전에 받은 파일」을 제 안에 넣어 두고 다시
> 안 받는 것입니다. 대개는 빨라서 좋지만, 파일이 바뀐 날에는 옛것을 보여 줍니다.

## 배포가 이미 해 둔 것 — 반쯤은 켜져 있을 수 있습니다

배포가 매번 `im-flow` 폴더에 `.htaccess` 라는 작은 설정 파일을 놓습니다.
그 파일에 「HTML 은 매번 확인」이라고 적혀 있습니다.

**다만 그 파일은 웹 서버가 Apache 일 때만 읽힙니다.** Synology 가 nginx 로
서비스하고 있으면 **조용히 무시됩니다** — 오류도 안 납니다.

★ 그래서 배포가 **실제로 켜졌는지를 재서** 적어 둡니다. GitHub 의 배포 실행
화면 맨 아래 요약에 이렇게 나옵니다.

- `화면 캐시: **매번 확인** (포트 8080)` → **이미 켜졌습니다. 아래를 하실 필요가 없습니다.**
- `화면 캐시: **아직 안 켜짐**` → 아래를 한 번 해 주십시오.

★ **배포가 재는 곳은 포트 8080 하나뿐입니다.** 사장님이 실제로 보시는 길은
443 이라 **재지 못한 길**입니다 — 그래서 위 4번에서 **두 줄 다** 켜시라고
적었습니다. 8080 만 켜면 배포는 「켜졌다」고 하는데 사장님 화면은 그대로입니다.
그 상태가 가장 나쁩니다 — **고쳤다고 적힌 채 안 고쳐진 것**입니다.

## 켜는 법 — 마우스로 (5분)

1. NAS 의 **DSM** 에 로그인하십니다.
2. 왼쪽 위 네모 네 개 아이콘(**주 메뉴**)을 눌러 **Web Station** 을 엽니다.
3. 왼쪽 목록에서 **웹 서비스 포털** 을 누릅니다.
4. 목록에서 줄을 **한 번 클릭**해 고르고 위의 **편집** 을 누릅니다.
   - ★★ **여기서 대개 막힙니다 — 줄을 안 고르면 [편집] 이 회색입니다.**
     〈2026-08-28 실측: 사장님 화면에서 실제로 회색이었다〉 목록만 보고 있으면
     단추가 고장 난 것으로 보입니다. **줄을 클릭하면 색이 들어옵니다.**
   - ★★★ **두 줄 다 해야 합니다** 〈2026-08-28 실측〉. 목록은 대개 이렇습니다:

     | 줄 | 포트 | 누가 쓰는가 |
     |---|---|---|
     | **기본 서버** (기본 포털) | 80 / 443 | 앱에서 화면을 여실 때 이 길로 옵니다 |
     | **기본 서버의 대체 포털** | 8080 | **배포가 재는 길**입니다 |

     두 포털은 **헤더 설정을 따로 가집니다.** 하나만 켜면 화면은 고쳐졌는데
     배포는 계속 「안 켜짐」이라고 하거나, 그 반대가 됩니다.
   - ★ 앞 판은 여기서 「문서 루트가 `web` 인 줄을 고르라」고 적어 두었는데,
     **DSM 목록에 문서 루트 칸이 없습니다**(상태·서비스·호스트 이름·포트·별칭).
     없는 것을 보고 고르라고 한 셈이라 포트로 고치 게 바꿨습니다.
5. 위쪽 탭에서 **사용자 지정 HTTP 헤더** 를 누릅니다.
   - DSM 판에 따라 **사용자 정의 헤더**, **HTTP 헤더** 로 적혀 있기도 합니다.
     셋 다 같은 자리입니다.
   - ★ 그 탭이 아예 없으면 이 포털은 nginx 가 아니라 다른 방식입니다.
     그때는 아래 **「탭이 없을 때」** 를 보십시오.
6. **생성** 을 누르고 두 칸을 채웁니다.
   - **이름**: `Cache-Control`
   - **값**: `no-cache, must-revalidate`
7. **확인** → **저장**.
8. 목록으로 돌아와 **나머지 한 줄**에 대해 4~7 을 그대로 한 번 더 합니다.

### 확인

브라우저에서 보고서 화면을 열고 **새로고침**을 두 번 하십니다.
빨간 띠가 안 뜨면 된 것입니다. 확실히 보시려면 다음 배포의 요약에서
`화면 캐시: **매번 확인**` 이 나오는지 보십니다.

### 이렇게 하면 무엇이 손해인가 — 하나 있습니다

이 설정은 그 포털의 **모든 파일**에 붙습니다. 스크립트·CSS 도 매번 확인하게
되어 화면 뜨는 것이 **아주 조금** 느려집니다(파일이 작아서 체감은 거의 없습니다).

「HTML 만」으로 좁히려면 Apache 쪽 길(위의 `.htaccess`)이 필요합니다.
지금 상태로는 **전부 매번 확인**이 더 안전합니다 — 옛 화면을 보시는 쪽이
훨씬 비쌉니다.

### ★★★ [편집] 이 회색이고 눌러도 안 열릴 때 — 기본 포털은 여기서 못 고친다

〈2026-08-28 실측 — 사장님 화면에서 줄을 골랐는데도 회색이었다〉

**기본 포털(「기본 서버」 80/443)은 DSM 이 만든 줄이라 Web Station 안에서
편집이 막혀 있는 판이 있습니다.** 사용자가 만든 포털(8080)은 열립니다.

먼저 **회색이어도 한 번 눌러 보십시오** — 눌리는 판이 있습니다.
창이 뜨면 5번으로 돌아가시면 됩니다. 아무 일도 안 나면 아래 둘입니다.

**㉮ 8080 줄부터 켠다 (쉽고 지금 바로 된다)**

「기본 서버의 대체 포털」은 **[편집] 이 열립니다.** 위 5~7 을 그대로 하십시오.
이것만 해도 **배포의 판정이 「매번 확인」으로 바뀝니다** — 배포가 재는 곳이
8080 이기 때문입니다.

★ **다만 사장님이 앱에서 보시는 길(443)은 아직 그대로입니다.**
  「배포는 켜졌다고 하는데 화면은 옛것」이 되므로, ㉯ 를 함께 보셔야 합니다.

**㉯ 443 쪽 — 역방향 프록시에 헤더를 단다**

앱이 쓰는 443 은 Web Station 이 아니라 **DSM 의 역방향 프록시**를 지날 수
있습니다.

> **역방향 프록시(reverse proxy)** — 밖에서 온 요청을 받아 안쪽의 다른
> 서버로 넘겨 주는 중계소입니다. 중계소를 지나면 헤더도 중계소가 정합니다.

**제어판** → **로그인 포털** → 위쪽 탭 **고급** → **역방향 프록시**
→ LinkPilot 로 가는 줄을 고르고 **편집** → **사용자 지정 헤더** 탭
→ **생성** → **사용자 지정 헤더** → 이름 `Cache-Control` ·
값 `no-cache, must-revalidate`

★ 목록이 **비어 있으면** 역방향 프록시를 안 쓰는 것입니다. 그러면 443 도
  Web Station 기본 서버가 직접 받으므로, 아래 Apache 길이 남습니다.

### 탭이 없을 때 — Apache 로 바꾸는 길

Web Station 의 **웹 서비스 포털 → 편집 → 일반** 에서 **HTTP 백엔드 서버**를
**Apache** 로 바꾸면 배포가 놓아 둔 `.htaccess` 가 읽힙니다. 그러면 **HTML 에만**
붙어 위의 손해가 없어집니다.

★ 다만 백엔드를 바꾸면 그 포털의 다른 동작(PHP 판·재작성 규칙)이 함께
바뀝니다. **다른 것이 같이 올라가 있는 포털이면 바꾸지 마십시오.**
위의 「마우스로」 길이 더 안전합니다.

## 안 해도 되나

됩니다. 안 켜도 화면이 스스로 한 번 다시 받으므로 빨간 띠는 대개 저절로
사라집니다. 이 설정은 **그 한 번마저 없애는** 것입니다.
