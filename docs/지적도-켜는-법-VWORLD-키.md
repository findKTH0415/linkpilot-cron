# 지적도를 켜는 법 — VWorld 열쇠 넣기

〈2026-08-24 · 사장님이 직접 하시는 일입니다. 15분쯤 걸립니다〉

---

## 이걸 왜 하나

지금 보고서의 건축물 3D 는 **대지를 직사각형으로 근사해서** 세웁니다.
그리고 **조감도는 아예 안 그립니다.**

고장이 아닙니다. 엔진이 일부러 안 그리는 것입니다 — 실제 로그가 이렇습니다.

> 지적 필지 형상이 없어 조감도를 그리지 않았다. 대지 모양을 근사해서 그리면
> **실제 필지처럼 보이는 그림**이 된다 — 그건 매스 검토와 달리 그럴듯하게 틀린다.

VWorld 열쇠를 넣으면 **국가 지적도의 실제 필지 모양**을 받아옵니다. 그러면:

- 매스가 **진짜 땅 모양대로** 섭니다 (직사각형 근사가 사라집니다)
- **조감도가 그려집니다**
- 개별공시지가·용도지역이 자동으로 들어옵니다 (지금은 안 들어옵니다)

**무료입니다.** 국토교통부가 운영하는 공공 서비스입니다.

붙여 넣기만** 하시면 됩니다.

## 1단계 · VWorld 에 가입하고 열쇠를 받는다

### ① 회원가입

브라우저에서 **`vworld.kr`** 로 갑니다. 오른쪽 위 **[회원가입]**.

- 개인 회원으로 가입하셔도 됩니다.
- 여기서 대개 막히는 곳: **본인확인**을 요구합니다. 휴대폰 인증이 가장 빠릅니다.

### ② 오픈API 인증키 신청

위쪽 메뉴에서 **[오픈API]** → **[인증키 발급]** 으로 갑니다.
(메뉴 이름이 바뀌어 있으면 **[개발자센터]** 안에 있습니다.)

**[인증키 신청]** 을 누르면 칸이 여럿 나옵니다. 채우실 것은 넷입니다.

| 칸 | 무엇을 넣나 |
|---|---|
| **활용 용도** | 「부동산 투자 검토 자료 작성」 정도로 적으시면 됩니다 |
| **서비스 구분** | **서버(Server)** 를 고릅니다 — 웹/모바일이 아닙니다 |
| **서비스 URL** | **★ 여기가 제일 중요합니다. 아래 ③ 을 보십시오** |
| **활용 API** | 아래 목록을 **전부** 고릅니다 |

고르실 API — 이 다섯입니다. 하나라도 빠지면 그 기능만 조용히 안 됩니다.

- **2D 지도 API** (위성지도)
- **지오코더 API** (주소 → 좌표)
- **데이터 API** (필지 조회)
- **국가공간정보 - 연속지적도** (필지 모양 — **조감도가 여기서 나옵니다**)
- **국가공간정보 - 개별공시지가**, **국가공간정보 - 용도지역지구**

### ③ 서비스 URL — 여기가 함정입니다

VWorld 는 **「어느 주소에서 부를 것인지」를 등록**받고, 요청이 올 때 그 주소와
대 봅니다. 안 맞으면 거절합니다.

★ **여기서 적으신 주소를 그대로 기억해 두셔야 합니다.** 2단계에서 **글자 하나
안 틀리게** 다시 넣습니다. 스크린샷을 찍어 두시는 것을 권합니다.

★★ **`https://` 를 빼지 마십시오.** 주소만 적고 `https://` 를 떼면
공시지가·용도지역 조회가 **다섯 번에 두 번꼴로** 거절당합니다. 그런데 나머지
세 번은 되기 때문에 **「가끔 값이 안 들어온다」로만 보여** 원인을 찾는 데
가장 오래 걸립니다. (이 저장소에서 실제로 겪은 일입니다 — CLAUDE.md §4.1)

무엇을 적을지 모르시겠으면 **LinkPilot 화면 주소를 그대로** 적으시면 됩니다.
그 주소가 무엇인지는 저(Claude)에게 물어보시면 알려 드립니다 — 이 문서에는
적지 않습니다(공개 저장소라서 그렇습니다).

### ④ 승인을 기다린다

대개 **즉시** 나옵니다. 늦어도 하루입니다.
**[오픈API]** → **[인증키 관리]** 에 들어가면 발급된 키가 보입니다.

키는 **영문·숫자·하이픈이 섞인 36자**입니다. 이렇게 생겼습니다 —
`XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX` (X 자리에 글자가 들어 있습니다).

## 2단계 · GitHub 에 넣는다

여기가 실제로 켜지는 곳입니다. **두 개**를 넣습니다.

### 어디로 가나

브라우저에서 `github.com/findKTH0415/linkpilot-cron` 로 갑니다.

**[Settings]** (저장소 이름 줄의 맨 오른쪽 톱니바퀴 탭입니다 — 계정 설정이
아니라 **저장소** 설정입니다)
→ 왼쪽 목록에서 **[Secrets and variables]**
→ 그 아래 **[Actions]**

★ 여기서 대개 막힙니다: **[Secrets and variables]** 를 누르면 접혀 있던 것이
펼쳐집니다. 그 안의 **[Actions]** 를 한 번 더 눌러야 합니다.

### 넣기

초록색 **[New repository secret]** 단추를 누릅니다. 칸이 둘 나옵니다.

**첫 번째 — 열쇠**

| 칸 | 넣을 것 |
|---|---|
| **Name** | `VWORLD_KEY` |
| **Secret** | 1단계 ④ 에서 받은 36자 키 |

**[Add secret]** 을 누릅니다.

**두 번째 — 주소**

다시 **[New repository secret]** 을 누릅니다.

| 칸 | 넣을 것 |
|---|---|
| **Name** | `VWORLD_DOMAIN` |
| **Secret** | 1단계 ③ 에서 **VWorld 콘솔에 적으신 서비스 URL 을 글자 그대로** |

**[Add secret]** 을 누릅니다.

### 넣으실 때 조심할 것 셋

1. **이름의 대소문자와 밑줄이 정확해야 합니다.** `VWORLD_KEY` 입니다 —
   `Vworld_Key` 나 `VWORLD-KEY` 는 다른 이름이라 안 읽힙니다.
2. **앞뒤 빈칸이 딸려 오지 않게** 하십시오. 복사할 때 딸려 오는 빈칸 하나가
   인증 실패를 만드는데, 화면에는 「키가 틀렸다」로만 나옵니다.
3. **따옴표를 붙이지 마십시오.** 값만 넣습니다.

★ 한 번 넣으면 **다시 볼 수 없습니다.** GitHub 이 값을 감춥니다. 틀렸으면
같은 이름으로 다시 넣으면 덮어씁니다 — 지웠다 만들 필요 없습니다.

## 3단계 · 배포를 한 번 돌린다

Secret 은 **다음 배포 때** NAS 로 옮겨집니다. 지금 켜려면 한 번 돌려야 합니다.

저에게 **「배포 돌려줘」** 라고 말씀하시면 제가 겁니다. 직접 하시려면:

같은 저장소에서 위쪽 **[Actions]** 탭 → 왼쪽 목록에서 **[deploy-nas]**
→ 오른쪽의 **[Run workflow]** → **`dry_run` 을 `false` 로 바꾸고**
**`engine` 을 `yes` 로** 두고 **[Run workflow]**.

★★ **`dry_run` 을 안 바꾸면 초록으로 끝나는데 아무것도 안 올라갑니다.**
기본값이 `true` 라서 그렇습니다. 「성공」이라고 뜨는데 켜지지 않은 상태가 됩니다 —
실제로 두 번 그랬습니다.

## 4단계 · 켜졌는지 확인한다

배포가 끝나면 그 실행 화면 맨 아래 **Summary** 에 이 줄이 있어야 합니다.

> **지적도: 켜짐 — 실제 필지 형상으로 매스가 선다**

이 줄이 셋 중 하나로 나옵니다. **셋이 서로 다른 뜻입니다.**

| 나오는 말 | 뜻 | 할 일 |
|---|---|---|
| **지적도: 켜짐** | 됐습니다 | 없음 |
| **지적도: 꺼짐** | 키가 안 들어갔습니다 | Secret 이름 철자를 다시 봅니다 |
| **지적도: 못 쟀다** | 재는 것 자체가 실패했습니다 | **꺼진 것과 다릅니다.** 저에게 말씀해 주십시오 |

그리고 **보고서를 한 번 만들어 보십시오.** 「매스 검토」 줄에 있던 노란 경고
두 개 — 「지적도 폴리곤이 없어 직사각형으로 근사했다」와 「조감도를 그리지
않았다」 — 가 **사라져 있어야** 합니다.

## 안 되면

**먼저 `MEMORY.md` 를 찾아 주십시오** — 같은 결의 사고가 이미 적혀 있을 가능성이
높습니다. 그래도 안 되면 저에게 말씀해 주시되, **화면에 나온 말을 그대로**
알려 주시면 훨씬 빠릅니다. 「안 돼요」와 「지적도: 못 쟀다」는 **다른 사실**이고
고치는 곳도 다릅니다.

## 딸려 오는 변화 하나 — 미리 알려 드립니다

이 작업을 하면서 배포의 열쇠 처리를 함께 고쳤습니다.

**앞 판은 배포할 때마다 NAS 의 열쇠 파일을 통째로 덮으면서 `GEMINI_API_KEY`
한 줄만 다시 썼습니다.** 그래서 NAS 에 손으로 넣어 두신 다른 키가 있었다면
**배포할 때마다 조용히 지워지고 있었습니다.**

이제는 아는 열쇠를 전부 Secret 에서 받아 쓰고, **앞 파일에 있었는데 Secret 에
없는 키가 있으면 이름을 대고 알려 줍니다.** 배포 Summary 에 이런 줄이 뜨면
그 키도 같은 방법으로 Secret 에 넣어 주시면 됩니다.

> ⚠️ 앞 파일에만 있던 열쇠: DATA_GO_KR_KEY (Secret 에 넣으면 다음 배포부터 실린다)

앞 판 파일은 NAS 에 `linkpilot.env.bak-<시각>` 으로 그대로 남아 있습니다.
