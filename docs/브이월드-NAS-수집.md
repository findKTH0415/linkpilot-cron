# 브이월드 수집을 «국내 자리(NAS)»에서 돌리는 법

〈2026-09-19 · D-223 · CLAUDE.md §4 · §12-33〉

**왜 국내 자리인가.** GitHub Actions 러너(해외 IP)에서 브이월드가 지오코더·이미지·WMS 를
**`502 Bad Gateway` 한 줄**로 끊는다(2026-09-18·19 실측 · 키·도메인 문제가 아니다 —
`data/yeoui893/vworld_diag.json`). NAS 는 국내 IP 다.

---

## 1. 무엇이 바뀌었나

| | 앞 판 (내림) | 지금 |
|---|---|---|
| 도는 자리 | 러너 → tailnet → ssh → NAS 의 curl | **NAS 가 스스로** |
| 거는 법 | Actions 의 `yeoui893-nas.yml` | DSM 「작업 스케줄러」 · `npm run yeoui893:nas` |
| 접속 자격증명 | **수집 잡이 들고 있었다** (규정집 2-8 위반) | **한 글자도 없다** |
| 결과 | 기본 가지에 자동 커밋 | NAS 안에 남는다 (아래 §3) |

★ **앞 판을 「지웠다」가 아니라 「내렸다」로 적는다** (§8 · M-52). 되살리는 법은 §5.

---

## 2. 사장님이 하실 일 — DSM 작업 스케줄러에 한 번 등록

**① 어디서** — 웹브라우저로 **NAS 관리화면(DSM)** 에 로그인 → **[제어판]** →
**[작업 스케줄러]**.

**② 무엇을** — 위쪽 **[생성]** → **[예약된 작업]** → **[사용자 정의 스크립트]**.

**③ 어떻게**
- **일반** 딱지: 작업 이름을 아무거나 적고(예: `여의동 브이월드 수집`),
  **사용자**를 엔진이 깔린 폴더를 읽을 수 있는 계정으로 둡니다.
- **스케줄** 딱지: 원하시는 주기. 하루 한 번이면 충분합니다 — 브이월드는
  **일 호출 한도**가 있습니다 (§4.5).
- **작업 설정** 딱지 → **사용자 정의 스크립트** 칸에 **두 줄**을 적습니다.
  첫 줄은 엔진이 깔린 폴더로 가는 `cd`, 둘째 줄은 `bash im-agent/tools/yeoui893-nas.sh`.
  ★ **폴더 주소는 여기 안 적습니다** — 이 저장소는 공개입니다 (§2 · D-10).
    그 값은 세션 답변으로 드렸습니다. `calendar-nas.sh` 작업이 이미 등록돼 있으면
    **그 작업의 첫 줄과 같은 폴더**입니다.

**④ 그러면** — 목록에 그 작업이 한 줄 생깁니다. 골라서 **[실행]** 을 누르시면 바로 한 번
돌고, **[작업]** → **[결과 보기]** 에 아래 §4 의 글이 그대로 찍힙니다.
★ 실패하면 **「node 를 못 찾았다」**가 먼저 뜹니다 — 그때는 §6 을 보십시오.

---

## 3. 결과가 어디에 남나

기본은 엔진 폴더 안 `data/yeoui893/` 입니다.

**앱이 HTTP 로 읽을 자리로 옮기려면** 작업 설정의 스크립트 첫 줄에
`export LP_YEOUI_WEB=…` 를 한 줄 더 넣으십시오. 그 값도 여기 안 적습니다 —
`calendar-nas.sh` 의 `LP_CALENDAR_WEB` 과 같은 결입니다.

★★ **저장소에는 자동으로 안 올라갑니다.** 앞 판 워크플로는 기본 가지에서 돌면
`data/yeoui893` 를 커밋했는데, 지금은 NAS 안에 남습니다 — **없어진 사실이라 적어 둡니다**
(§12 의 날씨 교훈). 저장소에 올리려면 사람이 받아서 커밋합니다.

---

## 4. 되돌아오는 값 — 값마다 하실 일이 다릅니다

| 값 | 뜻 | 하실 일 |
|---:|---|---|
| **0** | 받았다 | 없음 |
| **3** | 자리·node 가 없다 | §6 |
| **4** | 돌기는 했는데 **한 건도 못 받았다** | 요약 **맨 앞의 판정**을 봅니다 — 아래 ★ |
| **5** | 받았는데 **앱 자리로 못 옮겼다** | 그 폴더 권한 |

★ **값 4 안에 할 일이 정반대인 것들이 들어 있습니다.** 요약 맨 앞 판정이 그것을 갈라 적습니다 —
**「그쪽 서버 5xx」**(기다렸다 다시 · 우리 쪽에 고칠 것 없음) · **「인증 거부」**(브이월드 콘솔의
서비스URL·활용API) · **「못 닿음」**(그 자리에서 밖이 안 열림) · **「주소 미매칭」**(주소 표기).
**뭉뚱그려 읽지 마십시오** — 셋은 서로 다른 곳을 고치는 일입니다 (§12-24).

---

## 5. 되살리는 법 (Actions 로 다시 돌리고 싶을 때)

`git log --diff-filter=D -- .github/workflows/yeoui893-nas.yml` 로 내린 커밋을 찾아
`git revert` 합니다. 다만 그러면 **수집 잡이 NAS 접속 자격증명을 다시 갖게 되고**,
`im-agent/test/workflow-shape.test.js` 의 「수집 잡에 NAS 접속 자격증명이 없다」 칸이
**그 자리에서 빨개집니다** — 그것이 이 고침의 요점입니다 (§4 · 규정집 2-8).

★ 그 우회 코드(`VW_VIA=nas` · `viaNas`)도 같은 커밋에서 함께 지웠습니다.
「꺼 두기」로 남겨 두지 않은 이유는 §6-2-6 입니다 — 부르는 자리가 0곳인 코드를 남기면
누가 되살리는 순간 규칙이 다시 깨집니다.

---

## 6. 「node 를 못 찾았다」가 뜨면

DSM 「패키지 센터」에서 Node.js 가 **실행 중**인지 먼저 보십시오.
**실행 중인데도** 그 말이 나오면 **깔려 있지 않은 것이 아니라** 작업 스케줄러가 주는
`PATH` 가 좁아 그 자리를 못 보는 것입니다. 작업 설정 스크립트 첫 줄에 `PATH` 를 넓히는
한 줄을 더하면 됩니다 — 그 줄은 `calendar-nas.sh` 작업에 이미 들어가 있으므로
**그 작업의 설정을 그대로 보고 베끼시면 됩니다.**

★ 이 스크립트는 판 번호를 안 박고 **DSM 이 까는 자리 넷을 훑습니다** — v20 이든 v22 이든
다음 판이든 잡힙니다 (§4 의 그 교훈).
