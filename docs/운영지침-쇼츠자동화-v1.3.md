## 1. 목표와 기본 운영안

**한 기업·한 전환점·한 가지 적용 아이디어**를 전달하는 짧은 비즈니스 콘텐츠를 제작한다. 기업 성공담을 단순 요약하는 데서 끝내지 않고 확인된 사건·선택·성과와 시청자가 생각해 볼 질문을 연결한다.

| 항목 | 운영 초기 기본안 | 구분 |
|---|---|---|
| 대주제 | 글로벌 비즈니스 성공스토리 | 사용자 지정 고정값 |
| 주간 세부 주제 | 고객 문제 해결·위기 극복·해외 진출·사업모델 혁신 등 | 주간 편성값 |
| 발행량 | **주 1편** | 첨부 시안 기준. 이전 주 5편 제안은 확장 옵션으로 이동 |
| 길이 | **50~58초** | 기본안. 30초·2분 이내는 지원 채널을 확인한 선택 옵션 |
| 기본 화면 | 세로형 9:16, 1080×1920, 30fps, MP4(H.264/AAC) | 제작 기본안·채널별 지원 규격 대조 |
| 기본 언어 | 한국어 나레이션·한글 자막 | 영어·베트남어 음성과 자막을 별도 선택 |
| 기본 자막 제공 | 한글 자막 영상·한국어/영어 자막 파일 | 베트남어는 선택. 여러 언어를 한 화면에 겹쳐 넣지 않음 |
| 초기 배포 | **YouTube Shorts + 파일 내려받기** | TikTok·Reels는 권한·정책·구현 확인 후 활성화 |
| 회사·채널 정보 | **[회원 사용자]가 연결한 채널·프로필** | 다른 회원의 브랜드·계정과 분리 |

주간 대주제는 유지하고 세부 주제·국가·산업·기업·핵심 질문을 바꾼다. **국경을 넘는 거래·현지 파트너십·해외 진출·위기 극복·작은 회사의 도약**을 우선 관점으로 둔다. 매주 자동 실행할 시간·계정·예산은 앱 설정으로 받는다. 본 지침 작성만으로 실제 반복 작업을 만들지 않는다.

## 2. 앱 배치·메뉴

LinkPilot에 적용할 경우 **앱센터 → 쇼츠 자동화**로 제공하고, **오늘의 인사이트 → 동영상 만들기**에서 연결하는 구성을 기본안으로 한다. 현행 메뉴·권한과 중복 여부를 확인한 후 적용한다.

| 메뉴 | 주요 기능 |
|---|---|
| 주간 테마 | 주차·세부 주제·기업·국가·발행 편수·작업 진행 |
| 소재함 | 검색 후보·원문·중복 확인·후보 선택 |
| 검증함 | 주장별 근거·상충 정보·자료 이용 조건 |
| 대본·장면 | 내레이션 원고·자막·강조 문구·장면표 |
| 나레이션 | 목소리·언어·발음 사전·부분 재생성·길이 |
| 제작·편집 | 장면 카드·자산·자막·음악·선택 엔진 미리보기·부분 수정·최종 출력 |
| 배포·성과 | 채널·게시 설정·예약·처리 상태·게시 링크·성과 |

첨부 시안처럼 **왼쪽은 이번 주 설정, 오른쪽은 7단계 진행과 선택 단계 상세**로 구성한다.

- 왼쪽 설정: 고정 테마·이번 주 관점·나레이션 언어·자막 언어·길이·배포 채널.
- 오른쪽 단계: ① 소재 검색 → ② 검증 → ③ 대본 → ④ 나레이션 → ⑤ 영상 → ⑥ 최종 확인 → ⑦ 배포.
- 검증 확인과 최종 확인은 주의색 테두리·문구·아이콘으로 구분한다. 색만으로 구분하지 않는다.
- 상태는 실제 서버 작업 결과로 표시한다. 시안에 있는 ‘완료’, ‘사실 확인’, ‘54초’는 예시이며 초기 실제값으로 저장하지 않는다.
- 데스크톱은 설정–진행 2단, 모바일은 설정 접기·단계 상세·미리보기 순으로 구성한다.
- 작업 목록·현재 단계·미리보기·다음 행동을 보여주고 대기·실행·완료·오류·보류·재시도를 구분한다.
- 개발 용어와 내부 프롬프트는 회원 화면에 노출하지 않는다.

## 3. 주간 콘텐츠 편성

### 3.1 기본 주간 운영

주 1편을 기본으로 운영한다. 기존 ‘월~목 기업 4편 + 금요일 비교 1편’은 자료·예산·처리능력을 확보한 뒤 선택할 수 있는 확장 편성이다. 확장 편성에서도 확인 절차를 생략하지 않는다.

| 시점 | 작업 | 회원 개입·조건 |
|---|---|---|
| 월 08:53 | 소재 후보 5개 수집·상위 3개 요약·알림 | 첨부 시안의 초기 설정안. 시간대·계정·활성화는 회원이 지정 |
| 월~화 | 주제 1개 선택·사실 카드 검증 | **확인 A: 주제 선택·검증 예외 해결·사용할 사실 확인** |
| 수 | 대본·텍스트·장면·음성·영상 생성 | A 완료 후 ③~⑤를 이어서 실행 |
| 목 | 휴대폰 크기 미리보기·자동 점검 | **확인 B: 영상·설명문·채널·공개 설정·게시 시각 확인** |
| 금 18:00 | YouTube 예약 공개·다운로드 묶음 준비 | B가 완료된 지정 버전만 처리 |
| 게시 후 7일 | 주간 성과 리포트 | 실제 게시 시각 기준. 다음 월요일의 초기 관측과 구분 |

월요일 08:53·금요일 18:00은 시안의 제안 시각이다. 이 파일을 만들었다고 예약 작업이 활성화된 것은 아니다. 마감 전 확인이 없으면 해당 주를 보류한다. 다음 주로 임의 이월 공개하지 않는다. 휴일·시차·지연 시에는 새 게시 시각을 선택하게 한다.

### 3.2 주간 관점·중복 관리

- 해외 진출·현지 파트너십·위기 극복·작은 회사의 도약 중 이번 주 관점을 선택한다.
- 시안의 ‘지난 12주 국가 전체 제외’는 완화한다. **동일 기업+동일 사건의 반복을 우선 제외**하고 같은 국가의 다른 기업은 편성 균형을 보며 허용한다.
- 회원 관심국은 후보 정렬에 반영하되 특정 국가만 계속 선택되지 않도록 분포를 보여준다.
- 화제성·근거 확보 가능성·국경 간 사업 관련성·권리 부담이 낮은 시각화 가능성으로 후보를 비교한다.
- 선정 점수는 소재 선택 보조값이다. 사실 확인 완료 점수로 사용하지 않는다.

## 4. 소재 검색

### 4.1 수집 범위

- 기업 공식 연혁·연차보고서·투자자 자료·보도자료.
- 원문이 확인되는 인터뷰·공개 강연·공식 제품 설명.
- 사건·수치를 대조할 독립 언론·공공기관·연구 자료.
- 해당 국가 언어의 원문과 필요한 번역.

단순 검색 요약·재인용 글·SNS 문구만으로 핵심 주장을 확정하지 않는다. 동일 보도자료를 여러 사이트가 복제한 경우 독립 근거 여러 개로 세지 않는다.

초기 수집은 정상적으로 이용 가능한 무료 공개 자료를 우선한다. 위키백과·뉴스 제목·관심도 자료는 탐색 보조로 사용한다. SEC EDGAR·세계은행 통계는 해당 기업·주장과 관련 있을 때만 연결한다. 모든 기업에 공시나 통계가 있다고 가정하지 않는다. Google Trends 등은 실제 접근 가능한 제공 방식·조건을 확인하고, 미확인 무료 API가 있다고 기재하지 않는다. 유료 시세·신용정보는 초기 범위에서 제외한다. 무료 자료 수집과 AI 음성·영상 생성 비용은 별도이다.

### 4.2 소재 카드

| 필드 | 내용 |
|---|---|
| 소재 식별자 | 주차·기업·사건을 구분하는 내부 식별값 |
| 기업·국가·산업 | 원문에서 확인되는 기본 정보 |
| 후보 제목 | 사실을 벗어나지 않는 관심 유도 문구 |
| 핵심 사건 | 출시·전환·실패·확장 등 특정 사건 |
| 전달 질문 | 시청자가 생각해 볼 질문 |
| 원문 | URL·제목·언어·발표일·사건 발생일·확인일 |
| 과거 사용 | 기존 영상·동일 사건·유사 대본 여부 |
| 자료 후보 | 사진·영상·지도·도표와 확보 상태 |
| 다음 행동 | 검증·추가 수집·보류·제외 |

소재 추천 점수를 사실 검증 완료 표시와 혼용하지 않는다. 공개 자료에 연결된 날짜와 기업의 실제 설립·브랜드 출시·첫 매장 개점일을 구분한다.

## 5. 검증

### 5.1 주장별 근거 기록

대본의 핵심 사실마다 **주장 식별자·문장·원문 근거·위치·날짜·검증 상태**를 연결한다.

- 설립연도·제품 출시일·인물의 직책·성과 수치·발언을 확인한다.
- 매출·이익·거래액·누적 이용자·이용 건수를 다른 지표로 관리한다.
- 금액은 통화·기간·단위·연결/개별 기준을 확인한다.
- 회사 자체 설명과 독립 자료의 확인을 구분한다.
- **기본 확인 기준은 독립적으로 대조 가능한 출처 2곳 이상이며, 그중 1곳 이상은 회사 발표·공시·원문 인터뷰 등 1차 자료**로 한다.
- 동일 1차 자료를 인용한 재게시·백과 문서는 별개의 독립 확인으로 자동 계산하지 않는다.
- ‘회원 직접 입력’은 추가 주장 또는 회원 제공 자료이다. 별도 근거 검증 없이 두 번째 출처나 확인 완료로 바꾸지 않는다.
- 기준을 충족하지 못하면 숫자를 빼고 근거가 있는 표현으로 바꾸기·추가 조사·문장 제외·보류 중 선택한다. ‘공동 소유’처럼 일반화한 표현도 근거가 필요하다.
- 사실과 제작자의 해석을 분리한다. 성공을 특정 행동 하나의 결과로 확정하지 않는다.
- 과거 성과를 현재 규모로 표현하거나 계획·목표를 달성 실적으로 바꾸지 않는다.
- 실제로 하지 않은 말을 인용문으로 만들지 않는다.

### 5.2 검증 상태

| 상태 | 처리 |
|---|---|
| 제작 가능 | 최종 대본에 사용할 모든 사실 카드가 확인 기준을 충족하고 자산 조건이 갖춰진 소재 |
| 추가 확인 | 근거·시점·지표·자료 조건을 더 확인할 소재 |
| 보류 | 상충 정보·원문 부재·사용 불가 자산 등으로 진행할 수 없는 소재 |

사실 검증과 자산 이용 가능 상태는 별도로 기록한다. 대본에서 제외한 주장은 ‘미사용/제외’로 남기고 제작 입력에서 빼낸다. **실제 사용 문장에 연결된 사실 카드**가 기준을 통과해야 ③으로 진행한다. 제외한 후보 사실까지 확인 완료로 바꾸지 않는다. 시안의 예시 ‘확인’ 배지는 실제 검증 상태로 가져오지 않는다.

### 5.3 사진·영상·음성·음악

- 인터넷에 공개됐다는 이유만으로 재사용 가능한 자산으로 처리하지 않는다.
- 공식 기업 사이트의 사진도 이용 조건·출처 표시·허용 범위를 확인한다.
- 원본·소유자/제공자·취득 경로·허용 범위·조건·확인일을 저장한다.
- **초기 기본 정책은 실존 인물 얼굴 합성·목소리 모방·회사 로고·제품 사진을 사용하지 않는 것**이다.
- 지도·연표·숫자 그래픽·직접 제작 일러스트를 기본 시각 자산으로 사용한다. 기업명·제품명 텍스트와 해당 로고/제품 사진은 구분한다.
- 공식 사이트의 이미지가 사용 가능해 보이더라도 초기 정책에서 제외한 자산은 자동 삽입하지 않는다.
- 향후 자산 정책을 변경할 경우 실제 기업 영상·스톡·직접 제작 도표·AI 생성/재연 장면의 이용 조건을 각각 기록한다.
- AI 장면을 실제 당시 촬영 영상으로 표시하지 않는다.
- 실제 인물의 말·행동을 허위로 재현하지 않는다. 등록한 나레이션 음성 또는 적절한 사용 권한이 있는 음성을 사용한다.
- 불명확한 자산은 다른 자산·직접 제작한 도식으로 대체한다.

## 6. 대본·텍스트·장면 설정

### 6.1 대본 구성

**첫 3초 질문 → 출발 → 막힌 순간 → 전환점 → 확인된 결과·적용 질문** 순으로 구성한다. 50~58초가 기본이지만 실제 음성 길이로 확정한다.

- 첫 문장은 과장 대신 호기심을 유도한다. 첫 화면은 기업 로고·제품 사진 대신 질문 문구와 자체 시각 자산으로 구성한다.
- 한 편에서 사건 하나와 핵심 아이디어 하나를 중심으로 설명한다.
- 쉬운 한국어·짧은 문장을 사용한다.
- 모든 기업에 통하는 성공 공식처럼 표현하지 않는다.
- ‘무조건 성공’, ‘성공 이유는 단 하나’ 등 근거를 넘는 단정은 쓰지 않는다.
- 출처·작성과정·AI 작업 설명을 나레이션에 기계적으로 끼워 넣지 않는다. 출처는 설명란과 필요한 화면 주석에 연결한다.

### 6.2 세 가지 텍스트를 분리한다

| 텍스트 | 목적 |
|---|---|
| 나레이션 원고 | 음성으로 들었을 때 자연스러운 설명 |
| 자막 | 실제 음성과 동기화된 읽기 쉬운 문장 |
| 강조 문구 | 한 화면의 핵심 단어·질문·숫자 |

대본 전체를 강조 문구로 화면에 넣지 않는다. 화면 강조 문구는 시안처럼 10자 안팎을 작성 목표로 하되 강제 잘라내지 않는다. 자막은 짧게 나누고 기본적으로 2줄 안에서 읽히게 구성한다. 글자 수 제한은 실제 글꼴·기기·안전영역 미리보기로 정한다. **‘대본 168자=약 52초’ 등 글자 수만으로 재생시간을 확정하지 않는다.**

### 6.3 장면표 필드

장면마다 **장면 번호·예상 구간·연결 대본·강조 문구·화면 설명·자산·모션·출처·재연 표시·자막 위치**를 기록한다. 예상 시간은 나레이션 전 가안이다. 음성 생성 후 실제 시간을 기준으로 갱신한다.

## 7. 나레이션 — 필수 독립 단계

### 7.1 회원 설정

- 언어·목소리·해설 톤·속도·쉼·발음 사전.
- 초기 목소리는 차분한 해설형 2종을 기본안으로 등록한다. 실제 사용 가능한 음성만 노출한다. 짧은 미리듣기와 선택 결과를 저장한다.
- 한국어·영어·베트남어 중 실제 지원 언어의 음성을 선택한다. 동일 주간 시리즈의 기본 목소리를 재사용하되 회원이 변경할 수 있게 한다.
- 음성 사용 가능 범위와 연결 계정·서비스의 상태를 관리한다.

### 7.2 처리 순서

1. 검증된 대본 버전을 고정한다.
2. 기업명·인명·국가명·통화·연도·비율의 읽는 표현을 정리한다.
3. 나레이션을 생성한다.
4. 실제 길이·문장별 구간·쉼을 확인한다.
5. 오독·잘림·의미 변화가 있는 문장만 수정·재생성한다.
6. 확정 음성으로 자막과 장면 시간을 정렬한다.

### 7.3 발음·길이 검수

- ALDI·UNIQLO·Decathlon 등 이름은 선택 언어의 읽는 표현을 사전에 등록한다.
- 약어·소수·음수·연도·외화·단위를 원문의 의미에 맞게 읽는다.
- 표기 숫자와 읽는 숫자가 일치해야 한다.
- 길이가 초과하면 의미를 유지해 대본을 다듬고 필요한 사실을 재검증한다. 무리하게 음성을 빠르게 만들지 않는다.
- 나레이션 변경 시 이후 자막·타임라인·영상은 갱신 필요 상태로 전환한다.
- 음성 파일과 실제 재생시간·원고 버전·생성 조건을 함께 저장한다.

## 8. 영상 제작·편집 — OpenMontage + Remotion + HyperFrames

### 8.1 기본 제작 방식

**OpenMontage는 에이전트가 제작 절차와 도구를 실행하기 위한 기반으로 사용하고, Remotion과 HyperFrames는 승인된 장면 데이터를 영상으로 합성하는 선택 엔진으로 둔다. 데이터·도표 중심은 Remotion, 타이포그래피·모션 중심은 HyperFrames를 추천하되 실제 템플릿 지원 여부로 선택한다.** 웹 편집 화면·회원 권한·작업 큐·배포 어댑터는 LinkPilot에서 구현한다. 도구 설치만으로 회원용 자동화 서비스가 완성됐다고 표시하지 않는다.

지도·연표·숫자 그래픽·직접 제작 일러스트·나레이션을 기본으로 구성한다. 초기에는 실존 인물 얼굴 합성·목소리 모방·회사 로고·제품 사진을 제외한다. 필요한 장면에만 허용된 AI 영상을 사용하고 모든 장면을 새 AI 영상으로 만들도록 강제하지 않는다.

- 확정 음성을 기준으로 장면·자막·배경음악을 배치한다.
- 자막과 화면 문구가 플랫폼의 버튼·설명·프로필 영역에 가려지지 않게 한다.
- 한글·영문·숫자의 잘림과 줄바꿈을 미리보기로 확인한다.
- 사업구도·연혁·국가 이동은 편집 가능한 도식·지도 자산으로 제작한다. Figma를 사용할 경우 편집 원본·버전과 출력 자산을 연결한다.
- 배경음악이 나레이션을 가리지 않게 조정하고 음성 없는 구간·갑작스러운 음량 변화를 확인한다.
- ‘저작권 걱정 없는 음원’으로 일괄 표시하지 않는다. 음원별 출처 표시·상업 이용·사용 채널 조건을 기록한다. YouTube에서 확보한 음원을 다른 플랫폼에서도 사용할 수 있다고 자동 판단하지 않는다.
- MP4의 재생 정보(moov)를 앞쪽에 배치하는 faststart 옵션은 호환성과 스트리밍 시작을 위한 설정이다. 이것만으로 업로드 실패가 방지된다고 보장하지 않는다.
- 사실과 다른 로고·제품 외형·인물·수치를 AI가 생성한 경우 실제처럼 사용하지 않는다.

### 8.2 디자인 규칙

- 일반 한글 자막은 회원이 선택한 읽기 쉬운 글꼴을 사용한다. LinkPilot 기본안은 Paperlogy이다.
- 영문 제목·숫자 강조는 등록된 스타일을 선택할 수 있게 한다. 실제 파일과 지원 글리프를 확인한다.
- 기존 IM 문서의 pt 규격을 쇼츠 화면에 일괄 적용하지 않는다. 영상 해상도와 모바일 가독성에 맞는 별도 규격으로 관리한다.
- 회원 채널의 제목·색상·자막 스타일을 시리즈 전체에 일관되게 적용한다.
- 앱의 홍보 로고·문구를 강제로 넣지 않는다. 채널별 허용 범위와 사용자가 선택한 브랜딩을 따른다.
- 한글판·영문판은 음성 길이와 자막을 별도로 맞춘다. 한국어 음성의 시간표를 다른 언어 영상에 그대로 재사용하지 않는다.

### 8.3 1주차 레드불 견본 처리

첨부 시안의 레드불 대본은 **전체 문장 검증 전 견본**으로 보관한다. 하이라이트된 숫자만 검증하고 나머지 문장을 확정하는 방식은 쓰지 않는다.

| 구간 가안 | 장면 목적 | 실제 작성 조건 |
|---|---|---|
| 0~3초 | 국경 간 사업 연결에 관한 질문 | 미확인 ‘방콕 골목 가게’ 장면을 실제 사건처럼 단정하지 않음 |
| 3~12초 | 출발점·사건 | 인물·출장·음료 경험의 원문이 확인된 경우만 서술 |
| 12~22초 | 파트너 역할·제품 변화 | 합작·개발·맛/탄산 변화의 근거를 각각 연결 |
| 22~32초 | 과정의 장애·출시 | 출시 연도·규제·시장 반응을 자료 없이 극적 갈등으로 만들지 않음 |
| 32~42초 | 전략·전환 | ‘제품이 아니라 이야기였다’ 같은 단일 원인 단정 대신 확인된 활동 설명 |
| 42~52초 | 결과·현재 상태 | 최신 국가 수·지분·소유 구조는 기준일과 원문을 확인한 경우만 사용 |
| 52~58초 | 해석·적용 질문 | 확인된 사실에서 도출한 제작자의 해석임을 구분 |

검증 전에는 위 표의 구조만 사용한다. 미확인 문장을 영상·자막·나레이션·설명란으로 내보내지 않는다. 근거가 확보되지 않으면 문장 제외·대체 소재·보류로 처리한다.

시안의 ‘당신의 해외 거래는 LinkPilot에서’는 **선택 가능한 채널 홍보 문구**로 분리한다. [회원 사용자]가 편집·삭제할 수 있어야 하며 모든 회원 영상에 강제하지 않는다. TikTok판 등에서는 플랫폼 정책상 앱 홍보 문구·워터마크가 허용되는지 확인하고, 허용되지 않으면 해당 판에서 제외한다.

### 8.4 역할 분담과 연동 원칙

공식 저장소는 OpenMontage를 AI 코딩 에이전트가 제작 지침·도구·체크포인트를 실행하는 구조로 설명한다. 단일 호스팅 API로 간주하지 않는다. Remotion 공식 문서는 React 앱 내 Player와 서버 렌더링 API를 제공한다. HyperFrames 공식 저장소는 HTML 기반 영상 제작·렌더 도구를 제공한다. 다음 표의 연동·제품 동작은 **이를 바탕으로 정한 LinkPilot 개발 규격**이며, 이미 작동하는 연동 결과가 아니다.

| 구성 | 맡을 역할 | 별도로 구현할 부분 |
|---|---|---|
| LinkPilot Shorts | 회원 설정·주간 편성·사실 확인 A·최종 확인 B | 인증·권한·작업 큐·비용·버전·배포 상태 |
| OpenMontage 기반 실행기 | 승인 입력으로 장면 계획·자산 작업·품질 점검을 실행 | 비대화형 에이전트 실행 어댑터·중단/재개·결과 정규화 |
| 외부 TTS 어댑터 | 선택 음성으로 나레이션 파일 생성 | 공급자 인증·실제 지원 음성·발음·길이·시간 정렬 |
| Remotion Composition | 장면·도표·텍스트·자막·오디오를 프레임 기준으로 합성 | 시리즈 템플릿·소품 데이터 규격·레이아웃 |
| Remotion Player | 동일 Composition의 편집 미리보기 | 장면 선택·폼·타임라인 조작·저장·실행 취소 |
| Remotion Renderer | Remotion을 선택한 버전의 MP4·표지 이미지 출력 | 서버 워커·자원 제한·출력 검증 |
| HyperFrames 어댑터 | HTML/CSS·탐색 가능한 애니메이션 기반 제작·미리보기·렌더 | 공통 장면 데이터 변환·안전한 미리보기·워커·프레임 동기화 |
| FFmpeg·ffprobe | 필요한 변환·최종 미디어 검사 | 코덱·길이·오디오·재생 가능 여부 검사 |
| 배포 어댑터 | 승인 영상의 YouTube 전송·예약·상태 확인 | 채널 인증·중복 방지·동의·실제 공개 확인 |

- OpenMontage가 기획을 지원해도 5장의 주장별 검증 기준을 통과한 사실만 대본에 사용한다. 자동 점검은 사실 확인 A/B의 대체가 아니다.
- Remotion과 HyperFrames는 TTS나 생성형 영상 모델이 아니다. 나레이션·이미지·영상 파일을 입력받아 합성한다.
- Player만 연결하면 완성된 편집기가 생기는 것은 아니다. 편집 명령과 저장 동작은 별도 구현한다.
- 초기 기본값은 Remotion이며 HyperFrames 선택도 제공한다. 제작 제안 단계에서 `render_runtime`을 선택하고 해당 콘텐츠 버전에 고정한다. OpenMontage의 출력 경로를 조용히 전환하지 않는다. 실제 지원 옵션 이름은 채택한 저장소 버전에서 대조한다.
- Typecast 등 기존 음성은 별도 TTS 어댑터 또는 회원이 제공한 권한 있는 음성 파일로 받는다. OpenMontage의 기본 내장 연동으로 지원된다고 가정하지 않는다.
- 공개 홈페이지나 GitHub 코드 확인만으로 한국어 발음·자막 품질·상용 다중 회원 운영이 검증됐다고 표시하지 않는다.

### 8.5 제작·편집 화면

기존 7단계 중 **⑤ 영상**을 제작·편집 작업실로 확장한다. ④ 나레이션과 ⑥ 최종 확인은 유지한다. 회원 화면에는 도구명 대신 수행할 작업을 우선 표시한다.

| 화면 영역 | 표시·조작 |
|---|---|
| 상단 | 기업·주차·언어판·길이·저장 상태·현재 버전 |
| 왼쪽 장면 목록 | 질문·출발·문제·전환·결과·적용 질문의 장면 카드 |
| 중앙 | 9:16 선택 엔진 미리보기, 재생·일시정지·구간 이동·안전영역 미리보기 |
| 오른쪽 속성 | 문구·자산·강조색·글꼴·전환·자막 위치·음량 |
| 하단 타임라인 | 장면·나레이션·자막·음악 트랙과 실제 길이 |
| 하단 실행 영역 | 저장·선택 장면 다시 만들기·미리보기 갱신·최종 영상 만들기 |

- 장면 순서·길이·자산 교체·문구 수정·실행 취소를 제공한다. 첫 구현은 장면 카드와 속성 폼을 우선하고 자유 편집 타임라인은 후속으로 확장할 수 있다.
- 순서 변경 시 관련 음성·자막 구간도 함께 재배치한다. 대본 의미나 사실이 바뀌면 재검증 대상으로 돌린다.
- 상태는 ‘장면 준비 중·편집 가능·미리보기 준비·영상 출력 중·확인 필요·완료·오류’로 표시한다. 미리보기 재생 가능 상태를 최종 파일 완료와 구분한다.
- 나레이션 길이를 바꾸지 않는 색상·자막 위치 수정은 TTS를 다시 호출하지 않는다.
- 회원이 입력한 대본·URL을 실행 가능한 React 코드나 셸 명령으로 연결하지 않는다. 승인 템플릿과 검증된 데이터만 렌더 워커에 전달한다.

### 8.6 시리즈 템플릿과 장면 규격

| 템플릿 | 적합한 이야기 | 기본 시각 요소 |
|---|---|---|
| 창업·전환 스토리 | 출발과 사업모델의 변화 | 질문 카드·일러스트·전환 강조 |
| 해외 진출 스토리 | 국가·시장 간 확장 | 이용 권한이 있는 지도·이동 경로·연표 |
| 위기 극복 스토리 | 장애와 전략 변경 | 전후 비교·문제/선택/결과 카드 |
| 비즈니스 모델 설명 | 거래·유통·수익 구조 | 흐름도·주체별 역할·단계 강조 |
| 성과 데이터 스토리 | 확인된 지표의 변화 | 출처 연결 숫자·단위·기간·차트 |

표의 템플릿은 새로 구현할 규격이다. OpenMontage·Remotion·HyperFrames에 해당 이름으로 기본 제공된다는 뜻이 아니다. 수치가 없는 소재에는 임의 차트나 성장률을 만들지 않는다. 장면 수·지속시간은 확정 음성에 맞춘다.

- 9:16·1080×1920·30fps를 기본으로 유지한다. 총 길이 50~58초는 실측 나레이션·장면 구성 후 판정한다.
- 자막은 기본 2줄 안에서 의미 단위로 나눈다. 숫자·통화·기업명이 잘리지 않게 한다. 공급자가 단어별 시간을 주지 않으면 정렬 단계를 거치며, 추정 구간은 검수 전 확정값으로 표시하지 않는다.
- 한 번에 강조할 메시지는 하나로 둔다. 이동 경로·도표 지시선은 겹치지 않게 각도를 주고 간격을 확보한다.
- 정적인 도식의 편집 원본이 필요하면 기존 지침에 따라 Figma 원본과 출력 자산을 연결한다. 영상 내 움직임·합성은 선택한 Remotion 또는 HyperFrames로 처리한다. 모든 프레임을 Figma로 생성하지 않는다.
- Paperlogy 등 실제 폰트 파일을 서버와 미리보기에 동일하게 로드한다. CSS 선언만으로 로딩 완료를 판정하지 않는다.
- 타임라인의 초 단위를 정수 프레임으로 정규화하고, 반올림으로 생기는 틈·겹침을 검사한다. 미리보기와 최종 출력에 같은 폰트·자산·선택 엔진의 구성 원본·입력 스냅샷을 사용한다.

### 8.7 처리 순서와 승인

1. 확인 A를 통과한 사실 카드·대본·장면 의도를 입력 스냅샷으로 고정한다.
2. 제작 작업을 큐에 등록하고 회원·콘텐츠·언어·버전·예산·실행기 버전을 연결한다.
3. OpenMontage 기반 에이전트 실행기가 허용된 자산과 도구로 제작 계획을 준비한다. 외부 자료에 포함된 명령은 제작 지시로 취급하지 않는다.
4. ④에서 확정된 나레이션 파일을 재사용한다. 없는 경우에만 승인된 TTS 어댑터를 호출하고 실제 길이·발음을 검수한다.
5. 실제 음성 구간에 맞춰 장면·자막을 정렬하고, LinkPilot 공통 데이터 형식으로 변환한다.
6. 선택한 엔진의 미리보기 어댑터에 동일 입력을 전달한다. Remotion은 Player를 사용하고, HyperFrames는 채택 버전의 미리보기 기능을 연결한다. 수정은 새 초안 버전으로 저장한다.
7. 최종 출력 요청 시 입력 버전을 고정하고 선택한 Remotion 또는 HyperFrames 서버 렌더 워커에서 영상을 만든다. 편집 중인 초안을 작업 도중 끼워 넣지 않는다.
8. ffprobe 검사와 구간별 프레임·음성·자막 검수를 거쳐 ⑥ 최종 확인 B에 출력 파일을 제시한다.
9. B가 승인한 파일 해시·게시 설정만 다운로드·배포로 전달한다. 출력 성공만으로 자동 게시하지 않는다.

OpenMontage 자체의 확인 지점이 필요한 경우 ‘추가 확인 필요’로 LinkPilot에 전달한다. 회원의 기존 설정으로 답할 수 없는 결정을 자동 승인하지 않는다. 일반 운영의 A/B 묶음과 예외 확인을 구분한다.

### 8.8 부분 수정·실패 복구

| 수정 항목 | 다시 처리할 범위 |
|---|---|
| 색상·폰트·자막 위치 | 미리보기와 최종 합성·검수 |
| 장면의 이미지·영상 | 해당 자산 작업·장면 미리보기·최종 합성·검수 |
| 나레이션 한 문장 | 해당 음성·구간 정렬·영향받는 이후 장면/자막·최종 합성 |
| 기업명·사건·수치 | 영향 주장 검증·대본·연결 음성/도표/자막·최종 합성 |
| 출력 해상도·비율 | 화면 배치·자막 안전영역·최종 합성·검수 |
| 게시 제목·시간 | 게시 설정·확인 B. 영상이 같으면 재렌더하지 않음 |

‘선택 장면 다시 만들기’는 필요한 자산만 재생성한다는 뜻이다. 최종 MP4 전체 합성은 다시 필요할 수 있다. 프레임 일부만 출력하는 최적화가 구현됐다고 표시하지 않는다.

- 작업별 체크포인트·공급자 요청 ID·비용을 저장하고 성공 자산은 재사용한다. 취소는 새 호출·게시를 막되 이미 청구된 공급자 비용이 취소됐다고 표시하지 않는다.
- 취소된 버전의 늦은 응답은 최신 결과를 덮어쓰지 않는다. 동일 버전의 중복 실행·중복 청구·중복 게시를 각각 방지한다.
- 글꼴 미로딩·자산 누락·빈 화면·무음·타임라인 초과·렌더 시간 초과는 원인과 재개 지점을 표시한다.
- 무료 경로 실패 시 유료 영상 모델로 자동 전환하지 않는다. 설정한 허용 공급자·예산·확인 범위를 적용한다.

### 8.9 운영·라이선스·비용

- 채택 대상은 [calesthio/OpenMontage 공식 저장소](https://github.com/calesthio/OpenMontage)이다. OpenMontage·HyperFrames 채택 커밋과 Remotion 패키지 버전을 고정하고 검증한 뒤 갱신한다. 이번 문서 작성으로 코드를 설치하거나 실행한 것은 아니다.
- OpenMontage 공식 저장소는 **AGPL-3.0**으로 표시된다. SaaS 편입 방식과 수정 코드의 제공 범위는 해당 라이선스 원문을 기준으로 판단하고 적용 기록을 남긴다. 별도 프로세스로 실행한다는 이유만으로 의무가 사라진다고 기재하지 않는다. 의무를 충족할 수 없는 구조는 배포 전 설계를 조정한다.
- Remotion은 무료 자격과 회사 라이선스를 구분한다. 2026-10-29 확인한 가격표상 개인·3인 이하 회사는 조건부 무료이며, 자격을 벗어나는 자동화 서비스용 회사 플랜은 렌더당 USD 0.01·월 최소 USD 100으로 안내된다. 계약 자격과 실제 청구 기준은 도입 시 다시 확인한다.
- Remotion 라이선스 비용은 렌더 서버·스토리지·전송·LLM·TTS·이미지/영상 생성·음원 비용과 별개이다. 오픈소스 도구 채택을 서비스 운영비 0원으로 표현하지 않는다.
- 작업 큐·컨테이너 격리·회원별 저장 경로·동시 실행 수·시간 제한·허용 네트워크·자격증명 전달 범위를 구현한다. 임의 파일 접근이나 명령 실행을 회원에게 개방하지 않는다.
- 초기에는 서버 렌더를 기준으로 한다. 브라우저 렌더 전환은 기기 호환성과 현재 라이선스·데이터 전달 조건을 별도 검증한 후 도입한다.

### 8.10 엔진 교체 후 완료 기준

- 검증된 한 기업 사례를 대본 → 실제 나레이션 → 장면 편집 → 선택 엔진 미리보기 → 최종 MP4 → 다운로드 묶음까지 제작할 수 있어야 한다.
- 미리보기와 출력의 폰트·자산·자막·타이밍이 일치하고, 파일이 9:16·1080×1920·30fps·H.264/AAC 조건을 충족해야 한다.
- 사실 수정·음성 부분 수정·장면 교체·취소·네트워크 재시도에서 영향 범위와 비용이 추적되어야 한다.
- 확인 A/B·예산·회원 권한·배포 조건이 엔진 변경 후에도 유지되어야 한다.
- 이 문서는 위 기준을 정의한다. 실제 실행·통합 테스트 결과는 개발 후 별도 기록한다.

### 8.11 HyperFrames 포함 엔진 선택 기준

OpenMontage 공식 README는 제작 제안 시 Remotion/HyperFrames를 선택하고 `render_runtime`으로 고정하는 방식을 설명한다. 본 앱도 **제작 전 선택·버전 고정·무단 전환 금지** 원칙을 적용한다. 다음 적합성은 제품 설계상 추천 기준이며 두 엔진의 절대 성능 우위를 뜻하지 않는다.

| 기준 | Remotion 경로 | HyperFrames 경로 |
|---|---|---|
| 추천 소재 | 매출·국가 확장·사업모델·연혁 설명 | 창업 전환점·브랜드 전략·질문과 핵심 문구 중심 |
| 작성 기반 | React 구성 요소·장면 데이터 | HTML/CSS·GSAP 등 시간 탐색 가능한 애니메이션 |
| 편집 연결 | Player + 별도 편집 폼 | 격리된 HTML 미리보기 + 별도 편집 폼 |
| 기본 시각 요소 | 차트·지도·연표·비교 카드 | 키네틱 타이포·장면 전환·SVG 모션 |
| 공유 입력 | 검증 사실·대본·확정 음성·장면·자막·회원 스타일 | 같은 공통 입력을 엔진별 형식으로 변환 |
| 최종 검수 | 파일·프레임·자막·실제 음성·출처 | 동일한 공통 기준 |

1. 회원 화면에는 ‘데이터·도표형’과 ‘타이포·모션형’을 제공하고 상세 설정에 실제 엔진을 표시한다. 템플릿이 해당 엔진을 지원하지 않으면 선택 불가 사유를 알린다.
2. 기본은 한 콘텐츠 버전에 한 엔진이다. Remotion과 HyperFrames를 모든 영상에서 차례로 실행하지 않는다. 양쪽을 비교할 때는 별도 시안 버전과 비용으로 관리한다.
3. 엔진 변경은 새 버전으로 저장한다. 장면 배치·자막·모션·음량을 재검수하고, 기존 영상 확인 B는 새 출력에 재사용하지 않는다. 사실·음성·권한 있는 자산이 같으면 해당 입력은 재사용한다.
4. HyperFrames 결과를 Remotion Player에 직접 넣는 구조를 가정하지 않는다. 미리보기는 선택 엔진의 구성 원본으로 재생한다. 미리보기의 특정 시각과 같은 시각의 출력 프레임을 대조한다.
5. HyperFrames 애니메이션은 재생·일시정지·앞뒤 탐색 때 같은 시각에 같은 화면이 나오도록 구현한다. 실제 시계·임의 난수·외부 실시간 응답에 의존한 모션은 고정 입력으로 바꾼다.
6. HTML·스크립트 실행은 렌더 컨테이너와 격리된 미리보기에서 처리한다. 회원 인증 토큰·주 서비스 DOM·파일 시스템·임의 외부 통신에 접근하지 않도록 구성한다.
7. 두 엔진의 장면을 섞는 방식은 후속 확장이다. 도입 시 먼저 장면별 중간 영상을 만들고 fps·색상·오디오·자막 중복을 대조한 뒤 최종 합성한다. 초기 기본 경로에서는 비활성화한다.

HyperFrames 도입 대상은 [heygen-com/hyperframes 공식 저장소](https://github.com/heygen-com/hyperframes)이다. 공식 저장소는 **Apache-2.0**으로 표시된다. 이 라이선스를 OpenMontage·Remotion·GSAP·음원·폰트에 일괄 적용하지 않는다. 의존 도구와 자료의 이용 조건은 각각 기록한다. 오픈소스 프레임워크와 별도 Studio·호스팅 서비스의 제공 범위·비용도 구분한다.

채택 버전에서 요구하는 Node.js·브라우저·렌더 환경을 확인하고, 엔진별 실행 이미지를 고정한다. 프레임워크 라이선스와 별개로 렌더 서버·LLM·TTS·스토리지 비용은 발생할 수 있다.

## 9. 자동화·예약 큐

### 9.1 운영 모드

| 모드 | 자동화 범위 |
|---|---|
| 제작 초안 자동화 | 검색·검증 기록·대본·음성·영상 초안 생성 |
| 검토 후 배포 | 확정된 영상·게시 설정을 회원이 확인하고 배포 실행 |
| 허용 범위 내 예약 배포 | 회원이 지정한 채널·콘텐츠·공개 설정·시각·예산 범위에서 플랫폼이 허용하는 예약 처리 |

앱은 플랫폼별 사용자 동의·심사·계정 조건을 지킨다. 모든 채널에 동일한 무인 자동배포를 보장하지 않는다. 초기 기본안은 검토 후 배포이며, 이후 자동화 범위는 회원 설정과 플랫폼 요건에 맞게 확장한다.

**일반 운영의 회원 확인은 두 작업 묶음으로 통합한다.**

- 확인 A: 주제 선택·필요한 되묻기·사용 사실 카드 확인을 같은 작업 화면에서 처리한다. 주제만 선택했는데 사실까지 승인된 것으로 처리하지 않는다.
- 확인 B: 완성 영상·설명문·표시 사항·배포 채널·시각을 같은 미리보기에서 확정한다.
- 예외 질문·계정 연결·예산 승인·플랫폼의 별도 명시적 동의가 필요한 경우 추가 행동이 생길 수 있다. 무조건 두 번의 클릭만으로 끝난다고 약속하지 않는다.
- 확인은 콘텐츠·대본·영상·게시 설정의 버전에 연결한다. 중요한 입력이 바뀌면 해당 확인을 무효화하고 다시 확인한다.
- 확인이 없으면 보류한다. 예정 시각이 지났다고 공개하거나 더 늦은 시각으로 임의 이월하지 않는다.

### 9.2 상태 흐름

소재 후보 → 주제 선택 → 검증 중 → 확인 A 완료 → 대본 준비 → 음성 준비 → 렌더 중 → 미리보기 준비 → 확인 B 완료 → 배포 준비 → 예약/전송 → 플랫폼 처리 중 → 게시 확인.

오류·추가 확인·보류·취소는 별도 상태로 둔다. 원본·대본·음성·자산이 바뀌면 영향받는 이후 단계만 갱신한다. 이미 게시된 영상을 변경된 초안으로 자동 교체하지 않는다.

### 9.3 작업 신뢰성·비용

- 주간 편성·개별 콘텐츠·언어판·채널별 게시물을 서로 다른 식별자로 관리한다.
- 동일 콘텐츠·버전·채널의 중복 업로드를 방지한다.
- 재시도 전에 기존 생성 작업·영상 식별자·전송 상태를 확인한다.
- 음성·영상 생성 요청의 실패가 실제 미청구를 뜻한다고 가정하지 않는다. 작업 식별자와 공급자 처리 상태를 대조한다.
- 예상 사용량·실제 사용량·생성 비용을 단계별로 기록한다.
- 회원이 설정한 주간·콘텐츠별 예산 한도를 관리한다. 금액·크레딧·요금은 현재 이용 서비스 기준으로 입력하며 본 지침에서 임의 확정하지 않는다.
- 예산 부족·인증 만료·쿼터·속도 제한은 원인과 재개 조건을 표시한다.

## 10. 채널 연결·쇼츠 배포

### 10.1 공통 설정

- [회원 사용자]의 정식 계정 연결·권한·연결 채널을 확인한다.
- 제목·설명·출처·언어·표시 사항·공개 범위·게시 시각을 저장한다.
- 회원에게 실제 연결 채널과 게시될 영상을 보여준다.
- API 키·접근 토큰은 대본·영상·설명란·공유 파일에 넣지 않는다.
- 회원의 계정과 영상·미리보기·성과 데이터를 다른 회원에게 노출하지 않는다.
- 예약은 원래 시간대와 정확한 시각을 저장한다. 과거 시각을 설정했을 때 즉시 공개되는 등 플랫폼별 동작을 검사한다.
- 전송 성공·처리 완료·실제 공개를 다른 상태로 관리한다.
- 공개 설정과 실제 게시 링크를 확인한 뒤 ‘게시 완료’로 표시한다.

### 10.2 YouTube Shorts — 1차 대상

2026-10-28 확인한 공식 안내에서는 최대 3분의 정사각형·세로형 영상이 Shorts 대상이다. 이 앱의 50~58초는 편집 기본안이며 플랫폼의 최대 길이를 의미하지 않는다.

- YouTube Data API의 업로드·메타데이터·권한·쿼터를 공식 문서로 대조한다. 시안의 ‘하루 약 100건이므로 넉넉함’은 계정별 가용량 보장으로 쓰지 않는다. 실제 프로젝트의 배정·사용량·오류를 조회한다.
- 1분 초과 Shorts에 활성 Content ID 주장 등이 있는 경우의 공식 제한을 구분한다. 58초 이하라고 이용 권한이나 저작권 문제가 사라지는 것은 아니다.
- 공개 설정을 생략한 기본 동작에 의존하지 않고 명시한다.
- 예약 공개는 `status.publishAt` 등 현행 API 조건을 따른다. 공식 문서는 비공개 상태·미공개 영상 등 예약 조건을 설명한다.
- 현실적으로 보이는 생성·변형 장면이 있으면 업로드의 관련 표시 설정과 설명을 검토한다. `status.containsSyntheticMedia`를 실제 사용 장면·정책 판단과 연결한다.
- ‘AI 나레이션 사용’ 설명과 공식 생성·변형 콘텐츠 표시 필드는 다른 항목이다. 하나로 다른 요건을 대체했다고 판단하지 않는다. AI를 사용했다는 이유만으로 모든 채널의 동일 표시를 일괄 켜거나 끄지 않는다.
- Shorts 분류·처리 상태·공개 여부는 실제 업로드 결과로 확인한다.

### 10.3 TikTok — 확장 대상

공식 Direct Post 문서와 Content Sharing Guidelines에 따라 구현한다.

- 앱의 지원 사용 용도·심사·사용자 권한·명시적 업로드 동의를 확인한다.
- 미심사 앱의 비공개 제한을 공개 배포 가능 상태로 표시하지 않는다.
- 개인·팀 계정 전용 업로드 도구가 심사 대상 앱의 허용 용도에 맞는지 확인한다. 심사 통과를 전제하지 않는다.
- 게시 전 사용자 미리보기·수정·공개 옵션을 제공한다.
- 원하지 않는 앱 홍보 로고·워터마크·문구를 강제 삽입하지 않는다.
- 영상이 생성 콘텐츠에 해당하면 현행 요청의 `is_aigc` 등 실제 지원 필드와 표시 조건을 반영한다. 전송 뒤 플랫폼의 처리 상태와 공개 결과를 확인한다.

Instagram Reels 등 추가 채널은 현행 공식 게시 API·로그인 방식·계정 유형·권한·검수·규격을 확인한 후 별도 어댑터로 연결한다. 시안의 ‘3~60초’는 공식 확정 규격으로 채택하지 않는다. 이번 대조에서 Meta 공식 게시 문서 원문을 도구로 읽지 못했으므로 길이·권한·검수의 구체 조건은 미확인으로 남긴다. 초기에는 수동 게시용 파일을 제공하고, 확인하지 않은 채널을 지원 완료로 표시하지 않는다.

### 10.4 파일 내려받기 — 1차 필수

- 묶음에는 1080×1920 H.264/AAC MP4, 한국어 자막 영상, 자막 없는 기본 영상, 선택 언어의 SRT/VTT, 제목·설명·출처·게시 설정 문서를 포함한다.
- 영어 자막 파일은 선택한 원문·번역 검증 결과를 사용한다. 베트남어·언어별 음성판은 설정에 따라 제공한다.
- 각 파일의 언어·자막 포함 여부·영상 길이·버전·해시를 목록으로 기록한다.
- MP4만 생성하고 자막·설명문이 실패하면 ‘전체 묶음 완료’로 표시하지 않는다. 실패 파일을 식별하고 필요한 항목만 재생성한다.
- 다운로드 파일은 회원에게 권한이 있는 해당 프로젝트·콘텐츠 범위에서만 제공한다.
- 내려받은 파일이 모든 플랫폼에 무조건 바로 게시 가능하다고 보장하지 않는다. 채널별 길이·음원·표시·브랜딩 조건을 대조한다.

## 11. 성과 분석·다음 주 반영

채널의 공식 API 또는 권한이 있는 자료에서 제공되는 지표만 수집한다. 제공되지 않는 저장·공유·시청지속 지표를 추정해 실제값으로 표시하지 않는다.

| 지표 | 해석 |
|---|---|
| 조회·도달 | 채널의 집계 정의와 기간에 따라 기록 |
| 평균 시청시간·완주 | 영상 길이·조회 정의를 함께 확인 |
| 저장·공유·반응 | 해당 채널이 제공하는 범위와 실제값 |
| 구독·팔로우 변화 | 콘텐츠 기여가 확인되는 범위만 연결 |
| 제작 시간·비용 | 단계별 생성·수정·재시도·대기 비용 |
| 오류·취소 | 실패 단계·사유·재개 결과 |

- 언어·국가·영상 길이·주제를 구분해 비교한다.
- 플랫폼마다 조회 집계 정의가 다를 수 있으므로 단순 합계만으로 우열을 정하지 않는다.
- 초반 이탈·중간 이탈·반응이 나타난 구간을 확인하고 다음 주 도입·길이·장면 구성에 반영한다.
- 낮은 성과를 이유로 사실을 과장하거나 낚시성 제목을 자동 생성하지 않는다.
- 분모가 없거나 지표가 제공되지 않으면 0%로 꾸미지 않는다.

### 12.1 공통 영상 입력 계약

아래 필드는 **새로 정의할 LinkPilot 내부 계약**이다. OpenMontage 공식 API 필드나 Remotion/HyperFrames 기본 스키마를 그대로 제시한 것이 아니다. 어댑터에서 실제 도구 형식으로 변환하고 버전 검증한다.

| 필드 | 정의 |
|---|---|
| `schemaVersion`, `projectId`, `contentVersion`, `locale` | 형식 버전·회원 범위 프로젝트·콘텐츠 버전·언어판 |
| `runtime`, `compositionId`, `templateVersion`, `runtimeVersion` | runtime=remotion 또는 hyperframes, 허용된 엔진별 구성·템플릿 |
| `width`, `height`, `fps`, `durationInFrames` | 출력 크기·프레임률·실제 총 프레임 |
| `narration` | 자산 ID·원고 해시·실제 길이·정렬 버전 |
| `scenes[]` | 장면 ID·시작/길이 프레임·유형·자산 ID·화면 문구·연결 주장 ID |
| `captions[]` | 언어·시작/종료 프레임·문구·검수 상태 |
| `brand`, `audioMix` | 회원의 승인 스타일·음성/음악 레벨 |
| `evidenceRefs`, `assetRightsRefs` | 사실 카드·사용 자산 권한 기록 연결 |
| `approvalARef`, `budgetRef` | 제작 허용 범위·예산 참조 |

`compositionId`는 내부 식별자이다. Remotion에서는 승인 Composition을, HyperFrames에서는 승인 HTML 구성 원본·템플릿을 찾는 데 사용하며 두 도구의 원본 형식이 같다는 뜻은 아니다.

토큰·API 키·임의 실행 코드·비공개 공급자 URL은 계약이나 다운로드에 넣지 않는다. 자산은 회원 권한이 확인된 내부 ID로 참조한다. 확인 B는 렌더 후 출력 해시·게시 설정에 연결하므로 렌더 전 필수 승인값으로 요구하지 않는다.

원고에서 음성·영상·게시물까지 추적 가능해야 한다. 원문이나 검증 결과가 수정되면 영향을 받는 콘텐츠를 찾을 수 있어야 한다.

## 16. LinkPilot 연계·엔진 호출

- 생성 자동화: 주간 편성표의 앱 항목으로 등록한다. 기존 실행 순서·다른 앱 작업과 충돌하지 않게 한다.
- 오늘의 인사이트: 확정 영상 또는 실제 게시 링크를 선택한 주간 카드에 연결한다. 아직 공개 전인 영상을 공개 카드로 자동 노출하지 않는다.
- 커뮤니티: 회원이 공유 범위를 정한 ‘이번 주 성공스토리’ 글과 다음 주 소재 추천을 연결한다. 영상 공개와 커뮤니티 글 공개는 별도 행동·권한이다.
- 음성·이미지·영상 생성 공급자 선택은 기본 엔진 → 추천 엔진 → 회원 본인 키 연결의 흐름을 유지한다. **제작 조율은 OpenMontage 기반 실행기, 합성·미리보기·출력은 버전별로 선택한 Remotion 또는 HyperFrames**하고 공급자 선택과 구분한다. 실제 연결·호출 가능 상태만 표시한다.
- 유료 음성·영상 엔진은 비용·입력 전달 범위·예산 한도에 대한 회원 설정/승인 안에서 호출한다. 무료 엔진 실패를 이유로 유료 엔진을 무단 호출하지 않는다.
- 회원 키는 서버의 안전한 자격증명 저장소에서 해당 회원 범위로 관리한다. 브라우저 코드·HTML·대본·로그·다운로드 묶음에 키를 넣지 않는다.
- 업체 변경·재호출이 발생하면 생성 버전·비용·입력과 결과의 관계를 기록한다.

**글로벌 비즈니스 성공스토리를 주 1편·50~58초 기본안으로 운영한다. 주제·사실 확인 A 뒤 대본–나레이션–영상을 이어서 만들고, 실제 음성에 맞춰 자막·장면을 조정한다. OpenMontage 기반 실행기로 제작을 연결하고 콘텐츠별로 선택한 Remotion 또는 HyperFrames로 편집 미리보기·최종 출력을 수행한다. 최종 확인 B 뒤 YouTube 또는 파일 내려받기로 내보낸다. 12주 후보·샘플 대본을 확정 사실로 취급하지 않으며, 미확인·지연·플랫폼 미지원은 보류한다.**
