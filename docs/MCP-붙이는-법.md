# LinkPilot 을 대화에 붙이는 법 (MCP)

〈2026-08-25 · D-83 결정 반영〉

---

## 0. 무엇을 위해 하는가

지금은 「LP-DC-2026-001 의 대지면적이 어느 자료에서 나왔지?」를 알려면 **화면을 열고
프로젝트를 찾아 들어가야** 한다. 이 작업을 마치면 **대화창에서 그냥 물어보면** 된다.

```
"LP-DC-2026-001 의 대지면적 출처가 뭐야?"

→ 사업계획서.pdf 12쪽 (2026-03-01 기준) = 12,345㎡  · 채택
  토지대장.pdf 1쪽 (2026-02-10 기준) = 12,300㎡    · 후보(탈락)
```

**숫자만 오지 않는다.** 어느 자료 몇 쪽에서, 언제 기준으로 나왔는지가 함께 오고,
**채택되지 않은 후보도 그대로** 온다. 값이 갈리고 있으면 그것이 답이다.

### 낯선 말 세 개

| 말 | 뜻 |
|---|---|
| **MCP** | Model Context Protocol. 대화하는 프로그램(Claude Desktop 등)이 **바깥 프로그램의 기능을 부를 수 있게** 하는 약속. 「대화창에 꽂는 확장 플러그」라고 보면 된다 |
| **표준입출력(stdio)** | 프로그램끼리 **글자를 직접 주고받는** 통로. 인터넷 주소도 포트도 쓰지 않는다 — 그래서 밖에서 접속할 수가 없다 |
| **IM_AGENT_ROOT** | 프로젝트 폴더들이 들어 있는 자리. NAS 에서는 `/volume1/linkpilot/im-projects` |

---

## 1. 먼저 알아 둘 것 — 세 가지

### ① 읽기만 한다. 고치지 못한다

도구 여섯 개가 전부 **읽기**다. 대화에서 프로젝트를 만들거나, 값을 저장하거나,
자료를 지우는 일은 **할 수 없다.** 일부러 안 열었다 — 열면 대화 한 마디로 남의
프로젝트가 바뀔 수 있다.

### ② 포트를 열지 않는다

인터넷에 아무것도 노출하지 않는다. **이 프로그램을 띄울 수 있는 사람 = 이미 그
폴더를 읽을 수 있는 사람**이다. 그래서 붙인다고 해서 새로 열리는 문이 없다.

### ③ 키를 만지지 않는다

공공데이터 서비스키·카카오 토큰 같은 것을 이 길은 아예 쓰지 않는다.
값을 **들여오지** 않고 **이미 들어와 있는 것을 꺼내기만** 하기 때문이다.

## 2. 붙이기 — Claude Desktop (맥/윈도우 앱)

### 2-1. 설정 파일을 연다

앱 안에서 여는 것이 가장 안전하다.

1. Claude Desktop 을 연다
2. 맥이면 화면 맨 위 메뉴에서 **Claude → Settings…**
   윈도우면 왼쪽 아래 자기 이름 → **Settings**
3. 왼쪽 목록에서 **Developer** 를 누른다
4. **Edit Config** 버튼을 누른다

그러면 `claude_desktop_config.json` 이라는 파일이 편집기로 열린다. 자리는 여기다:

```
맥      ~/Library/Application Support/Claude/claude_desktop_config.json
윈도우  %APPDATA%\Claude\claude_desktop_config.json
```

> **여기서 대개 막힌다 ①** — **Developer 메뉴가 안 보이는 경우가 있다.**
> 앱 판이 오래된 것이다. 앱을 최신으로 올린 뒤 다시 본다.

> **여기서 대개 막힌다 ②** — **파일이 비어 있거나 없을 수 있다.** 정상이다.
> 그때는 아래 내용을 **통째로** 넣으면 된다.

### 2-2. 이 내용을 넣는다

이미 다른 것이 들어 있으면 `"mcpServers"` **안쪽에** `"linkpilot"` 줄만 더한다.

```json
{
  "mcpServers": {
    "linkpilot": {
      "command": "node",
      "args": ["/여기에/linkpilot-cron/im-agent/mcp/server.js"],
      "env": {
        "IM_AGENT_ROOT": "/여기에/im-projects"
      }
    }
  }
}
```

**고쳐야 하는 곳은 두 줄뿐이다.**

| 줄 | 무엇을 넣나 | 확인하는 법 |
|---|---|---|
| `args` | 이 저장소를 내려받은 자리 + `/im-agent/mcp/server.js` | 그 자리에서 `pwd` 를 쳐서 나온 값 |
| `IM_AGENT_ROOT` | 프로젝트 폴더들이 든 자리 | 그 안에 `LP-DC-2026-001` 같은 폴더가 보이면 맞다 |

> **여기서 대개 막힌다 ③** — **경로는 반드시 전체 경로**여야 한다.
> `~/linkpilot-cron/...` 이나 `./im-agent/...` 는 안 된다. `/Users/…` 또는
> `/volume1/…` 처럼 맨 앞이 `/` 로 시작해야 한다. 윈도우는 `C:\\Users\\…` 처럼
> **역슬래시를 두 개씩** 적는다 — 하나만 적으면 JSON 이 깨진다.

> **여기서 대개 막힌다 ④** — **쉼표.** 이미 다른 서버가 들어 있었다면 그 블록
> 끝에 쉼표를 찍고 `"linkpilot"` 을 이어 적어야 한다. 쉼표 하나 때문에 설정
> 전체가 무시되고, 증상은 **「아무 일도 안 일어남」**이라 원인이 안 보인다.

### 2-3. 앱을 완전히 껐다 켠다

**창만 닫으면 안 된다.** 맥은 **Claude → Quit Claude**(⌘Q), 윈도우는 작업표시줄
아이콘에서 종료까지 해야 새 설정을 읽는다.

### 2-4. 붙었는지 확인한다

대화창 아래쪽 입력칸 근처의 **도구 아이콘(🔨 또는 슬라이더 모양)** 을 누르면
붙은 도구 목록이 뜬다. `linkpilot` 아래에 **여섯 개**가 보이면 된 것이다.

```
linkpilot_projects   프로젝트 목록
linkpilot_progress   보고서 생성 진행 상황
linkpilot_lineage    값의 출처 계보
linkpilot_impact     값을 고치면 무엇이 흔들리는가
linkpilot_fields     데이터 사전 — 어떤 항목이 있는가
linkpilot_intake     무엇을 올릴 수 있는가
```

가장 확실한 확인은 **그냥 물어보는 것**이다.

```
"linkpilot 에 프로젝트 몇 건 있어?"
```

## 3. 붙이기 — Claude Code (터미널)

한 줄이면 된다. 저장소 폴더 안에서 친다.

```bash
claude mcp add linkpilot \
  --env IM_AGENT_ROOT=/여기에/im-projects \
  -- node "$(pwd)/im-agent/mcp/server.js"
```

확인·제거:

```bash
claude mcp list              # 붙은 것 목록
claude mcp remove linkpilot  # 떼기
```

## 4. 잘 붙었는지 손으로 재 보기

앱을 거치지 않고 **직접** 물어볼 수 있다. 붙지 않을 때 원인을 가르는 데 쓴다.

```bash
IM_AGENT_ROOT=/여기에/im-projects \
  printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' \
  | npm run --silent im:mcp
```

도구 여섯 개가 든 JSON 한 줄이 나오면 **서버는 멀쩡하다** — 그러면 문제는
설정 파일 쪽이다.

---

## 5. 남을 대신해 띄울 때 — 보이는 프로젝트를 좁힌다

기본은 **그 폴더의 프로젝트를 전부** 본다. 사장님 맥에서 사장님이 띄우는 경우라면
그대로 두면 된다 — 어차피 그 폴더를 읽을 수 있는 사람이 띄우는 것이니 새로
열리는 것이 없다.

**남에게 특정 딜만 보여 줘야 할 때**는 `env` 에 한 줄을 더한다.

```json
"env": {
  "IM_AGENT_ROOT": "/여기에/im-projects",
  "LINKPILOT_MCP_PROJECTS": "LP-DC-2026-001,LP-SOL-2026-003"
}
```

적힌 것 **말고는 목록에도 안 뜨고 열리지도 않는다.**

## 6. 안 될 때 — 증상별로

| 증상 | 대개 이것이다 |
|---|---|
| 도구 목록에 `linkpilot` 이 아예 없다 | 설정 파일 JSON 이 깨졌다 (쉼표·역슬래시). 앱을 **완전히** 껐다 켰는지도 본다 |
| 있는데 부르면 실패한다 | `args` 경로가 틀렸다. §4 로 직접 재 본다 |
| 「프로젝트가 0건입니다」 | `IM_AGENT_ROOT` 가 빈 폴더를 가리킨다. 그 안에 `LP-` 로 시작하는 폴더가 있는지 본다 |
| 「실행 기록이 없는 프로젝트」 | 고장이 아니다. 그 딜은 **아직 생성을 돌린 적이 없다**는 뜻이다 |
| 「이 서버는 N건만 봅니다」 | `LINKPILOT_MCP_PROJECTS` 로 좁혀 둔 상태다 (§5) |

> **`node` 를 못 찾는다고 나오면** `command` 를 `node` 대신 전체 경로로 적는다.
> 터미널에서 `which node`(윈도우는 `where node`)로 나온 값을 그대로 넣는다.
> 앱은 터미널과 다른 환경에서 뜨기 때문에 `node` 만으로는 못 찾는 경우가 있다.

## 7. 떼기

설정 파일에서 `"linkpilot"` 블록을 지우고 앱을 껐다 켠다.
**되돌릴 수 없는 것은 없다** — 읽기만 하는 프로그램이라 지워도 데이터에 아무
변화가 없다.

## 8. 왜 「들여오는 길」에는 안 쓰는가 (D-83)

바깥 컨텐츠(뉴스·시세·지도)를 **MCP 로 들여오지 않는다.** 그쪽은 `connectors/` 의
REST 커넥터 그대로다. 이유는 다섯이고, 전부 이 시스템의 1순위 원칙과 부딪힌다.

1. **출처** — 도구 결과가 모델을 거치면 기관·기준시점·모수가 문장 속으로 녹는다.
   `Fact.source` 를 채울 원본이 남지 않는다 (§4.7)
2. **호출 한도** — `connectors/cache.js` 를 안 지나면 data.go.kr 일 10,000건
   장부가 무너진다 (§4.5)
3. **시크릿** — MCP 서버가 키를 받으면 `SECRET_ENV` 마스킹 밖으로 나간다 (§2)
4. **가정 섞임** — 「예상 매출」 같은 계산된 값이 출처 있는 값과 구분되지 않은 채
   들어온다 (§4.8)
5. **실패 격리** — 커넥터는 3회 재시도 뒤 그 절만 비운다. MCP 서버가 죽으면
   연결 자체가 끊겨 그 격리가 안 걸린다 (§4.6)

**MCP 는 값을 들여오는 길이 아니라 LinkPilot 을 내보내는 길이다.**

프로바이더가 MCP 만 제공한다면 그때도 값의 길에 바로 꽂지 않는다 —
`connectors/` 에 어댑터로 감싸고 **KOSIS 와 같은 「대조용」 등급으로 시작한다.**
