# LinkPilot AI 투자자 찾기 — 재구성·보완 업무지침 v2.0

- 작성일: 2026-10-21, 한국시간
- 대상: 서비스 기획·디자인·개발·운영 담당자
- 적용 영역: 투자·정책지원 > AI 투자자 찾기
- 목적: 사용자의 사업을 이해하고 필요한 추가 답변을 받은 뒤, 근거가 있는 투자자 후보를 추천한다.
- 상태: 첨부 화면과 사용자 요청을 반영한 설계 업데이트. 실제 플랫폼 배포·연동·추천 성능 검증을 완료했다는 의미가 아니다.
- 관계: 앞선 투자·정책지원 보완 제안의 투자자 탐색 부분을 이 문서로 구체화한다. 커뮤니티 업무지침은 별도 문서로 유지한다.

## 1. 이번 업데이트의 핵심

기존 화면은 기관 목록·산업 태그·AUM·수동 조건 선택을 중심으로 한다. 기본 진입 화면을 다음 과정으로 재구성한다.

1. 새 프로젝트 입력 또는 기존 프로젝트 가져오기.
2. AI의 사업 요약·자금 수요 분석.
3. 누락·충돌 정보를 확인하는 추가 질문과 사용자 답변.
4. 사용자의 사업 요약·추천 조건 확인.
5. 투자기관·펀드 후보 검색과 출처 확인.
6. 추천 근거·미확인 조건·다음 행동 제시.
7. 사용자 선택 후보를 딜파이프라인에 저장하고 검토 진행.

핵심 문구: **“사업을 알려주시면 AI가 필요한 내용을 질문하고, 조건에 맞는 투자자를 찾아드립니다.”**

추천은 투자자의 검토·투자 의향을 확인한 결과와 구분한다. 실제 접촉이나 자료 발송은 별도 사용자 행동으로 수행한다.

## 2. 화면과 메뉴 재구성

### 2.1 투자·정책지원 내부 메뉴

| 메뉴 | 역할 |
|---|---|
| AI 투자자 찾기 | 기본 진입. 프로젝트 분석·추가 질문·근거 기반 후보 추천 |
| 투자기관 탐색 | 기존 국내외 기관 목록·은행·상세 필터를 통합 탐색 |
| 정책지원 찾기 | 기업 자격과 사업 조건에 맞는 공고·융자·보증 등 검색 |
| 저장·진행 현황 | 저장한 후보·추천 실행 이력·연결된 딜파이프라인 확인 |

블록체인·인프라·부동산 등은 투자 분야 필터로 연결한다. 기존 블록체인 자료 탭에만 있는 고유 기능이 있으면 탐색 화면 안에서 유지한다. 기존 탭·주소는 새 위치로 연결하고 데이터를 삭제하지 않는다.

### 2.2 첫 화면

- 제목: `AI 투자자 찾기`
- 설명: `프로젝트를 입력하거나 가져오세요. 사업을 분석하고 필요한 내용을 확인해 적합한 투자자 후보를 추천합니다.`
- 주요 버튼: `새 프로젝트 입력` / `내 프로젝트 가져오기`
- 보조 기능: `이어서 진행` / `투자기관 직접 탐색`
- 프로젝트 확정 전에는 특정 기관 상세를 대표 추천처럼 먼저 노출하지 않는다.
- 현재 기관명 검색은 투자기관 탐색으로 이동한다.
- `+ 추가`는 목적에 따라 `새 프로젝트 입력` 또는 `투자기관 등록`으로 구분한다. 기관 등록 권한은 기존 정책을 확인한다.
- ‘거주 국가’로 투자 대상 지역을 대신 판단하지 않는다. 사업 국가와 투자자 희망 국가를 따로 받는다.
- 배너를 줄이고 입력·가져오기·진행 중 분석을 첫 화면에 배치한다.

## 3. 프로젝트 입력·가져오기

### 3.1 새 프로젝트 입력

첫 화면에는 긴 신청서 대신 핵심 정보와 자유 서술을 받는다.

| 항목 | 입력 방식 |
|---|---|
| 프로젝트명 | 가칭 허용 |
| 사업 설명 | 자유 서술. AI가 구조화하고 사용자에게 확인 |
| 사업 국가·지역 | 실제 사업 소재지. 미정 선택 가능 |
| 분야 | 산업·자산 유형. 복수 선택 및 기타 허용 |
| 현재 단계 | 기획·사전검토·인허가·개발/건설·운영·인수 검토 등 |
| 필요한 금액 | 숫자·통화·범위. 미정이면 질문으로 보완 |
| 원하는 자금 | 지분·대출·혼합·인수금융·아직 모름 |
| 필요한 시점 | 희망 일자 또는 기간 |
| 사용자 역할 | 사업주·개발사·투자자·수임 자문사·소개자 등 |

서술 예시: “한국에서 데이터센터 개발을 준비하고 있습니다. 인허가를 진행 중이고 건설자금과 지분투자 파트너가 필요합니다.”

미정 항목을 가짜 값으로 채우지 않는다. 최소한 사업 내용·사업 국가·필요 자금의 용도가 파악되면 예비 분석을 시작하고, 금액·자금 방식·현재 단계 등 추천을 바꾸는 질문을 이어간다.

### 3.2 기존 프로젝트 가져오기

1. 본인이 열람·분석할 권한이 있는 프로젝트만 목록에 표시한다.
2. 프로젝트 선택 후 가져올 항목과 자료 범위를 미리 보여준다.
3. 이름·국가·산업·단계·예산·조달 계획·일정·요약을 가져온다.
4. 출처 프로젝트, 정보 기준일, 버전, 수정자를 기록한다.
5. 누락·충돌·오래된 값은 표시하고 사용자에게 확인한다.
6. 추천용 사업 정보 사본을 생성한다. 수정이 원본을 자동 덮어쓰지 않게 한다.

버튼: `선택 정보로 분석 시작`.

원본을 수정할 권한이 없는 참여자도 허용된 범위에서 분석할 수 있으나, 원본 수정·외부 공개 권한을 얻지는 않는다. 분석을 위한 AI 처리 권한도 별도로 확인한다.

### 3.3 문서·외부 자료 활용

- 기존 프로젝트에 연결된 사업계획서·IM·수지표·인허가 자료는 사용자가 분석 대상으로 선택한 경우에만 처리한다.
- 기존 기밀문서 외부 저장 방침을 유지한다. 접근 권한이 있는 자료만 읽는다.
- 읽지 못한 링크·스캔·표는 `분석하지 못함`으로 표시한다.
- 장기 보관 파일 업로드 기능은 별도 범위로 두고 이번 개선에 임의 추가하지 않는다.
- 처리 중 임시 파일의 보유·삭제 방식은 실제 연동 구조에 맞게 정한다.

## 4. AI 사업 분석 화면

### 4.1 사용자에게 보여줄 분석

| 분석 항목 | 출력 내용 |
|---|---|
| 사업 개요 | 무엇을 어느 국가에서 어떤 단계로 추진하는지 |
| 자금 수요 | 조달 목적·필요 금액·통화·필요 시점 |
| 수익·회수 구조 | 매출 발생 방식, 상환 재원 또는 투자 회수 계획 |
| 사업 준비 상태 | 부지·인허가·계약·자기자본 등 확인한 범위 |
| 후보 기관 방향 | 지분 투자자·대출기관·전략적 파트너 등 검토 방향 |
| 보완 정보 | 추천을 위해 추가 확인할 핵심 항목 |

모든 항목에 정보 구분을 적용한다.

- 사용자 입력.
- 프로젝트에서 가져옴.
- 자료에서 추출함: 문서·쪽 또는 표·기준일 연결.
- AI 해석: 해석 이유와 확인 필요 여부 표시.
- 미확인: 근거가 없거나 자료에 접근하지 못한 항목.

사용자의 예상 매출·예상 수익률은 실적과 구분한다. 사업성 검토는 입력 자료에 따른 예비 분석으로 제공하고 독립 실사나 감정평가를 완료한 것처럼 표현하지 않는다.

### 4.2 충돌·오류 확인

- 총사업비·확보 자금·필요 조달액의 범위가 같을 때 수치가 맞는지 확인한다.
- 총사업비와 이번 회차 조달액을 구분한다.
- 대출 만기·자금 필요 시점·준공 일정의 충돌을 확인한다.
- 인허가가 진행 중인데 완료로 요약된 경우 정정한다.
- 여러 통화가 있으면 원통화와 환율 기준일을 보존한다.
- AI가 새로운 가정을 추가할 때는 가정으로 표시하고 사용자 확인 전 확정값으로 사용하지 않는다.

## 5. 추가 질문과 답변

### 5.1 질문 생성 원칙

1. 이미 확인한 정보를 반복해서 묻지 않는다.
2. 자금 수단·국가·투자금액·사업 단계 등 후보를 크게 바꾸는 항목을 우선 질문한다.
3. 한 번에 3~5개 정도로 나눠 제시한다. 이는 초기 UI 제안이며 강제 질문 수가 아니다.
4. 선택형 답변과 짧은 설명을 함께 제공한다.
5. 각 질문에 필요한 이유를 짧게 표시한다.
6. `모름·미정·나중에 답변`을 허용하고 결과의 미확인 조건에 반영한다.
7. 답변으로 중요 조건이 확정되면 질문을 종료한다. 단순히 질문 수를 채우지 않는다.
8. 핵심 조건이 미정이면 예비 후보만 보여주고 확정 추천처럼 표시하지 않는다.

### 5.2 사업 유형별 질문 예시

| 사업 유형 | 질문 예시 | 추천 판단에 쓰는 항목 |
|---|---|---|
| 개발·건설 | 부지 사용권과 현재 인허가 상태는 무엇인가요? | 개발 단계·준비 상태 |
| 운영자산 | 실제 매출·현금흐름과 주요 계약 기간은 어떻게 되나요? | 운영자산 전략·계약 구조 |
| 대출·PF | 필요한 만기와 상환 재원은 무엇인가요? 기존 담보·선순위 채무가 있나요? | 대출 구조·담보·회수 |
| 지분 투자 | 사업 법인 지분 투자와 프로젝트 지분 투자 중 어느 방식인가요? | 투자 대상·거래 형태 |
| 기업 인수 | 매입 대금과 운영자금 중 어떤 자금이 필요한가요? | 인수금융·지분 전략 |
| 스타트업 | 제품·매출·고객 확보와 현재 투자 라운드는 어느 단계인가요? | 성장 단계·투자 규모 |
| 해외 사업 | 현지 법인·파트너가 있나요? 상대 투자자의 국가 제한이 있나요? | 지역·진입 조건 |
| 정책지원 병행 | 신청 주체의 소재지·업력·규모를 확인할 수 있나요? | 정책지원 자격 확인 |

인프라·메자닌·경영권 인수를 모두 투자 단계로 처리하지 않는다. 분야·금융 수단·거래 전략의 독립된 값으로 반영한다.

### 5.3 답변 충돌 처리

기존 자료와 새 답변이 다르면 양쪽 값과 기준일을 보여준다. 사용자가 이번 추천에 적용할 값을 선택하게 하고 변경 이력을 남긴다. 새 답변이 원본 프로젝트의 사실을 자동으로 변경하지 않게 한다.

## 6. 사용자 확인과 분석 조건 확정

추가 답변 후 `AI가 이해한 사업` 화면을 제공한다.

- 사업 요약.
- 필요한 자금과 허용 가능한 대안.
- 필수 조건: 변경하면 안 되는 국가·자금 방식·금액 등.
- 선호 조건: 선호 투자자 국가·전략·협업 방식 등.
- 미확인 정보와 추천에 미치는 영향.
- 활용한 프로젝트·자료와 기준일.

버튼: `정보 수정` / `추가 답변` / `이 조건으로 투자자 찾기`.

이 확인은 추천에 사용할 사업 조건을 확인하는 과정이다. 외부 공유·투자자 연락·자료 전송 동의와 합치지 않는다. 프로젝트를 선택했다는 이유만으로 추천 조건 확인 단계를 생략하지 않는다.

## 7. 투자자 탐색·추천 처리

### 7.1 탐색 순서

1. 확인된 프로젝트 조건을 구조화한다.
2. 보유 기관·펀드 자료에서 후보를 조회한다.
3. 기관·펀드·지점·모회사 관계를 구분하고 중복 후보를 정리한다.
4. 필요한 조건과 자료의 최신성을 공식 공개 자료로 보완한다.
5. 필수 조건을 대조한 뒤 선호 조건과 근거의 충분성을 비교한다.
6. 추천 이유·불일치·미확인 사항을 생성한다.
7. 결과와 사용한 사업 조건·자료 버전·확인 시점을 함께 저장한다.

외부 검색이 가능한 연동 환경에서만 공개 자료 보완을 수행한다. 검색에 실패하면 기존 자료의 기준일과 미확인 상태를 알린다. 실시간 확인을 하지 않았다면 최신 검증 완료로 표시하지 않는다.

### 7.2 기관과 투자 수단의 구분

- 운용사는 기관 정보로, 실제 투자 조건은 확인 가능한 개별 펀드·전략으로 연결한다.
- 운용사 전체 AUM을 개별 펀드 투자 여력으로 사용하지 않는다.
- 펀드 규모·건별 투자 범위·미집행 약정액·총자산·프로젝트 사업비를 별도 값으로 관리한다.
- 직접 투자자·LP·모태펀드·대출기관·자문사·거래소·수탁기관의 역할을 구분한다.
- 간접 출자기관은 적합한 경우 출자 펀드·운용사를 연결하는 경로로 제시한다.
- 협회 가입·SEC 등록·과거 PPI 프로젝트 참여만으로 현재 투자 의사를 추정하지 않는다.

### 7.3 후보 분류

| 결과 구분 | 기준 | 표시 방식 |
|---|---|---|
| 우선 검토 후보 | 확인한 핵심 조건이 맞고 명시적 필수 조건 불일치가 없음 | 맞는 조건·근거·남은 확인사항 |
| 추가 확인 후보 | 분야·국가 등 일부 근거는 있지만 핵심 조건이 미확인 | 미확인 사유·필요 질문 |
| 현재 조건 제외 | 공식 자료상 필수 조건과 명확히 불일치 | 제외 조건과 출처 |

핵심 필드가 비어 있는 기관을 ‘조건 일치’로 취급하지 않는다. 명시적 필수 조건을 위반한 후보가 높은 선호 점수로 우선 후보에 올라오지 않게 한다. 정보 부족과 불일치를 구분한다.

### 7.4 필터와 순위

- 같은 필터 항목 안의 복수 선택은 원칙적으로 OR, 서로 다른 항목은 AND로 처리한다.
- `무관·미정·전체`의 의미를 명확히 정의한다.
- 투자 규모 범위의 교집합, 국가 허용 범위, 분야, 단계, 수단, 거래 전략을 대조한다.
- 기관 AUM은 보조 정보로 사용하고 건별 투자 규모의 대용값으로 쓰지 않는다.
- 가중치·점수 산식은 검수할 수 있게 기록한다. 초기 화면에는 근거 기반 순위와 조건 비교를 우선 사용한다.
- `투자 성공률 92%` 같은 확률은 표시하지 않는다. 조건 점수를 쓰면 투자 확률과 다름을 명시하고 산식·미확인 항목을 공개한다.
- 추천 건수를 맞추기 위해 후보를 생성하지 않는다. 후보가 없으면 부족한 조건과 사용자가 선택할 수 있는 완화 대안을 제시한다.
- 국가·금액·수단 등 필수 조건을 사용자 확인 없이 자동 완화하지 않는다.

### 7.5 탐색 범위 표시

실제로 검색한 자료 범위, 중복 제거 후보 수, 확인 가능한 기관 수, 자료 기준일을 보여준다. 기존 화면의 239개사나 출처별 수치를 고정 추천 모집단으로 사용하지 않는다. 원천 행 수와 고유 기관 수를 분리한다.

회원 공개 자료에는 이용조건·출처를 유지한다. 개인 연락처·미공개 담당자를 지어내지 않으며 공식 문의와 투자제안 전용 경로를 구분한다.

## 8. 추천 결과 화면

### 8.1 화면 배치

- 상단: 사업 요약, 분석 기준일, 적용 조건, `답변 수정·다시 추천`.
- 본문: 우선 검토 후보 / 추가 확인 후보.
- 보조: 검색 범위, 제외 사유 보기, 저장 검색·변경 알림.
- 데스크톱: 후보 목록과 선택 후보 상세.
- 모바일: 요약→후보 카드→상세의 순서, 긴 조건과 출처는 접기·펼치기.

### 8.2 후보 카드 필수 내용

1. 기관명·공식 로고·기관 역할·본사 국가.
2. 연결된 펀드·전략과 확인 가능한 투자 지역.
3. 이 프로젝트에 추천한 이유.
4. 일치한 조건과 각 근거의 출처·기준일.
5. 불일치 또는 미확인 조건.
6. 건별 투자 범위와 확인일. 없으면 미확인.
7. 유사 거래 이력과 당시 조건. 거래 이력과 현재 의사를 구분.
8. 접촉 경로: 공식 제안·일반 문의·연락 경로 미확인.
9. 다음 행동: 보완 자료 준비·공식 접수 경로 확인·후보 저장.

주요 버튼: `추천 근거 보기` / `비교하기` / `딜파이프라인에 저장` / `공식 문의 경로`.

추천 결과에 연락처가 있다는 이유만으로 제안서·프로젝트 자료를 자동 발송하지 않는다.

## 9. 비교·후속 관리

### 9.1 비교 항목

국가, 분야, 사업 단계, 금융 수단, 거래 전략, 건별 금액, 펀드 상태, 유사 거래, 근거 기준일, 제안 경로, 미확인 조건을 비교한다.

### 9.2 딜파이프라인 연결

- 저장 시 프로젝트·기관·추천 실행을 연결한다.
- 상태: 후보 저장→내부 검토→자료 준비→접촉 기록→검토 진행→보류/종료.
- 접촉 기록은 사용자의 실제 기록이나 확인 가능한 연동 결과로 갱신한다.
- 공식 링크를 클릭한 것만으로 접촉 완료·제안 접수로 처리하지 않는다.
- 담당자·다음 행동·예정일·실제 답변을 기록하고 기존 할일·일정과 연결한다.
- 사용자가 후보를 제외하면 제외 이유를 받아 다음 추천 조건에 반영한다.

### 9.3 조건 변경과 재추천

- 답변 또는 프로젝트 원본 변경 시 기존 추천의 기준 버전을 표시한다.
- 원본 업데이트가 있으면 `새 정보로 다시 분석`을 제공한다.
- 새 추천 실행을 생성하고 이전 결과·사용자 메모를 보존한다.
- 추천에서 사라진 기관도 이미 저장된 딜 기록에서 자동 삭제하지 않는다.

## 10. 정책지원과의 연결

같은 프로젝트 정보를 활용하되 투자자 추천과 정책지원 자격 판단은 구분한다.

- 사용자가 정책지원 병행을 선택하면 신청 주체·소재지·업력·기업 규모·자부담·허용 비용 등 필요한 항목만 추가 질문한다.
- 결과는 조건 일치·추가 확인·불일치로 구분한다.
- 지원 방식·한도·지원율·자부담·신청기간·필수 서류·공식 원문을 표시한다.
- 해외 공고는 현지 법인·국적·파트너 요건을 확인한다.
- 투자자 추천과 정책지원 결과의 금액을 중복 조달 가능 여부 확인 없이 단순 합산하지 않는다.
- `공식 신청 페이지`로 연결하며 지원금 확정·선정 완료처럼 표시하지 않는다.

## 11. 정보·권한·AI 처리

- 프로젝트별 열람·분석 권한을 서버에서 검사한다.
- 추천용 요약과 답변은 기본 비공개로 저장한다.
- 외부 검색 질의에는 회사명·정확한 위치·미공개 거래조건 등 기밀을 불필요하게 포함하지 않는다.
- AI 처리와 외부 공개·연락 권한을 분리하고, 실제 사용한 처리 서비스·보관 방식은 구현에 맞게 안내한다.
- 외부 문서·투자기관 페이지의 문장은 분석 자료로만 취급한다. 문서 안의 지시문이 시스템 동작·권한·외부 전송을 바꾸지 않도록 한다.
- 원문을 읽지 못한 상태에서 읽은 것처럼 근거를 붙이지 않는다.
- 자료 접근 권한 회수 시 후속 재분석에서 차단하고, 기존 사본·분석 결과의 보존 범위도 정책에 따라 처리한다.
- 공유하기는 사용자가 공개용 사업 요약을 검토한 뒤 별도 실행한다.

## 12. 구현 순서

| 순서 | 개발 범위 | 확인 기준 |
|---|---|---|
| P0-1 | 새 입력·프로젝트 가져오기·권한 | 허용된 정보만 사본으로 가져옴 |
| P0-2 | 구조화·사업 분석·추가 질문 | 출처·미정·충돌을 구분하고 반복 질문 방지 |
| P0-3 | 사용자 확인·추천 조건 생성 | 실제 답변과 승인된 조건이 일치 |
| P0-4 | 기존 자료 기반 후보 조회·근거 표시 | 필수 조건·미확인·제외 사유 구분 |
| P1 | 공식 자료 보완·중복 정리·비교 | 기관·펀드·자료 기준일 일관성 유지 |
| P1 | 저장·딜파이프라인·재추천 | 중복 저장·이력 유실 방지 |

기존 수동 검색은 유지하되 AI 기본 흐름의 보조 탐색 기능으로 연결한다. 프로젝트 분석이 끝나기 전 다수의 수동 필터 선택을 사용자에게 요구하지 않는다. 이 문서로 회원 요금제·한도를 새로 변경하지 않는다.

## 13. 검수 시나리오

- [ ] 새 입력과 프로젝트 가져오기 모두 사업 분석으로 연결된다.
- [ ] 권한 없는 프로젝트·첨부·외부 링크를 분석할 수 없다.
- [ ] 원본의 값·버전·기준일이 추천용 사본에 기록된다.
- [ ] 원본을 수정할 권한이 없는 회원의 답변이 원본에 저장되지 않는다.
- [ ] 이미 답한 항목을 반복 질문하지 않는다.
- [ ] 모름·미정·분석 실패를 임의 값으로 채우지 않는다.
- [ ] 총사업비·조달액·기존 채무·자기자본의 서로 다른 범위를 혼용하지 않는다.
- [ ] 자료와 답변 충돌을 사용자에게 보여준다.
- [ ] 사용자 확인 전 최종 조건을 임의 확정하지 않는다.
- [ ] 본사 국가와 사업 국가·투자 대상 국가를 구분한다.
- [ ] 동일 필터 OR·필터 간 AND와 전체·무관 값의 처리 결과가 일치한다.
- [ ] 명시적 필수 조건 불일치가 높은 선호 점수로 상쇄되지 않는다.
- [ ] 미확인 투자금액·단계가 조건 충족으로 계산되지 않는다.
- [ ] 운용사 AUM·펀드 규모·투자 약정·건별 투자액을 혼용하지 않는다.
- [ ] 기관·펀드·LP·자문사를 구분하고 동일 기관을 중복 추천하지 않는다.
- [ ] 근거 링크가 실제로 해당 조건을 뒷받침한다.
- [ ] 외부 조회 실패 시 최신 확인 완료로 표시하지 않는다.
- [ ] 후보가 없으면 조건을 자동 완화하거나 기관을 생성하지 않는다.
- [ ] 추천 카드가 현재 투자 의향이나 투자 확약을 의미하지 않는다.
- [ ] 저장·공식 링크 클릭만으로 투자자에게 연락·자료 발송이 실행되지 않는다.
- [ ] 원본 변경 시 추천을 조용히 덮어쓰지 않고 재분석을 제안한다.
- [ ] 재추천 후 기존 딜·사용자 메모가 보존된다.
- [ ] 기밀 정보가 외부 검색·알림·공유 미리보기에 노출되지 않는다.
- [ ] 모바일·다국어·통화·시간대 표시가 일치한다.

대표 검수 사례: 운영 중인 인프라 자산의 대출 수요, 인허가 전 개발사업의 지분 수요, 초기 기술기업, 금액 미정 사업, 공식 조건 불일치, 투자기관 정보 부족, 권한 없는 프로젝트 가져오기를 포함한다. 위 항목은 구현 검수 요구사항이며 현재 통과 결과가 아니다.

## 14. 운영 지표와 완료 보고

운영 지표: 입력 시작 대비 사업 조건 확인 비율, 질문 단계 이탈, 질문 중복, 근거 확인 가능한 추천 비율, 정보 부족 후보 비율, 잘못된 필수 조건 일치, 후보 저장·비교·실제 후속 검토 전환.

연락·투자·선정 결과는 실제 확인 가능한 기록으로만 집계한다. 추천 점수와 투자 유치 성과를 동일시하지 않는다. 초기 운영과 표본 검토 후 목표값을 정한다.

완료 보고: 화면 변경, 실제 연결 데이터 범위, 추가 질문 예시, 근거 검수 결과, 권한 검수, 이전 자료 보존, 미반영 사항·이유·다음 단계.

## 15. 앞선 공식 자료 조사와의 연결

아래 자료는 앞선 투자·정책지원 분석에서 확인한 출처다. 이번 설계의 질문·순위·화면 구성은 LinkPilot용 제안이며 기관의 추천 알고리즘을 재현한 것이 아니다. 해당 서비스에 연동하거나 데이터를 새로 추출한 상태도 아니다.

- [미국 SEC IAPD](https://adviserinfo.sec.gov/IAPD/InvestmentAdviserData.aspx/): 등록·보고 정보의 활용 범위를 구분한다.
- [세계은행 PPI 방법론](https://ppi.worldbank.org/en/methodology/ppi-methodology): 과거 프로젝트 참여·투자 약정과 현재 투자 여력을 구분한다.
- [영국 Find government grants](https://www.gov.uk/guidance/find-government-grants): 지원사업 검색과 자격 확인을 연결한다.
- [프랑스 Bpifrance](https://www.bpifrance.fr/catalogue-offres): 사업 목적에 따른 지원 탐색을 참고한다.

## 16. 개발 담당자 최종 실행 지시

투자·정책지원 섹션의 기본 화면을 ‘AI 투자자 찾기’로 재구성한다. 새 프로젝트 입력과 기존 프로젝트 가져오기를 같은 사업 정보 구조로 연결한다. AI는 자료를 요약하고 후보 선정에 필요한 누락·충돌 정보만 질문한다. 답변 후 사용자가 사업 요약과 조건을 확인하면 보유 자료와 접근 가능한 공식 근거로 투자자 후보를 찾는다. 우선 검토·추가 확인·현재 조건 제외를 구분하고 추천 이유·출처·미확인 조건·공식 접촉 경로를 제시한다. 후보 저장과 후속 관리는 기존 딜파이프라인으로 연결한다. 원본 프로젝트·기존 자료·수동 검색을 보존하고 외부 연락·자료 발송은 사용자 실행과 분리한다.
