# 저장소 연결 — 콘솔 등록 4곳 + `.env` 키 4개

| | |
|---|---|
| **누가** | 사람 (콘솔 로그인이 필요하다) |
| **왜** | 이것이 없으면 「연결해서 쓰기」가 **「아직 열려 있지 않습니다」로 조용히 남는다** |
| **연결 방식** | **그때그때 고르기(chooser)** — 2026-08-20 결정 (D-69) |
| **넣는 곳** | NAS 엔진의 `.env` (`/volume1/docker/linkpilot/.env`) |

> **client secret 은 넣지 않는다.** 네 곳 모두 **공개 식별자 하나**만 쓴다.
> secret 을 넣어야 하는 상황이 나오면 그것은 범위를 넓게 잡았다는 뜻이다 —
> 멈추고 아래 범위를 다시 본다.

---

## 0. 먼저 — 왜 「그때그때 고르기」인가

| | 그때그때 고르기 **(이것)** | 폴더 연결 |
|---|---|---|
| 받는 것 | 사용자가 **고른 파일 하나**에 대한 단발 접근권 | 그 폴더를 **계속** 읽을 권한 |
| 우리가 보관하는 것 | **없다** | refresh token |
| 새면 | 샐 열쇠가 없다 | **그 폴더 전체** |
| 대신 | 자료가 늘 때마다 사용자가 다시 고른다 | 다시 고를 필요 없다 |

**보관하지 않는 열쇠는 샐 수 없다.** 그것이 이 선택의 전부다.

---

## 1. Dropbox

| | |
|---|---|
| 콘솔 | dropbox.com/developers → App Console → Create app |
| **되돌릴 수 없는 선택** | **Access type = `App folder`** |
| 범위 | `files.metadata.read` · `files.content.read` |
| `.env` | `DROPBOX_APP_KEY=` (App key) |

★★ **`Full Dropbox` 로 만들면 되돌릴 수 없다.** 앱을 지우고 다시 만들어야 하고,
그때까지 그 앱은 **사용자 드라이브 전체**를 볼 수 있는 앱이다. 만들기 화면에서
한 번만 묻고 다시 안 묻는다 — **거기서 틀리면 나중에 고칠 수 없다.**

★ Chooser 를 쓰려면 앱 설정의 허용 도메인(Chooser/Saver domains)에 앱 주소를
넣어야 한다. 넣지 않으면 **창이 열리고 아무 일도 일어나지 않는다** — 오류도 안 난다.

---

## 2. Box

| | |
|---|---|
| 콘솔 | app.box.com/developers/console → 새 앱 |
| 핵심 | 서비스 계정을 **그 폴더에만 협업자(Viewer)** 로 초대한다 |
| 범위 | `base_explorer` · `item_download` |
| **켜지 않는다** | `root_readwrite` · `root_readonly` |
| `.env` | `BOX_CLIENT_ID=` (Client ID) |

★ Box 는 **앱 범위만으로 폴더를 못 좁힌다.** 좁히는 것은 **협업자 초대**다 —
앱에 권한을 주는 것이 아니라, 그 폴더에만 사람을 넣는 것으로 막는다.
기업 계정이면 관리자 승인(App Authorization) 범위도 폴더 단위로 좁힌다.

★ 이 제약 때문에 Box 는 **범위를 코드로 확인할 수 없다**(`verifiable: false`).
「좁게 잡았다」를 우리가 확인해 줄 수 없으므로 **사람이 확인한다.**

---

## 3. Google Drive

| | |
|---|---|
| 콘솔 | console.cloud.google.com → API 및 서비스 |
| 범위 | **`https://www.googleapis.com/auth/drive.file` 하나만** |
| **요청하지 않는다** | `https://www.googleapis.com/auth/drive`<br>`https://www.googleapis.com/auth/drive.readonly`<br>`https://www.googleapis.com/auth/drive.metadata.readonly` |
| `.env` | `GOOGLE_CLIENT_ID=` (OAuth 클라이언트 ID · 웹 애플리케이션) |

★ `drive.file` 은 **사용자가 피커에서 고른 파일만** 보인다. 이것이 우리가
원하는 바로 그 범위다 — 넓히면 드라이브 전체가 열린다.

★ 승인된 JavaScript 원본에 앱 주소를 넣는다. 안 넣으면 피커가 안 뜬다.

☐ **콘솔에서 확인이 필요한 것**: 피커 사용에 Google Picker API 사용 설정과
별도의 API 키가 필요한지. 화면이 안 뜨면 그 두 가지를 먼저 본다.

---

## 4. OneDrive · SharePoint

| | |
|---|---|
| 콘솔 | entra.microsoft.com → 앱 등록 |
| 범위 | **`Files.Read.Selected`** · `offline_access` |
| **요청하지 않는다** | `Files.Read.All` · `Files.ReadWrite.All` · `Sites.Read.All` · `Sites.ReadWrite.All` |
| `.env` | `MS_CLIENT_ID=` (애플리케이션(클라이언트) ID) |

★ `Files.Read.All` 은 **조직 드라이브 전체**다. `Files.Read.Selected` 와 한 글자
차이인데 범위는 비교가 안 된다. 관리자 동의 화면에서 무엇을 승인하는지 읽는다.

★ 리디렉션 URI 는 **SPA(단일 페이지 애플리케이션)** 로 등록한다 — 웹(기밀)으로
등록하면 secret 을 요구하게 되고, 그러면 이 설계에서 벗어난다.

---

## 5. 넣고 나서 — **확인**

```bash
# NAS 에서
grep -c '^DROPBOX_APP_KEY=.\+' .env    # 1 이 나와야 한다 (빈 값이면 0)
./stop-engine.sh && ./start-engine.sh  # .env 는 기동 때 읽는다
```

그다음 앱에서 **[자료 업로드] → 「연결해서 쓰기」**를 연다.

| 보이는 것 | 뜻 |
|---|---|
| 제공자 목록에 이름이 뜬다 | 키가 읽혔다 |
| 「아직 열려 있지 않습니다」 | 키가 없거나 빈 값이다 |

★ **키를 넣어도 그 제공자만 열린다.** 넷 중 하나만 넣으면 나머지 셋은 계속
「아직」이다 — 그것이 정상이고, 조용한 실패가 아니다.

---

## 6. 하지 않는 것

| | 왜 |
|---|---|
| client secret 을 `.env` 에 넣기 | 이 설계에 필요 없다. 필요해졌다면 범위가 넓어진 것이다 |
| 키를 코드·커밋·로그에 적기 | §2. `SECRET_ENV` 에 넷 다 들어 있어 로그에서는 가려진다 |
| 범위를 「일단 넓게」 잡고 나중에 줄이기 | Dropbox 는 **되돌릴 수 없다.** 나머지도 이미 받은 동의는 남는다 |
| 안 되는데 넓혀서 뚫기 | 넓히면 열린다 — 그리고 그 상태가 그대로 운영이 된다 |

---

## 7. 남는 일 — **엔진 쪽**

키가 들어와도 그 다음이 아직 없다.

| | 무엇 |
|---|---|
| 피커 | 제공자 창을 띄우고 고른 결과를 `POST /projects/:id/linked` 로 넘긴다 |
| `headLinked` | 원본이 그대로인지 묻는다 (`POST /linked/verify`) |
| `fetchLinked` | 보고서를 만들 때 **잠깐** 받아 온다 (`linked.materialize`) |

★★ **여기에 아직 안 풀린 것이 하나 있다.** 장부(`linked.json`)는 설계상
**토큰도 주소도 담지 않는다**(`normalizeRef` 가 막는다 · 테스트로 고정). 그런데
「그때그때 고르기」는 **그 순간의 접근권**으로만 파일을 받을 수 있다. 그래서
고른 시점과 보고서를 만드는 시점 사이를 이어 줄 **장부 밖의 짧은 수명 보관소**가
필요하다 — 장부는 그대로 두고, 그 보관소만 시간이 지나면 스스로 비운다.

그 보관소를 어디에 어떻게 둘지가 다음에 정할 것이다 (등록부 D-69 ②).
