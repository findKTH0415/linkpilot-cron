# 작업지시서 — SketchUp Engineering Agent 를 이 저장소에 안정화해서 붙이기

작성 2026-08-24 · 대상 저장소 `findKTH0415/linkpilot-cron`
근거 문서 `LinkPilot SketchUp Engineering Agent — Master System Prompt v1.0` (사장님 제공, 45개 절)

---

## 0. 결론 — 먼저 세 줄

1. **열 개 스킬은 만들 것이 없다. 이미 있다.** 마스터 프롬프트 §3 의 열 개
   (`skill_sketchup-*`)는 **Trimble SketchUp MCP 서버가 제공하는 실제 스킬**이고,
   이름이 하나도 빠짐없이 그대로 맞는다. 2026-08-24 세션에서 `list_skills` 로
   실측 확인했다.
2. **그런데 그 스킬들은 이 저장소가 도는 곳에서 못 돈다.** MCP 의 `build_model` 은
   **살아 있는 SketchUp 앱에 파이썬을 밀어 넣는다.** NAS 엔진(리눅스 · 포트 8181)
   에도 GitHub Actions 러너에도 SketchUp 이 없다. **엔진이 직접 부르는 설계는
   반드시 실패한다** — 그것도 「가끔 안 된다」로.
3. **마스터 프롬프트의 절반은 이미 이 저장소에 구현돼 있다.** 오케스트레이터,
   승인 게이트, 감사 추적, 신뢰도 등급, 출처 추적, 3D 매스, IFC 물량이 전부
   있다. **없는 것은 「도면을 읽어 형상을 만드는 부분」 하나다.**

그래서 이 지시서가 정하는 것은 하나다 — **어디를 자를 것인가.**

### 1-2. 그 스킬이 도는 조건 — 여기가 급소다

`build_model` 은 **세션을 띄우고 살아 있는 모델에 파이썬을 실행**한다. 즉:

- **SketchUp 데스크톱이 켜져 있어야 한다.** (사장님 맥 또는 작업용 PC)
- **대화형으로 인증된 MCP 연결**이 필요하다. 크론·헤드리스 실행에서는 없을 수
  있다고 도구 설명이 명시한다.

그래서 **다음 셋은 전부 안 된다** — 시도하지 않는다.

| 하고 싶은 것 | 왜 안 되는가 |
|---|---|
| NAS 엔진(8181)이 보고서 생성 중에 SketchUp 을 부른다 | NAS 는 리눅스 · SketchUp 없음 |
| GitHub Actions 가 CI 에서 모델을 만든다 | 러너에 SketchUp 없음 · 라이선스도 없음 |
| 크론이 밤에 모델을 갱신한다 | 대화형 인증이 없다 |

> **〈2026-08-24 실측 보정〉 「SketchUp 데스크톱이 켜져 있어야 한다」는
> 틀렸다.** GitHub 에서 띄운 Claude 웹 세션에서 `build_model` 을 실제로
> 불렀더니 **클라우드에 SketchUp 세션이 떠서 성공했고**, `save_model` 은
> `.skp` 를 다운로드 주소로 돌려준다 — 데스크톱 설치가 필요 없다.
> **결론은 그대로다**: 위 표의 셋은 여전히 안 된다 — NAS 엔진(Node 코드)과
> Actions 러너에는 MCP 자체가 없고, 크론(예약 실행)에서는 대화형 인증
> 커넥터가 없을 수 있다(미실측). 바뀌는 것은 평면 B 의 준비물뿐이다 —
> SketchUp 설치 불필요, Claude + 커넥터 연결이면 된다. 사용 한도는 무료
> 구간 안내 도구(`usage_limit_reached`)가 존재하므로 한도가 있다 — 미실측.

## 2. 붙이는 방식 — 평면을 둘로 가른다

```text
┌─ 평면 A · 엔진 (NAS · GitHub · 자동) ────────────────────┐
│                                                          │
│  01_project → 02_extraction → 07_geo → … → 06_im_writer  │
│                     │                          ↑         │
│                     ↓                          │         │
│            12_sketchup_plan (신규)      13_sketchup_intake│
│         「무엇을 어디에 만들어라」        「만든 결과를 받는다」│
│                     │                          ↑         │
└─────────────────────┼──────────────────────────┼─────────┘
                      ↓  model-plan.json         │  model-result.json
                                                 │  project.skp / scene_*.png
┌─ 평면 B · 사람 자리 (SketchUp 이 켜진 PC) ───────────────┐
│                                                          │
│   Claude Code + Trimble SketchUp MCP                     │
│   read_skill ×7 → build_model → clean → solid → camera   │
│   → styles → scenes → save_model                         │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

★ **두 평면 사이를 오가는 것은 파일 두 개뿐이다.** 그래야 한쪽이 없어도 다른
쪽이 돈다 — 이 저장소의 실패 격리 원칙(CLAUDE.md §4.6)과 같다.

★ **평면 A 는 SketchUp 을 모른다.** `model-plan.json` 은 마스터 프롬프트 §11 의
중간표현(Intermediate Representation)이지 SketchUp 명령이 아니다. 나중에 Rhino
로 바꿔도 평면 A 는 안 바뀐다.

### 단계 2 — 평면 A · 계획 Agent (`12_sketchup_plan`)

`im-agent/agents/12-sketchup-plan.js` 를 만들고 `core/registry.js` 에 등록한다.

- **입력**: `ctx.dataset` (대지면적·건폐율·용적률·층고·용도) + `09_massing` 결과

- **LLM 미사용.** 09_massing 과 같이 결정적 계산만 한다
- 값이 없으면 **`MISSING` 으로 적고 계획을 내지 않는다** (§0 · CLAUDE.md §4.6)
- registry 등록값: `order: 8`(09_massing 뒤 · 05_validation 앞) ·
  `approvalRule: 'auto'` · `confidenceThreshold: 0.5`

**여기서 반드시 함께 고칠 것 — 빠뜨리면 화면이 거짓말한다:**

| 파일 | 무엇을 |

**인수조건**: `npm run im:demo` 로 `model-plan.json` 이 나오고, 진행 화면 단계 수가

### 단계 3 — 평면 B · 실행 절차서 (코드 0줄, 문서 1개)

`docs/스케치업-모델-만드는-법.md`. **사람이 화면을 눌러 가며 따라 하는 문서**이므로
CLAUDE.md §5 를 그대로 적용한다 — 낯선 말은 처음 나올 때 풀고, 붙여 넣을 명령에
바꿔 넣을 자리를 두지 않는다.

담을 절차:

1. SketchUp 을 **먼저 켠다** (안 켜면 MCP 가 세션을 못 잡는다 — 여기서 대개 막힌다)
2. Claude Code 를 그 PC 에서 연다
3. baseline 스킬 **일곱 개를 읽힌다** — MCP 계약이다 (§1-1)
4. `model-plan.json` 을 준다
5. 만들기 → `clean-geometry` → `solid-cleanup` → `camera` → `styles` → `scenes`
6. `save_model` 로 `.skp` 저장
7. 결과 파일들을 프로젝트 폴더 `04_Property/` 에 넣는다
8. `model-result.json` 을 함께 넣는다

**인수조건**: 이 문서만 보고 SketchUp 을 처음 만지는 사람이 끝까지 간다.

### 단계 4 — 평면 A · 수령 Agent (`13_sketchup_intake`)

만든 결과를 **되받아 검증한다.** 이것이 없으면 §31 FINAL CROSS VALIDATION 이 반쪽이다.

- `model-result.json` 을 읽어 **계획과 대조한다** (층수·연면적·객체 수)
- 어긋나면 **YELLOW/RED 플래그**를 `05_validation` 에 넘긴다
- `.skp`·PNG 는 **있다는 사실만** 기록한다 — 파싱하지 않는다 (rhino.js 와 같은 규칙)
- 결과가 아예 없으면 **`unavailable` 로 그 절을 비운다.** 지어내지 않는다

**인수조건**: 일부러 어긋난 `model-result.json` 을 넣으면 검증이 빨개진다.

- `changes.js` 에 등록하고 `shows` 에 **어디를 보면 확인되는지** 적는다

## 4. 정면으로 부딪히는 조항 — 여덟

마스터 프롬프트를 **글자 그대로 따르면 이 저장소의 규칙을 깬다.** 어느 쪽을
따르는지 여기서 못 박는다. 나중에 다시 논쟁하지 않기 위해서다.

### 4-1. §19 · §28 — 모델에서 나온 값을 IM 에 싣는다

**따르지 않는다.** CLAUDE.md §4.8 이 명시한다 — 가정계수가 하나라도 들어가면
사람이 넣는다. 모델의 랙 수·면적은 **우리가 만든 값**이지 근거가 아니다.
`connectors/rhino.js` 가 이미 같은 이유로 fact 를 등록하지 않는다(D-33).

★ **그래서 D-96 의 답은 「등록하지 않는다」를 권한다.** 검토 결과로만 내고,
사람이 채택할 때 사람 이름으로 들어간다.

### 4-2. §21 CONFIDENCE ENGINE — 95~100% HIGH …

**척도를 새로 만들지 않는다.** 이 저장소는 이미 `core/confidence.js` 의
**A~E 등급**을 쓰고, IM 본문 표기(`[추정]`·`[가정]`)까지 거기서 나온다.
백분율 밴드를 새로 들이면 **두 척도가 생기고 화면마다 다른 말을 한다.**

→ 마스터 프롬프트의 백분율은 **A~E 로 환산해서** 쓴다. 환산표는 단계 1 규격
문서에 적는다.

### 4-3. §17 SOLID VALIDATION — 비솔리드는 검증 실패

**조건부로 따른다.** MCP 의 `sketchup-solid-cleanup` 설명이 직접 말한다 —
**매싱 스터디·도시 맥락 블록·지형은 이 검사를 건너뛴다.** 이 저장소가 만드는
것은 대부분 매싱이므로, 솔리드 실패를 무조건 RED 로 올리면 **거의 매번 빨개진다.**

→ **엔지니어링 객체에만** 적용한다. 매스는 제외하고, **제외했다는 사실을 문서에
적는다** (조용히 빠지지 않는다).

### 4-4. §30 PPT GENERATOR

**지금은 하지 않는다.** pptx 를 만들려면 새 라이브러리가 필요한데 CLAUDE.md §5
가 새 의존성 최소화를 요구한다. 현재 경로는 A4 HTML → 헤드리스 크로미움 → PDF
(D-53)다.

→ **D-97 로 올려 사장님이 정하신다.** 정해지기 전까지 §30 은 미구현으로 둔다.

### 4-5. §12 — AI 결정을 SketchUp 명령으로

**어댑터를 우리가 만들지 않는다.** MCP 자체가 그 어댑터다(`sketchup-sdk` 가
baseline 인 이유). 우리가 만드는 것은 **그 앞단의 중간표현**까지다.

### 4-6. §41 OUTPUT PACKAGE — 폴더 이름

**이 저장소의 13개 폴더 체계를 따른다** (`01_Project` … `13_Distribution`).
마스터 프롬프트의 `/SKETCHUP`·`/RENDER` 는 각각 `04_Property/`·`04_Property/`
아래로 들어간다. **폴더 체계를 둘로 만들지 않는다** — 이미 겪은 자리다(D-74).

### 4-7. §33 VERSION CONTROL — 검증된 판을 덮지 않는다

**이미 있는 것을 쓴다.** `deploy/engine.sh` 가 되돌릴 자리를 먼저 만들고,
프로젝트 폴더는 `12_Final` 에 판을 남긴다. 새 버전 체계를 만들지 않는다.

### 4-8. §9 DRAWING RECOGNITION

**이 지시서는 답을 내지 않는다 (D-98).** 여기가 전체에서 가장 비싸고 가장
틀리기 쉽다. 마스터 프롬프트 자신도 「그럴듯해 보인다는 이유로 객체를 만들지
말라」고 적었다. 단계 1~5 는 **도면 인식 없이도 성립하도록** 설계했다 —
대지·용적률 값만으로 매스 계획이 나온다.

## 5. 하지 않는 것 — 다섯

1. **엔진이 MCP 를 직접 부르지 않는다.** 되는 것처럼 보이는 날이 있어도 안 된다 —
   그런 것이 가장 나쁘다.
2. **`.skp` 를 파싱하지 않는다.** 이진 포맷이고 SDK 가 필요하다. `.3dm` 을 안 받는
   결정(D-38)과 같은 이유다.
3. **형상에서 물량을 계산하지 않는다** (D-37). 필요하면 IFC 로 받는다.
4. **새 라이브러리를 들이지 않는다** (CLAUDE.md §5).
5. **모델 값을 IM 본문 숫자로 자동 승격하지 않는다** (§4-1 · 마스터 프롬프트 §37 도
   같은 말을 한다 — 「발표물에만 있는 값이 권위 있는 프로젝트 데이터가 되어서는
   안 된다」).

## 6. 못 하는 것 · 지금 막혀 있는 것

**있는 그대로 적는다.**

- **SketchUp 이 켜진 PC 가 어디인지 정해지지 않았다** (D-95). 이것이 없으면
  단계 3·4 는 **문서만 만들고 한 번도 못 돌려 본다.**
- **도면 인식이 미정이다** (D-98). 그래서 이 지시서가 세우는 것은 마스터 프롬프트
  전체가 아니라 **대지·법정한도 기반 매스까지**다.
- **MCP 가 자동 실행에서 살아 있는지 확인 못 했다.** 이 세션에서는 `list_skills`
  가 응답했지만, **크론·헤드리스에서 같은지는 재지 않았다.** 재기 전에는 된다고
  말하지 않는다.
- **PPT 경로가 없다** (D-97).
