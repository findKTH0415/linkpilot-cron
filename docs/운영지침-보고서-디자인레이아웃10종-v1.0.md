# LinkPilot 보고서만들기 — 디자인·레이아웃 10종 고정 시스템 작업지침

- 문서 버전: v1.0
- 작성일: 2026-10-25 · Asia/Seoul
- 적용 메뉴: 보고서만들기 / 관리자센터 → 디자인·레이아웃 관리
- 적용 문서: 사업계획서·일반 보고서·IM제안서·사업제안서·요약자료
- 상태: 개발·인수인계 규격. 플랫폼 수정·운영 배포·Figma 자산 제작을 완료했다는 뜻은 아니다.

## 1. 결론

**디자인 시스템 타입을 10개로 고정한다.** 타입을 선택하면 표지·목차·챕터·본문·도표·지도·마지막 페이지가 같은 규칙으로 연결된다. 문서 종류와 사업 분야는 별도 선택값으로 둔다.

**기본 디자인은 실제 CSS 선언값을 사용한다.** 사용자 지정 문서 규격과 현행 플랫폼 CSS를 구분한다. 확인하지 않은 색상 코드·여백·그림자·폰트 파일 경로를 현행 값으로 기재하지 않는다.

**표지·로고·회사명·연락처는 [회원 사용자]가 선택한 개인 또는 회사 프로필을 기준으로 적용한다.** 흑백 사진 표지와 부분 컬러 포인트는 공통 디자인 규칙이다. 다른 회원의 로고·회사정보가 섞이지 않도록 문서별 소유자와 선택 프로필을 연결한다.

## 2. 근거와 적용 우선순위

| 구분 | 확인 내용 | 적용 상태 |
|---|---|---|
| 최신 사용자 지시 | 10종 고정, [회원 사용자] 디자인, Figma, 지도·API, 문체·정렬·폰트 규격, 추가 영문 글꼴 6종 | 본 지침의 필수 요구사항 |
| 실제 CSS | 로컬 `linkpilot-platform.deploy.html`의 실제 style 블록 | 부록 A에 선언값·행·해시 기록 |
| 외부 스타일시트 | HTML에서 `fonts/pretendard.css` 참조 확인 | 파일 원문·계산 스타일은 미확인 |
| 추가 영문 글꼴 | 사용자가 6종과 용도를 지정 | 선택 규격 반영. 파일 등록·실제 출력은 후속 구현 |
| 통합작성지침 | 명칭 전달 | 원문 미확보. 세부 규칙을 임의 작성하거나 적용 완료로 표시하지 않음 |
| 디자인지침_API활용지침 | 명칭 전달 | 원문 미확보. 본 메시지에서 직접 지정한 API 요구사항만 반영 |
| 배포전_독립감사_교차검증_재검증 지침 | 명칭 전달 | 원문 미확보. 별도 검증자가 실제 수행한 결과만 기록 |

적용 순서는 **최신 사용자 지정 → 해당 문서·회사 규격 → 원문이 확인된 기존 지침 → 타입별 구성 → 공통 기본값**이다. 이번 지침은 실제 CSS가 확인된 로컬 스냅샷을 기준으로 한다. 운영 서버의 최신 CSS와 일치한다고 단정하지 않는다.

### LP-DS-01. 기업표준 그리드형

- 표지: 회사명·문서명·대표 사진·작성 기준일.
- 본문: 결론 요약을 먼저 놓고 설명·표·차트를 정렬한다.
- 도표: 비교표·역할표·핵심 수치표를 우선 사용한다.
- 마지막 페이지: 제안 요약·협의 요청·연락처.
- 컬러 참조: 본문 `--lp-ink`, 배경 `--lp-surface`, 강조 `--lp-lime-ink`, 강조 면 `--lp-lime-tint`.
- 금지: 페이지마다 다른 카드 모양·그림자·글꼴을 임의 적용하지 않는다.

### LP-DS-02. 부동산·투자 IM형

- 표지: 본건의 실제 사진을 전체 흑백 배경으로 사용한다. 사업명·투자요청 핵심 문구만 강조한다.
- 본문: 투자 포인트 → 사업개요 → 시장·입지 → 사업권·인허가 → 구조 → 재무 → 회수 → 제안 조건 순으로 구성한다. 실제 목차는 사업·투자 방식에 맞게 조정한다.
- 도표: 투자금 사용처·사업비·현금흐름·지분 및 자금구도·회수구조를 사용한다.
- 마지막 페이지: 투자 요청사항·협의 구조·담당 연락처.
- 컬러 참조: `--lp-ink`, `--lp-surface`, `--lp-info`, `--lp-info-tint`.
- 금지: 투자규모·수익률·인허가·회수 가능성을 자료 없이 확정 문구로 만들지 않는다.

### LP-DS-03. 사업계획 캔버스형

- 표지: 사업명·대상 고객·제공 가치가 드러나게 구성한다.
- 본문: 고객·문제·해결방안·수익모델·사업 실행·파트너·비용·재무·성장계획을 모듈로 배치한다.
- 도표: 사업모델·가치사슬·수익 흐름·단계별 실행계획을 사용한다.
- 마지막 페이지: 실행 요청·자원 요청·의사결정 사항.
- 컬러 참조: `--lp-ink`, `--lp-surface`, `--lp-lime-deep`, `--lp-lime-tint`.
- 금지: 일반 모듈 배치를 특정 외부 표준 캔버스와 동일하다고 표기하지 않는다.

### LP-DS-04. 공공·정책 보고형

- 표지: 문서명·제출기관·작성기관·기준일을 명확히 표시한다.
- 본문: 목적·근거·현황·추진내용·일정·예산·기대효과·결정사항으로 정리한다.
- 도표: 예산표·업무분장표·추진일정·정책 연계표를 사용한다.
- 글꼴: 한글·영문·숫자 모두 Paperlogy를 적용한다.
- 컬러 참조: `--lp-ink`, `--lp-surface`, `--lp-surface-alt`, `--lp-line-strong`.
- 금지: 기관 제출 양식이 있는 경우 고정 레이아웃으로 필수 항목을 누락시키지 않는다.

### LP-DS-05. 데이터분석 대시보드형

- 표지: 분석 주제·지역·대상 기간을 명시한다.
- 본문: 결론 → 핵심 지표 → 비교·추세 → 근거 → 실행·결정 순으로 배치한다.
- 도표: 비교는 막대, 시간 변화는 선, 구성비는 적합한 구성 차트를 사용한다. 자료 구조에 맞는 차트만 선택한다.
- 차트마다 제목·단위·기간·출처를 연결한다.
- 컬러 참조: `--lp-ink`, `--lp-info`, `--lp-info-tint`, `--lp-surface-alt`.
- 금지: 서로 다른 통화·기간·분모를 설명 없이 한 차트에 합치지 않는다.

### LP-DS-06. 인프라·사업구도형

- 표지: 대상 시설·사업지 실제 사진과 사업명을 사용한다.
- 본문: 사업구도·입지·수요·인허가·기술·자금 흐름·추진 체계를 배치한다.
- 도표: 참여자 관계·SPC/JV·자금조달·계약 구조·시설 연결을 Figma 도식으로 구성한다.
- 지도: 대상 필지·도로·진입로·시설 연결 정보를 별도 레이어로 표시한다.
- 컬러 참조: `--lp-ink`, `--lp-lime-deep`, `--lp-lime-tint`, `--lp-info-tint`.
- 금지: 계약관계·자금 흐름·물리적 시설 연결선을 같은 의미의 선으로 혼용하지 않는다.

### LP-DS-07. 로드맵·추진일정형

- 표지: 프로젝트명·추진 기간·현재 단계를 표시한다.
- 본문: 단계별 목표·일정·참여자 역할·선행조건·의사결정 시점을 연결한다.
- 도표: 타임라인·간트·단계별 산출물·역할분담표를 사용한다.
- 컬러 참조: 본문 `--lp-ink`, 진행 강조 `--lp-info`, 일정 주의 `--lp-warn`, 배경 `--lp-surface`.
- 금지: 미정 일정을 임의 날짜로 채우거나 계획을 완료 실적으로 표시하지 않는다.

### LP-DS-08. 분양·프로모션형

- 표지: [회원 사용자] 프로필의 사진·로고를 사용하며 흑백 전체 사진과 부분 컬러 원칙을 유지한다.
- 본문: 상품·시설·분양/가격 조건·적용 대상·유효기간·문의 순으로 구성한다.
- 영문·숫자 역할: 가격·분양 제목은 Bebas Neue, 할인·이벤트 강조 문구는 Anton을 사용한다.
- 도표: 가격 구성·공급 조건·면적·일정·상품 비교를 사용한다.
- 컬러 참조: 기본 `--lp-ink`, 가격 강조 `--lp-lime-deep`, 이벤트 강조 `--lp-warn`, 강조 면 `--lp-warn-tint`.
- 금지: 근거 없는 할인율·가격 우위·판매 실적·잔여 수량을 생성하지 않는다. 이벤트 면을 문서 전체 본문 스타일로 확장하지 않는다.

### LP-DS-09. 사진·브로슈어형

- 표지: 선명한 실제 사진을 전체 배경으로 사용한다. [회원 사용자] 표지는 흑백 사진과 부분 컬러 포인트로 처리한다.
- 본문: 사진과 설명을 교차 배치하고 시설 특징·위치·사용 장면을 보여준다.
- 도표: 면적·시설·접근성·상품 특징 등 필요한 정보만 간결하게 배치한다.
- 컬러 참조: `--lp-ink`, `--lp-surface`, `--lp-surface-alt`, `--lp-lime-ink`.
- 금지: 생성 이미지나 다른 시설 사진을 본건 실제 사진으로 표시하지 않는다.

### LP-DS-10. 프리미엄 투자제안형

- 표지: 전체 흑백 사진·절제된 제목·부분 컬러 포인트로 구성한다.
- 챕터·마지막 페이지: 사용자가 지정한 옅은 흑색 면과 일관된 로고 규칙을 적용한다.
- 본문: 큰 여백·짧은 핵심 문장·선택한 수치·정제된 도표를 사용한다.
- 영문·숫자 역할: Montserrat ExtraBold를 사용한다. 한글은 Paperlogy를 유지한다.
- 컬러 참조: `--lp-ink`, `--lp-ink-hover`, `--lp-surface`, `--lp-lime-ink`.
- 금지: 고급 이미지를 이유로 작은 글씨·읽기 어려운 사진 위 본문·과도한 장식을 적용하지 않는다.

**위 컬러 참조는 부록 A의 실제 CSS 변수 중 선택한 신규 문서 매핑 규격이다. 현재 문서 출력기에 해당 매핑이 이미 구현됐다는 뜻은 아니다.**

공통 버튼은 **[문서 전체 적용] [현재 챕터 적용] [현재 페이지 적용] [되돌리기] [내 디자인으로 저장]**이다.

- 타입을 바꾸면 레이아웃과 스타일을 다시 적용한다. 기존 문장·수치·출처·첨부자료를 자동 재작성하지 않는다.
- 해당 타입에 없는 레이아웃은 가장 가까운 지원 레이아웃을 미리 보여준 후 적용한다.
- 긴 문서는 페이지를 나눈다. 지정 글꼴 크기를 줄여 억지로 한 페이지에 넣지 않는다.
- 회사별 저장본은 원본 타입 ID와 버전을 유지한다.

### 4.3 관리자 화면

관리 경로는 **관리자센터 → 디자인·레이아웃 관리**이다.

| 고정 항목 | 관리자 변경 가능 항목 |
|---|---|
| 타입 ID·타입명·10종 체계·각 타입의 중심 레이아웃 | 노출 순서·사용/미사용·미리보기·지원 문서·출력 규격·버전·회사별 변형 |

- 새 타입 추가·기존 타입 삭제·다른 의미로 ID 재사용 금지.
- 사용 중지한 타입은 신규 문서 선택 화면에서 제외한다. 기존 문서는 원래 버전으로 열 수 있어야 한다.
- 디자인 개정은 새 버전으로 등록한다. 기존 문서를 자동 덮어쓰지 않는다.
- 앱센터에는 노출·반영 상태를 연결한다. 문서 생성 권한과 관리자 디자인 수정 권한은 분리한다.
- 회원 화면에는 CSS 변수·렌더러·프롬프트 등의 구현 용어를 노출하지 않는다.

## 5. 글꼴·크기 규격

### 5.1 사용자 지정 IM 기본 크기

| 역할 | 크기 | 적용 |
|---|---:|---|
| 표지 제목 | 18pt | 표지 문서명 |
| 슬라이드 제목 | 14pt | 슬라이드·해당 출력 규격의 페이지 제목 |
| 핵심 숫자 | 10pt | 요약 지표·강조 수치 |
| 본문 | 12pt | 설명 문장 |
| 표 안의 글자 | 10pt | 문자·숫자·일자 모두 |
| 각주 | 8pt | 표 아래 설명 |
| 주석 | 7pt | 출처 줄 |

위 크기는 사용자가 지정한 문서 규격이다. 현행 CSS에서 추출한 플랫폼 UI 글자 크기로 표시하지 않는다. pt와 px를 혼용하거나 검증 없이 환산값을 현행 수치로 기록하지 않는다.

### 5.2 기본 글꼴과 추가 영문 글꼴

- 기본 한글·일반 본문·표·일자: **Paperlogy**.
- 사용자 지정 굵기: Paperlogy 3 Light / 5 Medium / 6 SemiBold.
- 공공·정책형: 한글·영문·숫자 모두 Paperlogy.
- 그 외 타입: 사용자가 지정한 영문 제목·표시 숫자 역할에 아래 서체를 적용한다. 일반 본문·표 전체를 영문 전용 서체로 바꾸지 않는다.

| 사용자가 지정한 용도 | 글꼴 | 적용 역할 |
|---|---|---|
| 부동산·투자 IM | DIN Condensed Bold | 영문 제목·표시 숫자 |
| 분양·가격 광고 | Bebas Neue | 가격·분양 제목 |
| 굵고 묵직한 할인·이벤트 | Anton | 이벤트·할인 강조 문구 |
| 정돈된 사업·데이터 | Roboto Condensed Bold | 영문 제목·지표 이름·표시 숫자 |
| 브로슈어·광고 | Oswald Bold | 영문 제목·짧은 강조 문구 |
| 고급 투자제안서 | Montserrat ExtraBold | 영문 제목·표시 숫자 |

**영문 글꼴에 없는 한글을 억지로 렌더하지 않는다.** 한글·지원되지 않는 문자는 등록된 대체 글꼴로 처리한다. 글꼴 로딩이 끝난 후 줄바꿈·페이지 수·도표 크기를 다시 계산한다.

사용자가 제공한 `CIDFont+F1Paperlogy`, `CIDFont+F2Paperlogy`, `CIDFont+F4Paperlogy`, `CIDFont+F3CambriaRegular`는 출력물의 폰트 표기로 관리한다. 이를 CSS family 이름으로 그대로 쓰지 않는다. 현재 CSS에는 Cambria가 대체 스택으로 선언돼 있으나, 이것만으로 최종 PDF에서 Cambria 사용이나 임베딩이 확인된 것은 아니다.

폰트 자산 등록에는 **실제 family·굵기·파일 경로·파일 해시·출력 사용 가능 범위·대체 글꼴·검증 결과**를 기록한다. 파일이 없으면 임의 다운로드 경로를 생성하거나 설치 완료로 표시하지 않는다.

## 6. [회원 사용자] 표지·로고·챕터·마지막 페이지

### 6.1 [회원 사용자] 표지

- 선명한 본건 실제 사진을 페이지 전체에 배치한다.
- 표지는 전체 흑백 사진으로 처리한다. 부분 강조만 컬러로 남긴다.
- 제목·로고 뒤에 불필요한 흰 사각 바탕을 넣지 않는다.
- 배경 사진이 바뀌어도 제목·로고 가독성을 유지한다.

### 6.2 챕터와 마지막 페이지

- 각 챕터와 마지막 페이지에 옅은 흑색 면을 적용한다.
- 기존 CSS의 `--lp-ink-hover`는 실제 선언이 `#2B3440`이다. 본 지침에서는 옅은 흑색 면의 매핑 후보로 사용한다. 현행 IM 챕터 배경의 실측값이라고 단정하지 않는다.
- 챕터에는 번호·제목·짧은 설명·필요한 실제 사진을 배치한다.
- 마지막 페이지에는 제안 요청·다음 협의사항·회사명·담당 연락처를 배치한다.

### 6.3 [회원 사용자] 로고 자산

1. [회원 사용자]가 등록한 원본 로고를 사용한다. 흰 배경을 제거한 투명 배경 컬러 버전을 만든다.
2. 어두운 면에는 **흰색 로고 버전**을 사용한다. 흰 사각 배경판을 붙이는 것으로 대체하지 않는다.
3. 글자 내부·선·심볼이 잘리지 않게 한다. 비율을 유지한다.
4. 로고·텍스트 배경은 투명으로 유지한다. 사용자가 지정한 진한 검은 그림자는 로고 형태를 뭉개지 않게 적용한다.
5. 그림자 강도·거리·번짐의 실제 CSS 값은 현재 확인되지 않았다. 임의 수치를 CSS 추출값으로 기재하지 않는다.
6. 로고 원본이 없으면 회원명·회사명을 텍스트로 표시하거나 로고 없이 저장할 수 있게 한다. 회사 로고를 새로 그려 실제 로고처럼 넣지 않는다.
7. 회원 로고·사진은 해당 회원 또는 공유 권한이 있는 프로젝트 범위에서만 사용한다. 다른 회원의 자산을 기본값으로 노출하지 않는다.
8. 문서 생성 시 선택한 프로필·자산 버전을 기록한다. 회원 프로필 변경이 기존 문서를 자동 덮어쓰지 않도록 한다.

## 7. 표·차트·다이어그램

### 7.1 표 정렬과 강조

- **표의 문자·영문·일자·혼합 내용·숫자를 모두 좌측 정렬한다.** 일반적인 숫자 우측 정렬 규칙보다 이번 사용자 지시를 우선한다.
- 표 안의 글자는 10pt를 유지한다.
- 셀은 1줄을 원칙으로 한다. 여백·열 너비·항목명을 먼저 조정하고 불가피할 때 2줄로 배치한다.
- 2줄을 넘으면 표를 나누거나 내용을 본문·각주로 이동한다. 글씨를 더 줄이지 않는다.
- 강조할 항목·본건·[회원 사용자]·제안자에 해당하는 칸은 배경색과 굵은 글씨로 구분한다.
- 배경색은 실제 CSS 토큰 또는 기록된 회사 디자인 값에서 선택한다. 강조 때문에 숫자·의미를 변경하지 않는다.
- 수치·단위·기준일·출처를 연결한다. 공란을 0으로 바꾸지 않는다.

### 7.2 차트

- 같은 항목·회사·시나리오는 문서 전체에서 같은 색과 라벨을 사용한다.
- 디자인을 변경해도 축·단위·범례·계산 결과를 유지한다.
- 실제와 계획·가정을 구분한다. 수익·비용·차입·자본의 의미를 색상 변경으로 뒤바꾸지 않는다.
- 핵심 수치만 강조하고 원자료·기준일·출처를 보존한다.

### 7.3 Figma 시각화

- 사업구도·SPC/JV·참여자 역할·자금 흐름·업무 단계 등 설명을 도식화할 필요가 있는 구간은 **Figma에서 제작·관리**한다.
- 연결선은 꺾임이 있는 선을 사용하고, 교차·겹침·과도한 밀집을 피한다. 연결선은 박스 접점에 붙인다.
- 한 도식에서 서로 다른 관계는 선·화살표·라벨로 구분한다. 한 방향 흐름과 상호 관계를 혼용하지 않는다.
- 박스 안의 문구는 짧게 쓰고 전체 설명은 도식 아래 본문으로 옮긴다.
- 의미상 강조가 필요한 박스·칸에만 배경색을 적용한다.
- Figma 파일·노드·버전·내보낸 자산·원본 출처를 연결한다. 단순 이미지만 저장하고 편집 원본을 잃지 않는다.
- PDF·PPT·Word·HTML에 넣은 뒤 글자 누락·선 잘림·색 변화·배경 투명 여부를 확인한다.

본 MD를 작성하는 단계에서는 본건 사업자료나 로고를 받지 않았으므로 실제 사업 도식·로고 편집 완료를 주장하지 않는다.

## 8. API 자료소싱·브이월드 지도

### 8.1 자료소싱 원칙

- 프로젝트 입력값·첨부자료·공식 API·공시·공식 원문을 연결한다.
- 자료마다 출처·발표일·기준일·조회일·대상 지역·단위·변환 과정을 기록한다.
- 확정 사실·사용자 제공값·계획·가정을 분리한다. 없는 숫자·기관·계약·인허가·실적을 생성하지 않는다.
- 금융·시장 수치는 지표 정의와 기간을 맞춰 비교한다. 통화 변경은 적용 환율·기준일을 기록한다.
- API 키는 문서·공유 링크·다운로드 파일에 포함하지 않는다.
- 참고 지침 원문을 확보한 후 기존 API·작성·감사 규칙과 충돌을 대조한다.

### 8.2 지도 구성

| 레이어 | 표시할 내용 | 확인 범위 |
|---|---|---|
| 일반지도 | 주변 도로·시설·지역 맥락 | 배경지도 |
| 위성지도 | 사업지·주변의 실제 공간 모습 | 영상 촬영시점 별도 기록 |
| 지적도 | 대상지와 인접 필지 경계·지번 | 연속지적도 도형·속성 |
| 본건 강조 | 대상 필지 폴리곤·지번·범례 | 주소·필지 식별값 대조 |
| 도로 강조 | 도로 부분·도로 필지·접면 구간 | 확보한 도로 데이터의 범위 |
| 진입로 구상 | 대상지에서 도로까지 연결할 후보 필지 | 후보 경로와 권원 확보 상태 분리 |

- 입력 지번을 식별값과 연결하고 **본건 필지 폴리곤을 중심으로 화면 범위**를 잡는다.
- 브이월드 연속지적도의 도형·속성을 사용한다. 도로를 눈대중 선으로 그린 뒤 공식 도로 경계처럼 표시하지 않는다.
- 일반지도·위성지도를 전환해도 대상 필지·도로·진입로 강조를 유지한다.
- 본건·도로·진입로 후보의 색을 서로 구분한다. 실제 사용한 색·변수·범례를 저장한다.
- 공간 데이터의 좌표계를 통일한다. 경계 오차·접면 판정 기준은 사용한 데이터와 구현에 맞춰 기록한다.
- **도형상 접면 여부와 진입로 토지의 권원 확보는 다른 정보이다.** 지적 폴리곤 접촉만으로 법적 도로·통행권·소유권·사용승낙 확보를 확정하지 않는다.
- 진입로 확보 여부는 계약·등기·사용승낙 등 원문이 있는 경우에만 확정 상태로 기록한다. 자료가 없으면 내부 편집 상태에서 근거 부재로 관리한다.

### 8.3 지도 컴포넌트·자동 렌더 트리거

- 최초 생성: 대상 지번·식별값·필지 도형을 확보했을 때 지도 장면을 생성한다.
- 갱신: 지번·필지 목록·관련 도로·진입로 후보·도형 버전이 바뀌면 해당 지도만 갱신 대상으로 표시한다.
- 디자인 변경: 지리 도형과 권원 상태는 유지하고 표현 스타일만 변경한다.
- 출력: 지도 타일·도형·폰트·범례가 모두 로딩된 뒤 출력용 장면을 만든다. 대기 화면을 문서에 캡처하지 않는다.
- 재현 기록: 레이어·도형 버전·조회일·지도 범위·좌표계·디자인 버전·출처 표기를 저장한다.
- 실패: 잘못된 지번·API 실패·도형 미확보 시 내부 상태를 표시한다. 임의 경계·다른 필지를 대신 넣지 않는다.

## 9. 작성 문체·내용 기준

- 기본 순서는 **결론 → 근거 → 실행 → 결정**이다.
- 쉬운 단어를 사용하고 공무원식 간결체로 쓴다. `따랐습니다`는 `따랐다`, `입니다`는 `이다`로 정리한다.
- 중요한 단어·문구는 굵은 글씨와 필요한 컬러 포인트로 강조한다.
- 문서가 스스로 작성과정을 설명하는 문장, AI·작업도구·프롬프트를 언급하는 문장을 고객용 본문에서 제거한다.
- IM은 투자자에게 사업과 투자 조건을 제안하는 문서로 구성한다. 작성자의 자체평가·내부 작업 지시·보완 체크리스트를 본문에 붙이지 않는다.
- 내부 상태인 `확인해야 함`, `보완조치 필요`를 기계적으로 문장 끝에 덧붙이지 않는다.
- 다만 실제 미확정 계약·허가·사업권·조달 조건·핵심 위험은 삭제하거나 확정 사실로 바꾸지 않는다. 확인된 상태·조건·일정을 투자자가 읽을 수 있는 문장으로 제시한다.
- 원자료가 없는 필수 내용은 편집 화면의 자료 요청 목록으로 분리한다. 내부 자료 요청 목록은 투자자 출력물에 자동 삽입하지 않는다.
- 확정되지 않은 핵심 내용을 빼고도 제안이 정확하게 전달되는지 판단한 후 작성자가 최종 내용을 결정한다.

### 글꼴 우선순위에 영향을 주는 실제 규칙

```css
body *:not(svg):not(svg *):not(.lp-ic):not([data-lp-font-keep]){font-family:var(--lp-font)!important}
```

이 규칙은 일반 요소에 Paperlogy 스택을 강제로 적용한다. 부모에 `data-lp-font-keep`만 달아도 자식 전체가 예외가 된다고 가정하지 않는다. 문서 출력 영역은 별도 범위 또는 별도 렌더 문서로 격리하고, 필요한 요소의 명시적 글꼴이 출력까지 유지되는지 검증한다.
