# 안내 — 조감도 자동 렌더 (Gemini · Nano Banana Pro 계열)

〈2026-08-25 사장님 지시: 「D-34 — API 실측 전 자동화 보류하지 말고 자세히 안내해줘」〉

## 0. 무엇을 위해 하는가

표지·티저에 쓰는 **실사 조감도**를 사람 손(SketchUp + Veras) 없이도 만들 수
있게 한다. 엔진이 이미 그리는 **기하 조감도**(모든 선이 지적선·건축개요에서
나온 그림)를 원본으로 주고, AI 에게 「형태·층수·비례는 그대로, 재질과 주변만
실사로」라고 시킨다.

**역할은 셋으로 갈라져 있고, 이것이 D-34 개정의 전부다:**

| 단계 | 누가 | 무엇을 |
|---|---|---|
| ① 생성 | 자동 (`npm run im:render`) | 후보 이미지를 만든다 — 문서에는 아직 안 실린다 |
| ② 채택 | **사람** (`--adopt`) | 눈으로 보고 골라야 결과 파일에 실린다 |
| ③ 표기 | 자동 (규격 §3-1) | 「AI 렌더 — 실제 설계안이 아님」 + 도구·세대 기록이 후보 단계부터 붙는다 |

자동으로 문서에 싣지 않는 이유: AI 그림은 우리가 지어낸 형상이라 **그럴듯할수록
설계안으로 읽히는 사고**가 커진다. 쓰는 곳은 표지·티저뿐이고 IM 본문 조감도는
그대로 기하 조감도다 (D-34 원결정 유지).

표준(CLAUDE.md §7)은 Veras 4.0 (Nano Banana Pro 기반)이며, 이 경로는
**gemini + 같은 기반 모델**이라 표준으로 인정된다 — 수령 Agent 의
`RENDER_TOOL_NONSTANDARD` 검사를 통과한다.

## 1. 사람이 한 번 해야 하는 일 — API 키 발급·등록

**API 키**란 구글 서버가 「누가 부르는지」를 알아보는 긴 문자열 열쇠다.
이미 OCR(스캔본 읽기)에 쓰는 `GEMINI_API_KEY` 와 **같은 키**를 쓴다 —
NAS 에 이미 등록되어 있으면 **이 절은 건너뛴다** (`npm run im:env-doctor` 로
「GEMINI_API_KEY: 설정됨」이 나오면 있는 것이다).

없다면:

1. 브라우저에서 **aistudio.google.com** 에 접속한다 (구글 계정 로그인).
2. 왼쪽 위 **「Get API key」**(한국어 화면이면 「API 키 받기」) 를 누른다.
3. **「API 키 만들기」** 를 누르면 `AIza…` 로 시작하는 긴 문자열이 나온다 —
   **「복사」 단추로 복사**한다. 이 창을 닫으면 다시 못 보는 화면도 있으니
   복사부터 한다.
4. 등록은 두 곳이다 (§2 — 키는 GitHub Secrets 와 NAS 열쇠 파일에만 둔다):
   - **GitHub**: 저장소 페이지 → **Settings** 탭 → 왼쪽 **Secrets and
     variables → Actions** → **New repository secret** → Name 에
     `GEMINI_API_KEY`, Secret 에 복사한 값 → **Add secret**.
   - **NAS**: File Station 으로 엔진 폴더의 `.env` 파일을 열어
     `GEMINI_API_KEY=복사한값` 한 줄을 넣는다 (이미 있으면 그대로).
5. **여기서 대개 막힌다** — 키를 코드나 대화에 붙여 넣는 것. 키는 위 두 곳
   외에는 어디에도 적지 않는다. 실수로 붙였으면 AI Studio 에서 그 키를
   지우고 새로 만든다.

## 2. 만드는 법 — 명령 하나

NAS(키가 있는 자리)에서:

```
npm run im:render -- --project LP-DEMO-APT-000
```

- 원본은 그 프로젝트의 `04_Property/birdseye.jpg` (엔진이 만든 기하 조감도)를
  자동으로 집는다. 다른 그림을 쓰려면 `--image 경로` 를 준다.
- 결과는 `04_Property/render-candidates/render_SC-AERIAL-01_gemini_01.png` 로
  저장되고, 옆에 같은 이름의 `.json`(도구·세대·프롬프트·disclaimer 기록)이
  함께 생긴다.
- 지시문을 바꾸려면 `--prompt "…"` 를 준다. 기본 지시문은 「형태·층수·비례·
  배치·도로는 유지, 재질과 주변만 실사로, 새 구조물 추가 금지」다.

## 3. 채택하는 법 — 눈으로 보고 나서

후보 그림을 열어 **형태가 유지됐는지** 확인한 뒤:

```
npm run im:render -- --project LP-DEMO-APT-000 --adopt render_SC-AERIAL-01_gemini_01.png
```

- `model-result.json` 의 `renders` 에 실리고, 다음 보고서 생성에서 수령
  Agent 가 표기·표준을 검사한다.
- SketchUp 결과 파일(`model-result.json`)이 아직 없으면 채택이 거부된다 —
  렌더는 결과 파일에 실려야 대조가 돌기 때문이다.

## 4. 막히기 쉬운 곳 — 셋

| 증상 | 뜻 | 어떻게 |
|---|---|---|
| 「GEMINI_API_KEY 가 없다」 | 키 미등록 | §1 대로 등록 — 지어내지 않고 멈추는 것이 정상이다 |
| 「이미지 생성 전체 실패」 + 모델 이름 오류 | 이미지 모델 ID 가 문서 기준과 다르다 (실측 전) | 출력에 찍힌 서버 오류를 보고 `GEMINI_RENDER_MODELS=올바른이름` 으로 다시 — 그 출력이 실측 기록이다 |
| 형태가 바뀐 그림이 나온다 | AI 가 형상을 지어냈다 | **채택하지 않는다.** `--prompt` 로 유지 지시를 강하게 하거나 다시 생성한다 |

## 5. 비용 — 실측으로 확인됐다: 결제 연결이 필요하다

**〈2026-08-25 실측 · render-smoke #1〉** 지금 키(무료 티어)로 돌려 보니
키 인증과 모델 이름은 통과했고, 응답은 「Quota exceeded — free_tier_requests,
**limit: 0**」이었다. **무료 티어에는 이미지 생성 한도가 아예 0** 이다 —
텍스트(OCR)는 무료로 돌지만 이미지 렌더는 결제를 연결해야 열린다.

결제 연결(사람 몫, 한 번):
1. **aistudio.google.com** → 왼쪽 **「Get API key」** 화면에서 지금 키가 속한
   프로젝트 줄을 찾는다.
2. 그 줄(또는 화면 상단)의 **「Set up Billing」(결제 설정)** 을 누른다 —
   화면 문구는 구글이 바꿀 수 있으니 「Billing/결제」가 든 단추를 찾는다.
3. Google Cloud 결제 계정(카드)을 만들거나 골라 연결한다. 연결되면 쓴 만큼
   과금되는 방식으로 이미지 모델이 열린다.
4. 단가는 ai.google.dev 의 **Pricing** 페이지에서 확인한다 — 여기 적지 않는
   이유는 개정되면 이 문서만 옛말이 되기 때문이다. 한 딜에 후보 1~3장만
   만들고 대량 생성은 하지 않는다 (§4.5 와 같은 결).
