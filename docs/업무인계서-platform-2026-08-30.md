## 1. 기기 3대 제한 — 표식이 **탭마다** 만들어집니다 〈차단〉

### 증상

로그인 화면이 「이 계정은 기기 3대까지만 사용할 수 있습니다 · 등록된 기기 3/3」로
막습니다. 그런데 **지금 로그인하는 기기가 목록에 이미 있습니다.**

```
등록된 기기 3/3
 · Android · Chrome  2026-08-25
 · Android · Chrome  2026-08-29   ← 같은 폰의 다른 탭
 · Mac     · Chrome  2026-08-29   ← 지금 이 기기인데도 막힌다
```

### 원인

**기기 표식이 「기기마다」가 아니라 「탭마다」 만들어집니다.** 새 탭을 열 때마다
그 탭에는 표식이 없으니 새로 만들고, 서버는 그것을 새 기기로 받습니다.

실제로 쓰시는 기기는 **둘**(안드로이드·맥)인데 셋으로 세고 있었습니다.

### 왜 하필 그날이었나 — 날짜가 답입니다

| 날짜 | 무슨 일 | 그때 자리 |
|---|---|---|
| 08-25 | Android 등록 | 1 / 3 |
| 08-29 | Android **또** 등록 (같은 폰의 다른 탭) | 2 / 3 |
| 08-29 | Mac 등록 | **3 / 3** — 꽉 참 |
| 08-30 아침 | 맥에서 다시 열자 표식이 **또 새로** 생김 | 4번째 필요 → **막힘** |

고장이 그날 난 것이 아니라, **차오르다가 꽉 찼고 넘친 것**입니다. 그리고 자리는
**차기만 하고 비지 않습니다** — 만료도, 오래 안 쓴 기기가 물러나는 규칙도 없습니다.

### 재현 — 세 줄

1. 같은 브라우저에서 로그인한다 → 등록 1
2. **새 탭**을 열어 다시 로그인한다 → 등록 **2**  ← 여기서 갈립니다
3. 2번에서 등록이 안 늘면 고쳐진 것입니다

### 고칠 것

| 어디 | 무엇 |
|---|---|
| 화면 | 표식을 **탭 단위 저장소**가 아니라 **브라우저(기기) 단위 저장소**에 한 번만 만들어 두고, 다음 로그인부터 그것을 그대로 보냅니다. 앱·웹뷰라면 OS 저장소가 더 낫습니다 |
| 서버 | **같은 표식이 다시 오면 줄을 새로 만들지 않고** 마지막 접속 시각만 갱신합니다 |
| 데이터 | **이미 쌓인 중복 줄을 지웁니다** — 코드를 고쳐도 옛 줄은 자리를 차지한 채 남습니다 |

### ★★★ 함께 열어 주셔야 하는 문

지금 안내는 「기존 기기에서 **[내 정보 → 로그인 → 등록 기기]** 로 해제하라」인데,
**그 자리에 가려면 로그인을 해야 합니다.** 세 대가 다 어긋나면
**계정 주인이 자기 계정에 영영 못 들어갑니다.**

→ **로그인 화면에서 바로 해제**할 수 있게 해 주십시오. 목록은 이미 그리고 있으니,
각 줄에 [이 기기 해제] 를 붙이고 **비밀번호가 맞을 때만** 듣게 하면 됩니다.

**자세히**: `docs/전달-platform-기기-3대-제한-같은-기기가-두-번-등록됨.md`

## 2. 웹앱(PWA) 아이콘 — 매니페스트가 옛 파일을 가리킵니다

### 증상

크롬의 「설치 및 바로가기 만들기」 미리보기에서 **나침반 테두리가 아래쪽이 잘려**
있습니다. 아이콘을 새로 그렸는데도 계속 옛 모습입니다.

### 원인

아이콘은 **웹 매니페스트의 PNG** 에서 옵니다. 그림은 다 만들어졌는데
**매니페스트가 아직 옛 파일을 가리킵니다.**

### 고칠 것 — 복사만 하면 됩니다

**`docs/전달-webapp/` 폴더를 그대로 쓰십시오.** 안에 다 들어 있습니다.

| 파일 | 무엇 |
|---|---|
| `manifest.webmanifest` | 그대로 쓰시면 되는 매니페스트 |
| `linkpilot-192.png` · `linkpilot-512.png` | 안 오려 내는 자리용 (`any`) |
| `linkpilot-maskable-192.png` · `linkpilot-maskable-512.png` | **오려 내는 자리용** (`maskable`) |

1. 그림 넉 장을 웹 루트의 `icons/` 에 넣습니다 (다른 자리면 매니페스트의 `src` 넷을 고칩니다)
2. `manifest.webmanifest` 를 웹 루트에 넣습니다
3. 앱 페이지 `head` 에 매니페스트를 가리키는 `link` 한 줄 (`rel` 은 `manifest`)

★ `name`·`theme_color` 는 지금 앱에 맞게 고쳐 주십시오 — 화면에서 본 대로 적어 둔 것입니다.

### ★★ 왜 두 벌인가

안드로이드는 아이콘을 **동그랗게 오려 냅니다.**

- 오려 내는 판이 **없으면** — 투명 여백째로 오려서 **조그맣게 박힌 흰 동그라미**
- 오려 내는 판**만** 주면 — 안 오리는 자리에서 **각진 흰 네모**

안전 원은 한 변의 **80%** 이고, 이 그림은 가장 멀리 닿는 곳이 한 변의 **29%**
(지름 58%)라 넉넉히 들어갑니다 — `linkpilot-cron` 의 검사가 매번 잽니다.

### ★★★ 넣으신 뒤에도 저절로 안 바뀝니다

안드로이드는 아이콘을 **설치할 때 한 번** 가져가 런처에 박습니다.

1. 홈 화면에서 **아이콘을 길게 눌러 제거**
2. 크롬에서 앱 주소를 다시 열고 **⋮ → 앱 설치**
3. 새 아이콘으로 뜨는지 봅니다

★ 지우고 다시 설치하기 전에는 **무엇을 고쳐도 옛 아이콘이 보입니다.**

**자세히**: `docs/전달-webapp/읽어주십시오.md` · `docs/전달-platform-웹앱-아이콘-매니페스트.md`

## 3. 「보고서 만들기」 배너·탭이 두 벌로 보입니다

### 증상

한 화면에 사진 배너와 탭 줄(`보고서 만들기` / `완성 보고서`)이 **두 벌**로 나옵니다.
안쪽 상자마다 스크롤 막대가 따로 있습니다(두 겹).

### 왜 앱 쪽이라고 보는가 — 실측

- **`REPORT STUDIO` 라는 글자가 `linkpilot-cron` 저장소에 하나도 없습니다.**
  보고서 화면 일곱 어디에도 없고, 검사가 앞으로도 생기지 못하게 지킵니다.
- **탭 줄도 보고서 화면이 안 그립니다.** 탭 바는 앱이 그리는 것입니다.

그러므로 **두 벌 다 앱이 그린 것**이고, 앱 페이지가 두 번 렌더됐다는 뜻입니다.

### 고칠 것 — 한 줄

「보고서 만들기」 섹션이 **틀에 넣는 주소**를 보고서 생성 흐름 화면으로 바꿔 주십시오.
파일 이름은 `report-flow.html`, 화면들이 놓인 폴더 이름은 `im-flow` 입니다.

★ 그 주소가 **404 일 때 앱 첫 페이지를 돌려주는 설정**이면 주소를 바로잡아도 증상이
  같습니다. 그 설정도 함께 봐 주십시오.

**자세히**: `docs/전달-platform-이중-배너-앱이-앱을-품음.md`

## 4. 화면 경로 앞부분을 알려 주는 한 줄 (`lp:base`)

보고서 화면들의 형제 링크는 전부 **상대 경로**라, 앞부분을 만드는 쪽은 앱입니다.
앞부분이 어긋나 같은 결의 고장이 **네 번** 났습니다(겹침 `/im-flow/im-flow/…`,
빠짐 `/…`).

앱 페이지의 `head` 에 아래 이름의 메타 한 줄을 넣어 주시면 화면이 스스로 맞춥니다.

- 메타 이름: `lp:base`
- 값: 보고서 화면들이 실제로 있는 폴더 주소 (슬래시로 시작해 `im-flow` 로 끝나는 경로)

**자세히**: `docs/전달-platform-화면-경로-앞부분.md`

## 5. 맥 앱 아이콘

`LinkPilot.app` 의 아이콘이 **나침반 원이 사방으로 잘려** 있습니다. 맥 아이콘은
1024 칸 안에 **824 둥근 사각형**이 가운데 놓이는 규격인데, 그림을 칸 끝까지
늘려서 그렇습니다.

**`assets/brand/LinkPilot.icns` 를 그대로 쓰십시오.** 이미 묶어 두었으므로
맥에서 `iconutil` 을 치실 필요가 없습니다.

★ **웹앱(2번)과 맥 앱(5번)은 아이콘을 가져가는 자리가 다릅니다** — 한쪽만 바꾸면
  다른 쪽은 그대로입니다.

**자세히**: `assets/brand/README.md`
