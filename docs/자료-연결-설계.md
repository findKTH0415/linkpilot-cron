# 자료를 보관하지 않고 **연결해서** 쓴다

작성 2026-08-17 (KST) · 등록부 **D-65** ·
구현 `im-agent/connectors/storage.js` · `im-agent/core/linked.js`

> **한 줄:** 사용자의 Dropbox·Box·Google Drive·OneDrive 를 연결해서, **값을 읽어야
> 할 때만 가져와 읽고 곧바로 지운다.** 파일은 안 남기고 **어디서·어느 판을·언제
> 읽었는지와 그때의 지문**만 남긴다.

---

## 0. 「보관하지 않는다」가 무슨 뜻인지부터 정한다

세 가지가 서로 다른 말이고, 섞으면 사용자에게 거짓말이 된다.

| | 뜻 | 우리가 하는 것 |
|---|---|---|
| ① 손대지 않는다 | 파일을 한 번도 읽지 않는다 | **불가능** — 값을 뽑으려면 읽어야 한다 |
| ② **보관하지 않는다** | 읽을 때만 가져오고 **끝나면 지운다** | ✅ **이것** |
| ③ 흔적을 안 남긴다 | 무엇을 읽었는지도 안 남긴다 | ❌ **하면 안 된다** (§2) |

②를 말하려면 **지운다는 것이 코드로 보장되어야 한다.** 그래서 작업 사본은
`materialize()` → `dispose()` 한 쌍으로만 존재하고, **지웠다는 사실도 기록에 남는다.**

작업 사본은 **OS 임시 폴더**에 만든다. 프로젝트 폴더에 두지 않는 이유는 하나다 —
거기 두면 지우는 것을 잊었을 때 **그대로 보관이 되고 아무도 눈치채지 못한다.**

---

## 1. 파일을 안 갖는 대신 **열쇠를 갖는다** — 이쪽이 더 위험할 수 있다

가장 먼저 짚어야 하는 것이 이것이다. 자료를 안 갖는다고 위험이 준 것이 아니라
**위험의 종류가 바뀐 것**이다.

> **토큰이 새면 자료 한 건이 아니라 그 사용자의 드라이브 범위 전체가 샌다.**

그래서 두 가지를 한다.

### ① 토큰을 아예 안 갖는 길을 먼저 권한다

| | 그때그때 고르기 | 폴더 연결 |
|---|---|---|
| 열쇠 보관 | **안 한다** | **한다** (refresh token) |
| 좋은 점 | 새어 나갈 열쇠가 없다 | 자료가 늘어도 다시 안 골라도 된다 |
| 대가 | 자료가 늘 때마다 사용자가 다시 고른다 | **범위 전체가 노출면이 된다** |

### ② 붙일 때 범위를 좁힌다

| 저장소 | 좁히는 법 | 안 좁히면 |
|---|---|---|
| **Dropbox** | 앱 등록 때 **App folder** | Full Dropbox = 드라이브 전체. 되돌리려면 앱을 다시 만들어야 한다 |
| **Google Drive** | **`drive.file`** 범위 (피커로 고른 파일만) | `drive.readonly` = 드라이브 전체를 읽는다 |
| **OneDrive · SharePoint** | `Files.Read.Selected` | `Files.Read.All` = 조직 드라이브 전체 |
| **Box** | 관리자 승인 범위를 폴더 단위로 | 기업 계정 전체 |

**이건 코드가 못 막는다.** 각 콘솔에서 사람이 고르는 값이고, 잘못 고르면
드라이브 전체 권한이 붙은 채로 정상 동작한다 — 증상이 전혀 없다. 등록부 미결이다.

키는 `connectors/http.js` 의 `SECRET_ENV` 에 넣어 로그에서 가린다 (§2).

## 2. 보관하지 않는 대신 **근거는 반드시 남긴다**

이 시스템의 전제는 **「출처 없는 숫자는 들어오지 못한다」**이다. 그런데 원본이
남의 드라이브에 있으면 사용자가 언제든 고치거나 지울 수 있고, **그때 문서에는
아무 표시도 안 남고 숫자만 근거를 잃는다.**

그래서 파일 대신 이것을 남긴다 (`01_Project/linked.json`).

| 남기는 것 | 왜 |
|---|---|
| `provider` · `fileId` · `path` | 나중에 사용자가 **자기 드라이브에서 찾을 수 있어야** 한다 |
| **`rev` (판)** | 파일만 가리키면 「그 파일」은 가리켜도 **「그때 그 판」은 못 가리킨다** |
| **`sha256`** (우리가 읽은 바이트로 우리가 계산) | 「우리가 읽은 그 내용」을 증명한다 |
| `readAt` | 언제 읽었는가 (§4.7 기준시점) |

**`rev` 가 없으면 연결 자체를 거절한다.** 없어도 동작은 하지만, 없는 채로 두면
나중에 원본이 바뀌어도 알 방법이 사라진다.

### 제공자 해시를 그대로 믿지 않는다

| 저장소 | 주는 해시 |
|---|---|
| Dropbox | `content_hash` — 4MB 블록 SHA256 들의 SHA256 (표준 해시가 아니다) |
| Box | **sha1** |
| Google Drive | `md5Checksum` — **구글 네이티브 문서에는 아예 없다** |
| OneDrive | `quickXorHash` (업무용) · `sha256Hash` (개인) |

넷이 다 다르므로 **서로 비교가 안 되고**, 하나는 값이 없다. 그래서 **우리가 읽은
바이트로 우리가 sha256 을 계산**해 장부에 남기고, 제공자 해시는 「바뀌었는지 싸게
확인」하는 용도로만 쓴다.

### 원본 바이트가 없는 문서

구글 문서·스프레드시트는 **내보내야 바이트가 생긴다.** 다시 내보내면 바이트가
달라질 수 있어 **지문이 재현되지 않는다.** 값을 못 뽑는 것은 아니지만 출처에
그 사실을 적는다 (`exportedNote()`).

## 3. 보관하지 않아서 새로 생긴 일 — **물어봐야 안다**

사본이 없으므로 원본이 바뀌었는지는 **물어봐야만 안다.** 안 물으면 문서는 그대로
멀쩡하고 근거만 사라진다. 그래서 `verify()` 가 다섯으로 가른다.

| 결과 | 뜻 | 왜 갈랐는가 |
|---|---|---|
| `ok_` | 판이 그대로 | |
| `changed` | **판이 달라졌다** | 지금 다시 만들면 그때와 다른 값이 나온다 |
| `missing` | 원본이 없어졌다 | |
| `errors` | **확인하지 못했다** (토큰 만료·네트워크) | `missing` 과 섞으면 **멀쩡한 자료를 잃은 것으로 읽는다** |
| `unread` | 한 번도 안 읽어 지문이 없다 | 값의 근거가 될 수 없다 — **통과시키지 않는다** |

같은 판인데 내용이 달라진 경우도 잡는다 (`fingerprintChanged`) — 제공자가 판
번호를 안 올리고 내용만 바꾸는 경우가 있다.

**판이 올라가면 이전 판 기록을 지우지 않는다.** 지우면 「그때는 이 판을 보고
썼다」가 사라진다.

## 4. 코드가 거절하는 것

값을 내려는 것이 아니라 **못 하는 이유를 코드가 들고 있으려는 것**이다.

| 함수 | 거절하는 것 | 왜 |
|---|---|---|
| `keepCopy()` | 사본을 남겨 두기 | 「빠르니까 캐시해 두자」가 곧 보관이 된다. 그 순간 사용자에게 한 약속이 거짓이 되고 **화면 어디에도 안 나타난다** |
| `shareOutward()` | 원본 재배포 | 우리가 받은 것은 **읽을 권한**뿐이다. 「보고서에 원본을 첨부해 보내자」가 여기 걸린다 |
| `normalizeRef()` | `rev` 없는 참조 · **토큰이 섞인 참조** | 토큰이 참조에 섞이면 **장부에 그대로 저장된다** |

`linked.write()` 는 저장 직전에 장부 전체를 훑어 `token`·`secret` 류가 있으면
**예외를 던진다.** 실수로 한 번 들어가면 그 파일이 계속 남기 때문이다.

## 5. 새 엔드포인트

| | 무엇 | 비고 |
|---|---|---|
| `GET /projects/:id/linked` | 연결 목록 · 붙일 수 있는 저장소 · 방법 둘 | 응답에 `storesCopies: false` |
| `POST /projects/:id/linked` | 연결 | **가져오지 않는다** |
| `DELETE /projects/:id/linked/:key` | 연결 끊기 | `deletedOriginal: false` — **원본은 안 지운다** |
| `POST /projects/:id/linked/verify` | 원본이 그대로인가 | 조회기가 안 붙어 있으면 **501** — 조용히 「이상 없음」을 내지 않는다 |

## 6. 아직 안 한 것 — **실제 API 호출**

이 저장소에 있는 것은 **제공자 중립 계약과 장부·수명 관리**다. 실제 내려받기·
메타 조회(`fetchOne` · `headOne`)는 **본체 플랫폼이 넣는다** — OAuth 토큰이 거기
있기 때문이고, 토큰을 이 저장소로 가져오면 공개 저장소에 시크릿이 붙는 셈이 된다.

| | 상태 |
|---|---|
| 제공자 정의 · 범위 안내 | ✅ |
| 참조 정규화 · 지문 · 장부 · 수명 | ✅ |
| 거절 함수 | ✅ |
| **OAuth 흐름 · 실제 REST 호출** | ☐ 본체 플랫폼 |
| **각 콘솔 앱 등록** | ☐ 사람이 한다 (§1 ②) |
| **실측** | ☐ 이 환경은 망 정책으로 외부 호출이 막힌다 |

새 SDK 는 들이지 않는다 (§5). 전부 HTTPS REST 다.

## 7. `core/vault.js` 는 어떻게 되는가

**버리지 않는다.** 둘은 대상이 다르다.

| | vault | linked |
|---|---|---|
| 대상 | **우리가 보관하는** 자료 | **보관하지 않는** 자료 |
| 갖는 것 | 파일 + 장부 | **장부만** |
| 쓰이는 곳 | 보고서 생성 1단계의 직접 업로드 | 「자료」 탭 |

☐ **직접 올리는 길을 남길지 정해야 한다.** 연결만 남기면 **저장소를 안 쓰는
사람은 자료를 넣을 방법이 없다.** 남긴다면 두 경로가 공존하고, 그러면 사용자에게
「보관합니다/안 합니다」를 **경로마다 다르게** 말해야 한다.

☐ **자료 탭 등급도 다시 정해야 한다.** 등급별 **용량**으로 가르기로 했는데(D-63),
보관을 안 하면 **잴 것이 없다.** 연결 건수로 가를지, 그냥 무료로 열지 다시 정한다.
