# 〈전달용〉 웹앱(PWA) 아이콘이 안 바뀝니다 — 매니페스트와 **재설치**

〈2026-08-30 사장님 화면: 안드로이드 크롬 「설치 및 바로가기 만들기 / 앱이 이미
설치되어 있습니다」 · 「갱신한 주소로 접속해도 과거 버전이 다운로드됨」 · D-188〉

> **이 파일을 `linkpilot-platform` 을 만지는 분께 그대로 전달해 주십시오.**
> `linkpilot-cron` 은 저쪽 저장소에 쓰지 않습니다 (CLAUDE.md §8-2).

---

## 한 줄 요약

아이콘은 **웹 매니페스트의 PNG** 에서 옵니다. 그 목록을 바꿔 주셔야 하고,
바꾸신 뒤에도 **이미 설치된 것은 저절로 안 바뀝니다** — 지우고 다시 설치해야 합니다.

## 넣어 주실 것 — 그림 넉 장

`assets/brand/pwa/` 에 있습니다. 폴더째 가져가시면 됩니다.

| 파일 | 크기 | 쓰임 |
|---|---|---|
| `linkpilot-192.png` | 192 | 안 오려 내는 자리 (둥근 사각형 + 투명 여백) |
| `linkpilot-512.png` | 512 | 〃 |
| `linkpilot-maskable-192.png` | 192 | **오려 내는 자리** (가장자리까지 꽉 참) |
| `linkpilot-maskable-512.png` | 512 | 〃 |

### ★★★ 왜 두 벌인가 — 이것이 핵심입니다

안드로이드는 아이콘을 **동그랗게 오려 냅니다**(masking).

- **오려 내는 판을 안 주면** — 투명 여백째로 오려서, 아이콘이 **조그맣게 박힌
  흰 동그라미**가 됩니다.
- **오려 내는 판만 주면** — 오리지 않는 자리에서 **각진 흰 네모**로 뜹니다.

그래서 매니페스트의 `icons` 에 **`purpose` 를 갈라** 넉 장을 다 넣어 주십시오.
`purpose` 값은 안 오려 내는 쪽이 `any`, 오려 내는 쪽이 `maskable` 입니다.
`type` 은 넷 다 PNG 이고, `sizes` 는 파일 이름의 숫자와 같습니다.

★ 오려 내는 원은 한 변의 **80%** 입니다. 저희 그림은 한가운데에서 가장 멀리
  닿는 곳이 한 변의 **29%**(지름 58%)라 넉넉히 들어갑니다 — 검사가 지킵니다.

## ★★ 바꾸신 뒤에도 안 바뀝니다 — 재설치가 필요합니다

사장님 화면이 「**앱이 이미 설치되어 있습니다**」였습니다. 안드로이드는 아이콘을
**설치할 때 한 번 가져가** 런처에 박아 둡니다. 매니페스트를 고쳐도 **이미 설치된
것의 아이콘은 저절로 안 바뀝니다.**

그래서 확인하실 때는 이 순서로 하십시오.

1. 휴대폰 홈 화면에서 **LinkPilot 아이콘을 길게 눌러 제거**합니다.
2. 크롬에서 앱 주소를 **다시 열고**, 주소창 오른쪽 **⋮ → 앱 설치**(또는 「홈 화면에 추가」).
3. 새 아이콘으로 뜨는지 봅니다.

★ 지우고 다시 설치하기 전까지는 **무엇을 고쳐도 옛 아이콘이 보입니다.**
  「반영이 안 됐다」의 절반은 이것입니다.

## ★ 함께 봐 주시면 좋은 것 — 파일이 캐시에 잡혀 있지 않은지

매니페스트와 아이콘 PNG 가 **오래 캐시**되도록 서비스되고 있으면, 재설치해도
브라우저가 옛 파일을 씁니다. 두 가지를 확인해 주십시오.

- 매니페스트 응답에 긴 캐시 머리말이 붙어 있지 않은가
- 아이콘 파일 이름이나 주소에 **판 표시**가 붙어 있는가
  (이름이 그대로면 브라우저는 바뀐 줄 모릅니다)

## 맥 앱은 따로입니다

맥용 `LinkPilot.app` 을 만드실 때 쓰는 것은 `assets/brand/LinkPilot.icns` 입니다
(이미 묶어 두었습니다 — `iconutil` 을 치실 필요 없습니다). **웹앱과 맥 앱은
아이콘을 가져가는 자리가 다릅니다** — 한쪽만 바꾸면 다른 쪽은 그대로입니다.
