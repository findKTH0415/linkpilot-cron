| 엔드포인트 | 지금 | 열리는 조건 |

## 2. 본체가 넣어야 하는 함수 셋

`report-api.cjs` 의 `createRouter({...})` 에 그대로 넘긴다.
[`배포-지시서.md`](배포-지시서.md) §4-2 의 코드에 **세 줄을 더하는 것**이다.

```js
app.use('/api/linkpilot', reports.createRouter({
  agentRoot: ROOT,
  agentModulePath: AGENT,
  authenticate: (req) => req.session && req.session.user,
  startRun:   (id, spec, user) => queue.startRun(id, spec, user),
  runningFor: (id) => { const r = queue.latestFor(id);
    return r && (r.status === 'running' || r.status === 'queued') ? r : null; },

  // ↓ 이번에 더하는 셋
  fetchLinked:    (item) => storage.download(item),     // §2-1
  headLinked:     (item) => storage.head(item),         // §2-2
  extractOneshot: (id, files) => engine.extractInto(id, files),  // §2-3
}));
```

세 함수 모두 **토큰을 인자로 받지 않는다.** 본체가 자기 세션에서 꺼내 쓴다.
엔진은 어느 계정인지 모르고, **알 필요도 없다** (§5).

### 2-1. `fetchLinked(item)` — 실제로 내려받는다

```
fetchLinked(item) → Promise<{ok:true, buf:Buffer} | {ok:false, reason:string}>
```

`item` 은 장부에 있는 그대로다. 쓸 필드는 다섯이다.

| 필드 | 예 | 쓰임 |
|---|---|---|
| `provider` | `'dropbox'` `'box'` `'gdrive'` `'onedrive'` | 어느 API 를 부를지 |
| `fileId` | 제공자가 준 식별자 | 무엇을 받을지 |
| `rev` | `'0158...'` `'headRevisionId'` 값 | **어느 판을 받을지 — 최신이 아니라 이 판이다** |
| `name` | `사업계획서.pdf` | 임시 파일 이름 |
| `exported` | `true` | 구글 문서처럼 **원본 바이트가 없어 내보내야 하는** 경우 |

**규칙**

- **`rev` 를 무시하고 최신을 받지 않는다.** 장부에 적힌 판과 다른 것을 받으면
  출처가 가리키는 것과 문서에 실린 값이 갈린다. 판을 못 받는 제공자면
  `{ok:false, reason:'그 판을 받을 수 없습니다'}` 로 돌려준다.
- **예외를 던져도 된다** — 엔진이 잡아서 `failed` 로 센다. 다만 `reason` 을
  사람이 읽을 문장으로 준다. 「404」만 오면 사용자가 할 일을 모른다.
- **빈 버퍼를 성공으로 돌려주지 않는다.** 엔진이 실패로 센다.
- 못 받은 것은 **조용히 빠지지 않는다** — `materialize()` 가 `failed` 로 내고,
  그 사실이 보고서 앞에 선다.

### 2-2. `headLinked(item)` — 내려받지 않고 판만 본다

```
headLinked(item) → Promise<{ok:true, rev:string, providerHash?:string, missing?:boolean}
                          | {ok:false, reason:string}>
```

- **파일을 받지 않는다.** 매번 다 받으면 사용자 계정의 쿼터를 태운다.
- 원본이 **지워졌으면** `{ok:false, missing:true}` — 「오류」와 구분해서 준다.
  화면이 「원본이 사라졌습니다」와 「확인하지 못했습니다」를 다르게 말해야 한다.
- `rev` 가 장부와 다르면 엔진이 **`changed`** 로 분류한다. 그것이 이 기능의 요점이다 —
  사본을 안 갖고 있으므로 **물어봐야만 안다.**

### 2-3. `extractOneshot(projectId, files)` — 올린 파일을 읽는다

```
extractOneshot(projectId, files) → Promise<any>     // files: [{name, path, size, ext}]
```

- `files` 는 **OS 임시 폴더**에 잠깐 놓인 실제 파일이다. 경로를 그대로 읽으면 된다.
- 돌려준 값은 응답의 `read` 로 사용자에게 그대로 간다 — **무엇이 값으로 잡혔는지**
  보여 주는 자리다.
- **파일은 엔진이 지운다.** 이 함수가 던져도 지운다. 본체가 지우려 하지 않는다.
- **이 파일들을 어디에도 복사하지 않는다.** 복사하는 순간 「1회성」이 거짓이 된다.

**엔진이 함수를 내줬으므로 본체는 한 줄이다** (2026-08-17 `d0b0574` · §6-2):

```js
const engine = require(AGENT + '/pipeline');
extractOneshot: (id, files) => engine.extractInto(id, files),
```

★ **직접 구현하지 않는다.** 추출 결과를 반영하는 일은 다섯 단계다 —
옛 추출값 버리기 → 병합 → `resolve()` → 저장 → `extraction.json` 갱신.
복제하면 엔진이 바뀌는 날 **본체만 옛말을 하고, 그때 아무도 모른다.**

## 3. 콘솔 앱 등록 — **폴더까지만**

네 곳 모두 사람이 콘솔에서 해야 한다. **범위를 넓게 잡으면 되돌리기 어렵다.**

| 제공자 | 코드로 확인 | 사람이 확인할 것 |
|---|:--:|---|
| **Dropbox** | ❌ 불가 | 앱 등록에서 **Access type = App folder**. `Full Dropbox` 로 만들면 **되돌릴 수 없고 앱을 다시 만들어야 한다** |
| **Box** | ❌ 불가 | 서비스 계정을 **그 폴더에만 협업자(Viewer)** 로 초대. 기업 계정은 관리자 승인 범위도 폴더 단위 |
| **Google Drive** | ✅ 가능 | **`drive.file` 만** 요청. `drive` · `drive.readonly` · `drive.metadata.readonly` 는 **거절된다** |
| **OneDrive · SharePoint** | ✅ 가능 | **`Files.Read.Selected` + `offline_access`**. `Files.Read.All` · `Sites.Read.All` 은 **거절된다** |

### 3-1. 토큰을 받은 뒤 반드시 검사한다

```js
const storage = require(AGENT + '/connectors/storage');
const s = storage.checkScope(providerId, tokenResponse.scope);
if (!s.ok) return 연결거절(s.reason);          // 범위가 폴더를 넘는다
if (!s.verifiable) 화면에알림(s.reason);        // 코드로 확인 불가 — 사람이 봐야 한다
```

★ **`verifiable:false` 는 통과가 아니다.** Dropbox·Box 는 폴더 제한이 스코프
문자열에 안 나타난다 — 「코드로는 확인할 수 없으니 등록 화면을 사람이 확인해야
한다」는 뜻이고, **화면이 그렇게 말해야 한다.** 「확인됨」으로 표시하면 안 된다.

### 3-2. 토큰은 본체가 갖는다

- **엔진 장부에 토큰이 들어가면 저장이 예외로 막힌다** (테스트로 고정).
  `accessToken` `refreshToken` `token` `authorization` `secret` `password` —
  이 이름이 참조에 섞여 오면 `POST .../linked` 가 **400** 으로 거절한다.
- 갱신 실패 시 조용히 죽지 않는다. 연결이 끊긴 자료는 `headLinked` 가
  `{ok:false, reason:'다시 연결이 필요합니다'}` 를 돌려주게 한다.
- `.env` 의 `DROPBOX_APP_KEY` · `BOX_CLIENT_ID` · `GOOGLE_CLIENT_ID` ·
  `MS_CLIENT_ID` 는 **본체 프로세스**에 넣는다. GitHub Secrets 는 CI 용이라
  NAS 프로세스와 무관하다.

## 4. 화면 — 피커가 만들어 보내는 참조

`POST /api/linkpilot/projects/:id/linked` 의 본문:

```json
{ "ref": {
    "provider": "gdrive",
    "fileId":   "1AbC...",
    "name":     "사업계획서.pdf",
    "rev":      "0BxY...",
    "path":     "/딜/인천DC/사업계획서.pdf",
    "bytes":    2481234,
    "providerHash": "9f8e...",
    "exported": false
} }
```

| 필드 | 필수 | 안 지키면 |
|---|:--:|---|
| `provider` | ✅ | 400 「모르는 저장소입니다」 |
| `fileId` | ✅ | 400 (256자 넘어도 거절) |
| `name` | ✅ | 400 |
| **`rev`** | ✅ | **400 「판(rev/version)이 없습니다 — 파일만 가리키면 나중에 바뀌어도 알 수 없습니다」** |
| `path` | 권장 | 사용자가 **자기 드라이브에서 못 찾는다** |
| `providerHash` | 선택 | 종류(`hashKind`)는 엔진이 붙인다 |
| `exported` | 구글문서 | 출처에 「내보낸 사본」 표시가 안 붙는다 |

제공자별 `rev` 자리: Dropbox `rev` · Box `file_version.id` ·
Google `headRevisionId` · OneDrive `cTag`.

★ **토큰을 `ref` 에 넣지 않는다.** 넣으면 400 으로 거절된다 — 장부에 그대로
저장될 자리이기 때문이다.

### 4-1. 1회성 업로드

`POST /api/linkpilot/projects/:id/oneshot`

```json
{ "files": [ { "name": "감정평가서.pdf", "contentBase64": "JVBERi0..." } ] }
```

한도는 **파일 하나 20MB · 한 번에 60MB · 50개**. 넘은 것은 거절 목록에 이유와
함께 온다. 응답은 `reusable:false` · `verifiable:false` 를 말한다 —
**화면이 올리기 전에 그것을 알려야 한다.** 올린 뒤 「다시 못 씁니다」는 늦다.

## 5. 하면 안 되는 것

| | 왜 |
|---|---|
| **연결 자료의 사본을 서버에 남긴다** | 「보관하지 않습니다」가 거짓이 된다. 엔진은 OS 임시 폴더에 받고 `dispose()` 로 지운다 — 본체가 따로 복사하면 그 약속이 깨진다 |
| **1회성 파일을 재사용하려고 어딘가 둔다** | 같은 이유. 재사용이 필요하면 그건 1회성이 아니라 **연결**이나 **보관**이다 |
| **연결 끊기를 원본 삭제로 만든다** | 남의 드라이브다. 응답이 `deletedOriginal:false` 로 그 구분을 말한다 |
| **`rev` 없이 최신을 받는다** | 출처가 가리키는 판과 문서의 값이 갈린다 |
| **범위를 넓게 받아 두고 나중에 좁힌다** | Dropbox 는 되돌릴 수 없다. Google·OneDrive 는 엔진이 아예 거절한다 |
| **읽기 실패를 성공으로 돌려준다** | 값이 조용히 빠지고 문서는 멀쩡해 보인다 — 이 시스템에서 가장 나쁜 실패다 |

## 6. 엔진이 먼저 내줘야 하는 것 — **2건 완료 (2026-08-18)**

> **상태 (2026-08-18)** — 아래 두 건을 붙였다. 검사는 `test/linked-pipeline.test.js` 4건.
> - §6-1 `pipeline.run()` 이 `02_extraction` **앞에서** `linked.materialize()` 를 부르고, 추출기에
>   `extraFiles` 로 넘긴 뒤 **finally 에서 `dispose()`** 한다. 못 가져온 것은 추출기 `unsupported`
>   와 Agent 경고에 사유와 함께 선다. 내려받기는 `opts.fetchLinked`(함수) 또는
>   **`IM_LINKED_FETCHER`**(모듈 경로 — run-queue 가 cli.js 를 자식 프로세스로 띄우므로 함수를 못 넘긴다;
>   본체는 `module.exports.fetchLinked` 를 가진 파일을 만들어 그 경로를 환경변수로 준다) 로 받는다.
>   없으면 **읽지 않고 그 사실을 경고로 세운다** — 조용히 빠지지 않는다.
> - §6-2 `pipeline.extractInto(projectId, files) → {facts, documents, unsupported}` 를 내놓았다.
>   `run()` 과 **같은 병합 함수**(`mergeExtraction`)를 쓰고, `extraction.json` 은 이전 문서 목록을
>   지우지 않고 병합한다. 파일은 지우지 않는다(부른 쪽이 dispose). 본체(NAS `im-engine-server.cjs`)는
>   `extractOneshot: (id, files) => pipeline.extractInto(id, files)` 로 연결했다 → `POST …/oneshot` 이 열린다.
>
> 아래 원문은 그대로 둔다 — 무엇이 왜 필요했는지의 기록이다.

**이건 본체 일이 아니다.** 다만 본체가 §2 를 시작하기 전에 알아야 해서 적는다.

### 6-1. ✅ `linked.materialize` 를 파이프라인에 잇는다 〈2026-08-17 붙었다 · `d0b0574`〉

`core/linked.js` 의 `materialize()`(연결 자료를 실제로 가져오는 함수)를
**엔진의 어떤 코드도 부르지 않는다.** 즉 `fetchLinked` 를 넣어도 **연결한 자료가
보고서 생성 때 읽히지 않는다.**

- 붙일 자리: `pipeline.js` 의 `02_extraction` **앞**.
  추출기는 `input.files` 를 밖에서 받게 되어 있어(`agents/02-extraction.js`)
  임시 폴더 파일을 그대로 읽는다.
- 끝나면 **반드시 `dispose()`** — 안 지우면 그것이 곧 보관이 된다.
- `failed` 를 삼키지 않는다. 못 가져온 것은 경고로 세워야 한다.

### 6-2. ✅ `extractOneshot` 이 부를 함수를 엔진이 내준다 〈2026-08-17 내놓았다 · `d0b0574`〉

지금은 추출 결과를 dataset 에 넣는 일이 `pipeline.js` 안에만 있다
(옛 추출값 버리기 → 병합 → `resolve()` → 저장 → `extraction.json`).
본체가 이걸 복제하면 **엔진이 바뀌는 날 본체만 옛말을 한다.**

- 필요한 모양: `pipeline.extractInto(projectId, files) → {facts, documents, unsupported}`
- 그러면 본체는 `extractOneshot: (id, files) => engine.extractInto(id, files)` 한 줄이다.

> **둘 다 끝났다.** 이제 자료 탭을 막는 것은 **엔진이 아니라 §3(콘솔 앱 등록)과
> §2(본체 주입)** 다. 그 둘이 끝나기 전에 화면을 붙이면 사용자가 501 을 보게 된다.

## 7. 붙었는지 확인하는 순서

위에서부터 한 줄씩. **하나라도 다르면 거기서 멈춘다.**

| | 하는 일 | 되어야 하는 것 |
|---|---|---|
| 1 | 로그아웃 상태로 `POST .../linked` | **401** 「로그인이 필요합니다」 |
| 2 | 로그인 후 `ref` 에서 `rev` 를 빼고 호출 | **400** 「판(rev/version)이 없습니다 …」 |
| 3 | `ref` 에 `accessToken` 을 넣어 호출 | **400** 「참조에 토큰을 넣지 않습니다」 |
| 4 | 정상 `ref` 로 호출 | **200** · `item.fingerprint` 는 **`null`** (아직 안 읽었다) |
| 5 | `POST .../linked/verify` | **200** · 방금 연결한 것이 `unread` 에 있다 |
| 6 | 드라이브에서 그 파일을 고친 뒤 5번 다시 | **`changed`** 에 뜬다 (`was`/`now` 판이 함께) |
| 7 | 드라이브에서 그 파일을 지운 뒤 5번 다시 | **`missing`** 에 뜬다 (`errors` 가 아니다) |
| 8 | 보고서를 생성한다 | `09_IM/im.md` 출처에 **`… · 사본 보관 안 함`** 이 붙는다 |
| 9 | 생성 뒤 서버의 임시 폴더 | **비어 있다** (`linked-log.jsonl` 에 `dispose` 기록) |
| 10 | `POST .../oneshot` 로 1건 올린다 | **200** · `read` 에 잡힌 값이 온다 · `removed ≥ 1` |
| 11 | `GET .../oneshot` | 기록은 있고 **파일은 없다** · `reusable:false` |

**6번과 7번을 건너뛰지 않는다.** 「보관하지 않는다」의 대가를 갚는 자리가 거기다 —
원본이 바뀐 것을 못 잡으면 문서는 멀쩡하고 근거만 사라진다.

### 7-1. 위 표가 실제로 그렇게 도는지 — **엔진에서 미리 돌려 봤다**

가짜 제공자(`fetchLinked`·`headLinked` 를 즉석에서 만든 것)를 세워 두고 호출한
결과다. **본체가 §2 를 붙이면 같은 응답이 나와야 한다.**

```
✅ fetchLinked 없음 · POST linked        → 501
✅ headLinked 없음 · verify              → 501
✅ extractOneshot 없음 · oneshot         → 501
✅ GET linked 는 열려 있다               → 200
✅ 로그아웃                              → 401
✅ rev 없음                              → 400
     문구: 판(rev/version)이 없습니다 — 파일만 가리키면 나중에 바뀌어도 알 수 없습니다
✅ 토큰 섞임                             → 400
     문구: 참조에 토큰을 넣지 않습니다
✅ 정상 연결                             → 200 · fingerprint 는 null (아직 안 읽었다)
✅ verify · unread 에 있다               → 1
✅ 원본이 바뀌면 changed                 → 1
✅ 원본이 사라지면 missing               → 1   (errors 는 0 — 구분된다)
✅ 연결끊기 ≠ 원본삭제                   → deletedOriginal:false
✅ 출처 끝이 「사본 보관 안 함」
     Google Drive · /딜/x.pdf · 판 0BxY · 2026-08-17 읽음 · sha256 cb0f24046b50 · 사본 보관 안 함
✅ oneshot 200 · 파일을 지웠다 (removed 1) · reusable:false · 기록은 남는다
✅ gdrive drive.readonly 거절 / drive.file 통과
✅ onedrive Files.Read.All 거절 / dropbox 는 verifiable:false
✅ 파일 한도 20MB · 요청 한도 60MB
❌ materialize 를 부르는 곳 0            → §6-1 그대로 (주석 1줄 외에 호출 없음)
```

마지막 줄이 이 문서가 필요한 이유다 — **함수는 있는데 아무도 안 부른다.**
