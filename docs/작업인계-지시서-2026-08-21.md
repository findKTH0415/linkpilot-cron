## 1. 먼저 읽을 것 — **왜 이걸 했나**

전에는 자료가 **넣기만** 되고 읽히지 않았다. 읽는 것은 **보고서를 만드는 순간**이라,
자료를 넣은 사람이 2단계(가이드 필드)에 가면 **빈 칸만** 봤다.

**값이 없는 것이 아니라 아직 안 읽은 것**인데, 화면은 그 둘을 구분해 말하지
못했다. 사용자는 자기가 올린 자료를 탓하거나, 기능이 고장 난 줄 안다.
**오류는 아무 데도 안 뜬다** — 그래서 이 구멍은 눈으로 안 잡힌다.

지금은 셋(앱에서 가져오기 · 폴더 연결 · 파일업로드) 중 무엇으로 넣든
**한 길로** 읽어 값으로 만들고, 값이 들어가면 2단계로 넘긴다.

### 2-1. 프로젝트 고르는 자리는 **화면에 하나뿐**이다 🔴

처음에는 고르기가 **둘**이었다 — 화면 맨 위에 하나, 「＋ 앱 프로젝트에서
가져오기」 갈래 안에 또 하나. 같은 앱 딜이 두 곳에 뜨고 **둘이 같은 함수를 부르니
화면만 봐서는 어느 쪽이 진짜인지 모른다.** 그래서 **상단을 지우고 갈래 안으로
합쳤다** 〈2026-08-21 사용자 지시〉.

지금은 「LinkPilot 프로젝트에서 가져오기」 갈래 안에 **한 목록**이 있고, 그 안에 셋이
무리(`optgroup`)로 갈라져 있다:

```
— 고르세요 —
＋ 신규프로젝트                  ← 맨 위. 여기서 바로 만든다(다른 탭으로 안 보낸다)
[보고서 프로젝트]                ← 엔진에 이미 있는 것
[앱 프로젝트에서 가져오기]        ← 앱 딜. 고르면 엔진 프로젝트로 잇는다
```

- **처음 열릴 때 갈래는 「LinkPilot 프로젝트에서 가져오기」다.** 고르는 자리가
  거기뿐이라, 다른 갈래로 열면 **아무것도 못 하는 화면**부터 보게 된다.
- **다른 갈래에는 고르기를 또 그리지 않는다.** 대신 프로젝트가 없으면
  **「LinkPilot 프로젝트에서 가져오기」로 가기** 단추가 뜬다 — 자리를 하나로 모은
  대가다. 안내만 하고 길을 안 주면 **막다른 길**이 된다.
- 앱 딜을 고르면 갈래가 **자동으로 「앱에서 가져오기」로 맞춰진다.**

★ **앱이 프로젝트 고르기를 따로 두지 않는다.** 앞 문서 §3 의 경고와 같은 자리다 —
둘이 다른 것을 가리키는 순간 사용자는 **어느 프로젝트에 자료를 넣었는지 모른다.**

★ **앱이 할 일은 없다.** `appProjects`·`appLinks`·`fetchAppProject` 계약은
앞 문서 §2-1-2 그대로다.

★ 갈래 이름은 **화면 한 곳**(`files.html` 의 `WAYS`)에서 나온다. 앱이 따로
적지 않는다. 안내 문장도 이름을 손으로 적지 않고 `wayName()` 으로 가져간다 —

### 붙일 것

```js
// im-engine-server.cjs — createHandlers 에 넘기는 deps 에 한 줄
extractFiles: (projectId, files) => pipeline.extractInto(projectId, files),
```

**1회성(`extractOneshot`)에 이미 붙여 두었으면 그대로 돈다.** 둘은 같은 함수를
가리킨다 — 이름이 둘인 것은 1회성이 먼저 생겼기 때문이지 하는 일이 달라서가 아니다.
`extractFiles` 가 없으면 엔진이 `extractOneshot` 을 쓴다.

### 안 붙이면 — **501 이 온다. 조용한 성공을 주지 않는다**

```json
{ "error": "자료를 읽는 경로가 붙어 있지 않습니다 — 자료는 그대로 있으니 읽기가 연결된 뒤에 다시 눌러 주십시오" }
```

★★ **0건 성공을 돌려주지 않는 것이 설계다.** 0건을 200 으로 주면 화면은
「읽었는데 값이 없다」로 그리고, 자료는 멀쩡한데 **사용자가 자기 자료를 탓한다.**
진짜 원인(안 붙은 배선)은 아무도 못 본다.

★ 화면은 이 501 을 **빨간 오류로 그리지 않는다.** 「아직 안 붙었습니다」로 그린다 —
닫혀 있는 것은 사실이고 사용자 잘못이 아니다.

### 새 길 — `POST /projects/:id/scan`

| | |
|---|---|
| 인증 | 앞 길들과 같다. 플랜 **무료** |
| 몸통 | `{}` (지금은 없다. `{ "only": "kept" \| "linked" }` 로 좁힐 수 있다) |
| 무엇을 읽나 | ① 보관 자료(`02_Source_Data`) ② 연결 자료 ③ **앱에서 가져온 첨부**(②와 같은 길) |
| 1회성은 | **여기 안 온다.** 올리는 그 자리에서 이미 읽었고 파일을 버렸다 — 응답이 그렇게 적어서 온다 |
| 연결 사본 | 읽고 **반드시 지운다.** 읽다 죽어도 지운다 |
| 값이 가는 곳 | `01_Project/dataset.json` → `GET /projects/:id/facts` → 2단계 화면 |

```json
{
  "scanned": [
    { "name": "등기부.png",    "how": "ocr", "ocr": true,  "read": true,  "readable": true,  "note": "이미지입니다 — 글자로 옮겨서 읽습니다 (신뢰도를 낮춰 표시합니다)" },
    { "name": "사업계획서.pdf", "how": "pdf", "ocr": false, "read": true,  "readable": true,  "note": null },
    { "name": "스캔.tif",      "how": "convert", "ocr": false, "read": false, "readable": false,
      "why": ".tif 는 변환 없이는 못 읽습니다 — PDF 나 PNG 로 저장해서 올립니다" }
  ],
  "unread":  [ { "name": "감정평가서.pdf", "why": "원본을 찾을 수 없습니다", "from": "linked" } ],
  "facts": 12,
  "documents": 2,
  "ocr": 1,
  "empty": false,
  "oneshotNote": "1회성으로 올린 자료는 올릴 때 이미 읽었습니다 — 보관하지 않으므로 다시 읽지 않습니다."
}
```

### 칸 읽는 법 — **`readable` 과 `read` 는 다르다**

| 칸 | 뜻 |
|---|---|
| `readable` | **읽을 작정이었나** (형식만 보고 판정) |
| **`read`** | **실제로 읽혔나.** 화면·앱은 **이것을 본다** |
| `why` | `read:false` 일 때 **왜** 못 읽었나 — 실제 사유다 |
| `ocr` | 그 파일에 OCR 을 **걸었나.** 걸려다 못 하면 `false` 로 내려간다 |
| **최상위 `ocr`** | **실제로 OCR 이 돈 파일 수.** 「OCR 몇 건」을 적을 거면 이 숫자를 쓴다 |

★★ **`scanned` 와 `unread` 에 같은 이름이 두 번 나오지 않는다.** `unread` 에는
**아예 오지도 못한 것**만 있다(연결 자료 내려받기 실패 등). 온 파일의 실패는
그 파일 줄(`read:false` · `why`)에 적힌다.

> 처음 판은 그러지 않았고, **실제로 돌려 보고 잡았다** — 같은 파일이
> 「OCR — 글자로 옮겨 읽음」과 「못 읽음: 키가 필요합니다」 **두 줄**로 떴다.
> 사용자는 어느 쪽이 사실인지 알 방법이 없다. 지금은 **결과가 작정을 이긴다.**

### ★ OCR 은 **키가 있어야 돈다**

이미지·스캔본을 실제로 옮겨 적으려면 서버에 **`GEMINI_API_KEY`** 가 있어야 한다
(`IM_AGENT_OFFLINE=1` 이면 꺼진다). 없으면 그 파일만 이렇게 나온다:

```
· 등기부.png — 못 읽었습니다 — 이미지 파일 — 스캔본을 읽으려면 키가 필요합니다 (지금은 꺼져 있습니다)
```

**글자가 든 파일은 키 없이도 읽힌다.** 그래서 키가 없어도 스캔 자체는 돌고
값도 나온다 — **이미지만 빠진다.** 그 사실이 화면에 파일 단위로 적힌다.

★ 키 이름은 `connectors/http.js` 의 `SECRET_ENV` 에 있어 **로그·오류 메시지에
값이 안 실린다.** 값을 문서·커밋에 적지 않는다 (CLAUDE.md §2).

### ★★ 「전부 OCR 한다」가 **아니다**

OCR 은 **이미지·스캔본에만** 건다. 글자가 들어 있는 PDF·워드·엑셀을 굳이 그림처럼
옮겨 적으면 **신뢰도만 깎인다** — 옮겨 적은 글자는 원문 대조가 안 되기 때문이다
(`core/ocr.js` · `OCR_CONFIDENCE`).

그래서 응답이 **파일마다** `ocr` 을 따로 준다. 화면도 그대로 보여 준다.
앱이 어딘가에 「OCR 스캔 완료」라고 적을 거면 **이 값을 세어서** 적는다.

### 실패는 격리한다

- 연결 자료 하나를 못 가져와도 **보관 자료는 읽는다.** 못 읽은 것은
  `unread` 에 **이름과 사유로** 담긴다 (개수만 주면 무엇이 빠졌는지 못 찾는다).
- 추출기가 던지면 500 을 준다. 그때도 **연결 사본은 지운다.**

## 4. 앱이 할 일 ② — **탭 옮기기 신호를 받는다** 🔴

읽고 나면 화면이 앱에 **「2단계로 옮겨 달라」**고 알린다. 옮기는 것은 앱이다 —
이 화면은 탭 하나일 뿐이라 스스로 갈 수 없다.

| 이름 | 언제 | 실린 것 |
|---|---|---|
| **`lp-open-project`** | 자료를 읽어 값이 들어갔을 때 | `{ projectId, section: 'make', step: 'fields', why: 'scan' }` |

같은 출처면 `postMessage`, 조각으로 얹었으면 `CustomEvent` — **두 갈래로 다 쏜다.**
앱은 **둘 다 받아 두면** 얹는 방식을 바꿔도 안 끊긴다.

```js
window.addEventListener('message', (e) => {
  if (e.origin !== window.location.origin) return;       // 다른 출처는 버린다
  const m = e.data || {};
  if (m.type === 'lp-open-project') openTab(m.section, { projectId: m.projectId, step: m.step });
});

document.addEventListener('lp-open-project', (e) => {
  openTab(e.detail.section, { projectId: e.detail.projectId, step: e.detail.step });
  e.preventDefault();          // ← 이것이 「받았다」의 증거다. 빼면 안 된다
});
```

### ★★ `preventDefault()` 를 **빼면 안 된다**

화면은 그것으로 「앱이 받았다」를 판정한다. 안 하면 화면은 **아무도 안 받았다**고
보고 이렇게 띄운다:

> 이 화면은 탭 하나라 스스로 옮길 수 없습니다 — 위 탭에서 「보고서 생성」을 눌러 주십시오.

**탭은 바뀌었는데 그 안내가 같이 뜬다.** 사용자는 무엇이 맞는 말인지 모른다.

★ `section` 값은 `flow-core.js` 의 `SECTION.id` = **`'make'`** 다.
앱이 이 문자열을 **따로 적어 두지 않는다** — `flow-core` 를 읽는다.

★ `step: 'fields'` 는 **2단계 「가이드 필드」**다. 값이 들어간 곳이 거기다.
앱이 단계까지 못 열면 `step` 은 무시해도 된다 — 섹션만 열려도 쓸 수 있다.

### 「완성 보고서」의 [프로젝트 이동]과 **같은 신호**다

전에는 `outputs.html` 안에 손으로 적혀 있었다. 2026-08-21 에 `flow-core.js` 의
`openSection()` 한 곳으로 모았다. **앱은 받는 곳을 하나만 두면 된다.**

## 5. 값이 0이면 **넘어가지 않는다** — 지시와 다르게 한 곳

사용자 지시는 「읽고 나면 2단계로 자동 이동」이었다. 그대로 하면 **값이 하나도
안 나온 경우에도** 넘어간다.

넘어가면 사용자는 2단계에서 **빈 칸만** 보고 자기가 뭘 잘못한 줄 안다.
못 읽은 이유(글자 없는 스캔본 · OCR 키 없음 · 바꿔 올려야 하는 형식)는 자료 탭에
남아 있는데, 그걸 보려면 **되돌아와야 한다.**

**지금 코드는 값이 1개 이상일 때만 넘긴다.** 0이면 그 자리에서 이렇게 말한다:

> 값이 하나도 안 나와서 「보고서 생성」으로 넘어가지 않았습니다 — 넘어가도 빈 칸만
> 보입니다. 위 목록에서 못 읽은 것을 먼저 보십시오.

앱에서 가져오기도 마찬가지다 — **하나라도 실패했으면 자동으로 안 넘긴다.**

★ 등록부 **D-76** 에 올려 두었다. 「그래도 무조건 넘겨라」로 정하려면
**2단계 화면부터 고쳐야 한다** — 지금 2단계는 「값이 없다」와 「아직 안 읽었다」를
구분해 말하지 못한다. **반쯤 만들지 않는다.**

## 6-2. 앱이 할 일 ④ — **탭이 왔다갔다 한다** 🔴 〈2026-08-21 신고〉

### 증상 (사용자 실측 · 휴대폰)

「보고서 만들기」를 열면 **탭은 `자료 업로드` 로 켜져 있는데 내용이 두 번 바뀐다.**

```text
① 먼저    「프로젝트가 없습니다 / 프로젝트를 고르면 그 프로젝트에서
           나온 문서가 여기 뜹니다」          ← 이것은 outputs.html
② 잠시 뒤 「자료 붙이기 …」                    ← 이것이 files.html
   그리고 ①↔② 를 오간다
```

### 어느 화면인지 **문구로 확정했다**

| 화면에 뜬 말 | 그 말을 가진 파일 |
|---|---|
| 「…그 프로젝트에서 **나온 문서**가 여기 뜹니다」 | `outputs.html` (완성 보고서) |
| 「…그 프로젝트의 **자료**가 여기 뜹니다」 | `files.html` (자료 업로드) |

**탭 표시는 `자료 업로드` 인데 끼워진 화면이 `완성 보고서` 다.**

### ★★ 어느 화면을 끼울지는 **앱이 정한다** — 엔진 쪽 원인이 아니다

- `outputs.html`·`files.html` 어느 쪽도 **부모에게 탭을 바꾸라고 보내지 않는다.**
  나가는 메시지는 셋뿐이고 전부 탭과 무관하다:
  `lp-embed-ready`(한 번) · `lp-embed-height`(4px 넘게 바뀔 때만) ·
  `lp-files-project`(사용자가 프로젝트를 바꿀 때).
- 높이 알림은 **값이 안 바뀌면 보내지 않는다** — 리사이즈가 서로를 부르며
  도는 것은 이미 막혀 있다.

### 앱에서 볼 곳 — 셋

1. **기본 탭과 복원 탭이 따로 도는가.** ~~`TABS` 의 첫 항목은 `done`(완성 보고서)다.~~
   ★ **바뀌었다** 〈2026-08-23 · `f73b6b2` 사장님 지시〉 — 첫 항목은 이제 **`make`(보고서 만들기)** 다.
   목록을 여기 옮겨 적지 말고 `flow-core.js` 의 `TABS` 를 읽는다. 이 줄이 옛 차례로
   남아 있어 **앱이 이것을 보고 굳혔을 수 있다** (D-93).
   기본값을 적용하는 길과 「마지막에 본 탭」을 되살리는 길이 **둘 다 살아 있으면**
   ①→② 가 그대로 나온다. 늦게 도착하는 쪽이 이기므로 **번갈아 보이기도 한다.**
2. **iframe 을 하나로 쓰면서 `src` 를 두 번 넣는가.** 두 번째가 첫 번째의 load 를
   기다리지 않으면 서로를 덮는다.
3. **탭마다 iframe 을 만들어 숨김/보임으로 가르는가.** 그렇다면 「보임」을 정하는
   신호가 무엇인지 본다 — 준비 신호로 가르면 **늦게 준비된 쪽이 이긴다.**

★ 어느 화면인지는 준비 신호가 **이미 알려 준다**:
`lp-embed-ready` 의 `global` 이 `LINKPILOT_OUTPUTS` / `LINKPILOT_FILES` /
`LINKPILOT_REPORT_FLOW` 로 갈린다. 그 값으로 자리를 정하면 순서에 안 흔들린다.

## 8. 조용히 무너지는 것들 — **오류가 안 나서 더 위험하다**

### ① `preventDefault()` 를 안 하면 🔴

탭은 바뀌는데 **「스스로 옮길 수 없습니다」 안내가 같이 뜬다.** §4 를 읽는다.

### ② `flow-core.js` 만 옛 판이면 🔴

`openSection` 이 없어서 **탭 옮기기가 통째로 죽는다.** 화면은 「아무도 안 받았다」로
그리고, 배선을 아무리 봐도 원인이 안 나온다. **16개를 통째로 올린다.**

### ③ 읽기 배선을 안 붙이면

자료를 넣어도 **2단계가 계속 빈 칸**이다. 지금은 501 과 사람이 읽을 문장이 오므로
**화면에서 보인다** — 붙이기 전에 이 문장이 보이면 그게 정상이다.

### ④ 「OCR 스캔 완료」라고 앱이 따로 적으면

전부 OCR 하는 것이 아니다(§3). 세어서 적거나, 적지 않는다.
안 그러면 **글자 PDF 를 OCR 했다고 말하는 화면**이 되고, 그건 사실이 아니다.

### ⑤ 프로젝트를 바꿨는데 앞 프로젝트 값이 남아 있으면

화면 쪽은 고쳤다(프로젝트를 바꿀 때 스캔 결과를 버린다). **앱이 자체 캐시를
들고 있으면 같은 일이 다시 난다** — 「값 12개를 만들었습니다」가 엉뚱한
프로젝트에 떠 있고, 그럴듯해서 아무도 눈치채지 못한다.

### ⑥ `font:` 축약형에 `inherit` 를 쓰면 — **앱 화면에도 있을 수 있다**

```css
font: 700 13px/1 inherit;     /* ✗ 선언 전체가 버려진다 */
```

`font` 축약형의 마지막 자리는 **font-family** 이고 거기에 `inherit` 를 못 쓴다.
규칙에 어긋나면 브라우저는 그 자리만 무시하는 게 아니라 **줄 전체를 버린다.**
크기·굵기가 통째로 기본값으로 떨어지는데 **오류는 안 난다.**

이 저장소 화면 9곳 **58군데**가 그랬다. 실제로 15px 로 적어 둔 목록이
13.333px 로 그려지고 있었다. `font-weight` · `font-size` · `line-height` ·
`font-family` 를 **따로 적는다.** 앱 CSS 도 한 번 훑어보길 권한다.

## 8-2. **실제로 돌려 본 결과** — 이 문서가 시킨 그대로

인계서를 쓰고 **엔진을 띄워** §3 이 시키는 배선 한 줄만 붙이고 돌렸다.
`extractFiles` 는 **일부러 안 붙였다** — 「`extractOneshot` 만 있어도 돈다」가
사실인지 보려고.

```
1) 프로젝트를 만든다        LP-DC-2026-001 · datacenter
2) 자료를 놓는다            등기부.png · 사업계획서.txt · 스캔.tif
3) POST …/scan             HTTP 200
     · 등기부.png    — 못 읽었습니다 — 이미지 파일 … 키가 필요합니다 (지금은 꺼져 있습니다)
     · 사업계획서.txt — 본문을 읽음
     · 스캔.tif      — 못 읽었습니다 — .tif 는 변환 없이는 못 읽습니다 …
     실제로 OCR 이 돈 파일: 0건
     문서 1건 · 값 4개 · empty=false
4) GET …/facts             HTTP 200 · 값 8개
     land.area_sqm    = 12450  [출처: 사업계획서.txt · 신뢰도 0.7]
     building.gfa_sqm = 38200  [출처: 사업계획서.txt · 신뢰도 0.7]
     investment.total = 2846   [출처: 사업계획서.txt · 신뢰도 0.7]
     capacity.power_mw= 6.5    [출처: 사업계획서.txt · 신뢰도 0.7]
5) 배선을 뺀 채 다시        HTTP 501 · 자료를 읽는 경로가 붙어 있지 않습니다 — 자료는 그대로 있으니 …
```

**확인된 것 넷**

1. **`extractOneshot` 하나만 있어도 돈다.** 문서가 말한 그대로다.
2. **값이 2단계까지 간다.** `GET /facts` 에 출처와 신뢰도까지 실려 나온다.
3. **키가 없어도 스캔은 돈다.** 글자 파일은 읽히고 **이미지만** 빠진다 —
   그 사실이 파일 단위로 적힌다.
4. **배선을 빼면 501 + 사람이 읽을 문장.** 조용한 성공이 아니다.

**이 실행에서 버그 하나를 잡았다.** 같은 파일이 「OCR 로 읽음」과 「못 읽음」
두 줄로 나왔다 — 시험은 그때도 전부 초록이었다. §3 「칸 읽는 법」이 그 결과다.
