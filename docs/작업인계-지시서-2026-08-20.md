## 1. 무엇이 달라졌나 — 커밋 16개를 다섯 덩어리로

### ① 자료 붙이기가 **둘**이 되고, 실제로 붙는다

전에는 갈래가 셋이었고 **셋 다 설명만**이었다. 차이는 알려 주는데 정작 거기서
올릴 수는 없어서, 자료를 넣으려면 「보고서 생성」 1단계로 되돌아가야 했다.

| 지금 | 무엇 | 플랜 |
|---|---|:--:|
| **폴더 지정** | 남의 저장소 파일을 **가리킨다.** 사본을 만들지 않는다 | 무료 · 〈2026-08-23 이름 변경: 폴더를 연결해서 → 폴더 지정〉 |
| **파일업로드** | 읽고 **바로 버린다**(1회성). 다시 못 쓴다 | 무료 |

★ **2026-08-21 에 셋이 되었다** — 「LinkPilot 프로젝트에서 가져오기」가 갈래로 올라왔다.
  [`작업인계-지시서-2026-08-21.md`](작업인계-지시서-2026-08-21.md) §2 를 본다.

- **「올려서 보관 [Pro]」는 화면에서 뺐다** 〈2026-08-20 사용자 결정〉.
  서버 API(`POST /sources`)는 **그대로 있다** — 화면이 그 길로 안 들어갈 뿐이다.
  되살리려면 `files.html` 의 `WAYS` 에 한 줄을 더한다.
- 이름은 **화면 한 곳**(`files.html` 의 `WAYS`)에서 나온다. 앱이 따로 적지 않는다.

### ② 앱 프로젝트에서 가져와 잇는다 (`appProjects` · `appLinks`)

프로젝트 고르기가 **두 무리**로 나뉜다.

```
프로젝트 ▾
  ├ ＋ 신규프로젝트          ← 맨 위. 한 줄 적어 새로 만든다
  ├ 보고서 프로젝트          ← 엔진에 이미 폴더가 있는 것
  └ 앱 프로젝트에서 가져오기  ← 앱이 내려준 딜 목록 (고르면 엔진 프로젝트를 만들어 잇는다)
```

**엔진은 앱 데이터를 못 읽는다.** 목록도 짝도 앱이 내려준다 (§2). 짝의 **저장도
앱이 한다** — 엔진에 저장하면 앱 데이터의 정본이 둘이 된다.

### ③ 「＋ 신규프로젝트」를 **고르는 자리 맨 위**에

전에는 「보고서 생성 1단계에서 먼저 만드십시오」였는데, **그 1단계가 다른 탭**이라
자료를 손에 든 채 탭을 옮겨야 했다 — 옮기면 고른 파일이 사라진다.

**몰래 만들지는 않는다.** 무엇을 만들지 한 줄을 받는다 — 그 문장에서 자산군이
정해지기 때문이다. 비운 채 만들면 자산군이 `GEN` 으로 굳고, 굳은 뒤에는 보고서
목차가 통째로 어긋난다.

### ④ 화면 아무 데나 떨어뜨려 올린다 + 올라가는 과정을 그래프로

**점선 상자를 조금만 빗나가면 브라우저가 그 파일을 탭에 열어 버렸다.** 화면은
통째로 사라지고 올린 것은 없다 — 아무 오류도 안 나므로 「기능이 없다」로 읽힌다.
이제 문서 전체에서 먼저 막고, **카드 바깥 어디에 놓아도** 받는다.

올리는 동안은 칸 넷이 차례로 켜진다:

```
[고른 파일] ──▶ [보내는 중] ──▶ [서버가 읽는 중] ──▶ [붙었습니다]
                 (회선 문제)      (파일 문제 — 스캔본이면 오래 걸린다)
```

막대 하나로는 **어디서 걸렸는지** 알 수 없다. 앞이 느린 것과 뒤가 느린 것은
원인이 다른데, 같은 막대로 그리면 고장으로 읽고 창을 닫는다. 아래에는 진행률을
시간축으로 그린 자취가 함께 뜬다 — **멈춘 구간이 평평하게 남는다.**

「폴더를 연결해서」도 같은 그래프를 쓴다
(`저장소 열기 → 파일 고르기 → 장부에 적기 → 붙었습니다`).

### ⑤ iframe 없이 앱 안에 바로 얹는 조각

`npm run im:inline` → `files-inline.html`. **문서 하나로 합친 조각**이다.
어느 쪽으로 얹을지는 §5 에서 고른다.

## 2. 본체가 채우는 것 — `window.LINKPILOT_FILES`

화면이 읽는 값은 **이 전역 하나뿐**이다. 다른 곳에 값을 박지 않는다.

| 항목 | 형태 | 없으면 | 이번에 새로 |
|---|---|---|:--:|
| `api` | `'/api/linkpilot'` | 서버를 안 부른다 (미리보기가 된다) | |
| `session` | `{ authenticated, name, planId, status }` | 「로그인이 필요합니다」 | |
| `inTab` | `true` | 제목을 한 번 더 그린다 | |
| `projectId` | 미리 정해 열 때 | 안 고른 상태로 뜬다 | |
| `requiredPlan` | `'free'` | — 자료 넣는 길은 **무료**다 | |
| **`appProjects`** | `[{ id, title, client, owner }]` | 「앱 프로젝트에서 가져오기」 **무리가 아예 안 나온다** (그게 정직하다) | ★ |
| **`appLinks`** | `{ <앱 딜 id>: <엔진 프로젝트 id> }` | **고를 때마다 새 엔진 프로젝트가 생긴다** — §8 ①을 반드시 읽는다 | ★ |
| **`fetchAppProject`** | `(appId) => Promise<{content, files, images}>` | 「앱에서 가져오기」가 **개수 0 으로** 뜬다 (목록에 실어 보내면 없어도 된다) | ★ |
| **`pickFrom`** | `(provider) => Promise<{ref, access}>` | 「폴더를 연결해서」가 안 열린다 | ★ |
| `preload` | `{ projects: [...] }` | `GET /projects` 를 부른다 | |

### 2-1. `pickFrom` 의 계약 — **열쇠를 장부에 넣지 않는다**

제공자 창(Dropbox·Box·구글·원드라이브)은 **앱이 연다.** 그쪽에 계정과 SDK 가 있고
엔진은 어느 계정인지 모른다.

```js
window.LINKPILOT_FILES.pickFrom = async function (provider) {
  const picked = await openChooser(provider);      // 앱이 가진 SDK
  return {
    // ① 장부에 남는다 — 열쇠를 담지 않는다
    ref:    { provider, fileId, name, rev, path, bytes },
    // ② 장부에 남지 않는다 — 서버가 잠깐 들고 있다가 스스로 버린다
    access: { url: 'https://…', headers: {}, expiresAt: 1755… },
  };
};
```

| | 어디에 | 얼마나 |
|---|---|---|
| `ref` | `linked.json` (장부) | 계속 |
| `access` | **메모리만** (`core/handoff.js`) | **30분** · 제공자 만료가 더 짧으면 그쪽 |

- `access.url` 은 **`https://` 만** 받는다. `file:` 이 들어오면 서버의 파일을 읽게 된다.
- `access` 없이 `ref` 만 보내면 **400 「이 파일을 읽을 접근권이 없습니다」**로 거절된다.
  연결만 되고 안 읽히면 사용자는 자료를 넣었다고 믿는데 보고서에는 안 실린다 —
  그게 제일 나쁘다.
- 서버가 내려가면 `access` 는 함께 사라진다. **그때는 다시 고르게 한다** —
  남으면 안 되는 것이 남아 있는 편보다 낫다.

### 2-1-2. 앱에서 가져오는 자료 — **셋** 〈2026-08-20 요청〉

앱 프로젝트 하나가 들고 있는 것을 **셋으로 나눠** 받는다. 한 덩어리로 받으면
무엇이 들어왔는지 사람이 모르고, **틀린 것 하나 때문에 전부를 되돌려야 한다.**

| | 무엇 | 어디로 | 라우트 |
|:--:|---|---|---|
| ① | **프로젝트 내용** | 값(fact)이 된다 | `PUT /projects/:id/facts` |
| ② | **첨부파일** | 연결 장부 (사본 안 만든다) | `POST /projects/:id/linked` |
| ③ | **이미지파일** | 〃 (`ref.kind = 'image'`) | 〃 |

```js
window.LINKPILOT_FILES.fetchAppProject = async function (appId) {
  return {
    content: {
      updatedAt: '2026-08-19',
      summary: '한 줄 설명',
      // ★ `key` 는 **엔진 사전의 항목 이름**이다. 앱이 아는 것만 넣는다
      facts: [{ key: 'land.area_sqm', value: 12709, unit: '㎡', quote: '…' }],
      // ★ 사전에 없는 자유 입력은 **여기로.** 값으로 넣지 않는다
      notes: ['현장 방문 소견'],
    },
    files:  [{ id, name, bytes, mime, ref, access }],
    images: [{ id, name, bytes, mime, ref, access }],
  };
};
```

- `ref`·`access` 의 뜻은 **`pickFrom` 과 같다** (§2-1). 규칙을 두 벌로 만들지 않는다.
- **`ref.provider` 는 서버가 알려 준다** — `GET /projects/:id/linked` 의 `appProvider`
  (지금 값은 `linkpilot-app`). 〈2026-08-21 정정〉 처음에는 이 값을 문서·화면·검증기
  **세 곳에 따로** 적어 두었고, **검증기만 그 이름을 몰라 첨부가 전부 거절됐다** —
  실기기에서 「첨부 0개」로 드러났다 (§8 ⑥). 이제 서버가 정본이다.
- **`ref.rev` 는 필수다.** 판이 없으면 거절된다 — 파일만 가리키면 원본이 바뀌어도
  문서에 아무 표시가 안 남는다. 앱은 자기 판 번호를 그대로 넣으면 된다.
- 이 출처는 **연결 단추에 뜨지 않는다.** 고를 창이 없고, 등록할 콘솔이 없고,
  넓어질 OAuth 범위도 없다 — `providers` 목록과는 다른 자리다.
- **엔진 라우트를 새로 내지 않았다.** 셋 다 이미 있는 길로 간다 — 길을 새로 내면
  인증·한도·거절 규칙이 두 벌이 되고, 한쪽만 고치는 날이 온다.
- **값에는 출처가 붙는다.** 앱에서 왔다는 것 자체가 출처다 —
  `LinkPilot 앱 · <딜 id> · <갱신일>`. 출처 없이 보내면 **서버가 거절하고, 그게 맞다.**
- **사전에 없는 항목은 값이 되지 않는다.** 억지로 끼워 맞추면 문서에 「출처 있는
  값」으로 실린다. 그런 것은 `notes` 로 보내면 화면이 **「가져오지 않습니다」**라고 적는다.
- 목록(`appProjects`)에는 **개수만** 실어도 된다. 딜 54건의 첨부를 탭 열 때 전부
  내려받으면 여는 데만 한참 걸린다.

## 3. 본체가 **받아야** 하는 알림 — 셋

같은 출처면 `postMessage`, iframe 없이 얹었으면 `CustomEvent`. **두 갈래로 다 쏜다.**
앱은 **둘 다 받아 두면** 얹는 방식을 바꿔도 안 끊긴다.

| 이름 | 언제 | 실린 것 | 앱이 할 일 |
|---|---|---|---|
| `lp-files-project` | 프로젝트를 고를 때마다 | `{ projectId }` | **기반정보 내보내기**가 같은 것을 가리키게 한다 |
| **`lp-app-project-linked`** | 앱 딜 ↔ 엔진 프로젝트가 **처음 이어질 때** | `{ appProjectId, imProjectId }` | **짝을 저장한다.** 다음에 `appLinks` 로 다시 내려준다 |
| **`lp-open-project`** | 자료를 읽고 나서 **2단계로 옮길 때** 〈2026-08-21 추가〉 | `{ projectId, section:'make', step:'fields', why:'scan' }` | **탭을 바꾼다.** 받았으면 `preventDefault()` 로 답한다 |
| `lp-embed-height` | 조각/iframe 높이가 바뀔 때 | `{ height }` | iframe 을 그만큼 늘린다 (조각으로 얹으면 불필요) |

```js
window.addEventListener('message', (e) => {
  if (e.origin !== window.location.origin) return;      // 다른 출처는 버린다
  const m = e.data || {};
  if (m.type === 'lp-app-project-linked') saveLink(m.appProjectId, m.imProjectId);
  if (m.type === 'lp-files-project')      setExportTarget(m.projectId);
});
document.addEventListener('lp-app-project-linked', (e) => saveLink(e.detail.appProjectId, e.detail.imProjectId));
document.addEventListener('lp-files-project',      (e) => setExportTarget(e.detail.projectId));

// ★★ 탭을 바꿔 준 뒤 **preventDefault() 로 답해야 한다** 〈2026-08-21〉.
//   답하지 않으면 화면은 「아무도 안 받았다」로 보고 "위 탭에서 눌러 주십시오"를
//   띄운다. 바꿔 놓고 답을 안 하면 **바뀐 화면 위에 그 안내가 뜬다**
document.addEventListener('lp-open-project', (e) => {
  openTab(e.detail.section, { projectId: e.detail.projectId, step: e.detail.step });
  e.preventDefault();                                  // ← 이것이 「받았다」의 증거
});
```

★ **프로젝트 고르는 곳은 탭에 하나여야 한다.** 앱이 「기반정보 내보내기」쪽에
고르기를 하나 더 두면, 둘이 다른 것을 가리키는 순간 사용자는 **어느 프로젝트의
기반정보를 받았는지 모른다.** 받아 간 파일에는 그 사실이 안 적힌다.

## 3-2. 자료 스캔 — **넣은 것을 값으로 만든다** 〈2026-08-21 추가〉

### 무엇이 달라졌나

전에는 자료를 **넣기만** 되고 읽히지 않았다. 읽는 것은 보고서를 만드는 순간이라,
자료를 넣은 사람이 2단계에 가면 **빈 칸만** 봤다 — 값이 없는 것이 아니라 아직 안
읽은 것인데, 화면은 그 둘을 구분해 말하지 못했다.

지금은 셋(앱에서 가져오기 · 폴더 연결 · 파일업로드) 중 무엇으로 넣든 **한 길로**
읽어 값으로 만들고, 값이 들어가면 「보고서 생성」 2단계로 넘긴다.

### 본체가 붙일 것 — **한 줄이다**

```js
// 1회성(oneshot)에 이미 붙여 둔 것과 **같은 함수**다. 이름만 다르다
extractFiles: (projectId, files) => pipeline.extractInto(projectId, files),
```

- `extractFiles` 가 없으면 `extractOneshot` 을 쓴다 — 이미 붙여 두었으면 **그대로 돈다.**
- 둘 다 없으면 **501 을 준다.** 0건 성공을 주지 않는다 — 주면 화면은
  「읽었는데 값이 없다」로 그리고 사용자는 자기 자료를 탓한다.

### 새 길 하나 — `POST /projects/:id/scan`

| | |
|---|---|
| 무엇을 읽나 | ① 보관 자료(`02_Source_Data`) ② 연결 자료 ③ 앱에서 가져온 첨부(②와 같은 길) |
| 1회성은 | **여기 안 온다.** 올리는 그 자리에서 이미 읽었고 파일을 버렸다 — 응답이 그렇게 적어서 온다 |
| 연결 사본 | 읽고 **반드시 지운다.** 읽다 죽어도 지운다 |

```json
{ "scanned": [{ "name": "등기부.png", "how": "ocr", "ocr": true, "readable": true, "note": "…" }],
  "unread":  [{ "name": "감정평가서.pdf", "why": "원본을 찾을 수 없습니다", "from": "linked" }],
  "facts": 12, "documents": 3, "empty": false,
  "oneshotNote": "1회성으로 올린 자료는 올릴 때 이미 읽었습니다 …" }
```

★★ **「전부 OCR 한다」가 아니다.** OCR 은 이미지·스캔본에만 건다. 글자가 든
PDF·워드·엑셀을 굳이 옮겨 적으면 **신뢰도만 깎인다**(`core/ocr.js`). 그래서
파일마다 `ocr` 을 따로 준다 — 화면도 그대로 보여 준다.

★ **값이 0이면 화면이 넘어가지 않는다.** 넘어가면 2단계에서 빈 칸만 보고
사용자는 자기가 뭘 잘못한 줄 안다. 대신 무엇을 못 읽었는지를 그 자리에서 보여 준다.

## 5. 얹는 법 — 둘 중 하나를 고른다

| | iframe + 브리지 | **조각** (`im:inline`) |
|---|---|---|
| 만드는 법 | `npm run im:embed` | `npm run im:inline` |
| 설정 | 부모에 `window.LINKPILOT_EMBED` | 앱이 `window.LINKPILOT_FILES` 를 **먼저** 채운다 |
| 스크롤 | 높이를 앱이 맞춰야 한다 (`lp-embed-height`) | **하나뿐** |
| CSS | 완전히 격리 | `#lp-files` 아래로 **가둬서** 낸다 |
| 알림 | `postMessage` | `CustomEvent` |
| **파일 끌어다 놓기** | iframe 경계를 넘어야 한다 — **§8 ②를 읽는다** | 문제 없다 |

**끌어다 놓기를 쓸 거면 조각을 권한다.** iframe 은 브라우저·확대배율에 따라
드래그가 경계에서 죽는 경우가 있고, 그때 아무 오류도 안 난다.

조각 쪽 주의 하나: 앱은 `window.LINKPILOT_FILES` 를 **조각보다 먼저** 채운다.
조각 안의 설정 블록은 **대입이 아니라 병합**으로 바뀌어 나오므로 앱 값이 이긴다.

## 8. 조용히 무너지는 것들 — **오류가 안 나서 더 위험하다**

### ① `appLinks` 를 앱이 저장하지 않으면 — **프로젝트가 계속 새로 생긴다** 🔴

짝의 저장은 **앱 몫**이다. 앱이 `lp-app-project-linked` 를 받아 두지 않으면,
같은 딜을 고를 때마다 엔진 프로젝트가 **하나씩 새로 만들어진다.**

- 화면은 멀쩡하다. 오류도 안 난다.
- 사용자는 **「어제 올린 자료가 사라졌다」**고 말하게 된다. 사라진 것이 아니라
  **다른 폴더를 보고 있는 것**이다.
- 번호도 계속 소모된다.

**⑯ 을 반드시 실측한다.** 탭을 닫았다 다시 열어야 의미가 있다 — 안 닫으면
화면이 메모리에 들고 있던 짝으로 맞춰 준다.

### ② 앱이 `document` 에 자기 drop 핸들러를 걸고 있으면

화면은 문서 전체에서 `dragover`·`drop` 을 받아 `preventDefault()` 한다.
앱이 먼저 잡아 `stopPropagation()` 하면 **떨어뜨리기가 죽는다** — 오류는 없다.

iframe 으로 얹었을 때도 같은 종류의 문제가 난다 (§5).

### ③ Free 계정이 앱 프로젝트를 고르면 **탭 전체가 잠긴다** 🔴

「자료 업로드」는 **무료** 탭인데, 앱 프로젝트를 고르면 엔진 프로젝트를 만들려고
`POST /projects` 를 부른다. 이 길은 **Pro 부터**다.

지금 코드는 그 403 을 **화면 전체 게이트**로 올린다. 그러면 Free 사용자는
「Pro 부터입니다」 카드만 보게 되고, **이미 있는 프로젝트에 자료 붙이는 것까지
막힌다.** 새로고침해야 돌아온다.

- 「＋ 신규프로젝트」쪽은 **그 칸에서만** 말하도록 되어 있다 (`localGate`).
- **`pickAppProject` 도 같게 할지 정해야 한다.** 등록부에 올렸다 (§10 D-71).
- 정하기 전까지는 **양쪽 다 고치지 않는다** (CLAUDE.md §9).

### ③-2 제공자 단추가 눌리는데 아무 일도 안 나면 🔴 **고쳤다**

실서버에서 Dropbox·Box·Google·OneDrive 단추 넷이 멀쩡히 떠 있었고, 누르면
**브라우저 탓을 하는 문장**이 떴다 (2026-08-20 실측). 브라우저는 아무 상관이
없었다 — 두 겹으로 막혀 있었다:

1. 앱이 `pickFrom` 을 아직 안 넘겼다 (§2-1)
2. 넘겼더라도 **제공자 콘솔 등록**이 안 되어 있다 (§2-2)

그런데 화면은 **누를 수 있는 단추 넷**을 그렸고, 원인을 틀리게 말했다. 사용자는
그 문장을 읽고 브라우저를 바꾸러 간다. **틀린 원인을 말하는 것이 아무 말도 안
하는 것보다 나쁘다.**

고친 것 셋:

- **서버가 제공자마다 `configured` 를 말한다.** 키가 있는지는 서버만 안다.
  값이 아니라 **환경변수 이름(`keyEnv`)만** 내보낸다.
- **열 수 없는 단추는 눌리지 않는다.** 무엇이 빠졌는지 한 줄로 적는다.
- **지금 되는 길을 알려 준다** — 「파일업로드」 갈래. 이름은 화면이
  `wayName('oneshot')` 으로 **표에서 가져온다**(2026-08-21) — 문장에 손으로 적지 않는다.

★ 옛 서버가 `configured` 를 안 주면 **막지 않는다.** 모르는 것을 「안 된다」로
그리면 되는 것까지 못 쓰게 된다.

### ⑥ 같은 값을 문서·화면·검증기에 **따로** 적으면 🔴 **고쳤다**

2026-08-21, 본체 실기기에서 앱 첨부 2개를 골라 [가져오기] 했더니
**「값 0개 · 첨부 0개 · 이미지 0개」**가 나왔다. 사유는 항목마다 이렇게 떴다:

```
· 금호클래식카 회사 소개서.pdf — 모르는 저장소입니다 (dropbox · box · gdrive · onedrive 중 하나)
```

문서(§2-1-2)와 화면은 `linkpilot-app` 으로 정했는데 **검증기
(`connectors/storage.js`)만 그 이름을 몰랐다.** 같은 값이 세 곳에 따로 적혀
있었기 때문이다.

고친 것 넷:

- **아는 목록과 고르는 목록을 갈랐다.** `KNOWN`(참조를 받을 때) ≠
  `PROVIDER_IDS`(단추를 그릴 때). 앱 출처는 앞에만 있다.
- **출처 이름을 서버가 정한다** — `GET /linked` 의 `appProvider`. 화면은 그 값을
  먼저 쓰고, 안 주는 옛 판을 위해 같은 값을 대비로 들고 있다(검사가 대조한다).
- 출처 한 줄이 코드값이 아니라 이름으로 나온다 —
  `LinkPilot 앱 · <path> · 판 <rev> · <읽은 날> · sha256 … · 사본 보관 안 함`.
- 범위(scope) 검사는 **해당 없음**으로 답한다. 「검사했다」로 넘기지 않는다.

★★ **왜 미리보기에서 안 잡혔나** — 데모 서버가 진짜보다 너그러웠다.
`provider === 'linkpilot-app'` 이면 그냥 받아 줬고, 데모 참조에는 `rev` 도
없었다. 미리보기는 초록, 실기기만 빨강. 이제 데모 서버가 **진짜 목록을 심어
같은 기준으로** 거절한다 — 고치자마자 `rev` 누락이 바로 잡혔다.

### ④ 탭 이름을 앱이 따로 적고 있으면

실서버에 **「새 보고서 생성」**이 남아 있었다 (2026-08-20 실측). 이름은
`flow-core.js` 의 `TABS` **한 곳**에서 나온다. 앱이 적는 순간 갈리는 날이 오고,
그날 아무도 눈치채지 못한다. 앞 문서 §6 ⑦-2 로 **글자 그대로 대조한다.**

### ⑤ 「200 이 왔다」를 「최신이 올라갔다」로 읽는 것

`npm run verify:nas` 는 **지문(sha256)을 저장소와 대조한다.** 상태코드만 보면
**옛 판이 그대로 서빙되는 것을 못 잡는다** — 실제로 「11통과 0실패」가 나온
서버가 통째로 옛 판이었다.

| **NAS 실측** | **못 했다.** 이 세션에서 NAS 로 나가는 길이 프록시에 막힌다. `npm run verify:nas -- --base $LP_BASE` 는 **본체가 직접 돌려야 한다** |
| **앱 안에서의 동작** | 못 했다. 화면 단위로는 헤드리스 크로미움으로 실제 떨어뜨리고 올려서 확인했지만, **앱에 얹은 상태**는 §8 ②가 남아 있다 |
| **제공자 chooser** | 못 했다 — 계정과 SDK 가 앱에 있다. 엔진은 `access.url` 을 받는 쪽까지만 확인했다 |

**확인한 것:** 테스트 1368/1368 · 고아 모듈 0 · 실제 브라우저에서 카드 바깥에
떨어뜨려 붙는 것과 그래프가 네 칸을 끝까지 가는 것. 그 검사가 **실제로 깨지는 것**
(떨어뜨림 처리를 지우면 빨개진다)까지 확인했다 — 「부르지 않는 테스트」가 아니다.

## 12. 막히면 — 보고할 것
