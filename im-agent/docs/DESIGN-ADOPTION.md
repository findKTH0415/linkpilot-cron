# PDI 디자인 시스템 · IM RULES 적용 분석 (교차검증 결과)

검토 대상 4종:

| 문서 | 성격 | 이 저장소 적용 |
|---|---|---|
| `PDI SOLAR REPORT SPEC v1.0` | 주소 입력 → 리포트 대량생성 디자인 규격 | **핵심 원리 채택** |
| `design_handoff_grand_hyatt/README.md` | A4 IM hifi 디자인 핸드오프 | **디자인 토큰·구조 채택** |
| `STRUCTURE.md` | IM 표준 폴더구조 · 뷰/데이터 분리 | **데이터 계약 채택** |
| `IM RULES (25개 규칙)` | 뷰어·공유카드 운영 규칙 | **절반만 해당** — §3·§4·§5 제외 |

---

## 1. 결론

**디자인 시스템은 그대로 쓸 수 있다.** 두 핸드오프(Grand Hyatt / 태양광)의 팔레트·타이포·
페이지 구조가 동일하고, 이 저장소가 이미 만들고 있던 산출물(절 단위 마크다운 + 수치 출처표)과
구조적으로 충돌하지 않는다.

**IM RULES는 절반이 적용 대상 밖이다.** 25개 규칙 중 §3(뷰어 상단바)·§4(공유카드 share.php)·
§5(UI 신호)는 NAS 뷰어와 카카오톡 인앱 창의 규칙이다. 이 저장소는 뷰어를 만들지 않고
**데이터와 문서를 생산**하므로, 그 규칙들을 억지로 가져오면 쓰이지 않는 코드만 남는다.

가장 큰 수확은 디자인이 아니라 **태양광 스펙 §7~§10에 적힌 실전 사고 기록**이다.
이건 다른 곳에서 얻을 수 없는 자산이고, 그중 두 개는 이 저장소에 그대로 해당했다.

## 2. 충돌 교차검증

### 2-1. 실제 충돌 — 수정함

| # | 충돌 | 근거 | 조치 |
|---|---|---|---|
| C1 | **매스 SVG가 아침 브리핑 팔레트(`#C00000`/Arial)를 씀** | IM은 Navy `#10233C` + Gold `#A6813C` 체계. 브리핑 팔레트가 IM에 섞이면 핸드오프와 어긋난다 | `geo/mass.js` 를 디자인 토큰으로 재도색. glTF 재질·SVG·폰트 전부 교체. 게이트 `D5-palette` 로 재발 차단 |
| C2 | **IM 본문에 `⚠` 기호 사용** | 핸드오프·CLAUDE.md §6 모두 대외 문서 이모지 금지 | 감정평가 고지에서 제거. 게이트 `D3-no-emoji` 로 차단 |
| C3 | **표에 `자료출처:` 캡션 없음** | 핸드오프 공통 규칙 — 출처 없는 표는 IM에서 근거가 없는 것과 같다 | 재무·민감도·위험·입지·매스·감정평가·부록 전 표에 캡션 추가. 게이트 `D2-caption-prefix` |

C1~C3은 전부 **게이트를 먼저 만든 뒤 실제로 검출된 것**이다. 규칙만 문서에 적었다면
그대로 배포됐을 위반이다.

### 2-2. 겉보기 충돌 — 실제로는 아님

| # | 겉보기 충돌 | 판정 |
|---|---|---|
| N1 | CLAUDE.md `폰트 Arial/맑은 고딕, 포인트 #C00000` vs 핸드오프 `Noto Serif/Sans, Navy/Gold` | **적용 대상이 다르다.** 전자는 카카오톡 인앱 모바일 브리핑, 후자는 A4 인쇄 IM. 단 IM에 들어가는 산출물은 반드시 후자를 따라야 한다(→ C1) |
| N2 | CLAUDE.md `브리핑은 이모지 가능` vs 핸드오프 `이모지 금지` | CLAUDE.md §6이 이미 "대외 발송 문서는 PDI 하우스 스타일 적용"으로 구분해 둠 |
| N3 | 태양광 스펙 `§7 값 단독 치환 사고` | 이 저장소는 `{{key}}` 자리표시자 치환이라 **구조적으로 그 사고가 나지 않는다.** 값이 아니라 key로 치환하므로 `6.5%`가 할인율인지 IRR인지 헷갈릴 수 없다 |

### 2-3. 운영 충돌 — 채택하지 않음

| # | 충돌 | 이유 |
|---|---|---|
| X1 | **IM RULES §8: "정본은 NAS `/web/`"** | CLAUDE.md는 *NAS 불안정 때문에* GitHub Actions로 이관했다고 명시한다. 이 저장소가 NAS 배포를 구현하면 이관 사유를 되돌리는 것이다. → 산출물만 만들고 배포는 기존 `deploy-filestation.py` 흐름에 넘긴다 |

| X3 | **25개 Agent 전면 확장** | 데이터 소스가 없는 Agent를 만들면 껍데기만 남는다. 기존 9개에 흡수하고 미구현은 `PLANNED`로 정직하게 노출 |

### 2-4. 규격 자체가 서로 다른 것 — 정본을 정함

| 항목 | Grand Hyatt IM | 태양광 리포트 | 채택 |
|---|---|---|---|
| 금액 표기 | `1,634.3억원` / `1조762.4억원` | `28억 9,173만원` | **IM = Grand Hyatt 규칙**. 태양광 규칙은 `eokManwon()` 으로 별도 제공 |
| H1 크기 | 48px | 46px | IM 기준 48px |
| 챕터 수 | 13장 | 13장 | 자산유형별 프로파일로 분리 (현재 IM 20절) |

**챕터 수는 통일하지 않았다.** 호텔 IM 13장 · 태양광 리포트 13장 · 요청 사양 25절 ·
현재 구현 20절이 각각 다르다. 하나로 강제하면 어느 하나는 반드시 맞지 않는다.
`templates/im-outline.js` 를 문서유형별 프로파일로 쓰는 것이 맞다.

## 3. 채택한 것 (효과가 확인된 요소만)

### 3-1. 디자인 토큰 단일 소스 — `design/tokens.js`

두 핸드오프의 팔레트가 같으므로 하나로 통합했다. 색·크기를 코드 곳곳에 하드코딩하지 않는다.
IM RULES §4-10의 교훈("색을 눈대중으로 바꾸면 다음 화면과 어긋난다")을 코드로 강제한다.

### 3-2. A4 인쇄 HTML — `design/a4.js`

핸드오프 페이지 구조 그대로: 표지 → IMPORTANT NOTICE → 목차 → Chapter → 연락처(END).
챕터 오프너 `break-before: page`, 서명부(로고+3줄 가로 배치, IM RULES §1), 표 괘선 규격,
`print-color-adjust: exact`.

> 핸드오프는 `doc-page.js` 가 인쇄 기하를 소유하지만 그 런타임이 이 저장소에 없다.
> 그래서 산출물을 **두 갈래**로 낸다 — 자립형 A4 HTML(이 파일) / 기존 뷰어용 content.json.

### 3-3. 뷰/데이터 분리 — `design/content.js`

STRUCTURE.md의 핵심 원칙("수치 갱신은 JSON만 수정")에 맞춰 `content.json` 을 생산한다.
**뷰어를 다시 만들지 않는다.** 기존 `design_handoff_*/build/` 에 넣으면 그 뷰어가 그대로 렌더한다.
`sources[]` 에 `S001` 형태 참조번호를 붙여 요청 사양 §22(Source-to-IM Traceability)를 만족시킨다.

### 3-4. 규칙 단일 소스 + 게이트 — `design/rules.json` + `design/check.js`

IM RULES의 가장 좋은 패턴을 그대로 가져왔다: **규칙의 단일 소스는 JSON이고, 게이트와 문서가
같은 파일을 읽는다.** 규칙을 바꾸려면 JSON만 고친다.

RED 위반은 승인 게이트가 배포를 막는다(`core/gate.js`). 그리고 **게이트를 시험하는 테스트**를
같이 뒀다(`test/design.test.js`) — 일부러 위반을 만들어 실제로 검출되는지 확인한다.
IM RULES의 "게이트를 만들었으면 게이트를 시험해야 한다"를 따른 것이다.

### 3-5. 서식 적용 구간 안내 — 태양광 스펙 §10

> "값은 토큰으로 갈아끼워지지만 서술문은 그대로 남는다.
>  숫자는 게이트가 지키지만 문장은 지킬 수 없다."

이 저장소에 **그대로 해당한다.** 자산유형 템플릿의 기본 가정(공사기간·금리·Cap Rate)은
특정 규모대를 전제로 한다. 사업이 그 구간을 벗어나면 수치는 맞아도 서술이 다른 구간 기준이 된다.
→ `SCALE_BANDS` 를 두고, 벗어나면 IM 첫머리와 표지에 그 사실을 밝힌다.
구간 안이면 빈 문자열이라 문서가 달라지지 않는다.

### 3-6. Confidence A~E 등급 — 요청 사양 §27

**이중 관리하지 않는다.** 등급은 기존 `(confidence 0~1 + verified + source)` 에서 파생되는
표시 계층일 뿐이다. 두 곳에 따로 적으면 반드시 어긋난다.

```
A = 공적장부·감사자료·계산결과 (verified)
B = 신뢰할 수 있는 외부 출처 (단일 출처)
C = 문서 기반 추정
D = 템플릿 통상치·모델 가정
E = 출처 미확인  ← 본문 사용 금지
```

샘플 실행 실측: A 5건 / B 26건 / D 7건 / E 0건.

### 3-7. "빈칸이 정보다" — 태양광 스펙 §9

> "Pre-DD는 **무엇이 확인되지 않았는지**를 보여주는 문서다 — 빈칸이 정보다.
>  데이터에 없는 항목을 '충족'·'양호' 등으로 채우지 않는다."

이 저장소의 `[미확인]` / `[미검증]` 표기와 정확히 같은 철학이다. 이미 구현돼 있어 추가 작업은
없었지만, 이 문장이 설계 원칙을 가장 잘 요약한다.

## 4. 채택하지 않은 것과 그 이유

| 항목 | 이유 |
|---|---|
| 뷰어 상단바·닫기 FAB·번역 UI (IM RULES §3) | `index.html` 규칙. 이 저장소에 뷰어가 없다 |
| 공유카드 share.php 규칙 (§4·§5) | 카카오톡 인앱 창 규칙. 적용 대상 밖 |
| NAS 정본·deploy-filestation 게이트 (§8) | CLAUDE.md의 GitHub Actions 이관 사유와 충돌. 배포는 기존 흐름 유지 |
| 통화 USD 자동 변환 (§7) | 뷰어 런타임 기능. content.json 에 원화 원본을 그대로 담으면 기존 뷰어가 처리한다 |
| 태양광 리포트 13장 고정 구조 | 자산유형이 다르다. 태양광 프로파일이 필요해지면 그때 `im-outline` 에 프로파일로 추가 |
| 25개 Agent 전면 확장 | 데이터 소스 없는 Agent는 껍데기가 된다. 기존 9개에 흡수 |

## 5. 남은 과제

1. **doc-page.js 정합** — 기존 뷰어로 렌더할 때의 페이지네이션은 그쪽 런타임이 소유한다.
   자립형 A4 HTML과 뷰어 렌더 결과가 페이지 단위로 같은지는 실물 대조가 필요하다.
2. **PDI 로고 자산** — 현재 서명부는 텍스트 대체(`PDI` 원형)다. `pdi-logo.png` 를 받으면 교체한다.
3. **폰트** — Noto Serif/Sans KR 을 Google Fonts로 참조한다. 오프라인 인쇄 환경에서는
   자체호스팅(STRUCTURE.md의 Pretendard 방식)이 필요할 수 있다.
4. **챕터 프로파일** — 부동산개발 25절 프로파일은 요청 사양에 있으나 현재는 20절 IM 하나뿐이다.
   자산유형별로 분리할지는 실제 배포 문서를 보고 결정하는 게 맞다.
