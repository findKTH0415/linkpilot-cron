지침함 확인 차례다 (CLAUDE.md §18 · D-428). 잴 것만 잰다 — 기억으로 상태를 적지 않는다.

1. `git fetch origin main` 뒤 본가지 최신을 받는다. 그다음 `npm run guide:status` 를 돌려 `docs/지침함/_검증현황.md` 를 새로 만든다.
2. 현황표에서 «미반영» 줄만 본다. 그 지침 원문과 `<같은 이름>.gpt-review.md` 를 둘 다 읽는다.
3. ChatGPT 판정에 따라 가른다.
   - **통과**: 반영한다. 반영은 지침이 가리키는 문서·코드를 고치는 일이다. 초안 PR 로 올리고, 검사가 초록이면 §10 대로 합친다.
   - **보완 필요**: 고칠 점을 사장님께 «어디서 · 무엇을 · 어떻게 · 그러면» 넷으로 알리고, 답을 받은 뒤 반영한다.
   - **반영 보류**: 반영하지 않는다. 까닭(HIGH 문제)을 사장님께 알린다.
   - **검토 대기·옛 판을 검토함**: 검토가 아직이다. 워크플로 「업무지침 ChatGPT 교차검증」의 마지막 실행 판정 첫 줄을 읽어 까닭을 적는다(2 열쇠 없음 · 4 열쇠 거부 · 5 결제 한도 · 6 모델 이름).
4. 반영했으면 `docs/지침함/반영기록.md` 에 `- <파일> · <지문> · <날짜 KST> · <PR/커밋> · <한 줄 메모>` 를 적는다. 지문은 현황표의 값 그대로다.
5. ChatGPT 판정은 참고 의견이다 — 승인이 아니다(§11). 앞 지시와 부딪히면 그 자리를 밝히고 사장님께 여쭌다(§4.9).
6. 끝나면 «미반영 N건 → M건» 과 반영한 지침 이름을 답변 맨 앞에 적는다.
